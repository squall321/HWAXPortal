상태 **계획 확정 전 — 착수 보류**. 구현 착수는 §6 착수 게이트 통과 후.

## 0. 선행 검토와의 관계 — 본 계획이 다루는 계층

2026-07-21 GLM 튜닝 검토가 이미 심의 품질을 한 차례 진단하고 조치했다. 그 결과물이 `deliberation.py` 의 **품질 손잡이 7종**이며, 전부 기본 꺼짐 상태로 env 게이트에 시드되어 있다.

`DELIB_EVIDENCE_PREPASS`(T1 근거 선주입) · `DELIB_REBUT_QUOTE`(T2 반박 인용 계약) · `DELIB_PROSE_FIRST`(T3 산문 선행) · `DELIB_CROSS_EXAM`(2R 교차심문 — 지목 표적의 원본 전체에 반박) · `DELIB_ANCHOR`(3R 입장 앵커 재주입) · `DELIB_CHAIR_BESTOF`(의장 best-of-n) · `DELIB_CHAIR_CITE`(결정문 출처 태깅)

꺼둔 이유도 코드와 문서에 남아 있다 — **"GLM급은 다중 제약에서 지시 추종 예산이 분산돼 기법 적층이 상쇄된다(단일 변수 A/B만)"**. 그리고 실행 순서가 **T0 계측 하네스(비용 0, 선행 필수) → T1 → T2 → T3 → T4 → T5 → T6** 로 규정되어 있다.

### 0-1. 두 계획의 경계

| 계층 | 다루는 것 | 소관 |
|---|---|---|
| **A. 발언 품질** | 한 라운드 안에서 무엇이 어떻게 말해지는가 — 프롬프트 계약, 절단, 반박 형식, 근거 주입, 의장 합성 | **선행 검토(T0~T6)**. 본 계획은 신규 조치를 넣지 않는다 |
| **B. 좌석 구성** | 누가 그 방에 앉는가 — 페르소나 선정, 이어하기 좌석 재심사, 승계, 신규 좌석 앵커링 | **본 계획의 고유 영역**. 선행 검토가 다루지 않았다 |
| **C. 산출물 표기** | 독자가 근거의 강도를 알 수 있는가 — 근거 등급, 투표 형식 | 본 계획 |
| **D. 사람 개입** | 심의 도중 사람이 방향을 줄 수 있는가 | 본 계획 |

### 0-2. 계층 B 가 "동시 적용 금지" 제약을 받지 않는 이유

선행 검토의 단일 변수 A/B 원칙은 **프롬프트 안의 제약이 늘어날수록 GLM 의 지시 추종 예산이 분산된다**는 관찰에서 나왔다. 계층 B 의 조치는 프롬프트 제약을 늘리는 것이 아니라 **참가자 집합을 바꾸는 것**이다. 각 페르소나가 받는 지시문의 복잡도는 그대로다. 따라서 계층 B 는 T-서열과 간섭하지 않으며 병행 진행할 수 있다.

계층 C 중 근거 등급 표기는 의장 프롬프트에 규칙을 하나 더하므로 계층 A 에 간섭한다. 이 항목만 T-서열 안에서 다룬다.

### 0-3. 선행 검토가 이미 짚은 것 — 본 계획에서 중복 제거

작성 과정에서 제안했다가 기존 조치와 중복임이 확인되어 철회한 항목이다.

| 철회 항목 | 기존 대응 |
|---|---|
| 라운드 간 반박 원문 전달 | `DELIB_CROSS_EXAM` 이 이미 구현. 지목 표적의 직전 라운드 발언 **전문**을 주고 반박하게 한다(라운드로빈 배정). 제안했던 것보다 강한 형태다 |
| 결정문 출처 태깅 | `DELIB_CHAIR_CITE` 이미 구현 |
| 반대 심문관 좌석 | 선행 검토가 "전담 챌린저"로 검토하고 **조건부 보류**했다 — 판정자가 같은 GLM 이라는 상한 + 근거 팩 전제 |
| 모델 다양화로 상관 오류 완화 | 선행 검토가 "원리적 한계 — 모델 교체 없이 불가"로 이미 규정 |
| 평가 세트 | **T0 계측 하네스와 동일**. 다만 선행 검토는 이를 *선행 필수*로 두었고 본 계획 초안은 후순위로 두었다 — 초안이 틀렸으므로 선행 검토를 따른다 |

## 1. 진단 — 관측된 결함

S26U 화면 붉어짐 심의 2회(본심의 3라운드 + 이어하기 2라운드, 총 20 에이전트)를 사례로 평가했다.

### 1-1. 잘 작동한 것 — 유지해야 할 자산

- **교차 반박이 실제로 오류를 죽였다.** 2라운드에서 `sw-color-management` 가 자신이 1라운드에 세운 "스크린샷 무재현 = 비SW" 등식을 철회했다. 4개 도메인에서 동시에 반례가 들어온 결과다. 단일 응답 경로에는 이 과정이 구조적으로 없다.
- **선택지 밖 모드를 발굴했다.** `disp-burnin` 이 제기한 "보상 이력 오염"은 제시된 5개 후보 어디에도 없던 은닉 모드였다.
- **독립 수렴이 교차 검증 역할을 했다.** `disp-burnin` 과 `disp-color-calibration` 이 서로 다른 논리로 동일 문턱(0.0005 Δu'v'/주)에 도달했다.
- **양보 불가 항목이 운영 조항이 됐다.** "리셋 전 교체 금지", "파형 미고정 측정 무효" 는 그대로 지침에 넣을 수 있는 문장이다.

주의할 점 — 위 성과는 손잡이 7종이 **전부 꺼진 상태**에서 나왔다. 기본 구조 자체는 작동하고 있다.

### 1-2. 계층 B·C·D 의 결함 — 본 계획의 대상

결정문 품질을 다음 인과 사슬로 본다. 앞 단계가 뒤 단계의 상한이다.

```text
좌석 구성 ──▶ 근거의 질 ──▶ 발언·상호작용 ──▶ 합성 ──▶ 결정문
 (천장)                      (선행 검토 소관)
```

착석하지 않은 전문가는 어떤 라운드 수로도, 어떤 손잡이로도 만들어낼 수 없다. 그래서 좌석 계층이 최상단이다.

| # | 결함 | 근거(관측) |
|---|---|---|
| D1 | **페르소나 선정이 천장을 정하는데 단일 무검증 호출이다.** `recommend_agents(q=question)` 결과 상위 N명(기본 5)을 그대로 착석시킨다. 질문의 어휘가 도메인을 고정하고, 그 도메인 밖 가설은 발생 경로 자체가 없다 | S26U 심의는 디스플레이 6인만 착석했다. 재료·화학·신뢰성 좌석이 없었고, 그 결과 현재의 주가설(산소 소광)이 5라운드 동안 한 번도 제기되지 않았다 |
| D11 | **이어하기에서 좌석이 고정된다 — D1 이 증폭되는 지점.** 웹 경로는 `continue_personas` 가 있으면 발굴을 통째로 건너뛴다. MCP 경로는 좌석을 항상 호출자가 준다. 코드 주석이 근거를 밝히고 있어 의도된 설계이나(스티어링 일관성), 사람 의견이 주제를 다른 도메인으로 옮겨도 명단이 따라가지 못한다 | S26U 경시성 이어하기의 `humanNote` 는 5개 항목을 요구했고 그중 ④ 보증·교체(서비스 운영)와 ⑤ 모니터링(필드 텔레메트리)은 착석 6인 누구의 담당 범위도 아니었다. 페르소나 프롬프트는 "영역 밖은 아는 척 금지"를 명시하는데 그 영역을 담당할 좌석이 없어, 디스플레이 전문가가 서비스센터 운용 기준을 답하는 형태가 됐다 |
| D12 | **이어하기 승계가 호출자가 만든 텍스트 요약 한 덩어리뿐이다.** `continueFrom: {summary, roundsSoFar}` 에서 `roundsSoFar` 는 번호 오프셋일 뿐이고, 이전 논의는 `summary` 문자열이 전부다. 원문 발언·양보 불가 조항·소수의견은 요약에 넣지 않으면 소실된다 | S26U 이어하기 요약은 사람이 손으로 구성하고 7000자로 절단했다. 양보 불가 조항이 승계된 것은 작성자가 그렇게 선택했기 때문이며 구조가 보장한 것이 아니다 |
| D13 | **신규 착석자가 이전 결론에 앵커링된다.** 이어하기 1라운드 지시문은 "위 [이전 심의 요약]을 읽어라(당신이 이전에 참여했다면 …)" 이다. 코드가 이미 미참여자를 상정하면서도 그에게 요약을 먼저 읽힌다 | 기존 `DELIB_ANCHOR` 는 페르소나 **자신의 1라운드 입장**을 되돌려주는 기능이라 신규 좌석 앵커링과 다른 문제다 |
| D2 | **근거 0건 심의와 근거 충분 심의의 출력 형식이 동일하다.** 6/6 만장일치·수치 문턱·조항 형식이 그대로 나온다 | S26U 결정문은 VOC 텍스트만으로 작성됐고 정량 계측 0건이다. 결정문이 스스로 그 사실을 §5 에 적었으나 본문 구조는 확정 결론과 구분되지 않는다. 형식의 권위가 근거의 강도를 초과한다 |
| D7 | **투표가 정보를 담지 못하는 경우가 있다.** `options` 가 비면 자신들이 공동 작성한 실행안을 승인하는 형태가 된다. 근거가 0건이어도 표결이 강제된다 | 이어하기 심의의 `vote` 필드는 6인 전원이 "5개 항목 통합 실행안 채택 찬성"이었다. 상호 배타적 선택지가 없어 정보량이 사실상 0이다 |
| D9 | **인간 개입 지점이 시작 1회뿐이다.** `question` 과 `humanNote` 이후 종료까지 사람이 끼어들 지점이 없다 | 이번 세션에서 가장 큰 품질 개선이 사람의 중간 개입에서 나왔다. 관측 3건(액자 기하·부팅 래치·UV 리셋) 추가가 라운드 추가보다 훨씬 크게 결론을 바꿨고, 주가설의 논리 결함도 사람이 잡았다 |

### 1-3. 계층 A 결함 — 선행 검토 소관, 본 계획은 관찰만 기록

| # | 결함 | 대응 |
|---|---|---|
| D3 | 라운드 간 컨텍스트가 `summarize()` 한 줄로 압축되어, 다음 라운드는 원문이 아니라 요약을 보고 수렴한다 | `DELIB_CROSS_EXAM` 이 지목 표적의 원문을 전달해 부분 해소. T-서열에서 A/B |
| D4 | 라운드가 `parallel` 이라 같은 라운드 내 상호작용이 0이다 | 선행 검토가 다루지 않은 항목이나, `CROSS_EXAM` 의 표적 배정이 실질적 대체재다. T-서열 완료 후 재평가 |
| D5 | 합의 자체를 공격하는 좌석이 없어 만장일치 편향이 있다 | `DELIB_ANCHOR`(동조 붕괴 방어)가 부분 대응. 전담 챌린저는 선행 검토가 조건부 보류 |
| D6 | 결정문 합성이 단일 무검증 에이전트다 | `DELIB_CHAIR_CITE`·`DELIB_CHAIR_BESTOF` 존재. 합성 **검증기**는 미구현 — T5(의장 2-pass)에서 다룰 항목 |
| D8 | 동일 모델이라 오류가 상관된다 | 선행 검토가 원리적 한계로 규정. 완화만 가능 |
| D10 | 효과가 측정된 적이 없다 | **T0 계측 하네스** — 선행 필수인데 미구현 |

## 2. 조치 항목

### T0. 계측 하네스 — 모든 조치의 선행 조건

**선행 검토가 이미 규정했으나 미구현이다.** 손잡이 7종이 켜지지 않은 채 남아 있는 것도 이것이 없기 때문이다.

**변경.** 심의 산출물에서 자동 산출하는 지표 집계기를 만든다 — 수치 인용 밀도(근거 유래/비유래 분리), 반박 타겟률, 신규 개념 도입률, 결정문 수치 밀도, 가드레일(파싱 실패율·필드 원본 길이). 계층 B 용 지표를 추가한다 — **착석 도메인 다양성**, 이어하기 좌석 변동률, 승계된 `non_negotiable` 보존율.

**검증.** 손잡이 전부 꺼진 현행 심의 3건에 돌려 기준선을 확보한다.

**비용.** 에이전트 0. 기존 저널·결정문 텍스트 파싱만으로 산출한다.

### 계층 B — 좌석 구성 (본 계획의 고유 영역)

#### F1. 도메인 커버리지 게이트 — D1 대응

**변경.** 페르소나 발굴을 2단으로 만든다.
1. 현행 `recommend_agents(q=question)` 로 주 도메인 N명 선정.
2. **역질의 1회 추가** — "이 문제의 원인이 〈선정된 도메인 목록〉 밖에 있다면 어느 분야인가" 를 질의로 `recommend_agents` 를 다시 호출하고, 상위 1~2명을 **반대 도메인 좌석**으로 강제 착석시킨다.
3. 결정문 서두에 **참여 도메인 / 검토했으나 미착석한 인접 도메인** 을 명시한다.

**설계 근거.** 역질의는 질문 어휘가 만든 프레임을 벗어나는 유일한 자동 수단이다.

**수용 기준.** S26U 원 화두를 그대로 재실행했을 때 재료·화학·접착·신뢰성 계열 중 최소 1명이 착석해야 한다. 추가로 산소·소광·계면 관련 가설이 라운드 발언에 등장하는지 확인한다.

**비용.** 도구 호출 1회, 에이전트 +1~2.

#### F10. 이어하기 좌석 재심사 — D11 대응 · F1 과 짝

**현행 동작과 그 근거.** 웹 경로는 `continue_personas` 가 있으면 발굴을 건너뛰고 이전 좌석을 재사용한다. 코드 주석이 이유를 밝힌다 — "같은 전문가가 이전 결론을 이어받아 사람 의견에 맞춰 다시 토론해야 스티어링이 일관된다". **의도된 설계이며 목적 자체는 타당하다.** 좌석을 전원 교체하면 이전 입장을 방어하거나 수정할 당사자가 사라지고, 이전 결론이 반박 불가능한 전제로 굳는다.

**변경.** 연속성을 지키면서 커버리지를 여는 구조로 바꾼다.
1. 이어하기 시작 시 **실효 질문(원 질문 + 이전 결론 요약 + 사람 의견)** 으로 `recommend_agents` 를 재실행한다.
2. 결과를 이전 좌석과 대조해 **유임 / 신규 / 하차 후보** 로 분류한다.
3. **유임 최소 보장** — 이전 좌석 중 `max(2, 절반)` 을 반드시 유지한다. 현행 설계가 지키려던 연속성을 명시적 제약으로 보존한다.
4. 기본 동작은 **유지 + 신규 추가**(정원 확대)다. 하차는 정원 상한이 걸린 경우에만 적용한다.
5. 결정문 서두에 좌석 변동을 기록한다 — 유임 N · 신규 M(합류 사유) · 하차 K.

**수용 기준.** S26U 경시성 이어하기를 원 `humanNote` 그대로 재실행했을 때 서비스 운영·필드 데이터 계열이 최소 1명 신규 착석하고, 동시에 이전 6인 중 최소 3명이 유임되어야 한다.

#### F11. 이어하기 승계의 구조화 — D12 대응

**변경.** `continueFrom` 을 텍스트 한 덩어리에서 구조체로 바꾼다.

```text
continueFrom: {
  decision,                                    // 이전 의사결정문
  finalPositions: [{persona, position, nonNegotiable, vote}],
  openIssues: [{issue, owner, dueKind}],       // 이전 심의의 미해결 쟁점
  roundsSoFar
}
```

워크플로가 이전 실행 산출물에서 자동 구성하고(가능하면 `runId` 만으로), 호출자가 손으로 요약을 만들 필요를 없앤다. **`nonNegotiable` 승계는 필수 항목으로 강제한다** — 이전 심의가 조항으로 못박은 제약이 이어하기에서 사라지면 결정이 소리 없이 되돌아간다.

**수용 기준.** 이전 심의의 `non_negotiable` 전건이 이어하기 프롬프트에 포함되고, 이어하기 결정문이 그중 하나라도 뒤집으면 명시적 근거를 적도록 한다.

#### F12. 신규 좌석의 앵커링 차단 — D13 대응 · F10 의존

**변경.** 이어하기 1라운드에서 좌석별로 입력을 다르게 준다.
- **유임 좌석** — 현행대로 이전 요약을 받는다. 자신의 이전 입장을 방어·수정하는 것이 역할이다.
- **신규 좌석** — 1라운드에서는 **이전 요약 없이** 질문 + 사람 의견 + 자기 도메인 지식만으로 독립 판단을 낸다. 2라운드부터 이전 결론을 받고 조정한다.

**설계 근거.** 새 관점을 얻으려고 부른 좌석에게 기존 결론을 먼저 읽히면 동조 압력을 받아 추가의 의미가 사라진다. 신규 좌석의 독립 1라운드 판단이 기존 결론과 충돌하면, 그 충돌이 이어하기에서 얻을 수 있는 가장 값진 신호다.

**기존 `DELIB_ANCHOR` 와의 차이.** `ANCHOR` 는 수렴 라운드에서 페르소나 **자신의 1라운드 입장**을 되돌려주는 동조 붕괴 방어다. F12 는 이어하기 1라운드에서 **신규 좌석에게 이전 결론을 감추는** 것으로, 대상도 시점도 다르다.

### 계층 C — 산출물 표기

#### F2. 근거 등급 가시화 — D2 대응 · 일부는 T-서열 안에서

**변경.**
1. **근거 프로파일 자동 집계**(T0 하네스 산출물 재사용, 프롬프트 무관) — 결정문 헤더에 "도구 조회 N건 · 지식카드 인용 M건 · 경험칙 K건 · 실측 0건" 한 줄.
2. **근거 0건 표기 강제**(프롬프트 무관) — 도구 조회 성공 0건이면 제목에 `[가설 단계]` 부착 + 고정 문구 삽입.
3. **결정 항목별 근거 등급 태깅**(의장 프롬프트 변경 — **계층 A 간섭**) — [측정] / [문헌·규격] / [경험칙]. 이 항목만 T-서열 안에서 `CHAIR_CITE` 와 함께 A/B 한다.

**설계 근거.** 근거를 늘리는 것은 데이터 가용성에 의존해 통제가 어렵지만, 근거 없음을 드러내는 것은 항상 가능하다. 1·2번은 코드 집계라 지시 추종 예산과 무관하다.

#### F6. 투표 정상화와 판정 불가 허용 — D7 대응

**변경.**
1. 상호 배타적 `options` 가 2개 미만이면 투표를 생략하고 `stance` 만 기록한다.
2. 투표 선택지에 **"판정 불가 — 다음 측정 지정"** 을 항상 추가한다. 이 표가 과반이면 결정문 결론부는 판정이 아니라 **측정 계획**이 된다.

**설계 근거.** 근거가 없을 때 결론을 강제하는 구조가 "복합" 같은 안전한 답으로 수렴하는 압력을 만든다.

**주의.** 2번은 수렴 라운드 프롬프트를 건드리므로 계층 A 간섭이다. T-서열의 A/B 대상에 포함한다. 1번은 코드 분기라 무관하다.

### 계층 D — 사람 개입

#### F7. 인간 체크포인트 1회 — D9 대응

**변경.** 1라운드 종료 시점에 선택적 중단점을 만든다. 사람에게 (i) 1라운드 전원 입장 요약, (ii) 착석 도메인 목록, (iii) "빠진 관점이나 추가 관측이 있습니까" 를 제시하고, 응답을 `humanNote` 로 받아 2라운드부터 반영한다. MCP 경로는 `continueFrom` 이 이미 있으므로 1라운드까지 실행 후 반환하는 모드만 추가하면 된다.

**설계 근거.** 이번 세션에서 가장 큰 품질 개선이 사람의 중간 개입에서 나왔다는 관측이 근거다. 비용은 거의 0이다.

**F10 과의 상승 작용.** 체크포인트에서 사람이 관점을 추가하면 그것이 실효 질문에 들어가고, F10 의 재심사가 그에 맞는 좌석을 불러온다. 두 조치가 붙으면 "사람이 방향을 주면 방 구성이 따라온다"가 성립한다.

## 3. 우선순위와 단계

| 단계 | 항목 | 근거 |
|---|---|---|
| **0차 — 선행 필수** | T0 계측 하네스 | 선행 검토가 이미 규정했고 미구현이다. 이것 없이는 손잡이 7종도, 본 계획의 조치도 효과를 판정할 수 없다. 에이전트 비용 0 |
| **1차 — 계층 B, T-서열과 병행** | F1, F10 | 좌석 계층은 프롬프트 제약을 늘리지 않아 단일 변수 A/B 원칙과 간섭하지 않는다. 커버리지가 천장이므로 먼저 올린다. F1 과 F10 은 `recommend_agents` 재호출이라는 동일 메커니즘이라 한 묶음이다 |
| **2차 — 계층 B·C·D 확장** | F11, F12, F2(1·2), F6(1), F7 | 스키마·흐름 변경을 수반한다. F12 는 F10 이 선행되어야 대상이 생긴다. F2 의 1·2번과 F6 의 1번은 코드 집계·분기라 계층 A 와 무관하다 |
| **T-서열 — 선행 검토 소관** | 손잡이 7종 A/B, F2(3), F6(2) | T0 → T1 → T2 → T3 → T4 → T5 → T6 순서를 따르고 **동시 적용을 금지**한다. 의장 프롬프트를 건드리는 본 계획 항목은 여기 편입한다 |

**계층 B 를 먼저 하는 이유.** 인과 사슬의 최상단이기 때문이다. 커버리지가 낮은 상태에서 발언 품질을 올리면 틀린 도메인 안에서 더 정교하게 틀린 결론이 나온다.

**F10 을 F1 과 같은 단계에 두는 이유.** 이어하기는 회차가 늘수록 문제가 누적된다. 주제는 사람 의견을 따라 이동하는데 좌석은 최초 질문에 고정되므로 괴리가 단조 증가한다. 초기만 고치고 이어하기를 두면 사람이 개입할수록 상태가 나빠진다.

## 4. 회귀 방지

- **S26U 화두를 고정 회귀 케이스로 삼는다.** 본심의 화두와 경시성 이어하기 `humanNote` 를 그대로 재실행해 좌석 변화와 가설 다양성을 본다.
- **두 경로 동기.** `deliberation.py` 와 `hwax-deliberate.js` 는 별개 구현이므로 항목마다 양쪽 반영을 짝으로 확인한다.
- **기존 테스트 유지.** `tests/test_grounding.py` 29건 통과를 유지한다.
- **저장 계약 불변.** Report Archive 블록 구조와 `save_conversation` 메시지 스키마는 바꾸지 않는다.
- **손잡이 기본값 불변.** 본 계획의 조치는 손잡이 7종의 기본값을 건드리지 않는다. 활성화는 T-서열의 A/B 결과로만 결정한다.

---

## 5. 하지 않기로 한 것

- **손잡이 7종의 임의 활성화.** 계측 없이 켜는 것은 선행 검토의 단일 변수 A/B 원칙을 깨뜨린다. T0 이 먼저다.
- **라운드 수·페르소나 수 증설.** 커버리지 문제는 인원수가 아니라 도메인 다양성의 문제이고, 라운드 증설은 수렴 압력만 키운다.
- **전 라운드 순차화.** `CROSS_EXAM` 의 표적 배정이 실질적 대체재다.
- **계층 A 신규 조치 추가.** 선행 검토의 T-서열이 진행 중인 영역에 새 변수를 넣지 않는다.
- **결정문 자동 승인·자동 배포.** 심의 결과는 사람이 읽고 판단하는 입력이지 실행 지시가 아니다.
