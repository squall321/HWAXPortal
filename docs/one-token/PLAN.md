# 토큰 하나 — 포털에서 발급하면 하위 전부에서 쓴다

> 2026-09-23 착수. 사용자 요구가 정본이다. 판단 근거는 `context-notes.md`, 진행은 `checklist.md`.

## 0. 요구 (사용자 확정)

1. **HWAX 포털에서 토큰 하나**를 발급하면 **하위 사이트 전부**에서 공용으로 쓴다.
2. 다만 **그 사람의 포털 접근권한**에 따라 무엇이 열릴지 결정된다.
3. **모든 REST API 를 MCP 로 얇게 얹어** LLM 이 제출까지 할 수 있게 한다.

**OData 는 이번 범위에서 제외**(사용자가 뺐다). 나중에 대상이 정해지면 같은 방식으로 audience 하나를 더한다.

## 1. 지금 왜 안 되나 — 부품은 있는데 두 자리가 안 이어져 있다

| 겹 | 상태 | 근거 |
|---|---|---|
| 포털이 **다중 audience 토큰**을 낼 수 있나 | ✅ 설계돼 있다 | `config.py` `pat_default_audiences = "mx-white-paper,heax-hub,ai-data-hub,signalforge,mcp-gateway"` · 주석 "a PAT is just longer-lived, **multi-audience**, scope=api" |
| 포털이 **JWKS** 를 공개하나 | ✅ 200 | `/.well-known/jwks.json` (실호출 확인) |
| 허브가 **포털 JWT 를 검증할 줄** 아나 | ✅ 안다 | `HEAXHub/backend/app/api/v1/portal_sso.py` — JWKS 가져와 RS256·aud·exp 검증(300초 캐시) |
| 발급 화면이 그 설계를 쓰나 | ❌ **좁힌다** | `TokenPage.tsx:649` 가 `audiences: ['mcp-gateway']` 를 박아 보낸다 |
| `/apps/*` 게이트가 포털 PAT 를 받나 | ❌ **안 받는다** | `/api/v1/authz` 는 쿠키 또는 `heax_pat_` 만 본다. 포털 JWT 검증은 `scope=launch` 단명 토큰 경로에만 있다 |

**즉 "설계가 없다" 가 아니라 "화면이 안 쓰고, 게이트가 안 잇는다".**

## 2. 권한은 토큰이 아니라 **포털이** 정한다

이 스택은 **토큰에 박힌 합성 그룹을 일부러 안 믿는다** — 거둔 권한이 토큰 수명 동안 남지 않게(access-control D-2).
그래서 "포털 접근권한에 따라 열린다" 는 토큰에 권한을 더 박는 것이 **아니라**, 게이트가 요청마다 포털에 묻는 것이다.

그 부품도 이미 있다. 포털이 `/internal/access/policy` 와 `/internal/access/entitlements` 를 내고,
**게이트웨이가 요청마다 그것으로 권한을 다시 계산한다**(`gateway.py` 879·922, `_backend_allowed`).
`/apps/*` 게이트가 같은 패턴을 쓰면 된다 — 새로 지을 것이 없다.

## 3. 열기 **전에** 닫아야 하는 것 (적대 검토 대상)

토큰을 합치면 **폭발 반경이 커진다.** 지금은 새어도 한쪽만 열리는데, 합치면 전부다. 그래서 여는 것보다 먼저 본다.

- **`scope`(read/write)가 하위에서 실제로 강제되나.** 안 되면 "토큰 하나 = 전권" 이다.
- **포털이 안 닿을 때 게이트가 어느 쪽으로 닫나.** 열리면 최악이다.
- **폐기가 한 곳에서 되나.** 포털에서 끊었을 때 허브·앱·게이트웨이 캐시가 언제 반영되나(숫자로).
- **감사에 누가 한 일인지 남나.** 안 남는 경로가 새로 생기면 안 된다.

**포털이 안 닿을 때 — 문마다(2026-10-17 코드 대조, docs/leftovers-1017).** 받아 둔 값으로 버티는 문이 많고, 닫히는 문은 사람이 바뀌는 자리다.

| 문 | 포털이 안 닿으면 | 근거 |
|---|---|---|
| 게이트웨이 PAT 서명(`/mcp` · `/api/`) | 이미 받은 키(kid)로는 계속 검증한다 — 열림. 포털이 키를 바꾼 뒤의 새 kid 는 못 받아 닫힌다 | `rest_proxy.py` `get_signing_key_from_jwt`(kid 캐시) |
| 게이트웨이 폐기 목록 | 60초마다 받고, 못 받으면 **직전 목록을 유지**한다 — 그 뒤에 폐기한 토큰은 포털이 돌아올 때까지 통한다(열림, 알고 받아들인 것 — 닫으면 포털 재기동마다 전원이 막힌다). 갱신 실패는 경고 줄로 남는다 | `rest_proxy.py` `_revoked_set`(두 곳) |
| 게이트웨이 백엔드 권한 정책 | 60초마다 받고, 못 받으면 직전 정책을 유지한다(디스크 캐시 — 재부팅도 버틴다). **한 번도 못 받았으면** 사람별 위임 백엔드만 닫고(`policy_not_ready`) 나머지는 연다 | `gateway.py` `_refresh_access_policy` · `_deny_reason` |
| 게이트웨이 사람별 권한 키 | 60초 보관. 못 받으면 직전 값으로(만료 없음) 버티되 관리자 표지는 뗀다. 직전 값이 없으면 권한 키가 없다 | `gateway.py` `_portal_access` |
| 게이트웨이 소속(조직 공유 읽기) | 못 받으면 빈 값이다 — 닫힘 | `gateway.py` `_portal_affiliation`(`allow_stale=False`) |
| 게이트웨이 등록 연결 토큰(RA · TestScope) | 찾은 것은 300초(`GATEWAY_CONN_TTL`) 보관한다. 조회 실패는 30초 캐시하고 그 호출을 거절한다 — 닫힘(서비스 계정으로 내려가지 않는다) | `gateway.py` `_portal_connection` · `conn-lookup-error` |
| HEAXHub 앱 진입(`/apps/*` 실행 JWT) | 포털 JWKS 를 300초 보관한다 — 그동안 열림, 지나면 새로 못 받아 닫힌다 | `HEAXHub backend/app/api/v1/portal_sso.py` `_JWKS_TTL` |

## 4. REST 를 MCP 로 — "얇게" 가 핵심이다

수백 개 도구를 쏟아 내면 모델 컨텍스트·이름 충돌·`tools/list` 크기가 먼저 무너진다.
그래서 두 갈래를 저울질한다 — **OpenAPI 에서 자동 생성** vs **경로 하나로 부르는 일반 도구**.
그리고 자동 생성이 깨지는 자리(멀티파트 업로드·SSE·오래 걸리는 잡·바이너리 응답·페이지네이션)를
먼저 적고 각각을 어떻게 표현할지 정한다.

## 5. 아직 안 정해진 것

- 앱 슬러그(`/apps/<slug>`) ↔ 권한 키(`plat:`) 대응이 이미 있나, 새로 둬야 하나.
- 허브 자신의 API(`/api/v1/*`)도 같은 토큰으로 열 것인가.
- 앱마다 따로 있는 자격(`kr_`·`ste_pat_`·`heax_pat_`)을 **없앨 것인가 남길 것인가.**
  남기면 "하나로" 가 반쪽이고, 없애면 앱 단독 운영이 불가능해진다.
