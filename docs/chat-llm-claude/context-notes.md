# 웹 챗을 Claude API 로 — 결정과 까닭

## CC-1 (11-22) 사용자 지시 둘
- 「클립보드에 내 Claude API 키가 있다 — dev 서버는 웹 챗의 LLM 을 이걸로 해 둬라」(두벌식 자판으로 입력된 것을 읽음).
- 이어서 「dev 에서는 Claude API 를 정본으로 하고 cae00 에서는 선택할 수 있게. 운영자가 지정한 몇 사람은 Claude API 를 쓰고 그 외 사람은 기존처럼
  Qwen 으로」. 「선택」 은 운영자가 사람을 고르는 것으로 읽었다 — 지정된 사람의 웹 챗은 저절로 Claude 로 간다(대화마다 고르는 토글은 짓지 않았다 —
  요청이 오면 화면에 더한다).

## CC-2 (11-22) 키는 사람이 파일에 넣는다 — 세션이 클립보드를 읽지 않는다
- 세션이 X 화면 클립보드를 읽으려던 것은 권한 판정이 막았다. 우회하지 않았다. 키는 사용자가 0600 파일에 직접 넣고(`read -s`) 서버가 기동 때 그
  파일을 읽는다 — 세션은 키 값을 한 번도 보지 않는다. 추적 파일 · 로그 · /health 에는 「파일 있음 · 읽음」 만.

## CC-3 (11-22) Anthropic 공식 SDK 길 — OpenAI 호환 길로 붙이지 않는다
- 에이전트 서버의 챗 LLM 은 OpenAI 호환 클라이언트(langchain-openai)다. Claude API 에도 OpenAI SDK 호환 끝점이 있어 설정만 바꿔 붙일 수 있지만,
  Claude API 안내서는 그 길을 쓰지 말라고 한다 — 생각 깊이(effort) · 생각 블록 되돌리기 · 거절 · 캐시 같은 Claude 쪽 칸이 맞지 않는다.
  langchain-anthropic(공식 SDK `anthropic` 위)로 짓는다.
- 서비스 venv 에 꾸러미를 넣는 것은 권한 판정이 막았다(라이브 서비스 환경을 바꾸는 일). 시험은 스크래치 폴더에 받은 꾸러미로 하고, 서비스 venv
  설치는 배포 때 사용자 확인을 받는다. langchain-core 판(1.4.7)을 묶으면 새로 드는 것은 셋뿐이다 — langchain-anthropic 1.4.8 · anthropic 0.125.0 ·
  docstring_parser 0.18.0(최신 판은 langchain-core 를 1.7 로 올려 다른 길을 흔든다).
- 의존성은 `requirements-anthropic.txt` — 운영 박스 update-all 이 새 꾸러미를 받다 실패하지 않게 기본 설치에 넣지 않는다.

## CC-4 (11-22) 「몇 사람」 은 개별 허가로만 열리는 키
- 권한은 기본 ∪ 소속 ∪ 개별 허가이고 CAEG 소속은 `"*"` 다 — 보통의 `feat:` 키를 더하면 CAEG 전원 · 관리자 전원에게 열린다. 그래서 항목 표지
  `grant_only` 를 두었다 — `"*"` 와 관리자 전권이 펼치지 않고, 개별 허가 · 키 이름을 글자로 적은 grants 로만 열린다. 다른 키의 implies 로는 열지
  않는다(표 검사가 막는다). 관리자도 자기에게 개별 허가로 준다 — 비용 · 반출(대화가 사외 API 로 간다)이 걸린 기능이다.
- 에이전트 서버는 권한 칸이 없는 호출(옛 포털 · 서비스 호출)에 Claude 를 주지 않는다(닫힌 쪽).

## CC-5 (11-22) 모델 · 생각 깊이
- 기본 모델 `claude-opus-5-5`(Claude API 안내서의 기본). 생각은 끌 수 없어 깊이는 effort 로만 — 웹 챗 기본 `medium`(Opus 5.5 의 기본, Qwen 의
  xhigh 를 따르지 않는다 — 비용 · 지연). 값은 박스 설정으로 바꾼다.
- 비용 — Opus 5.5 는 입력 $4 · 출력 $20 / 1M 토큰. 챗 턴은 도구 목록 · 시스템 글을 매번 싣는다 — 캐시를 건다(캐시 읽기는 싸다).

## CC-6 (11-22) 에이전트 서버 — 지은 꼴
- 사람마다 고른다 — 켜져 있고 · 포털이 실은 요청 시점 권한(`entitlements`)과 사람(`user_email`)이 있고 · `CLAUDE_CHAT_FOR` 가 `all` 이거나 그 사람이
  `feat:chat-claude` 를 가졌을 때만. 권한 칸이 없는 옛 호출(보고서 만들기 등)은 기본 길이다. 포털 중계는 그 칸을 검증된 주체로 덮어쓴다. 에이전트 서버는
  127.0.0.1 에만 붙어 루프백에 닿는 쪽이 칸을 지어 보낼 수 있다 — 심의 권한과 같은 신뢰 모델이다.
- 앱 본문이 content 를 글로 읽으므로 모델 쪽 어댑터 한 곳에서 맞췄다 — 받을 때 글은 content, 생각 요약은 `reasoning_content`, 원래 블록(인덱스 · 서명)은
  따로 두었다가 보낼 때 되돌린다. 루프 맞추기 · 도구 그림이 앞 메시지를 바꾸는 경우를 위해 `prefix_mismatch_behavior: drop_block` 을 보낸다(400 대신 그
  생각 블록만 버린다).
- 넘김 — 연결 · 시간 초과 · 429 · 401 · 403 · 5xx 는 그 박스의 기본 챗 길로. 400 은 넘기지 않는다. Claude 턴의 창은 1M − 출력 몫이다(두 서버 중 작은 값을
  쓰면 dev 에서 128K 로 줄어든다) — 넘겨받는 쪽 창을 넘는 요청은 그쪽 400 으로 보인다.
- 남은 것 — 서버 쪽 대체 모델이 답해도 「답한 모델」 은 요청 모델로 보인다 · cae00 에서 Qwen 이 그림을 못 받으면 그림 실린 넘김은 400 · 루틴 실행기 ·
  띵킹은 고르기 범위 밖(지금 LLM).
- 의존성 설치는 자동 모드가 막았고(라이브 서비스 환경) 사용자 확인으로 넣었다 — langchain-core 판은 그대로다.
