# 임베더를 BGE-M3 로 — 한국어 질의와 영어 카드의 정합성

> 받은 것 — 사용자(2026-10-16) "BGE-M3로 바꿔서 정합성을 향상시키는걸 해줬으면 좋겠어", "모든 데이터를 검색하는게 빠른것도 중요한데
> 시멘틱이 잘 되어야 하거든". 근거는 한국어 검색 기준선(`docs/improvement-1015` IM-D22, AIDataHub `docs/ko-search-baseline.md`).
> 결정과 까닭은 [context-notes.md](context-notes.md), 할 일은 [checklist.md](checklist.md).

## 1. 왜

기준선에서 한국어 카드는 이미 거의 다 찾는다(좌석이 받는 것 0.98~1.00, 늘 거절되는 mx 좌석 제외). 약한 곳은 **한국어 질의로 영어 카드를
찾는 것**이다(0.39~0.57, 전역 의미검색 0.10). 지금 임베더 `intfloat/multilingual-e5-base`(768차원)는 두 언어를 한 공간에 놓기는 하지만
교차 언어 정렬이 약하다. `BAAI/bge-m3`(1024차원, 568M)는 다국어 · 교차 언어 검색에 맞춰 학습됐고 입력 한도도 8,192토큰이다(e5 는 512 —
긴 절의 뒤쪽이 지금은 벡터에 들지 않는다).

먼저 고친 것 — 큰 좌석에서 HNSW 가 히트를 잃던 결함은 정확 범위 검색으로 고쳤다(AIDataHub `5507c68`). 영어 카드 부진의 일부가 그 결함
탓이었으므로, 견주기는 그 수정 위에서 한다.

## 2. 무엇이 바뀌나 — 전수

| 자리 | 지금 | 바꾼 뒤 |
|---|---|---|
| 임베더(AIDataHub `embedding.py`) | `e5_base` — 접두사 `query:`·`passage:` | `bge_m3` — 접두사 없음(모델 이름에 e5 가 없으면 이미 안 붙인다), 입력 한도는 모델 값 |
| 벡터 열 넷 | `vector(768)` — 절 · 레코드 서명 · 에이전트 표본 · 업로드 설명 | 새 열 `halfvec(1024)` 를 **나란히** 둔다(무중단 — 아래 3절) |
| 색인 | `record_sections` HNSW(`vector_cosine_ops`) 등 | 새 열에 HNSW(`halfvec_cosine_ops`), `CREATE INDEX CONCURRENTLY` |
| 백필 | 빈 절 전부를 메모리에 올리고 끝에 한 번 커밋 · 30분마다 겹쳐 띄움 | 키셋 페이지로 청크마다 커밋 · advisory lock 으로 한 번에 하나 · 이어하기 · 슬롯별 |
| 읽기 | 의미검색 · 하이브리드 · agent_search · 서명 유사도 · 에이전트 추천 · 업로드 검색이 `embedding` 열 | 설정 한 줄(활성 슬롯)이 고른 열과 그 슬롯의 임베더 |
| `/api/embed` | e5-base 벡터 | 활성 슬롯의 모델 벡터 + 응답에 `model` · `dim` |
| 포털 대화 검색(`conv_search.py`) | 모델 표지 상수 `aidh-768` | AIDataHub 응답의 모델을 따른다 + 다시 색인 |
| 에이전트 서버 도구 벡터 캐시 | 도구 이름 서명만 | 서명에 모델 · 차원 |
| 게이트웨이 search_tools 의미 순위 | (기본 꺼짐) | 이미 차원이 바뀌면 다시 색인한다 — 손댈 것 없음 |

## 3. 무중단 전환 — 슬롯 둘

예전 384→768 이행(AIDataHub alembic 0013)은 임베딩을 전부 비우고 열 형을 바꾼 뒤 백필했다 — 그동안 의미검색이 빈다. 110만 절을 다시
임베딩하는 동안 그럴 수 없으므로 슬롯을 둘 둔다.

1. **열 더하기(이행)** — 네 표에 `*_m3 halfvec(1024)` · `*_m3_model` 를 더한다(비어 있음). 지금 열(v1)은 그대로다.
2. **백필(dev GPU)** — 새 백필이 v2 열을 BGE-M3 로 채운다. 읽기는 그동안 v1(e5-base) 그대로다.
3. **색인** — v2 열에 HNSW 를 `CONCURRENTLY` 로 짓는다.
4. **견주기** — 같은 평가셋(`/data/svc/aidh/eval/ko-search-20261016/queries.jsonl`)으로 v1 · v2 를 같은 DB 에서 잰다(활성 슬롯만 다른 API 를
   다른 포트에 하나 더 띄워서).
5. **전환** — 활성 슬롯 설정 한 줄 + 재기동. 되돌리기는 그 줄을 되돌리고 재기동이다(v1 열은 그대로 있다).
6. **정리(나중)** — 한동안 돌려 본 뒤 v1 열 · 색인을 지운다(별도 이행).

전환 전까지 새로 들어오는 절은 두 슬롯 다 채운다(백필이 슬롯별로 빈 것을 찾는다).

## 5. 속도

- 저장 — `halfvec(1024)` 는 벡터 하나 2KB 로 지금 `vector(768)`(3KB)보다 작다. 색인도 작아진다.
- 질의 임베딩 — GPU 수 ms, CPU 수백 ms.
- 전역 HNSW — 차원 비례분(1.33배)이 있지만 읽는 바이트가 줄어 비슷하다.
- 좌석 범위(정확 검색) — 좌석 안 절 수 × 차원에 비례. 견주기에서 지연도 함께 잰다.
