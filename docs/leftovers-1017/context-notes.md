결정 기록으로 근거를 대게 했다. 큰 문서 둘(옛 리스크 설계 122줄, 클러스터 배포 55줄)은 성격이 갈렸다 — 옛 리스크 설계는 대부분
'이미 함'(리스크 앱 리포가 '포털 체크리스트는 일부러 미체크로 남겼다' 고 적었다), 클러스터 배포는 08-02 이후 손대지 않은 계획이라
사용자 결정(§11 · 계획 합의) 뒤로 전부 미룸이다.

**LO-D2 대화 종류는 바꾸지 않는다.** 감사가 짚은 W-8 ② — 화면 `ConvKind` 에 `risk-review` 가 없다. 들여다보니 지금 보이는 결함이
아니다. 화면은 탭마다 한 종류만 보인다(심의 탭 = `deliberation`, 챗 탭 = `chat`, `ChatContext` 의 `m.kind === serverKind`). 리스크 앱은
그래서 패널 대화를 `deliberation` 으로 만들어 심의 탭에 보인다. 종류를 `risk-review` 로 바꾸면 그 대화가 심의 탭에서 사라지고, 탭을
여럿 받게 고치는 일은 화면 동작을 바꾸는 결정이다. 리스크 앱 `engine_client.py` 의 주석('포털이 아직 risk-review 를 받지 않는다')만
틀렸다 — 포털 백엔드는 받는다(`agent/routes.py` `ConvCreate.kind`). 주석을 진짜 까닭으로 고친다.

**LO-D3 심의 방법 8번째 카드는 짓지 않는다.** 옛 설계(design-risk-review)는 `/deliberate` 에 '리스크 심사' 카드를 더하려 했다.
지금 포털에는 `/risk` 화면이 이미 있고, 리스크 심사는 재설계 뒤 리스크 앱(셀 · 쟁점 · 종합)과 Claude 길로 돈다. 같은 입구를 하나 더
두는 것은 제품 결정이다.
