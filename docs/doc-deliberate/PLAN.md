# 문서(HTML·PPT·Word·PDF) 업로드 → 내용 읽고 심의 — 계획

사용자 요청(2026-09-12): "html ppt word pdf 를 업로드하면 그 내용을 읽고 그거에 대한 심의를
하는 것도 되었으면. 다만 **업로드하는 PC 의 오피스 COM 을 이용해 한 번 읽고 출력**하는 게
되었으면 — 그걸 전제로 해야 **DRM 이 안 걸린다**."

## 이 요구가 설계를 가르는 지점

DRM 문서는 **그 사람의 PC, 그 사람의 세션**에서만 복호화된다. 서버가 원본을 받아 파싱하면
암호화된 바이트만 본다. 그래서 **추출은 반드시 클라이언트에서** 일어나야 하고, 서버로 가는
것은 원본이 아니라 **추출된 텍스트**다. 이 한 줄이 아래 구조를 전부 결정한다.

    [사용자 PC]  원본(DRM) --Office COM--> 평문 텍스트/구조
                                    |
                                    v  (원본은 PC 를 떠나지 않는다)
    [포털·클로드]                 텍스트 --> 심의

## 두 표면, 하나의 추출기

추출 코어(PowerShell + Office COM)는 **하나만 만들고** 두 가지로 감싼다.

| 표면 | 흐름 | 장점 | 비용 |
|---|---|---|---|
| **A. 개인 클로드(MCP)** | 로컬 stdio MCP 서버가 `extract_document(path)` 제공 → 클로드가 바로 심의 | **업로드 자체가 없다**(텍스트도 PC 밖으로 안 나감·사내 반출 심사 부담 최소) · 오늘 만든 클로드 심의와 그대로 접속 | 개인 클로드를 쓰는 사람만 |
| **B. 웹 포털** | 내려받은 추출기(.bat)가 COM 으로 읽어 텍스트를 포털에 POST → 챗/심의 | 포털 사용자 전원 | **문서 텍스트가 서버로 간다**(반출 판단 필요) |

권고 — **A 먼저**. DRM 문서를 다루는데 내용을 서버로 보내지 않는 경로가 있으면 그쪽이 먼저다.
B 는 A 의 추출기를 그대로 쓰되 전송 단계만 더한다.

## 추출기 — 형식별 방법과 함정

| 형식 | 방법 | 함정 |
|---|---|---|
| Word | `Word.Application` → `Documents.Open(ReadOnly)` → `Content.Text` 또는 `SaveAs2(wdFormatText)` | 매크로·리비전 표시로 본문이 오염될 수 있다. `Visible=$false`, `DisplayAlerts=0` 필수 |
| PowerPoint | `PowerPoint.Application` → 슬라이드별 `Shapes..TextFrame.TextRange.Text` | PPT 는 **Visible 을 false 로 못 두는** 버전이 있다(COM 제약). 노트·표·그룹 도형을 따로 훑어야 텍스트가 다 나온다 |
| PDF | Word 로 열어 변환(Word 2013+) 또는 Acrobat COM | Word 변환은 레이아웃이 무너진다. 스캔 PDF 는 OCR 없이는 빈 텍스트 |
| HTML | 파일 직접 읽기(COM 불필요) | DRM HTML 은 드물다. 인코딩 판별 필요 |

**공통 함정** — ① COM 은 **데스크톱 세션**이 있어야 한다(서비스·무인 실행에서 실패).
② Office 가 설치돼 있어야 한다. ③ 실행 후 프로세스를 반드시 `Quit()` 하고 COM 객체를 해제하지
않으면 WINWORD.EXE 가 쌓인다. ④ **DRM 정책이 자동화 자체를 막을 수 있다** — 읽기는 되는데
`SaveAs`·클립보드가 막히는 제품이 흔하다. 그래서 `Content.Text` 직접 읽기를 1순위, 파일 저장은
폴백으로 둔다. **이건 실제 DRM 으로 시험해야 안다.**

## 심의로 넘기는 계약

추출 결과는 심의 입력의 **근거 채널**로 넣는다(화두가 아니라).
- 클로드 경로: 텍스트를 그대로 읽고 `use_experts` 로 좌석을 세워 심의(오늘 만든 흐름).
- 포털 경로: `delib_opts.evidence` 채널에 실어 기존 엔진에 넘긴다(문서는 좌석 발언이 아니라
  근거다 — 헌법 P1 "브리프에 결론 금지, 원천만" 과 같은 원칙).

## 단계

1. 추출 코어(PowerShell) — Word/PPT/PDF/HTML, 텍스트+구조(제목·슬라이드 번호·표)를 JSON 으로.
2. 로컬 MCP 서버 — `extract_document(path)`·`list_recent_documents()`. 포털 토큰 페이지에서
   등록 명령을 내려 준다(기존 .bat 생성기 옆에).
3. 문서 심의 흐름 — 추출 텍스트를 근거로 좌석 발굴 → 심의.
4. (선택) 포털 업로드 경로 — 추출기가 텍스트를 POST, 기존 업로드 오케스트레이션에 연결.

## 미결

- **DRM 제품이 COM 자동화를 허용하는가** — 이것부터 확인해야 한다. 막히면 설계가 바뀐다
  (예: 사용자가 직접 '다른 이름으로 저장'한 텍스트를 올리는 수동 경로).
- 표·이미지를 어디까지 살릴 것인가(텍스트만인지, 표 구조까지인지).
- 포털 경로에서 문서 텍스트 서버 전송이 사내 반출 심사에 걸리는가.
