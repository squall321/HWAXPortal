# 웹 리서치 도입 — 결정 기록

작업 중 내린 판단과 그 이유를 계속 덧붙인다. 다음 세션이 같은 논쟁을 다시 하지 않도록.

## 2026-08-08 · 착수 전 실측

**dev 박스는 인터넷 직결이고 TLS 가로채기가 없다.** proxy 환경변수 없음, google/duckduckgo/
pypi/wikipedia 전부 200, `www.google.com` 인증서 issuer 가 Google Trust Services(사내 CA 아님).
검색 결과 수신과 임의 페이지 본문 추출(위키 3,687자) 모두 실제로 성공했다.

**운영(cae00)은 다르고, 아직 재지 않았다.** 프로세스 전역에 `http(s)_proxy` 가 걸려 있고
내부 IP 는 `NO_PROXY` 로 빼는 것이 확립된 패턴이다(`infra/env-kits/agent-server.env:14-16`).
과거 공개 레지스트리가 MITM 으로 깨졌을 때의 해법이 "네트워크를 안 쓴다"(오프라인 번들)였는데,
검색 기능에는 그 회피가 통하지 않는다. 그래서 P0(망 실측)이 0단계다.

**현재 인터넷 검색은 안 된다 — 도구가 없다.** 게이트웨이 225개 중 웹 검색·페이지 fetch 가 0개다.
챗에 "인터넷에서 논문 검색해줘"를 넣으면 모델이 사내 문서 검색(`search_documents`)을 집어 들고
"인터넷 전체를 검색하는 기능은 없습니다"라고 답한다(실측). **망이 열린 것과 기능이 있는 것은 다르다.**

## 2026-08-08 · 설계 변경 — 소스별 토글 (사용자 결정)

사용자가 "챗이나 심의 밑에 체크하는 옵션을 두고 켜면 쓰고 끄면 안 쓰게" + "공공 학술 API 도
고를 수 있으면" 을 요청했다. 두 가지를 바꿨다.

**하나. 소스를 한 스위치로 묶지 않는다.** 세 소스는 나가는 곳도 승인도 위험도도 다르다.
묶어 두면 일반 웹 승인이 안 난 동안 공공 학술까지 못 쓴다 — 승인 리드타임이 이 로드맵의 가장 큰
도박인데 거기에 학술 검색까지 거는 셈이 된다.

**둘. 차단은 바인딩 단계에서 한다.** 앞선 대화에서 "대화 단위 토글만으로는 차단이 안 된다"고
말했는데 그건 `pinned_apps` 의 우선순위 의미를 두고 한 말이었고, 지금 설계에는 맞지 않아 정정했다.
토글이 꺼지면 도구를 **바인딩하지 않는다** — 모델에게 금지를 지키게 하는 것과 도구가 존재하지
않게 하는 것은 다르다. 챗은 `_agent_for()`→`_select_tools()`, 심의는 자유 조회 `_g` 딕셔너리에서
거른다. 심의 쪽은 2026-08-08 앱 좁힘 작업으로 이미 그 자리가 있다.

**파생 결정 — 도구를 소스별로 쪼갠다.** `search_scholar` 와 `search_web` 을 별개 도구로 낸다.
하나의 도구에 `source` 인자를 두면 바인딩 단계에서 소스를 가릴 수 없어 토글이 프롬프트 지시로
퇴화한다. P2 에서 정해지면 뒤집기 어려운 결정이라 여기 남긴다.

**토글 UI 는 P4 에 붙인다.** P2 에 먼저 만들면 켤 대상이 없는 체크박스가 되고, 켜도 아무 일이
없으면 사용자에게 '고장난 기능'으로 보인다.

## 2026-08-08 · 앱 소스 배치

매니페스트에 `source` 블록이 없으면 in-tree 모드로 `integrations/<slug>/` 자체가 워크스페이스가
된다(`integrations_scanner.py` SourceSpec docstring). 기존 5개 앱 중 in-tree SIF 빌드 선례는 없다 —
4개는 GitHub 소스이고 `kooremapper-mcp` 는 `external_proxy`(이미 도는 서비스로 프록시)다.

새 GitHub 레포를 만드는 것은 외부로 코드를 내보내는 행위라 사용자 확인 없이 하지 않는다.
로컬 git 저장소를 만들고 `source.url` 을 `file://` 로 가리키는 방식을 먼저 검증한다 — git 이라는
검증된 메커니즘을 그대로 쓰면서 외부 공개를 피한다. 나중에 GitHub 으로 옮기려면 매니페스트
한 줄만 바꾸면 된다.

cae00 은 SIF 를 Drive 로 받으므로(`dist-from-drive.sh`) 소스 접근이 필요 없다. 다만 cae00 에서
자체 재빌드는 불가능해지므로, GitHub 으로 옮길지는 사용자 결정 사항으로 남긴다.

## 2026-08-08 · P3 착수 전 실측 — 세 가지가 데이터로 정해졌다

### 1. 임베딩 절대 임계값은 못 쓴다 (계획서 §3-E 정정)

계획서는 독립군 판정에 "임베딩 코사인 ≥0.93"을 썼다. **이 서비스에서는 성립하지 않는다.**
AIDataHub `/api/embed`(dim 768) 실측 —

    한:배터리 ↔ 영:배터리(같은 주제)   0.836
    한:배터리 ↔ 한:점심(무관)          0.843   ← 무관이 더 높다

전체 쌍 평균 코사인 0.803. 공간이 심하게 비등방이고 **의미가 아니라 언어/스크립트로 뭉친다.**

**centering(배경 코퍼스 평균벡터 차감)이 교정한다.** 같은 실측에서 0.388 > 0.276 으로 순서가
정상화됐다. 다만 스케일이 완전히 달라지므로 임계값은 골든셋으로 새로 잡아야 한다.

속도는 문제가 아니다 — 문장당 0.8ms, 974문장 문서가 0.8초.

기존 사용처 주석의 경고도 그대로 적용된다. 배치 128 이상에서 GPU 가 붐비면 HTTP 500(CUDA OOM)
이 나는 **부하 의존 간헐 고장**이고, 기존 코드는 예외를 삼켜 랭킹이 조용히 퇴화했다.
EMBED_BATCH=64 가 양쪽 조건에서 통과한 값이다. 같은 실수를 반복하지 않는다.

### 2. 추출은 trafilatura (골든셋 실측)

순진한 정규식 추출과 비교했다. 보일러플레이트 잔존 개수 —

    wiki_libatt   naive 54 → trafilatura 1
    wiki_oled     naive 80 → trafilatura 0
    wiki_sv       naive 14 → trafilatura 0
    arxiv_list    18,510자 → 2,442자 (87% 감축, 목록 페이지가 올바르게 접힘)

속도는 최대 216ms(1.1MB 위키). 메타데이터(title/date/author)도 같은 라이브러리로 나온다 —
arxiv 는 저자·발행일까지 정확히 뽑았다. 최신성 판단에 직결되므로 이게 크다.

**본문 미반환 계약이 필수임이 재확인됐다.** trafilatura 로 걸러도 wiki_libatt 는 120,483자
(≈48K 토큰)다. dev 16K 는 물론이고 어떤 모델에도 그대로 넣을 수 없다.

### 3. 전재본 판정의 난이도가 낮아졌다

trafilatura 가 껍데기(내비·푸터·광고)를 걷어내면 **전재본 5개의 본문이 바이트 동일**해진다
(sha256 앞 12자리가 같음). 독립 문서 2개는 각각 다르다. 즉 골든셋 정답 3군이 해시만으로 나온다.

이건 좋은 소식이면서 동시에 **골든셋의 한계**다. 합성 세트라 전재 시 매체가 문장을 손보는
현실(제목 변경·문단 재배열·요약)이 빠져 있다. SimHash·임베딩 경로는 이 골든셋으로는
검증되지 않는다 — 실물 전재본을 나중에 보태야 한다.
