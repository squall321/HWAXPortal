# Report Archive 연결에 조직(워크스페이스) 선택 붙이기

## 지금 어떻게 되어 있나 — 배선은 있는데 사람이 못 고른다

RA 연결 등록은 이미 워크스페이스 슬러그를 다룬다. 저장 칸도 있고(`connections.workspace`),
게이트웨이도 그 값을 `X-Workspace-Slug` 헤더로 실어 보낸다. 빠진 것은 **선택**이다.

```
사용자가 rat_ 토큰 붙여넣기
  → 포털이 RA /api/me 로 검증
  → ws_slug = home_workspace_slug, 없으면 personal 아닌 첫 멤버십      ← 자동 유도뿐
  → connections 에 저장
  → 게이트웨이가 X-Workspace-Slug 로 실어 RA 호출
```

`RaConnectionCard` 는 등록 뒤 그 값을 **읽기 전용으로 보여주기만** 한다. 바꾸려면 연결을
해제하고 다시 등록해야 하는데, 다시 등록해도 같은 값이 유도된다. 즉 **바꿀 방법이 없다.**

## 실측 (2026-09-09)

RA `/api/me` 응답(서비스 계정 `dev@hwax.local`).

```
home_workspace_slug: 'dev'
memberships:
  slug='dev'        kind='org'       name='Dev (개발)'        role='manager'
  slug='personal-2' kind='personal'  name='Dev Admin (개인)'  role='manager'
```

포털에 등록된 연결은 1건뿐이고 `workspace='dev'` 다. 등록하지 않은 사용자는 게이트웨이가
서비스 계정으로 폴백하므로 보고서가 **서비스 계정의 개인 워크스페이스**에 쌓인다
(실제로 `/w/personal-3/reports/53` 에 있었다).

## 고칠 것 셋

### ① 자동 유도가 개인 워크스페이스를 고를 수 있다

지금은 `home_workspace_slug` 를 **그대로** 쓴다. RA 계정의 home 이 `personal-N` 이면 조직이
아니라 개인 워크스페이스가 박히고, 사용자는 그것을 바꿀 수 없다. 조직 멤버십이 있으면
그쪽을 먼저 고르고, 없을 때만 home 으로 떨어져야 한다.

### ② 사람이 고를 수 없다

여러 조직에 속한 사용자가 어디에 쌓을지 정할 방법이 없다. 부서를 옮겨도 마찬가지다.

### ③ 고를 후보를 보여주지 않는다

멤버십 목록이 등록 시점에만 쓰이고 버려진다. 화면은 무엇을 고를 수 있는지 모른다.

## 무엇을 만드나

**계약 셋을 더한다.** 토큰을 다시 넣지 않고 조직만 바꿀 수 있어야 한다.

| 엔드포인트 | 하는 일 |
|---|---|
| `PUT /auth/connections/reportarchive` | 기존 + 선택 `workspace` 를 받는다. **멤버십에 없는 슬러그는 거절**하고, 응답에 후보 목록을 싣는다 |
| `GET /auth/connections/reportarchive/workspaces` | 저장된 토큰으로 RA 에 물어 고를 수 있는 목록을 준다(토큰 재입력 없음) |
| `PUT /auth/connections/reportarchive/workspace` | 토큰은 그대로 두고 슬러그만 바꾼다. 역시 멤버십 검증 |

**저장소**에 `set_connection_workspace` 하나를 더한다(토큰을 건드리지 않는 갱신).

**화면**은 등록 뒤 `<select>` 로 조직을 고르게 하고, 개인 워크스페이스는 그렇다고 표시한다.
지금 어디로 저장되는지 한 줄로 늘 보인다.

## 원칙

- **멤버십에 없는 슬러그는 저장하지 않는다.** 오타 하나로 보고서가 사라지고, 실패가
  "저장은 됐는데 어디에도 없다" 로 나타난다 — 가장 나쁜 실패 모양이다.
- **개인 워크스페이스를 고르는 것 자체는 막지 않는다.** 다만 기본값이 되지 않게 하고
  화면이 개인임을 밝힌다. 사용자가 알고 고르는 것은 그의 선택이다.
- **빈 슬러그는 지금처럼 헤더 삭제**다(RA 가 토큰의 기본 워크스페이스로 보낸다).
  '지정 안 함' 과 '조직 지정' 을 구분해 화면이 그렇게 말한다.
- 토큰은 어떤 응답·로그에도 싣지 않는다. 표시용은 끝 4자뿐이다.

## 범위 밖

- RA 쪽 워크스페이스 생성·권한 변경 — 이 리포는 RA 에 커밋하지 않는다(API 만 쓴다).
- SSO 로 이 등록부 자체를 없애는 일 — 그날 오면 자연 소멸할 브리지다.
