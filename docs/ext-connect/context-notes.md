# 외부 연결을 설정만으로 — 결정과 까닭

> 계획 [PLAN.md](PLAN.md) · 요청서 [request.md](request.md) · 체크리스트 [checklist.md](checklist.md). 앞선 결정은
> [sso-delegation/context-notes.md](../sso-delegation/context-notes.md)(D-1 ~ D-20).

**EC-D1 요청서를 사양으로 삼고 dev 리포 두 곳만 고친다(2026-10-21).** 요청서는 cae00 에서 포털 `2e514e3` · 게이트웨이 `8e30ee5` 를 읽어
대조했고, dev 의 두 리포가 같은 커밋이라 `파일:줄` 이 그대로 맞는다(읽어서 확인). cae00 반영(4절)은 '운영 쪽 — 요청 아님' 이라 하지 않는다.
요청서 사본은 내부 주소 · 담당자 메일 주소만 자리표시로 바꿔 [request.md](request.md) 에 둔다(이 리포는 GitHub 에 있다).

**EC-D2 남은 질문(1-9)은 구현을 막지 않는다 — 설계의 기본값으로 짓고 결정은 사람에게 남긴다.** ③ 평문 토큰은 알리기만(이번 범위 밖),
④ 등록은 세션 + CSRF 만(PAT 거절 — 설계 그대로), ⑤ 신원 없는 호출은 거절(설계 그대로 — 절차 사전 점검을 넓히는 것은 따로),
①②⑥⑦⑨ 는 설정 · 운영의 일이고 ⑧ ⑩ 은 별도 요청이다.

**EC-D3 모르는 칸이 든 `connect:` 블록은 통째로 버린다(PB3).** 칸 표에 없는 이름(`verfy: url` 같은 오타)을 건너뛰고 나머지를 받으면
주인 확인을 켜려던 블록이 확인 없이 붙는다 — 오타가 검사를 조용히 끄는 쪽으로 틀린다. 버리고 알림(`Policy.warnings` → 배선 설정 ·
update-collab ①)을 남긴다. 다른 정책은 그대로 읽힌다(SSO 행 버리기와 같은 자세).

**EC-D4 `feat:connect` 는 `compute()` 한 곳에서 붙인다(PB12).** 화면이 받는 entitlements(`session.py` · `agent/routes.py`)와 게이트웨이가
읽는 `/internal/access/entitlements` 가 모두 `compute` → `with_entitlements` 를 지나므로 따로 고칠 곳이 없다. 사유는
`implied:plat:<id>` 이고 관리자도 받는다(관리자는 모든 `plat:` 을 가진다). 표의 항목이 아니라 요청 · 허가 대상이 아니다.

**EC-D5 PB14(선택)는 하지 않는다.** 선언 백엔드는 게이트웨이가 세션을 열기 전에 `_bypass_proxy_for` 로 호스트를 프록시에서 빼고(GW5),
포털 확인은 `trust_env=False` 라(PB9) 박스 `NO_PROXY` 가 덮지 않아도 새지 않는다. `check-egress.sh` 의 '덮이지 않음' 점검에 넣으면 고칠 것
없는 경고가 매번 뜨고, 셸이 포털 내부 정책을 읽으려면 공유 비밀을 다뤄야 한다. 호스트를 보려면 게이트웨이 `/health` 의 `conn_platforms`
와 로그(키 · 호스트 · 상태)를 본다.

**EC-D6 포털 전체 시험의 실패 둘은 이 작업과 무관하다(2026-10-21).** `test_llm_pool_lib.py::test_셀_수_없으면_0_이_아니라_모른다` ·
`test_llm_pool_update_all.py::test_임시_파일을_못_만드는_박스에서_풀을_꺼도_라우터를_내리지_않는다` 는 깨끗한 HEAD(`2e514e3`) 사본에서도 같이
실패한다(3,202 통과 · 2 실패). 둘 다 `ulimit -f 1` 로 here-doc 임시 파일 실패를 흉내 내는데, 그 실패가 일어나지 않아 시험 스스로
'시험이 헛돈다' 로 멈춘다. 원인은 확인하지 않았다(이 박스 bash 5.1 이 작은 here-doc 을 파이프로 보내는 것으로 짐작한다). 범위 밖이라 남긴다.

**EC-D7 목록 응답에 `owner_checked` 한 칸을 더한다(PB7 밖, 10-21).** 카드의 고정 안내 「이 토큰의 주인은 확인하지 않습니다 …」 는
`owner_field` 를 켠 플랫폼에는 틀린 말이다. PB7 의 칸에는 주인 확인 여부가 없어 화면이 고를 수 없었다. 그 플랫폼에는 「포털 계정과 같은 이메일의
<label> 계정 토큰만 연결됩니다.」 를 보인다. 칸이 없으면(옛 백엔드) 확인하지 않는 쪽으로 읽는다.

**EC-D8 재활 잠금은 모듈에 한 번 둔다(GW6 — 요청서는 'lifespan 에서 만든다').** anyio 4.14 의 `Lock()` 은 루프 밖에서 만들어도 여러 이벤트 루프에서
다시 쓸 수 있다(실측 — 경합 포함). lifespan 에서 만들면 lifespan 없이 `_revive_once` 를 부르는 시험 · 경로가 `None` 을 만난다. 시험은 시험마다
새 잠금을 건다. 위험은 실재한다 — 한 패스가 재연결 루프에서 `backends` 를 돌며 기다리는 사이 다른 패스가 백엔드를 넣으면
`dictionary changed size during iteration` 으로 패스가 죽는다(잠금을 뺀 변이로 재현, heax 합류에도 같은 위험이 있었다). 같은 키가 두 번
생기는 쪽은 아니었다 — 맞추기는 조회(await) 뒤 확인 · 등록을 한 번에(await 없이) 한다.

**EC-D9 지킴(`_CONN_ACTIVE`)은 첫 연결 **전에** 단다(GW5 — 요청서 순서는 마지막).** 첫 연결이 취소 · 실패한 채 표에만 남으면 다음 패스가
그 키를 '선언이 아닌 백엔드' 로 읽는다. 맞추기는 선언이 아닌 백엔드가 이미 쓰는 키를 덮지 않고 `collision` 으로 두므로(검사를 지났어도 — 표에
먼저 있는 쪽이 이긴다) 순서가 바뀌면 그 키가 영영 붙지 않는다.

**EC-D10 주소 · 목록 토큰은 같고 선언만 바뀌면 세션은 두고 재집계만 한다.** 선언 지문(`spec_fp`)을 견준다. 이것이 없으면 `read_tools` · 이름 ·
안내를 고쳐도 다른 변화가 생길 때까지 카탈로그 · 읽기 힌트가 옛것이다(1-7 ⑨ '저장하면 바로 반영').

**EC-D11 로그 가리기(GW16, 선택)는 접두 뒤가 8자 이상이고 숫자가 든 것만.** 접두가 `fmea_` 처럼 백엔드 키와 같으면 도구 이름(GW19 의 접두
이름 · 호출 별칭 `fmea_list_projects`)까지 가려 로그가 읽히지 않는다. 무작위 토큰에 숫자가 하나도 없을 확률은 무시할 만하다(16진 32자면 10⁻¹³대).

**EC-D12 `_call_tool` 은 `backends.get` 으로 백엔드를 찾는다.** 떼어 낸 뒤 다음 재집계 전까지 경로만 남은 순간의 호출이 `KeyError` 대신
「이 앱은 방금 게이트웨이에서 빠졌다」 와 감사 줄을 받는다(heax 앱을 뗄 때도 같은 틈이 있었다).

**EC-D13 스모크(PX1) · update-all(PX2)은 `conn_platforms` 가운데 붙어 있는 것(ok · down)만 외부 연결 플랫폼으로 본다.** `collision` ·
`invalid` · `no-policy-row` 의 키는 선언이 아니다 — 같은 키의 진짜 백엔드(예: 옛 `PER_USER_SSO_APPS` 로 만든 정적 백엔드)는 종전대로 검사 ·
복구한다.

**EC-D14 `update-collab.sh` 는 이 리포에 없다.** 요청서(cae00 기준)가 가리키는 운영 스크립트라 절차서에는 'cae00 운영 스크립트 — 이 리포의
추적 파일이 아니다' 라고 적었다. 그 ① · ⑥ 검사가 새 선언을 어떻게 보는지는 dev 에서 확인하지 못했다.

**EC-D15 10-21 초안 정정(D5 · D6 — 초안은 리포에 없다).** D5 — 초안 2절(P1~P10 · G1~G6, 앱마다 TestScope 카드를 복사하는 길)은 요청서
1절이 대신한다. 초안 G5(「MANAGED 에 matnexus · fmea 를 넣는다」)는 틀렸다 — 넣으면 provision 이 `<P>_MCP_URL` 백엔드를 만들지 않고 건너뛴다
(GW18, `MANAGED` 는 그대로 두고 시험이 지킨다). D6 — 초안의 보안 메모 「10-03 D-13 에서 Fernet 을 걷었다」 는 틀렸다. 등록 토큰은 처음부터
평문이다. 10-03 D-8 이 자동 연결용으로 Fernet 을 계획했으나 커밋되지 않은 작업 트리째 D-13 에서 걷혔다(sso-delegation context-notes D-8 ·
D-13). 확인 — `git log -S Fernet` 은 문서 · 이력 커밋만 내고 코드 경로(`backend/app` · 의존성 · `infra`)는 0건이다(2026-10-21).

**EC-D16 화면 확인은 임시 포털로 했다(2026-10-21).** 빈 포트 · 임시 저장소 · 사본 권한표(`ACCESS_PATH`)에 게이트웨이 주소 · 공유 비밀을 비워
실 DB 와 dev 게이트웨이를 건드리지 않았다. 다른 프로세스에서 원장을 고치면 원장 행 캐시(`USER_ROW_TTL_S`, 기본 3초)가 그 시간만큼 옛 행을
낸다 — 임시 포털은 0 으로 띄웠다. 27개 확인(권한 단계별 문 · 메뉴 · 카드 둘 · 등록 · 해제 · 고아 · 404 · 주소 인코딩 · `javascript:` 링크 막힘 ·
390 폭) 모두 통과.
