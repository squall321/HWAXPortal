## 0. 한눈에

- E-5 는 '누가 맡나' 를 고르는 세 자리 — 띵킹 소집 · 심의 좌석 발굴 · 지목 전문가의 도구 — 와 '맡은 사람이 없다' 판정을, 코어 어휘표에 더하는 얇은 연결(도메인 ↔ 코어 타입 ↔ 도구 영역 · 앱)로 받친다. 지식 전문가 도구 고르기의 손 표(`_AREA_HINT`)는 이 연결로 바꾼다.
- **먼저 잰다.** 기준선(B0)은 동작을 하나도 바꾸지 않고, 누설 없는 평가셋으로, cae00 에서 잰다. B0 가 이미 높으면 좌석 덮기는 하지 않고 도구와 '없음' 판정만 고친다(관문 G0, 2.7).
- 평가셋은 넷이다 — A 저작 혼동(ExpertAgents 반례 2,813 → 층화 600), H 실사용(cae00 질문 190 — 사람이 순위를 보지 않고 정답을 단다), N 맡은 사람 없음(실사례 · 코어 데이터 질문 · 도메인 지우기), 진단용 P · C. 전문가 표본(7,671)과 골든(6,050)은 정답이 새므로 기준에 쓰지 않는다.
- 기준선은 고정 숫자가 아니라 **같은 날 같은 풀에서 끈 쪽**이다. 켠 쪽과 짝으로 견준다.
- PLAN E-5 행의 근거 다섯 가운데 넷은 낡았고, 할 일 하나(카드 바인딩 저장소 둘)는 10-30 AD-20 으로 끝났다(1.4). 문제는 남아 있지만 모양이 다르다 — 도구는 '같은 29종' 이 아니라 '안 맞는 전문가도 다 받는다' 이고, '없음' 은 세 갈래로 흩어져 있다.

### 1.2 '맡은 사람이 없다' 는 세 갈래로 흩어져 있다

- 추천의 `low_confidence` — 어휘 일치 최고값 < 0.40. 심의 미리보기 화면(ExpertPicker · HandoffBrief)이 경고로 쓴다.
- 띵킹의 '아무도 답하지 못함' — 좌석 자기판정(LLM)이 전원 기권. 띵킹은 `low_confidence` 를 쓰지 않는다(띵킹 D0 ① — 질의별 값이라 좌석 판정에 못 쓴다).
- 심의 엔진에는 없다. 좌석이 2석 아래일 때 `no_personas` 로 멈출 뿐이다.
- '코어 데이터 질문(과제 코드 · 고장모드 조회)이라 전문가 몫이 아니다' 를 가르는 판정은 어디에도 없다.

## 2. 기준선 — 누설 없는 평가셋과 재는 법

### 2.1 누설 — 신호마다 새는 길과 규칙

| 신호 | 보는 것 | 새는 길 | 규칙 |
|---|---|---|---|
| 표본 | 질의 ↔ 전문가 표본 임베딩 | 질의가 표본이거나 표본을 바꿔 쓴 글이다 | **L1** 정답의 표본 · 골든과 3글자 조각 자카드가 0.5 이상이면 뺀다. S1 · S2 는 기준에 안 쓴다 |
| 어휘 | 질의 낱말 ↔ 이름 · 설명 · 태그 | 정답 이름 · 키를 그대로 쓴다. 정답 범위 글을 옮겨 쓴다 | **L2** 이름 · 키가 든 질의는 '이름 묶음' 으로 떼어 따로 낸다. **L3** 어휘 일치 칸(0.40 아래 · 위)마다 따로 내고, A 의 머리 숫자는 H 의 칸 비율로 무게를 맞춘다 |
| 카드 · 예심 | 질의 ↔ 좌석 카드 절 | 정답 카드에서 지은 질의다 | **L4** 카드 유래(S5)는 진단으로만 쓴다 |
| 자기판정(LLM) | 좌석 역할 글 + 카드 | 역할 글에 그 문구가 그대로 있다(S4 는 글을 쓴 전문가의 역할 글에 있다) | **L5** 위임 문구는 '문구 → 전문가' 한 단계만 잰다 |
| 정답 표시 | — | 시스템 순위를 보고 정답을 고른다. 띵킹이 답한 좌석 · 심의 좌석을 정답으로 쓴다 | **L6** 표시 화면에 순위 · 점수 · 지금 좌석을 보이지 않는다. 시스템이 고른 좌석은 정답이 아니다 |
| 손보기 | — | 시험 묶음을 보고 연결 · 현장 용어 · 덧씌우기를 고친다 | **L7** A 는 정답 전문가 단위로 개발 · 시험을 반씩 가르고, 시험 쪽 qid 목록의 sha256 을 8절에 적어 봉인한다. H 는 전부 시험이다. 연결 · 덧씌우기는 A-dev 와 도메인 검토만 보고 쓰고, 연결을 쓰는 사람은 H 를 보지 않는다(같은 사람이면 연결을 먼저 쓰고 단다) |
| 판 | — | 풀 · 임베더 · 어휘표가 바뀐 뒤의 숫자를 옛 숫자와 견준다 | **L8** 끈 쪽과 켠 쪽을 같은 날 같은 풀에서 잰다. 결과마다 판 지문을 싣는다 |

### 2.2 묶음

**A — 저작 혼동.** S3 를 L1 · L2 와 대상 거름(일반 대상 · 풀에 없는 키 · 자기 자신)으로 거른 2,813건에서 층화로 600건을 뽑는다.
- 몫 — HW 12 도메인(rel · disp · mech · cam · soc · pcb · rf · passive · pwr · sh · mem · sim) 각 30, 업무(xd) 60, 표준 · 오픈소스 · 규제(std · oss · misc) 있는 만큼(27), SW 120. 남는 몫은 HW 로 채운다. 포털 사용자가 HW · 해석 쪽이라 SW 를 덜 싣는다 — 숫자는 갈래마다 따로도 낸다.
- 한 정답 전문가 2건, 한 (정답, 글쓴이) 쌍 1건까지.

- 정답 전문가 단위로 A-dev 300 · A-test 300 을 가르고 A-test 를 봉인한다(L7).

  웹 심의 화면은 추천 상위 다섯을 기본으로 골라 두어 사람이 고친 것인지 모른다(L6 — 시스템이 고른 좌석은 정답이 아니다, 반대 검토 10-31 · C-48). 사람이 고른 전문가와 표시를 견주는 것은 지목 출처뿐이다(2.4).
- 거름 — 홀로 서지 않는 발화('그럼 그건?')를 뺀다. 3글자 조각 자카드 0.8 이상의 중복은 하나만 둔다. 8자 아래는 뺀다.
- 맡은 질문 150 + 맡은 사람이 없는 질문 40 을 사람이 단다(2.4). 출처마다 몫을 고르게 둔다.
- 전부 시험이다 — 손보기에 쓰지 않는다(L7).

**N — 맡은 사람 없음.**
- N1 실사례 — H 에서 '없음 — 풀 밖' 으로 단 것, 띵킹이 전원 기권했고 사람이 맞다고 본 것.
- N2 코어 데이터 질문 — cae00 16문항 점검기의 조회형 질문과 H 에서 '없음 — 코어 데이터' 로 단 것. 정답은 '전문가 몫이 아님 — 정본 허브' 다.

**P — 위임 문구(진단).** S4 3,605 에서 300건. `recommend_agents(문구, top_k=3)` 에 대상이 드는가를 본다 — 띵킹 위임 홉의 그 단계다.

**C — 카드 유래(진단).** S5 397건. 카드 주인이 상위 5에 드는가 — 카드 신호가 살아 있는지만 본다.

**쓰지 않는 것.** S1 표본 · S2 골든(누설). 심의 좌석 · 띵킹이 답한 좌석을 정답으로 쓰는 것(L6). 표본을 LLM 으로 바꿔 쓴 글 — 뜻이 그대로 새고 LLM 버릇이 더해진다.

### 2.3 크기 — 왜 이 수인가

| n | 0.5 근처 95% 구간 반폭 | 쓰임 |
|---|---|---|
| 40 | ±15.5%p | N1 + N2 의 바닥 |
| 150 | ±8.0%p | H(맡은 질문) |
| 300 | ±5.7%p | A-test |
| 600 | ±4.0%p | A 전체 |

짝 비교(McNemar)로 보면 엇갈린 짝이 20% 일 때 H 150 은 +10%p 를 잡는다(χ² 7.5 · p ≈ 0.006). +5%p 는 못 잡는다(p ≈ 0.17). A-test 300 은 +6%p 쯤부터 잡는다(p ≈ 0.02). 그래서 H 는 '크게 나아졌나' 를, A 는 '도메인 이웃을 가르나' 를 본다.

### 2.4 정답 표시 규약

- 표시 칸 — 주 전문가(1 ~ 3) · 같이 맡을 만한 전문가(0 ~ 5) · '없음 — 코어 데이터(정본 허브)' · '없음 — 풀 밖' · '모르겠음'(빼고 센다).
- 화면 — 질문 글과 도메인 나무(조직도 라벨 정본 그대로) · 전문가 카드(이름 · 설명)만 보인다. 추천 순위 · 점수 · 지금 좌석은 보이지 않는다(L6). 이름 찾기 칸은 두되, 찾아서 고른 것인지 나무에서 고른 것인지 적는다.
- 두 사람 — 한 사람이 190건을 달고, 다른 한 사람이 그중 30건을 겹쳐 단다. 주 전문가가 겹치는 비율과 도메인 일치도(κ)를 낸다. κ < 0.6 이면 엄격 지표 대신 관대 지표(주 ∪ 같이)와 도메인 지표를 머리 숫자로 쓴다.
- 지목 전문가 출처는 사용자가 고른 전문가를 화면에 보이지 않고 단 뒤, 둘이 얼마나 맞는지를 따로 낸다(사람이 고른 전문가를 얼마나 믿을 수 있는지).
- 저장 — cae00 박스 파일. 포털이 관리자 세션 + CSRF 로 받아 에이전트 서버 창구(공유 비밀)에 넘긴다. E-9 '도구 검색 검토' 와 같은 꼴이다.

### 2.7 성공 기준(안 — 결정 D-E5-7)

**관문 G0(B0 뒤).** H 의 심의 hit@5(관대) ≥ 0.85 · 띵킹 '정답이 물어본 좌석에 듦' ≥ 0.85 · 지금 신호 가운데 가장 나은 '없음' 이 정밀도 ≥ 0.80 · 재현율 ≥ 0.50 이면 좌석 덮기(E5-7 의 나)는 하지 않는다. 도구(E5-5)와 갈래 있는 '없음' 판정(E5-6)만 한다. 아니면 계속한다. 모자란 좌석(1.4)은 판정이 아니라 결함이라, B0 에서 0 이 아니면 관문과 상관없이 고친다(E5-7 의 가).

**켜는 기준(같은 날 같은 풀, 끈 쪽 대비 짝 비교).**
1. H 의 심의 hit@5 · 띵킹 '정답이 물어본 좌석에 듦' 가운데 하나 이상이 오르고(McNemar p < 0.05), 다른 하나는 −3%p 안이다.
2. A-test 에서 혼동 상대가 정답 위에 선 비율이 내려가거나 같고, acc@3 은 −3%p 안이다.
3. 갈래(HW · SW · 업무 · 기타, 어휘 칸 둘) 어디도 −5%p 넘게 떨어지지 않는다.
4. '없음' — N1 + N2 정밀도 ≥ 0.80 · 재현율 ≥ 0.50, H 의 맡은 질문에서 잘못 '없음' ≤ 5%. N3 은 잡음 띠와 함께 낸다.
5. 도구 — 앱 전문가의 앱 도구가 우선 12종 안에 100%, 사람 판정 정밀도@12 ≥ 0.80(또는 B0 + 20%p), 연결 없는 전문가의 우선 목록은 비었다.
6. 지킴 — 운영자 · 지워진 키 0, 띵킹 소집 + 예심 p95 +10% 안, 게이트웨이 도구 검색 평가 순위가 바이트까지 같다, 세 리포 시험이 통과한다.

## 3. 연결 표 — 안

### 3.1 칸

코어 어휘표(`backend/config/core_vocab.json`, 박스 덧씌우기 `core_vocab.local.json`)에 `personas` 한 칸을 더한다(권장 — D-E5-3).

```json
"personas": {
  "domains": {
    "<도메인 코드>": {"core_types": ["failure_mode"], "areas": ["calc", "material"], "apps": []}
  },
  "experts": {
    "<전문가 키>": {"apps": ["<게이트웨이 앱 키>"]}
  },
  "data_types": ["plm_task", "plm_model", "plm_project"],
  "no_tools": ["sw"]
}
```

- `domains` — 키는 전문가 키의 앞부분이다(`_dom_of` · `list_agent_domains` 와 같은 규칙). 라벨은 조직도 라벨 정본(`frontend/src/components/chat/orgTaxonomy.json`)에 두고 여기 옮기지 않는다.
- `core_types` — 어휘표 `types` 의 값(박스 덧씌우기로 더한 타입 포함)만 쓴다. 그 도메인이 판단을 맡는 코어 타입이다.
- `areas` · `apps` — 게이트웨이 `tool_areas.json` 의 영역 · 앱 키만 쓴다. 그 도메인 전문가에게 앞에 세울 도구의 범위다.
- `experts` — 자기 앱이 있는 지식 전문가(적층 계산 · 열충격 예측 · 물성 · 낙하 해석 · 변환 · 백서 · 시장(VOC) — 열 명 안팎)만 덮어쓴다. 781명에게 한 줄씩 쓰지 않는다.
- `data_types` — 조회가 답인 코어 타입이다. 이 타입만 가리키는 질문은 '전문가 몫이 아님 — 정본 허브' 갈래다(U4).
- `no_tools` — 도구를 일부러 주지 않는 도메인이다. 줄이 없는 도메인(아직 모름)과 가른다.
- 운영자(`he`)는 넣지 않는다. 운영자의 앱은 `infra/personas/he-team.json` 에 있다.
- 형제 리포 시험이 실제 파일로 대조한다 — 도메인이 조직도 라벨에 있다 · 타입이 `types` 에 있다 · 영역 · 앱이 게이트웨이 표에 있다 · 조직도 도메인마다 줄이 있거나 `no_tools` 에 있다. 틀린 줄은 그 줄만 버리고 까닭을 `/health` `core_vocab` 에 싣는다(C-11 과 같은 꼴).
- 게이트웨이 검색은 이 칸을 읽지 않는다. 그래서 도구 검색 순위는 바이트까지 같다(지킴 시험). 다만 어휘표 지문은 표 전체라 이 칸을 고쳐도 바뀐다 — E-7 검색 기록을 견줄 때 그 사실을 안다.

### 3.2 쓰는 곳

- **U1 도구(챗 지목 전문가 · 심의 좌석).** 후보는 연결된 영역 · 앱의 도구다(전문가 덮어쓰기 ∪ 도메인 줄). 후보 안에서는 질문 낱말과 도구 이름 · 설명의 겹침으로 세운다(`_trim_free_tools` 와 같은 셈, 입구 도구 먼저). 어느 좌석에나 필요한 입구(지식 · 보고서 · 시스템의 찾기 · 목록 도구)는 지금처럼 함께 준다. 역할 낱말 점수와 `_AREA_HINT` 는 걷는다. 연결이 없으면 우선 도구를 주지 않는다(D-E5-5) — 챗은 지금처럼 질문으로 고르고, 심의 좌석은 같은 자유 조회 풀을 질문 순으로 받는다. 띵킹 좌석에는 여전히 도구를 주지 않는다(띵킹 D3).
- **U2 코어 타입 감지.** 질문 → 어휘표 `types` · `search.words` → 타입 → 그 타입을 맡는 도메인 D(q). 낱말 셈은 챗 코어 규칙과 같은 함수를 쓴다.
- **U3 좌석 덮기(심의 발굴 · 띵킹 소집).** (가) 모자란 좌석부터 고친다 — `recommend_agents` 에 `top_k = 필요 수 + 제외 수 + 여유` 를 넘긴다. (나) D(q) 가 있는데 첫 좌석 · 후보에 D(q) 의 도메인이 하나도 없으면, 추천 40 안에서 그 도메인의 가장 앞선 전문가를 '덮기' 좌석으로 **더한다**. 빼지 않는다(delib-ux D-3). 띵킹은 후보에 더한다.
- **U4 갈래 있는 '없음'.** 넷으로 말한다 — ① 코어 데이터 질문(타입이 다 `data_types` 이고 분석 낱말이 없다) — '정본 허브에서 조회할 질문 — 전문가 몫이 아님' ② 풀 밖(D(q) 없음 · 어휘 최고 < 0.40 · 예심 근거가 드묾) ③ 도메인은 있는데 근거가 없음(띵킹 전원 기권 · 그 도메인 좌석이 있었다) ④ 답함. 띵킹 요약, 심의 상태 줄과 결정문의 덮음 줄, 미리보기 경고(두 입구가 같은 신호 — delib-ux D-11)에 같은 갈래를 싣는다.
- **U5 위임(띵킹 홉).** v1 은 지금 그대로다(지목 문구 → 추천). 관계를 쓸지는 P 진단 숫자를 보고 정한다(D-E5-4).

DB 읽기 질의 — 쓰기 없이 센다. AIDataHub 는 Postgres 이고, 박스 DB 에 읽기 전용으로 붙는 길은 AIDataHub 배포 문서를 따른다.

```sql
-- C-E5-1 · AIDataHub — 전문가 표에 없는 키 수, 그 키에만 묶인 살아 있는 카드 수
SELECT count(DISTINCT k) FROM records r, unnest(r.agents) AS k
 WHERE r.deleted_at IS NULL AND k NOT IN (SELECT agent_type FROM agents);
SELECT count(*) FROM records r
 WHERE r.deleted_at IS NULL AND cardinality(r.agents) > 0
   AND NOT EXISTS (SELECT 1 FROM unnest(r.agents) AS k JOIN agents a ON a.agent_type = k);
```

포털 대화 저장소는 SQLite 다. 경로는 포털 설정 `conv_store_path`(기본 `backend/data/conversations.sqlite` — 데이터 루트를 옮긴 박스는 심링크)이고, `sqlite3 -readonly <경로>` 또는 파이썬 `sqlite3.connect('file:<경로>?mode=ro', uri=True)` 로 연다. 백업과 같은 방식이라 저장을 막지 않는다(WAL).

## 9. 위험 · 열린 점

- **저작 어휘 치우침.** A 는 ExpertAgents 저작자의 말이다. 그래서 A 는 보조이고 H 가 기준이다. 어휘 칸 무게 맞춤(L3)은 H 를 단 뒤에야 된다.
- **표시 일치가 낮을 수 있다.** 같은 도메인 이웃이 많다(A 의 84%). 엄격 지표보다 관대 · 도메인 지표가 머리 숫자가 될 수 있다(2.4).
- **H 의 크기.** 60일 재료가 190건에 못 미치면 기간을 늘리거나 N 을 줄인다(C-E5-2 를 보고 정한다).
- **개인 대화를 표시에 쓰는 일.** 이름을 떼도 질문 글에 과제 이름이 들 수 있다. 사용자 허락 범위(D-E5-2) 안에서만 쓰고, 박스 밖으로 내지 않는다.
- **GLM 을 함께 쓴다.** LLM 겹은 심의가 없는 때에 돈다(띵킹 본심 100건이면 좌석 호출 수백 번).
- **dev 숫자는 dev 것이다.** 1.3 · 1.5 의 숫자는 dev 도구 지도(574종)와 dev 전문가 표로 셈했다. cae00 은 도구가 1,600개를 넘어 도구 쪽 숫자가 다르다 — 그래서 도구 지표도 cae00 에서 잰다.
