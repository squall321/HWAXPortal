# 클러스터 배선 — 컨텍스트 노트

> 결정과 **그 이유**를 이어 붙인다. 다음 세션이 같은 판단을 다시 내리지 않게.

## D-1 이름 하나가 토폴로지 전체를 바꿨다 (2026-09-22)

하루에 **세 번** 바로잡혔다. 적어 두지 않으면 네 번째가 난다.

1. 기록에 `stc→STE / stcx→SmartTwinMCP` 라고만 있었다. 규모가 없었다.
2. "stcx.sec.samsung.net 이 MCP 대상과 같다" 는 말을 듣고 **"그럼 한 클러스터가 두 얼굴"** 로 접었다. 틀렸다.
3. 사용자가 규모를 줬다 — **ste 24대, stcx 356대, 다른 클러스터.** 그제야 전부 맞아떨어졌다.

교훈은 이름이 아니라 **판별 기준**이다. `stc`/`stcx`/`ste` 는 한 글자 차이라 사람도 에이전트도 틀린다.
규모(24 / 356)를 같이 적으면 틀릴 수가 없다. 그래서 문서·기억에 규모를 박았다.

두 번의 오판이 각각 **없는 문제를 만들거나 있는 다리를 못 보게** 했다.
- "한 클러스터" 로 보면 → "파일을 어떻게 옮기나" 가 없는 문제가 된다(같은 `/data` 니까).
- "완전히 단절된 둘" 로 보면 → **이미 있는 공유 NFS** 를 못 보고 없는 전송 계층을 새로 짓는다.

진짜 구조는 **다른 클러스터 둘 + 공유 NFS 하나**다. 그래서 ③ 은 전송이 아니라 **경로 규약** 문제다.

## D-2 조사를 두 번 버렸다 — 전제가 틀린 조사는 결과도 틀린다

틀린 용어 규율을 심은 채로 6축 조사를 띄웠고, 사실이 바뀔 때마다 **중단하고 다시 태웠다**(두 번).
아까워 보이지만, 전제가 틀린 조사 결과는 그럴듯해서 더 위험하다 — 특히
"전각도 낙하를 ste 앱으로 올릴 수 있나" 같은 질문은 전제에 따라 **판정이 정반대로** 나온다.

규칙으로 남긴다: **에이전트에 심는 전제가 바뀌면 결과를 고쳐 쓰지 말고 다시 돌린다.**

## D-3 `stc` 를 지우되 ssh 별칭은 건드리지 않는다

`stc` 는 클러스터 이름으로는 없애지만 **`ssh stc`(Teleport 경유 ste 헤드노드 접속) 별칭은 그대로 둔다.**
`~/.ssh/config`·`rsync -e`·배포 스크립트가 그 이름으로 접속한다 — 바꾸면 배포가 조용히 깨진다.
이름 정리가 **접속을 깨는 것보다 중요한 적은 없다.**

같은 이유로 `ste-stcx.conf.snippet` 처럼 **참조가 딸린 파일 이름**은 참조를 전부 찾은 뒤에만 건드린다.

## D-4 ste 등록 파일(`ste-sync.json`) — 먼저 고친 것 (커밋 6fd4e0e)

이 배선 작업 앞에, 사용자가 ste 에 붙지 못하던 실제 원인 둘을 고쳤다.
안내의 예시 주소가 `stcx.sec.samsung.net/ste` 였는데 **개인 PC 는 stcx 에 못 닿는 경우가 있다** —
기본을 포털(`hwax.sec.samsung.net/ste`)로 바꿨다. 그리고 40자 PAT 를 명령 프롬프트에 붙여 넣게 하던 것을,
웹이 `ste-sync.json`(주소+토큰)을 내려 주고 exe 가 옆에서 읽게 바꿨다.

㉰(포털 로그인으로 PAT 자동 연결)이 들어가면 **이 파일도 필요 없어진다.** 그때까지의 다리다.
