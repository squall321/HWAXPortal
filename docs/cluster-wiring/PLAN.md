## 3. 아직 안 정해진 것

### ⚠ 실측으로 깨진 전제 둘 (2026-09-22)

**(1) ste 업로드 착지 경로는 `/data/SmartTwinExplorer` 가 아니다.** 코드 기본값은 그렇지만
배포 설정이 전부 덮는다 — `examples/cluster.prod.yaml:87`·`examples/dev_2vm.yaml:76` 둘 다
`shared: /srv/ste` 다. **아무 배포 경로도 코드 기본값을 고르지 않는다.** 그러면 "ste 가 올린
파일이 stcx 와 공유하는 `/data` 에 떨어진다" 는 말이 성립하지 않는다 — `/srv/ste` 는 ste 헤드가
**자기 계산노드에** 내보내는 export 일 수 있다. ③ 의 설계가 여기 걸려 있으므로 실박스에서
`systemctl show ste-backend -p Environment` 와 `findmnt` 로 확정해야 한다.

**(2) `:5013` 에서 도는 코드는 `SmartTwinMCP` 리포가 아니다.** 실측 —
`KooSlurmInstallAutomationRefactory/dashboard/smarttwin_mcp` 가 `--tools-root` 까지 그쪽을 보며
돈다(pid 1776). **`~/claude/SmartTwinMCP` 를 고쳐도 도는 것은 안 바뀐다.** 어느 쪽이 정본인지
사용자 결정이 필요하고, 그 전에는 그 리포의 도구를 고치지 않는다.

### 조사 대기

- **착지 경로가 stcx 에서도 같은 볼륨인가.** 경로 이름이 같은 것과 같은 볼륨인 것은 다르다 — `stat -c '%d:%i'` 로 대조해야 한다.
- **권한** — stcx 쪽 실행 계정이 ste 잡 폴더를 읽을 수 있나. ste-run 은 `UMask=0027` 이고 export 가 `root_squash` 라 추측이 아니라 **시도**가 답이다.
- **㉮ 를 어느 길로** — DynaForge 가 SmartTwinMCP 도구를 재사용하나, 직접 ssh 하나. 자격증명 확산 대 중복 구현의 교환이다.
- **에어갭에서 JWKS** — ste 헤드노드는 인터넷이 전무하다. ㉰ 의 가장 큰 함정일 수 있다.
- **ste 의 관리자 승인제**를 포털 로그인이 갈음하는가, 신원만 잇고 승인은 남기는가.
- **ste 의 "SSO 리다이렉트 없이 백엔드가 401"** 요구와 ㉰ 가 충돌하지 않는가.

## 4. 규율

- **dev 에서 검증 가능한 것과 실박스(cae00·ste·stcx)에서만 가능한 것을 갈라 적는다.** 후자는 사용자 몫으로 뺀다.
- **최소 구현.** 요청 밖의 기능·추상화·설정 가능성을 넣지 않는다.
- 내부 IP·토큰·비밀번호를 추적 파일에 적지 않는다. 이 리포는 GitHub 에 있다.
