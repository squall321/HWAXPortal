## 2. 작업 여섯

| # | 무엇 | 성공 기준(검증 가능한 형태) |
|---|---|---|
| ① | **표기 규율** — ste/stcx 를 코드·문서에서 바로잡고 가드로 못 박는다 | 가드 테스트가 통과하고, 위반 목록이 **줄어들기만 한다**. `ssh stc` 별칭은 건드리지 않는다 |
| ② | **ste 업로드 스트리밍화** — 지금은 `await f.read()` 로 통째 메모리 | 큰 파일 제출 시 백엔드 RSS 가 파일 크기에 비례하지 않는다. 상한 초과는 **읽기 전에** 413 |
| ③ | **stcx 반입 자동화** — 사람이 scp 하던 것 | 공유 NFS 가 확인되면 "옮기기" 가 아니라 **"경로 잇기"** 다. ste 잡 디렉터리를 `work_dir` 로 그대로 넘길 수 있다 |
| ④ | **cae00→stcx ssh 왕복** — 실패 모드가 전부 같은 모양으로 보이지 않게 | 호스트 없음·인증서 만료·명령 실패·타임아웃이 **반환값에서 구분**된다 |
| ㉮ | **stcx 잡을 DynaForge 작업 옵션으로** | DynaForge 에서 모델을 고르고 "stcx 로 전각도 낙하" 를 선택해 제출된다. 잡 상태가 DynaForge 로 되먹여진다 |
| ㉯ | **ste 를 MCP 로 포털에 붙인다** | 게이트웨이 `tools/list` 에 ste 도구가 뜨고, 포털 챗에서 ste 잡을 제출·조회할 수 있다 |
| ㉰ | **포털 로그인 → ste 계정·PAT 자동 연결** | 사용자가 ste 에 따로 가입하거나 PAT 를 옮겨 적지 않는다. 잡 소유자가 **본인**으로 남는다 |

## 3. 아직 안 정해진 것 (조사 대기)

- **공유 NFS 가 정말 같은 경로인가.** ③ 전체가 여기에 걸려 있다. 근거가 메모 한 줄뿐이라 실박스 확인이 필요하다.
- **㉮ 를 어느 길로** — DynaForge 가 SmartTwinMCP 도구를 재사용하나, 직접 ssh 하나. 자격증명 확산 대 중복 구현의 교환이다.
- **에어갭에서 JWKS** — ste 헤드노드는 인터넷이 전무하다. ㉰ 의 가장 큰 함정일 수 있다.
- **ste 의 관리자 승인제**를 포털 로그인이 갈음하는가, 신원만 잇고 승인은 남기는가.
- **ste 의 "SSO 리다이렉트 없이 백엔드가 401"** 요구와 ㉰ 가 충돌하지 않는가.

## 4. 규율

- **dev 에서 검증 가능한 것과 실박스(cae00·ste·stcx)에서만 가능한 것을 갈라 적는다.** 후자는 사용자 몫으로 뺀다.
- **최소 구현.** 요청 밖의 기능·추상화·설정 가능성을 넣지 않는다.
- 내부 IP·토큰·비밀번호를 추적 파일에 적지 않는다. 이 리포는 GitHub 에 있다.
