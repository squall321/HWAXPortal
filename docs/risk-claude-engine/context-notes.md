# 리스크 심사 Claude 길 — 결정과 까닭

**X-D1 사용자 결정(2026-10-15).** "일단 현행 계획대로 완료해주고 완전 클로드 버전으로도 할 수 있게끔만 해두고 그거는 테스트는 하지 말고 유저가 원하면 할 수 있게끔만 하자." — M3 는 GLM 으로 끝내고, Claude 길은 지어 두되 기본 꺼짐이다. '테스트는 하지 말고' 는 실제 Claude 로 심사를 돌리는 시험(사용량)을 하지 않는다는 뜻으로 읽었다 — 가짜 응답자로 배선이 깨지지 않았는지 보는 코드 시험은 넣는다(전역 지침 8 '테스트 후 완료').

**X-D2 사용량 어림(10-15, 실측 아님 — ±40%).** M3 전원 한 번은 호출 약 17,000(거르기 꺼짐)·10,000(켬), 입력 약 2.4억·1.5억 토큰, 출력 약 3,500만·2,200만 토큰이다. 바탕 — 카드 전부 평균 57,072자·카드당 약 1,900자·점검 카드 12.9장(8장씩 셀당 2번)·글자/토큰 2·단위 본문 3,000자(M0-c 미실측이 가장 큰 불확실). Claude Code 서브에이전트로 돌리면 호출마다 기본 문맥이 붙어 묶어 처리하지 않으면 두 배 가까이 된다. 그래서 전원 전부를 Claude 로 돌리는 것은 구독 한도로는 현실적이지 않다고 사용자에게 말했고, 나눠 쓰기(카드 대조 GLM · 쟁점 패널·종합만 Claude, 약 3,000만 토큰)와 대표 9명 비교 실행(600만~800만 토큰)을 권했다.

**X-D3 모양 — 앱이 아니라 엔진의 LLM 자리에 꽂는다.** 앱이 Claude 에게 직접 과제를 주면 엔진의 프롬프트·파서·보충 되묻기를 둘로 갈라 지녀야 한다(엔진과 앱의 정체성 규칙이 어긋나 D-44·D-46 의 결함이 났던 것과 같은 길). 엔진의 `delib_llm` 자리에 외부 응답자를 꽂으면 계약·검사·원장이 하나로 남는다. 쟁점 패널은 외부 응답자가 엔진의 도구를 실행할 수 없어 evidence_only 로 돈다.
