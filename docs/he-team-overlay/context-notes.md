# HE팀 운영자 박스 덧씌우기 — 결정 기록

계획은 [PLAN.md](PLAN.md), 할 일은 [checklist.md](checklist.md)다. 날짜는 KST.

**HO-1 사용자 결정 11-04 — 덧씌우기(git 기본 + cae00 박스 파일).** 사용자 물음 「he-team.json 은 왜 추적 파일이냐」 · 「사내에는 있는데 이 개발에는 없는 것들이 있다 —
cae00 에서 관리하는 게 맞을 것 같다」 에서 고른 안이다. 버린 것 — ① cae00 전용 운영자를 git 에서 걷어 박스 파일로만(공개 리포에서 사내 전용 정의가 빠지지만 그 몫은
git 이력 · dev 시험이 없다), ② 정본을 통째로 박스 파일로(리뷰 · 이력 · 시험 고정이 없어진다), ③ 지금대로(고칠 때마다 받은 편지함으로 한 바퀴). 9-11 의 D-4(정본은 git,
AIDataHub 는 사본 — docs/org-chart)는 그대로이고, 박스마다 다른 것을 박스 파일이 덮는 칸이 하나 생긴 것이다.

**HO-2 꼴 — 운영자 키로 묶은 merge patch.** 운영자는 정본에서 목록(`personas[]`)이라 RFC 7386 을 문서 통째로 걸면 덧씌우기가 목록 전체를 다시 적어야 한다. 그래서
`personas` 만 운영자 키로 묶은 객체로 받는다 — 있는 키는 그 운영자에 merge patch, 없는 키는 새 운영자, `null` 은 뺀다. 운영자 안의 목록(writes · confirm · optional …)은
RFC 7386 대로 통째로 바뀐다 — 덧붙이기 꼴(`writes+`)을 따로 두면 셈이 둘이 되고 읽는 곳 셋이 모두 알아야 한다. 코어 어휘표 덧씌우기와 같은 셈이라 cae00 이 하나만 익힌다.

**HO-3 깨지면 통째로 버린다.** 반쯤 읽힌 덧씌우기는 어느 운영자가 덮였는지 사람이 알 수 없다. 코어 어휘표와 같이 버리고 기본 정의로 돌며, 까닭을 동기화 미리보기 ·
update-all · `/health` 에 찍는다. 확인 관문은 이때 기본 목록으로 돈다(덧씌우기로 더한 확인 이름이 빠진다 — 그래서 크게 알린다).

**HO-4 읽는 셈은 포털 모듈 하나 + 에이전트 서버 사본.** 동기화(시스템 python3 로 도는 스크립트)와 포털 백엔드는 `infra/personas/he_team.py`(표준 라이브러리만)를
같이 쓴다. 에이전트 서버는 같은 셈을 따로 둔다 — 실행 중에 형제 리포의 코드를 들이면 판이 어긋날 때 서버가 뜨지 못한다(지금 형제 리포의 JSON 을 읽는 것과 무게가 다르다).
에이전트 서버 시험이 형제 리포의 `he_team.py` 를 들여 같은 입력에 같은 합친 정의 · 지문이 나오는지 견준다.
