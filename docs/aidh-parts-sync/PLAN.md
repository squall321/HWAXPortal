## 2. 조각 스냅숏

- **dev(`parts-to-drive.sh`, 하루 한 번 — 전체 덤프 뒤)** — 표마다 정해진 열을 이진 COPY 로 내고, 레코드에 딸린 큰 표(records · record_sections ·
  record_attachments · agent_records)는 `record_id` 해시로 **64 조각**, 나머지는 한 조각이다. 조각 파일은 `ORDER BY` 키 · `gzip -n` 이라 같은 데이터면 같은
  바이트다 — 이름에 내용 해시를 달아 **안 바뀐 조각은 다시 올리지 않는다**. 스키마(색인 · 제약 뺀 pre-data)도 같은 꼴로 한 파일, 목록(manifest)이 조각마다 해시 ·
  줄 수 · 열 목록을 적는다. 목록은 3판을 두고 어느 목록도 가리키지 않는 조각은 지운다(AP-11).
  - 내지 않는 열 — 이 박스 몫인 조회 통계(`records.read_count` · `last_accessed_at` — dev 의 조회가 조각을 매일 바꾸지 않게) · 박스마다 따로 매기는 대리 id
    (`record_sections.id` · `external_id_map.id` · `agent_sample_embeddings.id` — 병합도 쓰지 않는다).
- **cae00(update-all §3)** — 목록(작다)만 받아 지난번 병합한 목록과 견주고 **해시가 다른 조각만** 받는다(받은 조각은 박스에 둬 다시 받지 않는다). 다른 것이
  없으면 그 자리에서 끝난다. 있으면 스키마로 **빈 스테이징**(색인 없음)을 만들고 받은 조각만 싣고 **지금의 병합 규칙 그대로**(`merge_table` · `merge_samples` — m3
  슬롯 채움 · 이 박스 조회 통계 지킴 · agent 단위 표본 · dev 에만 있는 열이면 3) 병합한다. 운영 전체 스냅숏 대신 **덮을 줄의 앞 모습과 새로 든 키**만 남긴다
  (`rollback-parts.sh` 로 되돌린다). 표본 표는 전문가 조각이 바뀌어도 함께 싣는다(병합이 sample_queries 와 견준다). 목록이 가장 새 전체 덤프보다 하루 넘게
  낡았으면(dev 의 하루 한 번 내기가 멈췄다) 받기가 5 로 끝나 전체 덤프 길로 간다 — 낡은 채 '바뀐 것 없음' 으로 머물지 않는다(AP-14).
- **같은 줄은 다시 쓰지 않는다** — 바뀐 시각 칸이 없는 표의 덮기에 `WHERE (열…) IS DISTINCT FROM (EXCLUDED 열…)`. 전체 덤프 병합에도 같이 든다.
- **전체 덤프는 그대로** — 재해 복구 · 조각이 없을 때의 길이다. 조각 목록이 없거나 조각 길이 실패하면 update-all 은 지금의 전체 병합으로 돌아간다.

## 3. 기대

| 경우 | 받기 | 쓰기 |
|---|---|---|
| 바뀐 것 없음(거의 매일) | 목록 하나(수십 KB) | 없음 — 곧 끝 |
| 논문 하나 · 레코드 몇 | 그 조각들(조각 하나 ≈ 레코드 1/64 — 실측 절 조각 ≤ 100 MB · 레코드 조각 ≤ 13 MB) | 그 레코드의 줄만 — 수 분 |
| 전부 바뀜(전체 다시 임베딩 등) · cae00 첫 조각 병합 | 조각 전부(실측 6.4 GiB — 덤프 10.3 GiB) | 스테이징 색인 · 전체 스냅숏 없이 — 지금보다 빠르다 |

dev 첫 내기(11-05) — 264 파일 · 6.4 GiB · 1,719초(캐시가 빈 채 · 다른 시험과 겹쳐). 레코드가 늘면 조각이 커질 뿐 조각 수는 그대로다(AIDH_PARTS_N).

## 4. 시험

dev 에 PostgreSQL 16 + pgvector 가 있다 — 임시 클러스터로 끝에서 끝까지(내기 → 목록 → 다른 조각만 → 병합 → 같은 결과). 전체 병합과 조각 병합이 같은 데이터에서
같은 결과인지 · 바뀐 것 없으면 건너뜀 · 레코드 하나 → 그 조각만 · dev 에만 있는 열 → 3 · 표본 규칙 · 되돌리기 · 해시 결정성(같은 데이터 두 번 → 같은 바이트).
