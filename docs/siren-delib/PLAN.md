# SIREN 을 심의 · 리스크 심사에서 — 11-04 연동 뒤 개발 쪽 요청 반영

> 요청서 정본 — [request.md](request.md)(cae00 세션 11-04 · 11-05, 사용자가 11-06 에 넘김). 결정 · 까닭은 [context-notes.md](context-notes.md),
> 할 일은 [checklist.md](checklist.md), cae00 사람 몫은 [server-setup.md](server-setup.md), 리스크 앱 화면 몫은 [frontend-request.md](frontend-request.md)다.

## 1. 무엇을 · 왜

cae00 이 사내 불량 · 대책 사례 DB 인 SIREN(MCP 도구 다섯)을 게이트웨이에 '외부 연결'(박스 권한표 `connect:`)로 붙였다. 챗에서는 돌았고, 사용자가
SIREN 을 **심의 · 리스크 심사에서도** 쓰기로 했다(11-04 밤). 그러려면 네 리포를 고쳐야 한다 — 요청서 2 ~ 4절의 아홉 항목과 그것이 기대는 포털 칸 둘이다.

## 3. 고치는 것

| 항목 | 리포 | 무엇이 바뀌나 |
|---|---|---|
| HG-26 | 게이트웨이 | 등록 토큰 길(as-conn)의 실패를 그쪽이 준 상태로 가른다 — 401 만 '다시 등록', 429 는 '잠시 뒤(Retry-After 초)', 403 은 '권한 · 출발 IP — 관리자에게', 그 밖은 '그쪽 서버 오류'. 실패 감사 줄에 부른 사람 · `as-conn` · corr · `status:NNN` · 토큰 지문 |
| HG-27 | 게이트웨이 · 포털 | 선언 백엔드 호출마다 `X-Request-Id`(새 UUID) — 감사 줄 `rid` 에 같은 값. 선언 칸 `request_id: false` 로 끈다(내장 RA · TestScope 에는 싣지 않는다) |
| HG-28 | 게이트웨이 | `tool_areas.json` 의 앱 기본값에 `siren` → 이미 있는 영역 `quality`(품질·불량 이력) |
| HG-29 | 게이트웨이 · 포털 | 선언 칸 `mask_keep_hosts`(사설 IPv4 목록, 기본 비움) — 그 주소가 링크의 호스트(`http(s)://` 바로 뒤)로 올 때만 가리지 않는다. 다른 사설 주소 · 글 속 같은 주소는 그대로 가린다(D-2) |
| HA-36 | 에이전트 서버 | 좌석 자유 조회에 선언 백엔드의 **확인된** 읽기(게이트웨이 `/tools-map` 의 `panel_read`)를 들인다 — 겹침 접두 사본(운영 사본)은 빼고, 기준일 심의는 들이지 않는다. 리스크 심사 · 리스크 앱 패널에도 들이고(앱이 실은 앱 목록의 좁히기에서도 남긴다), 닫기 목록 · D-18 거름이 앞선다. 한 실행의 줄 — 선언 백엔드마다 동시 `DELIB_CONN_CONCURRENCY`(기본 2)건, 429 · 미연결을 받은 백엔드는 그 실행에서 다시 부르지 않는다(SD-17 ~ SD-20) |
| HA-37 | 에이전트 서버 | 지정 도구 차례를 원래 이름 · 제 앱 키 머리를 뗀 꼴로 본다 — `siren_list_groups` · `siren_search_cases` 가 `siren_get_case` 보다 먼저(같은 무리 안은 받은 차례) |
| HA-38 | 에이전트 서버 | 수치 대조의 천 단위 쉼표는 뒤 묶음이 모두 세 자리일 때만 수 하나다 — 쪽 번호 `p.2,3,10,11,23` 을 3101123 으로 읽지 않는다(챗 근거 블록 · 심의 결정문이 같은 판정) |
| RK-12 엔진 몫 | 에이전트 서버 | 지정 도구가 외부 연결에서 미연결(등록 토큰 없음 · 401) · 한도 초과(429)로 끝나면 다시 시키지 않고 경고 사건(`conn_unregistered` · `conn_rate_limited` — backends · labels · tools)과 '지정 도구 미실행' 카드로 낸다. 신뢰 · 확인 칸(`trust` · `human_verified`)이 있는 외부 연결 결과에는 trust 안내 한 줄(지정 도구는 결과 머리줄, 좌석 조회는 결과 머리 — SD-18) |
| RK-12 | 리스크 앱 | 박스 손잡이 `HWAXRISK_CASE_TOOLS`(기본 SIREN 셋, `off` 로 끔) — **러너가 패널을 띄울 때** 게이트웨이 `/tools-map` 에 있는 것만, 보통 패널은 지정 도구 상한 6 의 남은 자리만큼, 쟁점 패널은 셋 다, 패널 호출 상한 안에서만 · Claude 잡은 빼고(SD-27 ~ SD-29). 실은 것 · 싣지 않은 까닭은 패널 품질(`case_tools` · `case_tools_skipped`), 엔진 경고는 품질 표지(`conn_unregistered` · `conn_rate_limited` — 표시 이름 목록)로 남기고, 보고서의 쟁점 줄에 '외부 사례: SIREN 미연결' |
| 포털 | 포털 | 권한표 `connect:` 가 새 칸 둘(`request_id` · `mask_keep_hosts`)을 알아보고 게이트웨이에 넘긴다(모르는 칸이면 블록 통째로 버리는 규칙은 그대로) |

## 4. 하지 않는 것

- 리스크 앱 좌석 계약표(엔진 · 워크플로 · 앱 자산 세 곳 대조)는 고치지 않는다 — trust 규칙은 엔진의 결과 한 줄로 지킨다(사용자 결정).
- 리스크 앱 보고서의 결정적 '사례 · trust 표' — 결과 본문을 앱이 받지 않아(이벤트 압축) 새로 지어야 한다. 사용자가 엔진 한 줄을 골랐다.
- MCP 길(Claude Code 가 패널을 도는 `hwax-risk-review.js`)은 지정 도구를 돌리지 않는다 — 그 길의 패널에는 SIREN 이 실리지 않는다(지금 구조 그대로, 5절).
- Claude 잡(웹 러너의 외부 응답자)의 패널에도 SIREN 지정 도구를 싣지 않는다 — 반출 동의문이 외부 사례 DB 를 말하지 않는다(SD-28, 실으려면 동의문 · 사용자 결정).
- HP-62(SIREN 운영자)는 cae00 박스 덧씌우기로 이미 반영했다(요청서 1절).
- 리스크 앱 화면 — 화면 세션 몫이다(요청서는 [frontend-request.md](frontend-request.md)).

## 5. 알려진 빈 곳

- 줄(_ConnGate)은 **잡 하나** 안의 것이다. 잡 주인이 같은 리스크 잡의 패널 둘을 함께 돌리면(동시 실행 2) 두 잡의 SIREN 호출은 서로를 모른다 — 그때의 429 는
  각 잡이 받고 그 잡에서 멈춘다.
- 보통 패널은 같은 변경 요지로 SIREN 을 패널마다 찾는다 — 같은 인자면 게이트웨이 응답 캐시가 합치지만 LLM 이 인자를 조금씩 바꾸면 그대로 부른다.
- 경고의 표시 이름(labels)은 에이전트 서버가 게이트웨이 앱 목록에서 읽는다 — 못 읽으면 백엔드 키(`siren`)로 남는다.
