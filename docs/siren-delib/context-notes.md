# SIREN 을 심의 · 리스크 심사에서 — 결정 기록

> 날짜는 한국 시각이다. 요청서 [request.md](request.md), 계획 [PLAN.md](PLAN.md).

**SD-1 사용자 결정 넷(11-06).** HA-36 은 리스크 심사에도 · RK-12 는 보통 · 쟁점 패널 둘 다 · trust 규칙은 엔진이 결과에 한 줄 · HG-29 는 손잡이만(PLAN 2절).
리스크 심사의 자유 조회에 넣는 길(`_RISK_KEEP_TOOLS` 에 이름을 더하는 길)은 요청서 5절대로 쓰지 않았다 — 이름이 아니라 게이트웨이의 확인된 읽기로 일반 판정에 넣었다.

**SD-2 HA-36 의 판정은 `panel_read` 다(이름 낱말 없이).** `/tools-map` 에는 읽기 목록이 둘이다 — `routine_read`(앱 표지 · 읽기 목록 · 조회 낱말)와
`panel_read`(앱 표지 · 읽기 목록만). 이름 낱말 갈래는 울타리가 아니므로(반대 검토 10-31 — `job_info_cleanup` 같은 쓰기가 조회 낱말로 열렸다) 좌석에 여는
판정은 닫힌 쪽 `panel_read` 를 쓴다. SIREN 다섯은 박스 권한표 `connect.read_tools` 로 표지가 달려 `panel_read` 에 든다(요청서 5절).

**SD-3 겹침 접두가 붙은 선언 도구는 들이지 않는다.** 운영 사본(stepforge-prod 등)은 허브 앱과 같은 도구라 게이트웨이가 선언 쪽에 접두를 단다 — 그것을
들이면 같은 도구가 두 벌이 된다(F0 가 선언 백엔드를 원래 이름 판정에서 뺀 까닭과 같다). 제 이름으로 붙은 것(`siren_search_cases` — 노출 이름 = 원래 이름)만
든다. `/tools-map` 의 `orig` 를 모르는 옛 게이트웨이면 가를 수 없어 아무것도 들이지 않는다.

**SD-4 기준일 심의는 외부 연결을 들이지 않는다.** 소급 검증(as_of)은 그 날 뒤의 자료가 섞이면 안 되는데 SIREN 사례를 날짜로 거를 길이 없다 — F0 의 OF-22 와
같은 닫힌 쪽이다.

**SD-5 리스크 심사에서는 앱 목록 좁히기에서도 남긴다.** 리스크 앱은 패널마다 앱 목록(어댑터 앱 셋까지)을 실어 엔진이 자유 조회를 그 앱들로 좁힌다 — 그대로면
SIREN 이 다시 빠져 사용자 결정(리스크 심사에도)이 먹지 않는다. 그 앱 목록은 사람이 고른 것이 아니라 앱이 싣는 것이라, 리스크 심사 의장 · 앱이 띄운 패널에서만
외부 연결 읽기를 남긴다. 사람이 앱을 고른 일반 심의는 고른 앱의 것만 남는다(종전 그대로).

**SD-6 줄은 잡 하나 · 선언 백엔드 하나마다.** 좌석들은 잡 주인 토큰 하나로 그쪽을 부른다(SIREN — 토큰당 동시 2 · 검색 1분 10번). `DELIB_CONN_CONCURRENCY`
(기본 2)건씩 줄 세우고, 429 를 받은 백엔드는 그 잡에서 다시 부르지 않는다(막은 호출은 실패 글로 까닭을 말한다 — 좌석이 인자를 바꿔 되풀이하지 않게). 같은 도구 ·
같은 인자는 잡 캐시가 먼저 합치므로 줄은 그 안쪽(실제 호출)에 건다. 지정 도구(엔진 로드)와 좌석 조회(따로 로드)가 같은 줄을 쓴다.

**SD-7 지정 도구의 미연결 · 한도 초과는 다시 시키지 않는다.** 종전엔 거절 글이 계획자에게 '직전 오류' 로 돌아가 한 번 더 불렸다(같은 거절을 한 번 더 받는다).
등록 토큰 없음 · 401 은 `/tokens?tab=connect` 안내가 실린 실패, 429 는 실패 글 속 `429` 로 가른다(게이트웨이 HG-26 문구와 옛 문구 둘 다). 한도 초과를 먼저
가른다 — 옛 게이트웨이는 429 에도 '다시 등록하세요' 라고 썼다.

**SD-8 리스크 앱은 글이 아니라 경고 code 로 안다.** 엔진은 '지정 도구 미실행' 카드(글)와 함께 경고 사건 `conn_unregistered` · `conn_rate_limited` 를
backends · labels(게이트웨이 앱 표시 이름) · tools 와 낸다. 리스크 앱 엔진 클라이언트가 그 칸을 받아 두고 러너가 `quality[code] = [표시 이름 …]` 과
플래그로 남긴다 — 화면 · 보고서 회의록이 '○○ 미연결' 로 보인다. 카드 글을 읽어 가르면 문구를 고칠 때 조용히 끊긴다.

**SD-9 trust 안내는 결과의 머리에 둔다(꼬리가 아니라).** 좌석 발언 턴에 실을 때 몫에 맞춰 결과의 뒤를 자르므로 꼬리에 두면 잘린다. 지정 도구 결과는 묶음의
머리줄(`### 도구 ← 인자`) 다음 줄에, 좌석 조회 결과는 결과 글 맨 앞에 둔다. 실패 글 · 오류 봉투 · 빈 결과에는 붙이지 않는다 — 빈 결과에 붙이면 근거로 읽힌다.
안내는 SIREN 전용 글이 아니라 외부 연결 결과 일반의 글이다('결과가 주는 신뢰 · 확인 칸을 그대로, 사람이 확인하지 않은 것은 후보로만 · 비었다고 리스크
없음이 아니다') — 그런 칸이 없는 플랫폼(FMEA · MatNexus)에는 아무 일도 하지 않는다.

**SD-10 HG-26 은 셋만 가른다.** 401 · 403 · 429 를 JSON-RPC 오류 문구 맨 앞(SIREN — HTTP 200 + `401 token_invalid` 꼴), HTTP 오류의 상태 · Retry-After
머리글, 문구 속 'NNN 이유' 꼴 순으로 본다. 묶음(ExceptionGroup — 단발 세션의 태스크 그룹이 한두 겹 싼다)은 안까지 본다. 그 밖은 모두 '그쪽 서버 오류'다.
게이트웨이는 어느 쪽이든 다시 부르지 않는다(종전 그대로). 실패 감사 줄에 부른 사람 · `mode=as-conn` · corr · `status:NNN` · 토큰 지문을 단다 — 종전 실패 줄은
caller 가 없어 누구의 호출인지 감사로 잇지 못했다.

**SD-11 HG-27 은 호출마다 새 UUID 다(corr 가 아니라).** 대화 상관 ID 를 바깥 팀에 주면 우리 대화의 묶음이 밖으로 나간다. 호출 하나 = 값 하나라 감사 줄 하나와
정확히 맞는다. 기본은 켬(선언 백엔드만) — 끄기는 선언 칸 `request_id: false`.

**SD-12 HG-28 은 새 영역이 아니라 `quality` 다.** 이미 '품질·불량 이력'(사내 PLM 불량 · FMEA)이 있다 — 요청서의 `siren` 키는 '예' 였다. 영역 키를 늘리면 화면
선택 상태가 갈라진다. 설명에 '부품 불량 · 대책 사례(SIREN)' 를 덧붙였다.

**SD-13 HG-29 는 링크의 호스트 자리만.** 가림 예외 주소가 `http(s)://`(JSON 이 빗금을 `\/` 로 적은 꼴 포함) 바로 뒤에 올 때만 그대로 둔다. 글 속에 따로 쓴
같은 주소 · 다른 사설 주소는 가린다(D-2 그대로). 값은 사설 IPv4 글자만 받는다(가림이 사설 IPv4 만 가리므로 다른 꼴은 뜻이 없다) — 포트 · 이름 주소는 틀린
선언으로 버린다. 먼저 SIREN 이 이름 주소 링크를 주게 하는 것(R-9)이 낫다 — 그쪽이 못 할 때 cae00 이 켠다.

**SD-14 포털이 먼저다(새 칸 둘).** 포털 권한표는 모르는 칸이 있는 `connect:` 블록을 통째로 버린다(오타가 칸을 조용히 기본값으로 남기지 않게 — EC-D3). 그래서
cae00 은 새 판(포털 · 게이트웨이)을 받은 **뒤에** 박스 권한표에 `request_id` · `mask_keep_hosts` 를 적는다 — 먼저 적으면 SIREN 연결이 통째로 빠진다. 게이트웨이는
모르는 칸을 무시하므로(새 포털 ↔ 옛 게이트웨이) 문제가 없다.

**SD-15 RK-12 손잡이는 이름 목록이고 기본이 SIREN 셋이다.** 기본을 비우면 cae00 이 손잡이를 잊었을 때 SIREN 이 조용히 빠진다. 기본을 SIREN 셋으로 두고 게이트웨이
`/tools-map`(사람 시야와 상관없는 전체 지도)에 있는 것만 싣는다 — SIREN 이 없는 박스(dev)는 그대로다. 지도를 못 읽으면 싣지 않는다(없는 도구를 실으면 엔진이
패널마다 '지정 도구 없음' 을 남긴다). 끄기는 `HWAXRISK_CASE_TOOLS=off`(빈 값은 '적지 않음' 이라 기본값이 된다 — 손잡이 규칙).

**SD-16 쟁점 패널은 셋 다, 보통 패널은 남은 자리만큼.** 보통 패널의 지정 도구는 대개 넷이라(차이 · 스냅샷 도구) 남은 두 자리에 그룹 목록 · 사례 검색이 들고
사례 카드는 빠진다(검색 결과에 사례마다 trust · 요약이 온다). 쟁점 패널은 지정 도구가 없던 패널이라 셋이 다 든다 — 호출 셈(llm_calls_planned)에 도구마다
인자 짓기 둘을 더한다(보통 패널 예산식의 2T 와 같다). 포털 `DelibOpts.tools` 상한이 6 이라 넘지 않는다.

## 반대 검토 11-06(세 갈래 — 게이트웨이 + 포털 · 에이전트 서버 · 리스크 앱)

**SD-17 429 는 상태 꼴로만 본다.** 실패 글 속 아무 '429' 에 걸리면 사람 이메일(kim429@)이나 인자를 되울린 글(C-429) 때문에 그 잡에서 그쪽을 통째로 껐다.
게이트웨이 안내 '(429 — …)' · 원래 오류의 repr "'429 rate_limited'" · httpx "'429 Too Many Requests'" 꼴만 보고, 등록 안내('등록되어 있지 않습니다')가 먼저다.

**SD-18 trust 안내는 결과에 신뢰 · 확인 칸이 있을 때만 붙인다(SD-9 를 좁힌다).** cae00 의 선언 백엔드에는 MatNexus(물성 DB) · FMEA · 운영 사본도 있다 — 그런 칸이
없는 결과에 '사람이 확인하지 않은 것은 후보로만' 을 붙이면 좌석이 측정값까지 후보로 낮춘다. JSON 칸 `trust` · `human_verified` 가 있을 때만 붙인다(지정 도구
머리줄 · 좌석 조회 결과 머리 둘 다). 줄(동시 2 · 429 뒤 안 부름)은 요청서대로 선언 백엔드 모두에 건다.

**SD-19 미연결도 그 잡에서 기억한다.** 등록 토큰 없음 · 401 을 한 번 받으면 같은 잡의 뒤 지정 도구(인자 짓기 LLM 도 부르지 않는다)와 좌석 조회는 그쪽에 가지
않고 막은 글을 받는다 — 같은 거절이다. 토큰 없는 잡 주인의 심의에서 좌석마다 조회 몫을 거절 받는 데 쓰던 것을 막는다. 좌석 조회에서 처음 닫히면 라운드 끝에
경고 사건(`conn_unregistered`)과 카드 한 장을 낸다(리스크 앱이 지정 도구 없이도 '미연결' 을 안다).

**SD-20 줄은 한 실행에 하나다.** 진입점(일반 심의 · 시뮬 심의 · 시험 계획)이 새로 두고 그 실행의 단들이 같이 쓴다(ContextVar) — 시뮬 심의 1단이 받은 429 · 미연결을
2 · 3단이 다시 두드리지 않는다. 끊긴 잡을 되살리면 새 실행이라 새 줄이다.

**SD-21 안내 머리줄을 건너 절단 표식을 잰다.** 좌석 조회 결과의 원문 길이는 조회 턴 래퍼가 자른 자리의 표식으로 읽는데(engine-budget A23-6), 머리에 안내 한 줄이
붙으면 그 자리가 어긋나 원문 길이를 잃었다. `_capped_at` 이 안내 머리줄을 건너 잰다.

**SD-22 게이트웨이 시간 초과 길과 UI 자원 읽기에도 요청 ID.** 머리글은 이미 나갔으므로 시간 초과 감사 줄에도 `rid` · `as-conn` · 토큰 지문을 남긴다 — 바깥 팀이 가장
자주 물을 줄이다. 선언 백엔드의 UI 자원(`resources/read`)도 같은 머리글 · 감사 칸이다.

**SD-23 403 · 모르는 실패의 문구.** 403 은 둘 다 말한다 — 범위가 모자라면 그 범위를 가진 토큰을 다시 등록하고, 출발 IP 면 관리자에게(포털 등록 확인은 403 을 토큰
문제로 본다 — SIREN 의 `403 scope_denied` 도 토큰으로 풀린다). 상태를 가리지 못한 실패는 '토큰 문제가 아니다' · '잠시 뒤 다시' 를 단정하지 않는다 — 가운데서
끊긴 쓰기는 두 번 돌 수 있다(`_late_text` 와 같은 자세).

**SD-24 맨 앞의 수는 JSON-RPC 오류에서만 상태다.** 다른 예외 문구 맨 앞의 수('429 bytes read' · '401.5 seconds')는 상태가 아니다 — httpx 꼴 'NNN 이유' 만 더 본다.

**SD-25 선언이 바뀌면 그 백엔드의 응답 캐시를 버린다.** 가림 예외를 걷어도 옛 선언으로 지은 결과(가리지 않은 링크)가 캐시 TTL(300초) 동안 나갔다.

**SD-26 포털 `request_id:` 빈 값은 기본(켬)이다.** 다른 선택 칸처럼 — 빈 값 하나로 SIREN 블록이 통째로 빠지지 않게.

**SD-27 리스크 앱은 러너가 패널을 띄울 때 붙인다(계획 때가 아니라).** 처음엔 계획(planned_tools)에 넣었다 — 과제 만들기의 비용 어림(tier_plan)이 게이트웨이를
묻게 되어 '외부 호출 0' 시험(E2E · ECAD)이 깨졌다. 요청서 문구도 '러너가 패널 심의를 띄울 때' 다. 계획 · 어림은 종전 그대로이고, 러너가 엔진에 보내기 직전에
`planner.case_tools_plan` 으로 붙인다. 어댑터 발견이 받은 `/tools-map` 은 지도 캐시에도 담아 띄울 때 다시 묻지 않는다.

**SD-28 Claude 잡에는 SIREN 지정 도구를 싣지 않는다.** 리스크 앱 반출 동의문(패널 잡 · 검토 잡)이 외부 사례 DB 를 말하지 않는다 — 이미 동의한 Claude 잡이 이 판부터
SIREN 사례를 Claude 로 보내게 된다. 패널 동의문은 '좌석이 조회한 결과' 를 말하므로 엔진의 좌석 자유 조회(HA-36)는 그 안이다. Claude 잡에도 실으려면 동의문을
고치고 사용자가 정한다(그때까지 패널 품질에 `case_tools_skipped: claude_job`).

**SD-29 패널 호출 상한 안에서만 · 까닭을 남긴다.** 도구 하나가 인자 짓기 LLM 을 두 번까지 부르므로 `est_high + 2 × 도구 ≤ HWAXRISK_PANEL_LLM_CAP` 안에서만 싣는다
