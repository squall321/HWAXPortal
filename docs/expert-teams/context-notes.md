# 전문가 팀 — 결정과 까닭

## ET-1 (11-22) 사용자 요청 · 결정
- **요청** — 「실제 업무에 도움이 되는 페르소나 조합을 미리 만들어 두고, 특정 업무를 할 때 쓰는 자동화 조합에 그 에이전트를 패턴화해서 쓰게. 절차 프로세스에도
  1+4 전문가 설정이 되면 가장 좋다」.
- **지금 상태(코드 대조)** — 챗의 1+4 는 그때그때 고르고 저장이 없다. 루틴 단계 · 절차에는 전문가 칸이 없다. 심의는 좌석을 추천 · 손으로 고르고 틀의 지정석만
  저절로 앉는다. HE팀 운영자가 앱 단위의 고정 조합이다.
- **사용자 결정** — 범위는 **개인 + 소속에 공유**(권장안, 관리자가 「공식」 표지) · 쓰는 자리는 **챗 · 분석 루틴 · 절차**(심의 화면의 좌석 미리 채우기는 고르지
  않았다 — 절차의 「심의로 넘기기」 에 팀이 실리는 것은 절차 칸의 설명에 든 것이라 짓는다).

## ET-2 팀은 사람을 묶고, 보이는지는 쓰는 순간 다시 본다
공유받은 팀에 내가 볼 수 없는 페르소나가 들 수 있다(소속마다 시야가 다르다). 팀 저장 때 걸러 두면 다른 사람에게는 맞지 않는다. 쓰는 순간 그 사람의 권한으로
푼다 — 에이전트 서버 `_persona_meta(groups)` 가 이미 그렇게 하고, 못 보는 사람은 빠지고 알린다(닫힌 쪽).

## ET-3 챗은 복사, 루틴은 실행 때 사본
- 챗은 고르는 순간 지정값으로 복사한다 — 나중에 팀을 고쳐도 이미 연 대화가 무엇으로 답했는지 흔들리지 않는다. 에이전트 서버 계약은 그대로라 새 칸이 없다.
- 루틴은 실행을 만들 때 사본을 원장에 남긴다 — 실행 도중(이어서 · 다시 붙기 포함) 팀을 고쳐도 그 실행은 같은 사람들로 끝난다. 원장이 「누구의 판단으로
  돌았나」 를 남긴다.

## ET-4 루틴의 울타리가 팀보다 앞선다
루틴 단계는 정해진 백엔드 · 읽기 도구 안에서만 돈다(AR-D 계열 — 확인된 읽기만). 팀의 운영자 보조가 그 울타리 밖 앱을 몬다고 해서 그 도구를 묶으면 울타리가
샌다. 루틴에서 팀은 목소리 · 판단 기준 · 지식카드만 보태고 도구는 바꾸지 않는다. 앱 · 도구 칸은 챗(그리고 절차의 챗 넘기기)만 쓴다.

## ET-5 리스크 심사에는 팀을 앉히지 않는다(D-18)
리스크 심사는 좌석 편성 · 근거 울타리가 따로 있다(D-18 — 대상까지). 루틴의 심의 단계 `job` 이 리스크 심사 계열이면 팀을 넘기지 않고 실행 보기에 남긴다.

## ET-6 (11-22) 저장소는 절차 저장소의 표 하나
과제 인사이트 · 분석 루틴과 같은 자리(procedures.sqlite 의 연결을 같이 쓰는 표 `expert_teams`)다 — 설정 · 서비스 표 · 백업 · 기동 · 시험 격리에 이미
등록된 저장소라 새로 등록할 것이 없다. 이관은 기동의 `CREATE TABLE IF NOT EXISTS` 하나다. 지우면 행이 사라진다 — 이미 만든 사본(루틴 실행 원장 · 연 대화)은
제 사본을 쥐어 흔들리지 않는다. 팀 id 는 `tm_<32 hex>` 다.

## ET-7 (11-22) 같은 소속 공유의 소속 — 만들 때, 주인이 고치면 그때
PLAN 1절은 `owner_aff` 를 「만든 때 소속」 이라 적었다. 주인이 소속을 옮긴 뒤 고치면 그 팀은 옛 소속에 계속 열려 있게 되므로, **주인이 고칠 때는 주인의 지금
소속으로 다시 새긴다**(관리자가 고칠 때는 그대로). 소속이 없는 사람은 같은 소속으로 공유하지 못한다(422 — 빈 소속끼리는 같지 않다). 보이기의 소속은 읽는
사람의 지금 원장 소속(과제 인사이트 카드와 같은 셈 — `known_affiliation`)이다. 판단이 갈리면 「만든 때만」 으로 되돌리는 것은 `update` 의 `owner_aff` 인자
하나다(사용자 확인 거리로 보고).

## ET-8 (11-22) 사본(resolve)의 규칙 — 닫힌 쪽
- 그 사람이 못 보는 팀 · 없는 팀은 같은 「찾을 수 없다」(null) — 있는지 드러내지 않는다.
- `feat:expert-chat` 이 없으면 null(루틴 · 절차는 팀 없이 돈다).
- **주 전문가를 못 쓰면 null** — 보조를 주로 올리지 않는다(목소리가 바뀐다 · 챗도 주 전문가 없이 보조만 두지 않는다). 보조를 못 쓰면 그 사람만 빼고 `hidden` ·
  `why` 로 알린다.
- 「못 쓴다」 는 포털의 `agent_guard.persona_allowed`(HE팀 운영자의 앱 권한) 판정이다 — 챗 요청의 `check_chat` 이 403 을 내는 것과 같은 판정이라, 사본을 그대로
  지정값으로 복사해도 챗이 막히지 않는다. 그 밖의 페르소나는 에이전트 서버가 쓰는 순간 다시 본다(ET-2).
- 사본 꼴은 PLAN 3-2 그대로 — `{id, name, version, lead, helpers, apps, tools, resolved_at}`. resolve 창구는 `hidden` 을 덧붙여 준다.

## ET-9 (11-22) 루틴 실행 보기의 꼴(에이전트 서버 실행기와의 계약)
- 사본은 계획(`plan_json`)에 넣는다 — 실행 원장 표에 칸을 더하지 않는다. 이어서 · 다시 붙기 · 보고서 다시 내기 모두 같은 계획을 읽는다.
- 위 칸 `team` — 루틴 팀의 사본 또는 `null`(루틴 팀을 안 적었거나 못 풀었다), 못 풀었으면 `team_why`. 루틴은 팀이 없고 단계만 덮었어도 `team: null` 이 선다.
- 단계 `team` — **덮은 단계에만** 선다. 사본, 또는 `false`(빈 글 = 팀 없이 · 못 푼 단계 팀 · 리스크 심사 계열). 못 풀었거나 리스크 심사로 막았으면 `team_why`.
  **못 푼 단계 팀은 루틴 팀으로 대신하지 않는다** — 그 단계를 짠 사람이 다른 팀을 고른 자리다.
- 실행기는 「단계에 `team` 칸이 있으면(`false` 포함) 그것, 없으면 위 `team`」 으로 읽는다 — 칸이 있는지로 가른다(값이 거짓인지로 가르면 `false` 가 루틴 팀으로 샌다).
- 스펙이 팀 칸을 안 쓰면 스펙 저장 · 내보내기 · 계획 · 실행 보기 · 준비도가 팀 전과 **바이트까지 같다** — 직렬화가 `team: null` 을 빼고, 계획은 팀 칸을 안 쓸 때
  손대지 않는다. 바탕 판(`ece8172f`)과 같은 입력으로 찍어 맞대 확인했다(시험은 칸 차례 · `team` 글자 없음으로 지킨다).

## ET-10 (11-22) 리스크 심사 계열 — 일 또는 의장 틀이 risk-review*
루틴 심의 단계의 `deliberation.job` 이나 `chair_template` 이 `risk-review` 로 시작하면(봉인 포함) 리스크 심사 계열이다(인사이트 `risk_family` · 에이전트 서버
`delib_decision.risk_family` 와 같은 머리). 그 단계에 팀 id 를 직접 적으면 저장 422(빈 글은 된다), 루틴 팀이 닿으면 실행 보기의 단계 `team` 이 `false` +
`team_why` 다 — 실행기가 판정을 빠뜨려도 포털이 막는다. 절차의 「심의로 넘기기」 는 심의 화면에 리스크 심사 입구가 없고 중계가 리스크 심사 계열 + 절차 실행을
거절하므로 따로 막을 길이 없다.

## ET-11 (11-22) 저장 권한 — 두 권한
루틴 · 절차 스펙이 팀 칸을 쓰면(빈 글 포함) 저장 · 판 더하기 · 가져오기에서 `feat:expert-chat` 도 본다(PLAN 1 — 「각 기능 권한도 함께」). 팀이 그 박스에 있는지 ·
그 사람이 볼 수 있는지는 저장 때 막지 않는다 — 실행 때 사본이 null + 까닭이 되고 준비도가 말한다(cae00 에서 짠 루틴을 dev 로 가져오는 길, 루틴의 백엔드 판정과
같은 자세).

## ET-12 (11-22) 절차 넘기기 두 길
- 「챗으로 가져가기」 — 만든 대화의 사람 발화 meta 에 챗 중계가 적는 꼴 그대로(`pinned_agent` · `pinned_agent_name` · 보조가 있을 때만 `pinned_agents`)를 남겨
  다른 기기에서 열어도 전문가가 산다. 응답에 사본을 실어 화면이 앱 · 도구 · 보조 이름까지 대화에 복사한다(`openServerConversation` 의 pins). 서버 사본에는 앱 ·
  도구가 남지 않는다 — 챗에서 고른 앱 · 도구도 서버에 안 남는 것과 같다(이번에 넓히지 않음).
- 「심의로 넘기기」 — 미리보기 응답에 사본(`team` · `team_why`)을 싣고 심의 화면이 추천 대신 그 사람들로 좌석을 채운다(사람이 빼고 더한다). 못 풀었으면
  추천으로 채우고 까닭을 칩에 적는다.
- 절차의 팀은 판본의 칸이라 바꾸면 새 판본이다(주인만) — 절차 보기 응답에 `mine` 을 더해 화면이 주인에게만 「팀 정하기(새 판본)」 를 보인다. 도구 단계는
  바뀌지 않는다.

## ET-13 (11-22) 챗 화면 — 시작 화면은 칸을 채우고, 알약은 곧바로
시작 화면(StartPicker)은 원래 고르기 칸에 담았다가 「적용하고 대화 시작」 에서 확정하는 화면이라, 팀을 고르면 칸(주 · 보조 · 앱 · 도구)을 그 사본으로 채우고 확정은
그대로 사람이 한다. 입력창 전문가 알약 → 가벼운 선택기 → 「팀에서 고르기 · 지금 조합 저장」 은 고르는 순간 지정값으로 복사한다. 두 길 모두 팀을 가리키지 않는
복사다(ET-3). 빠진 전문가가 있으면 팀 창을 닫지 않고 알리고, 못 푸는 팀은 지정값을 건드리지 않는다. 새 단추는 기존 화면 시험이 쓰는 `.pp-expand` 와 다른
`.pp-teams` 다(같은 꼴 — 처음에 같은 꼴 이름을 썼다가 「대화 중 보조 더하기」 시험이 두 단추를 집어 붉어졌다).

## ET-14 (11-22) 공식 표지 · 목록 차례
공식 표지는 판 번호 · 고친 때를 바꾸지 않는다(구성이 바뀐 것이 아니다 — 들고 있는 판으로 고친 사람이 409 를 맞지 않게). 공식 팀은 주인도 고칠 수 있고 지우기는
관리자만이다. 목록은 공식 → 고친 때 → 같은 초면 나중에 넣은 행 차례다(고친 때가 초 단위라 같은 초에 만든 두 팀의 차례가 id 무작위로 갈려 시험이 가끔
붉었다).
