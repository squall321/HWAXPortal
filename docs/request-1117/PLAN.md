## 0. 사용자 결정(11-17)

- 리스크 앱 일곱 건을 **한 번에**(P0 셋만이 아니라). 백엔드만 — 화면은 화면 세션 몫(HWAXRisk CLAUDE.md).
- RK-02 의 묶음을 엔진이 id 로 받아 푸는 일(DL-01)은 **앱 몫을 먼저** — 앱이 묶음 id 로 `deliberate_start(evidence=…)` 에 그대로 넣을 근거 목록을 준다.
  엔진이 id 를 받아 푸는 길은 포털 요청(DL-01)으로 이어서 짓는다.
- 수용은 **dev 합성 시험 → PC 에서 실제 대조**. 과제 자료는 리포 · dev 에 들이지 않는다(보안 승인 전).
- 차례 — 리스크 앱 일곱 → 포털 열(사용자 '위에 것 한 다음 아래 것').

## 1. 리스크 앱(HWAXRisk) — 백엔드

| ID | 급 | 한 줄 | 짓는 꼴 |
|---|---|---|---|
| RK-01 | P0 | 판정표(원장)를 앱이 판으로 둔다 — 덮어쓰기 층 차례를 데이터로, 판끼리 비교 · 내보내기 | 칸 정의(칸 이름 · 차례 · SP 사전 키 칸 표지)를 **데이터로 등록**한다(과제 고유 칸을 코드에 박지 않는다). 판 = 기준 판 + 층들(차례대로 덮음, 덮은 앞 값 기록). 비교 = 바뀐 코드 · 칸 · 앞뒤 값 · 등급 바뀐 코드 수. csv · json 내보내기(첫 줄 보안 문구). 행 열쇠는 코드(참조번호는 리비전마다 바뀐다) |
| RK-02 | P0 | 원장 행 → 심의 근거 묶음(칸별 상한 · 개인정보 가림 · 크기 점검) | 묶음 = 엔진 근거 항목 꼴 그대로(contracts §1). 전체 행 ID 색인 항목이 늘 맨 앞. 틀(칸별 상한 · 합 상한)을 데이터로. 엔진 상한(항목 수 · 합 자수 — 설정)을 넘으면 만들 때 거절. 지문 · 칸별 자수 · 잘린 칸 · 가림 건수 |
| RK-03 | P1 | 결정문 → 원장 칸 반영(빈칸 · 충돌 표시) — RK-01 층으로 | 입력은 결정 JSON(DL-03 꼴) 또는 결정문 글(지금 `parse_risk_spec` 으로) 또는 job_id. 칸 매핑 표를 데이터로. 칸마다 채움 · 빈칸 · 충돌 · 원천 없음, 표결 집계, '합의' 문장과 표결 불일치 표지 |
| RK-04 | P1 | 숫자 원장과 금지값 점검 | 숫자 행(이름 · 값 · 단위 · 정의 · 리비전 · 출처 · 줄 · 지표 키) · 코드별 금지값. 글 · 묶음의 숫자를 원장 · 금지값과 대조 — 원장에 없는 수 · 금지값 쓰임 · 단위 불일치의 건수와 위치. 작은 정수 · ID 꼴도 범위(게이트웨이 verify_answer 의 범위 밖) |
| RK-05 | P2 | 원장 → 보고 묶음(facts JSON + 그림 참조 + 출처) | facts 틀(키 목록 · 칸 ← 원장 칸 대응)을 데이터로 등록. 빈 키는 null 과 까닭. 렌더는 ReportArchive 몫 |
| RK-06 | P0 | 스냅샷 · 등록부 · 단면 자리 · 다음 걸음 응답에 원천의 단계 · 판 · 환경(provenance) | 앱이 이미 가진 것(`rr_sources` app_key · ref · probe, `rr_snapshots` source_ids · app_versions · 노드 수)을 싣고, 모르는 칸은 '모름'(지어내지 않는다). 판 불일치 · 개수 불일치 경고. StepForge 사본 단계 · DynaForge 덱 요소 수는 그쪽이 값을 내줄 때(요청 SFR-04 등) 채운다 |
| RK-07 | P1 | 등급 · 유형 · 주의 등급 · 판정 글자 분리 | 축별 표기 규칙(`risk_taxonomy(part="labels")`) — 등급은 축 낱말이 붙은 표기, 판정은 SP 판정 키. RK-02 · RK-05 출력이 이 규칙을 쓴다. 축 낱말 없는 단독 대문자 A ~ J 0건 검사 |

스키마는 **v8** 하나에 새 표를 모은다(재설계 M4 의 `rr_reports.ra_*` 는 v9 로 민다 — context-notes R-3).

## 3. 수용 — dev 합성 → PC 실제 대조

요청서의 수용 기준은 PC 과제 폴더의 판정표 · 근거 args · 결정 파싱 · 점검기 · facts 출력과 칸 단위 대조다. dev 에는 그 자료가 없고 들이지
않는다. dev 시험은 같은 **꼴**을 합성 자료로 재현한다 — 층 다섯의 덮어쓰기 차례 · 칸별 상한(합 20,000자 틀) · 엔진 상한 거절 · 합의 문장과 표결
불일치 · 금지값 · 판 · 개수 불일치 경고. PC 대조 절차는 [acceptance-pc.md](acceptance-pc.md)(짓고 나서 쓴다).
