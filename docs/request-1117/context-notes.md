# 11-17 요청 — 결정 기록

계획은 [PLAN.md](PLAN.md), 꼴은 [contracts.md](contracts.md), 할 일은 [checklist.md](checklist.md).

**R-1 사용자 결정 셋(11-17).** 리스크 앱 일곱 건을 한 번에 · 엔진이 묶음 id 를 받아 푸는 길은 앱 몫 먼저(포털 DL-01 로 이어서) · 수용은 dev 합성
뒤 PC 실제 대조. 차례는 리스크 앱 → 포털.

**R-2 과제 고유 칸은 데이터로 등록한다 — 코드에 박지 않는다.** 요청서의 판정표 칸 20개(RK-01)와 facts 키 24개(RK-05)는 원문에서도 '…' 로 줄여져
전부가 없고, 과제 고유 낱말이 섞인다. 칸 정의 · facts 틀을 API 로 등록하는 꼴로 지어(판정표 칸 정의 판 · facts 틀 판), PC 수용 때 그 정의를 등록한다.
리포에는 일반 꼴(칸 이름 · 차례 · SP 사전 키 칸 표지 · 등급 칸 표지)만 들어간다.

**R-3 스키마 v8 은 이 일의 표다 — 재설계 M4 의 `rr_reports.ra_*` 는 v9 로 민다.** v7 까지 굳었다(HWAXRisk `tests/test_store.py` PUSHED_DDL_SHA256).
M4 는 아직 짓지 않았고(cae00 M3 실주행 수치 뒤), 이 일이 먼저 나간다. 앱 CLAUDE.md · 시험 주석의 'M4 는 v8' 을 'v9' 로 고친다.

**R-4 요청서 원문은 리포에 넣지 않는다.** 미출시 과제 자료(과제 이름 · 모델 개정 이름 · 부품 · 넷 이름 · PC 경로)를 담고 있고 요청서 스스로 '넘기기 전
보안 승인 필요' 라 적었다. PLAN 에 과제 이름을 뺀 요약만 둔다.

**R-5 포털 쪽 사용자 결정 넷(11-17).** ① GW-01 은 카탈로그만이 아니라 **중계 업로드까지** 짓는다(11-12 '업로드는 포털 관리 세션' 결정을 넘어선다 —
사용자 결정으로 뒤집음). ② GW-03 은 좌석이 본 '실적 0' 이 어느 도구 · 칸이었는지와 stcx 월별 완료 수를 읽는 법을 **cae00 에 먼저 묻고** 짓는다(dev
소스에서 그 수치를 내는 도구를 찾지 못했다 — 짐작으로 짓지 않는다). ③ DL-02 의 끝남 알림은 **포털 알림 + 상태 조회**(바깥 주소로의 웹훅 없음).
④ GW-04 는 **점검표 문서 + 읽기만 하는 훑기 보고**(관리자 도구 · 저장 없음).

**R-6 GW-01 중계의 울타리(짓기 전에 정함).** 대용량은 MCP 로 못 나르므로 게이트웨이 REST 창구가 그 사람 PAT 로 받아 **흘려서**(메모리에 통째로 두지
않고) 앱의 선언된 적재 경로로 넘긴다. 토큰 종류는 선언이 정한다 — 포털 PAT 은 그 사람 것을 그대로, 앱 전용 토큰(kr_ PAT 따위)은 그 사람이 등록한
연결 토큰만(없으면 거절과 등록 길 안내), SSO 는 지금의 사람별 위임 단언. 서버 경로를 읽는 꼴(`upload_via_path`)은 박스가 정한 준비 폴더 하나 안에서만,
기본 꺼짐 — 임의 경로를 읽으면 파일 반출 길이 된다. 크기 상한 · 감사 한 줄 · 업로드 id · 상태.

**R-7 GW-02 — 읽기 전용 PAT 도 박스 덧씌우기를 읽고, 둘 다 바뀐 시각으로 다시 읽는다.** 지금 `read_tools.json` 은 기동 때 한 번만 읽고
(`READ_TOOLS = _load_read_tools() | READ_OVERRIDE`), `read_tools.local.json` 은 루틴 단계만 쓴다(`_routine_read_tools`). 읽기 전용 PAT 에서 덧씌우기를 뺀
기록된 까닭은 찾지 못했다 — 같은 박스 관리자가 쓰는 파일이라 신뢰가 같다. 닫기 목록(deny)은 그대로 먼저 이긴다.

**R-8 사용자의 11-17 결정 문서(「플랫폼 개발 요청서 — 결정 사항 · 항목별 제안 v1.0」)를 얹는다 — GW-01 중계는 하지 않는다.** 문서의 C3 은 'GW-01 은
게시만 — 게이트웨이 안에서 적재를 대신 받거나 계산하지 않음', D4 는 'DynaForge 공식 답 전에는 11-12 결정(포털 관리 세션이 올림) 유지' 다. 같은 날
앞서 이 세션의 물음에는 '중계까지 짓는다' 를 골랐다(R-5 ①). 둘이 어긋나 **나중에 온 결정 문서를 따랐다** — 게이트웨이 가지에서 중계를 빼게 했고, 중계가
필요하면 사용자가 다시 말한다. 함께 반영한 것 — D5 환경 값 이름 · C1 인용 형식과 묶음 종류 · C2 DL-01 차례 · C4 GW-03 원천 · D1 을 GW-04 점검 항목으로
(contracts §5). 받는 쪽 세션(DynaForge · KooSlurm 둘 · ReportArchive 둘 · WebDesignAgents 둘)에는 그쪽 몫만 골라 보냈다(사용자 지시 '관련 세션에 보내라').
이 박스에 세션이 없는 MatNexus · SIREN · PLM/failuretrace · SP 사전 주인 · 자주검증 Datahub 몫은 보내지 못했다. 결정 문서 §5 의 사용자 확인 항목(C6 · C7
기본안 등)은 사용자 몫이다.

**R-9 GW-03 의 cae00 물음(받은 편지함 11-17 Q2 · Q3)은 C4 로 거의 풀렸다.** 원천이 KC-01 매니페스트 → DynaForge 캠페인 적재 상태로 정해져 stcx 월별
수를 게이트웨이가 셀 일이 없다(Q3 거둠). Q2(좌석이 본 '실적 0' 이 어느 도구였나)는 그 도구의 안내를 고칠 때 쓰려고 남긴다 — 급하지 않다.

**R-10 게이트웨이 가지(wt1117/gw) — 짓고 나서 정한 것.** ① 환경을 적지 않은 박스는 `unknown`(에이전트는 `dev` 로 채웠으나 고쳤다 — 운영 박스가
적기 전 운영 앱이 dev 로 보이면 요청이 막으려던 오판이다, contracts §5). cae00 은 게이트웨이 `app_keys.local.json` 에 `{"default_env": "prod"}`,
dev 는 `"dev"` 를 적는다. ② 읽기 전용 PAT 도 닫기 목록(deny)이 맨 먼저 이긴다(R-7 — 종전엔 읽기 전용 PAT 이 deny 를 보지 않았다, 닫는 쪽 변경).
③ 관리자 보기 `gateway_readonly_allowlist` 는 관리자의 tools/list · 검색에만 보인다(`/tools-map` 수에는 든다). 관리자의 웹 챗 묶음에서도 빼는 일은
에이전트 서버 `_UNBOUND_TOOLS` 에 더한다(병합 때). ④ 적재 경로 점검(`last_check`)은 메모리에만 — 재기동하면 없다. ⑤ 토큰 종류 낱말은
`portal_pat` · `app_token` · `sso` — 앱 쪽이 이 낱말을 받는지 확인할 것. ⑥ KooRemapper 의 `/system/capabilities` 는 적재를 말하지 않고 MCP 도구
`report_upload_instructions` 의 글만 있다(512 MB/파일 · 풀어 2,048 MB · kr_ PAT) · StepForge `upload_instructions` 는 아직 2 GB(포털 nginx 는 10 GB)
— 두 앱의 구조화된 공식 선언이 오기 전까지 추적 `ingest_routes.json` 의 routes 는 비어 있다(짐작하지 않는다 — 결정 D4).

**R-11 리스크 앱 가지(wt1117/rk) — 짓고 나서 정한 것(앱 결정 LG-1 ~ LG-10 은 HWAXRisk context-notes).** 스키마 v8 새 표 아홉(판정표 틀 · 층 ·
판 · 행 · 칸, 근거 묶음, 숫자 · 금지값 · 내보내기 기록) — 모두 대상(`target_key`)에 매달려 반출 · 회수를 따른다. 칸 정의 · facts 틀 · 결정 칸 대응은
**대상 단위로 판을 매겨 등록하는 데이터**(R-2)이고, 등록 · 한눈 입구로 `risk_ledger_put_template` · `risk_ledger_overview` 를 더했다(도구 39 → 52).
묶음 id `eb_` · 보고 묶음 `rb_`, cite `source_version` 은 `"v<판>/c<칸 정의 판>"` 꼴. 개인정보 가림 `app/pii.py` 는 메일 · 전화 · 사설 IPv4 · 주민번호 꼴 ·
표지 붙은 사번만 가린다(사람 이름은 가리지 않는다 — 숫자 · 코드를 망가뜨리지 않는 쪽, HG-21 교훈). RK-06 은 앱이 가진 값만 — StepForge 과제 단계 · 판 이름,
DynaForge 덱 선언 요소 수 · 겹친 요소 id · 덱 판은 그쪽이 아직 내주지 않아 `unknown`(11-17 두 세션에 칸을 청했다). 판정 SP 키는 요청서의 `VRD-COND`
말고는 같은 꼴로 정한 자리(`VRD-GO` · `VRD-NOGO` · `VRD-UNDET`, `sp_keys_status: unconfirmed`) — SP 사전 주인(D3)과 맞출 일. MCP 읽기 문은 기존 읽기 도구와
같이 조직 공개 과제도 연다(REST 는 구성원) — 기존 규칙과 같게 두었다.
