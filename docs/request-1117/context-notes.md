**R-6 GW-01 중계의 울타리(짓기 전에 정함).** 대용량은 MCP 로 못 나르므로 게이트웨이 REST 창구가 그 사람 PAT 로 받아 **흘려서**(메모리에 통째로 두지
않고) 앱의 선언된 적재 경로로 넘긴다. 토큰 종류는 선언이 정한다 — 포털 PAT 은 그 사람 것을 그대로, 앱 전용 토큰(kr_ PAT 따위)은 그 사람이 등록한
연결 토큰만(없으면 거절과 등록 길 안내), SSO 는 지금의 사람별 위임 단언. 서버 경로를 읽는 꼴(`upload_via_path`)은 박스가 정한 준비 폴더 하나 안에서만,
기본 꺼짐 — 임의 경로를 읽으면 파일 반출 길이 된다. 크기 상한 · 감사 한 줄 · 업로드 id · 상태.

**R-7 GW-02 — 읽기 전용 PAT 도 박스 덧씌우기를 읽고, 둘 다 바뀐 시각으로 다시 읽는다.** 지금 `read_tools.json` 은 기동 때 한 번만 읽고
(`READ_TOOLS = _load_read_tools() | READ_OVERRIDE`), `read_tools.local.json` 은 루틴 단계만 쓴다(`_routine_read_tools`). 읽기 전용 PAT 에서 덧씌우기를 뺀
기록된 까닭은 찾지 못했다 — 같은 박스 관리자가 쓰는 파일이라 신뢰가 같다. 닫기 목록(deny)은 그대로 먼저 이긴다.

앞서 이 세션의 물음에는 '중계까지 짓는다' 를 골랐다(R-5 ①). 둘이 어긋나 **나중에 온 결정 문서를 따랐다** — 게이트웨이 가지에서 중계를 빼게 했고, 중계가
필요하면 사용자가 다시 말한다. 함께 반영한 것 — D5 환경 값 이름 · C1 인용 형식과 묶음 종류 · C2 DL-01 차례 · C4 GW-03 원천 · D1 을 GW-04 점검 항목으로

이 박스에 세션이 없는 MatNexus · SIREN · PLM/failuretrace · SP 사전 주인 · 자주검증 Datahub 몫은 보내지 못했다. 결정 문서 §5 의 사용자 확인 항목(C6 · C7
기본안 등)은 사용자 몫이다.

**R-10 게이트웨이 가지(wt1117/gw) — 짓고 나서 정한 것.** ① 환경을 적지 않은 박스는 `unknown`(에이전트는 `dev` 로 채웠으나 고쳤다 — 운영 박스가
적기 전 운영 앱이 dev 로 보이면 요청이 막으려던 오판이다, contracts §5). cae00 은 게이트웨이 `app_keys.local.json` 에 `{"default_env": "prod"}`,
dev 는 `"dev"` 를 적는다. ② 읽기 전용 PAT 도 닫기 목록(deny)이 맨 먼저 이긴다(R-7 — 종전엔 읽기 전용 PAT 이 deny 를 보지 않았다, 닫는 쪽 변경).
③ 관리자 보기 `gateway_readonly_allowlist` 는 관리자의 tools/list · 검색에만 보인다(`/tools-map` 수에는 든다). 관리자의 웹 챗 묶음에서도 빼는 일은
에이전트 서버 `_UNBOUND_TOOLS` 에 더한다(병합 때). ④ 적재 경로 점검(`last_check`)은 메모리에만 — 재기동하면 없다. ⑤ 토큰 종류 낱말은
`portal_pat` · `app_token` · `sso` — 앱 쪽이 이 낱말을 받는지 확인할 것. ⑥ KooRemapper 의 `/system/capabilities` 는 적재를 말하지 않고 MCP 도구
`report_upload_instructions` 의 글만 있다(512 MB/파일 · 풀어 2,048 MB · kr_ PAT) · StepForge `upload_instructions` 는 아직 2 GB(포털 nginx 는 10 GB)
— 두 앱의 구조화된 공식 선언이 오기 전까지 추적 `ingest_routes.json` 의 routes 는 비어 있다(짐작하지 않는다 — 결정 D4).

**R-11 리스크 앱 가지(wt1117/rk) — 짓고 나서 정한 것(앱 결정 LG-1 ~ LG-10 은 HWAXRisk context-notes).** 스키마 v8 새 표 아홉(판정표 틀 · 층 ·
판 · 행 · 칸, 근거 묶음, 숫자 · 금지값 · 내보내기 기록) — 모두 대상(`target_key`)에 매달려 반출 · 회수를 따른다. 칸 정의 · facts 틀 · 결정 칸 대응은
**대상 단위로 판을 매겨 등록하는 데이터**(R-2)이고, 등록 · 한눈 입구로 `risk_ledger_put_template` · `risk_ledger_overview` 를 더했다(도구 39 → 52).
묶음 id `eb_` · 보고 묶음 `rb_`, cite `source_version` 은 `"v<판>/c<칸 정의 판>"` 꼴. 개인정보 가림 `app/pii.py` 는 메일 · 전화 · 사설 IPv4 · 주민번호 꼴 ·
표지 붙은 사번만 가린다(사람 이름은 가리지 않는다 — 숫자 · 코드를 망가뜨리지 않는 쪽, HG-21 교훈). RK-06 은 앱이 가진 값만 — StepForge 과제 단계 · 판 이름,
DynaForge 덱 선언 요소 수 · 겹친 요소 id · 덱 판은 그쪽이 아직 내주지 않아 `unknown`(11-17 두 세션에 칸을 청했다). 판정 SP 키는 요청서의 `VRD-COND`
말고는 같은 꼴로 정한 자리(`VRD-GO` · `VRD-NOGO` · `VRD-UNDET`, `sp_keys_status: unconfirmed`) — SP 사전 주인(D3)과 맞출 일. MCP 읽기 문은 기존 읽기 도구와
같이 조직 공개 과제도 연다(REST 는 구성원) — 기존 규칙과 같게 두었다.

**R-12 사용자 결정 넷(11-17 — 반대 검토 뒤).** ① 게이트웨이 개인정보 가림이 근거 묶음 글을 바꿔 엔진의 지문 대조가 늘 실패한다(엔진 가지가 확인 —
`_pii_mask` 가 위임 세 갈래 모두에서 결과 글을 가린다) → **`heax-hwax_risk:risk_get_evidence_bundle` 하나만 게이트웨이 가림에서 빼고, 리스크 앱이 묶음을
늘 가린다**(가림을 끌 수 없다 — 개인정보는 앱 한 곳이 책임). ② DL-02 끝남 알림은 **포털 알림을 지금 짓는다** — 엔진이 끝난 묶음 목록을 내고(공유 비밀),
포털이 주기적으로 물어 건 사람에게 알림을 남기고 화면이 보인다(contracts §7). ③ 리스크 앱 판정표 · 근거 묶음의 MCP 읽기는 **구성원만**(REST 와 같게 —
기존 읽기 도구는 그대로). ④ DL-01 RA 파일은 **글 파일만**(문서 변환은 나중). 열린 채로 둔 것 — 묶음 멈춤은 줄에 선 잡만 취소(도는 잡은 그대로) ·
HTTP 묶음 시작은 공유 비밀 + 신원 머리(게이트웨이와 같은 믿음 — 긴 묶음은 토큰을 쥐지 않는다).

**R-13 묶음 끝남 알림 — 포털 가지(wt1117/notice)가 짓고 정한 것.** ① **원장은 새 sqlite 파일이 아니라 대화 저장소 파일(conversations.sqlite) 안의 표 둘**
(`notices` · `notice_cursors`)이다. 새 파일은 데이터 경로 레지스트리(cae00 은 `/data` 로 옮기는 needs_bind 클래스 — update-all 이 재기동하며 옮긴다) · 백업 ·
start.sh env 전달 · ui-check · conftest 에 모두 올려야 하는데, 알림은 대화와 같은 몫의 사람별 데이터(mirror)라 이미 다 오른 파일에 둔다 — 과제 인사이트가
절차 저장소에 표를 더한 길과 같다. 연결은 따로 연다(대화 저장소의 잠금을 다투지 않는다). 시험 격리는 `test_suite_isolation` 이 알림 원장이 격리된 대화 파일을
여는지 본다. ② **같은 묶음은 한 번** — (kind, source_id) 유일 색인 + INSERT OR IGNORE 로 경계 반복(엔진 next_since 는 마지막 묶음의 시각) · 재기동 · 여러
일꾼을 모두 막는다. 커서는 알림을 쓴 **뒤에** 옮기고 앞으로만 간다(MAX) — 그 사이에 죽으면 같은 쪽을 다시 읽을 뿐이다. 일꾼 사이 잠금(리스)은 두지 않았다 —
포털은 일꾼 하나이고, 여럿이어도 중복이 생기지 않는다(같은 쪽을 두 번 물을 뿐). 쪽 크기는 2 이상이어야 한다 — 꽉 찬 쪽이 모두 같은 시각이면 돌지 않고
까닭을 남긴다. ③ 주인은 엔진의 owner(퍼센트를 풀고 소문자)이고 **포털 원장(users)에 행이 있을 때만** 남긴다(상태는 보지 않는다 — 정지된 사람은 어차피 못
들어온다). ④ 링크는 비워 둔다 — 묶음 하나를 보여 줄 포털 화면이 아직 없다(목록에 묶음 id 를 보여 `deliberate_batch_status` 로 이어 보게 했다). 원장 · 화면은
포털 안 경로만 링크로 받는다. ⑤ `created_at` 은 묶음이 끝난 시각(엔진 finished_at, 지금보다 미래면 지금) — 당기기가 멈췄다 따라잡아도 목록 차례가 일이 일어난
차례다. ⑥ 손잡이 `DELIB_BATCH_NOTICE_S`(backend/.env, 기본 60 · 0 끔)는 `infra/.env.example` 에 넣지 않았다 — 포털 손잡이(INSIGHT_SYNC_S · WDA_DECK_ENABLED)는
backend/.env 에 적고 env-sync 는 infra/.env 몫이다. 시험(conftest)과 화면 점검 임시 포털(ui-check.sh)은 0 — 떠 있는 에이전트 서버를 실제 비밀로 부르지 않게.
⑦ 실패 로그는 까닭이 바뀔 때와 같은 까닭 60번(한 시간)마다 한 줄 · 다시 닿으면 한 줄(포털은 INFO 를 버리므로 둘 다 WARNING). **cae00 이 할 일은 없다** — 기본
켜짐이고 공유 비밀(GATEWAY_SHARED_TOKEN)은 인사이트 당기기가 이미 쓰는 그 값이다. 끄려면 backend/.env 에 `DELIB_BATCH_NOTICE_S=0` 을 적고 포털만 다시 띄운다.
엔진(DL-02)이 같이 나가야 한다 — 먼저 나가면 'HTTP 404 — DL-02 전의 판' 경고 한 줄을 남기고 기다린다.

**R-14 사용자 결정 둘(11-17 — 올린 뒤).** ① **StepForge `interference_recheck` 는 읽기로 본다** — 게이트웨이 `read_tools.json` override 에 더했다(게이트웨이
`master` — 시험 1,084). 검출 간섭을 다시 재기만 하고 장부를 안 바꾸며, 한 호출 상한에 멈추면 측정 잡 한 줄을 건다(StepForge D-706 · `app/kept.py`). RF-29 의
단면 · 적층 잡 도구 넷과 같은 갈래라 읽기 토큰 · 루틴 단계가 스스로 걸고 확인 카드가 뜨지 않는다. 이름 규칙(`recheck`)은 쓰기로 남겨 둔다 — 덧씌우기를
걷으면 다시 닫힌다. 웹훅을 바깥으로 보내는 `job_subscribe` 는 그대로 쓰기이고, HE팀 StepForge 운영자 목록은 StepForge 의 MODIFY 집합과 같아야 해서(HA29)
`interference_recheck` 를 넣지 않은 채 그대로다. ② **dev AXWB 의 죽은 인스턴스를 이 세션이 되살린다** — squashfuse 사고(11-17)로 목록에만 남았던
`axwb_redis` · `axwb_caddy` 를 그 리포의 `stop.sh` → `start.sh` 로 다시 띄웠다(PONG · caddy admin · `/health` 200). `axwb_postgres` 도 같은 꼴(이미지가 끊겨 새 연결이
곧바로 비정상 종료 — 떠 있는 postmaster 만 남음)인데, 재기동은 자동 모드가 막아 사용자에게 넘겼다.
