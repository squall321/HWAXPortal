## HA-20 · HP-42 — 포털 챗의 MCP Apps 패널 1단계(사용자 결정 10-31, 구현 P1 ~ P4)

설계는 [`design-ha09-ha20.md`](design-ha09-ha20.md) B 절이다. 사용자가 B8 의 일곱 물음에 모두 권한 길 (가)를 골랐다(10-31, 포털 본 세션의 답).
이번 회차는 B6 의 P1 ~ P4 다 — SimFlow 의 답(C1 Q-S1 ~ Q-S9)이 아직 없어 진짜 mcp 1.28 FastMCP 로 지은 가짜 패널 앱(도구
`_meta.ui.resourceUri` · ui:// 리소스 · 결과 `_meta`)으로 시험했다. 세 리포 모두 브랜치 `wt1031/ha20` 이고 병합 · 올리기 · 재기동은 하지 않았다.

### 사용자 결정(10-31)

- **B-1 (가)** 박스 손잡이 + 새 권한 `feat:panels`, 파일럿 소속에만 먼저. 손잡이는 포털 `MCP_APPS_HOST`(`backend/.env`, 기본 0)이고 끄면 패널 창구
  다섯이 404 이며 챗 중계가 표지를 싣지 않는다. 에이전트 서버에는 급히 끄는 `CHAT_UI_HOST`(기본 1 — 표지를 따른다, 0 이면 HA-05 그대로)가 따로 있다.
- **B-2 (가)** 패널 세션의 첫 쓰기에서 포털이 확인을 묻는다(세션마다 한 번). 쓰기 판정은 게이트웨이가 읽기로 확인한 도구(`/tools-map` 의
  `routine_read`)가 아니면 쓰기이고, 읽기 목록을 모르면 다 쓰기로 본다.
- **B-3 (가)** srcdoc · 같은 출처 없음(`sandbox="allow-scripts"` 하나뿐) · CSP 메타를 문서 맨 앞에. 포털 문서에 CSP 헤더를 나중에 걸면 srcdoc 이
  물려받아 패널이 깨진다 — 그때 B-3 (나)(다른 출처 프록시)로 옮긴다(B7).
- **B-4 (가)** 패널은 그 탭에서만 산다. 기록(서버 사본)에는 포인터만 남고 '패널 — 다시 열기' 카드가 다시 읽어 입력만 보낸다.
- **B-5 (가)** 1단계에서 패널은 모델 맥락을 바꾸지 못한다 — `ui/update-model-context` · `ui/message` · `ui/request-display-mode` 는 '지원 안 함' 오류로 답한다.
- **B-6 (가)** 결과 `_meta` 는 패널에만 준다. 모델 · 근거 블록 · 다음 턴 이력 · 자기검증 · 서버 사본 · 브라우저 사본에는 싣지 않는다.
- **B-7 (가)** 도구 설명은 그대로 두고 파일럿 동안 지켜본다(SimFlow 의 '먼저 호출' 문구 — PA-04).

### 구현에서 정한 것과 까닭

- **패널 도구는 둘로 알아본다** — HA-05 이름 집합(`_CHAT_PANEL_TOOLS`)과 도구 목록의 `_meta.ui.resourceUri`(옛 키 `ui/resourceUri`, ui:// 만)다.
  표지 없는 턴 · 심의 · 루틴 · 카탈로그는 둘 다 묶지 않는다(설계 P1 의 '늘 안 묶임'). 집합 밖 이름도 주소로 알아보는 까닭은 가짜 앱 · ARP 처럼
  이름을 모르는 패널 도구가 표지 없는 턴에 글 몇 줄로만 보이는 HA-05 의 문제가 그대로라서다. 이름 집합이라도 주소가 없으면(`panel_upload_*`)
  표지 턴에도 모델에 묶지 않는다(패널이 부르는 도구다). `_meta.ui.visibility` 에 `model` 이 없는 도구는 표지 턴에 모델에 묶지 않는다(표지 없는 턴은
  HA-05 밖을 바꾸지 않으려 종전 그대로 둔다).
- **사건은 끝 사건에서 낸다** — `adispatch_custom_event` 는 실행 설정의 부모 실행(LangGraph Send 노드)으로 매겨져 상태줄의 `call`(도구 실행 id)과
  이어지지 않았다(10-31 실측). 그래서 `capped` 가 턴 그릇(`ui_panels.Turn`)에 두고 스트림이 그 도구의 `on_tool_end` 에서 같은 `call` 로 낸다. 끝
  사건이 없는 길(재시도의 ainvoke)은 턴 끝에 `call` 없이 낸다. 자기검증 감싸개는 result · meta · done 만 붙잡아 사건은 턴 도중에 나간다.
- **원 결과는 인터셉터가 붙잡는다** — 어댑터(langchain-mcp-adapters 0.3)가 결과 `_meta` 를 버린다. 표지 턴의 클라이언트만
  `tool_interceptors=[ui_panels.capture]` 를 달고, 인터셉터는 문맥 변수 그릇에 적기만 하고 결과는 그대로 넘긴다(모델에 가는 글이 바이트까지 같다 —
  표지 그릇 없이 부른 같은 도구가 오라클이다). 문맥 변수는 시험이 다시 읽지 않는 작은 모듈(`ui_panels.py`)에 둔다.
- **캐시 · 스냅샷 키에 표지를 넣었다** — 넣지 않으면 표지 턴이 묶은 패널 도구를 표지 없는 턴이 에이전트 캐시나 게이트웨이 불통 때의 스냅샷 폴백으로
  받아 HA-05 가 풀린다(변이로 확인). 키의 마지막 칸(자격 해시)을 강등 저장이 갈아 끼우므로 표지는 그 앞에 둔다.
- **invoke_tool 경유는 늘 막는다** — 게이트웨이 목록에서 본 패널 도구 이름(`ui_panels.known`)도 막는다. 표지 턴이면 '직접 묶인 그 이름으로 부른다' 고
  말한다(경유로는 사건이 도구 목록의 `_meta` 를 못 본다).
- **패널 PAT 는 청중을 따로 둔다**(`mcp-app-panel`) — 판별 셋(purpose `mcp-app` · jti 머리 `mcpapp-` · panel `{app, uri}`)은 설계 그대로이고, 청중을
  더 갈랐다. 옛 게이트웨이는 그 청중을 몰라 401 로 닫히고(패널 PAT 가 그 사람의 일반 PAT 시야로 새지 않는다), 포털 `/agent/chat` · 게이트웨이 REST
  다리도 청중이 달라 받지 않는다. 사람이 `/auth/pat` 으로 그 청중을 찍을 수 없다(허용 청중 목록 밖).
- **게이트웨이는 패널 표지가 하나라도 있으면 패널로 다룬다** — 꼴이 하나라도 어긋나면(청중에 MCP 청중이 같이 있음 · 수명 900초 초과 · 챗 PAT 이름 ·
  ui:// 아님 · 앱 `_gateway`) 401 이다. 일반 PAT 로 떨어뜨리면 그 사람의 시야 전부가 된다. 범위 머리(`x-hwax-panel`)는 게이트웨이만 싣고 두 인증
  분기 모두 클라이언트 사본을 버린다. 머리를 못 읽으면 아무것도 열지 않는 범위다.
- **게이트웨이 막음 목록** — 앱과 무관하게 게이트웨이 자체 도구 전부(invoke_tool · rest_call · rest_catalog · 검색 · 대화 · 루틴 …) · 되돌리기 어려운
  정확 이름(`_INVOKE_DENY_EXACT` — 절차 면제는 패널에 없다) · 외부 응답자 과제 셋. tools/list · resources/list 는 그 앱의 것만, resources/read 는 그
  앱의 ui:// 만(아니면 없는 주소와 같은 -32002), prompts 는 비운다. 끄기(muted)는 패널에 걸지 않는다(사람이 그 패널을 열었다). 감사는
  `via=mcp-app` 과 그 패널 주소(`uri`)이고, 포털이 실은 `X-HWAX-Corr`(`panel:<id8>:<n>`)로 포털 감사와 잇는다.
- **포털 창구는 세션 + CSRF 로만** 받는다(Bearer PAT 는 401). 표지는 세션 쿠키 요청이고 화면이 정확한 글자를 보냈고 손잡이 · `feat:panels` 가 있을
  때만 에이전트 서버로 옮긴다 — PAT 로 온 챗(스크립트 · 개인 Claude)에는 패널을 그릴 화면이 없다. 요청 칸은 넓게 받는다(다른 판의 글자로 422 를
  내지 않는다).
- **열기는 그 도구가 단 주소만** 연다 — 게이트웨이가 패널 PAT 로 보여 준 그 도구의 `_meta.ui.resourceUri` 와 다르면 404(`panel_uri_mismatch`).
  같은 앱의 다른 ui:// 를 '패널' 로 여는 길을 닫는다(패널 안의 resources/read 는 `/agent/panel/read` 로 따로 간다).
- **허용 도구** = 게이트웨이가 패널 PAT 로 보여 준 목록 ∩ 지도에서 그 앱 − 포털 막음 목록 − `visibility` 에 `app` 이 없는 도구. 게이트웨이도 같은 것을
  다시 막는다.
- **패널 세션은 포털 프로세스 메모리** — 유휴 30분 · 최대 4시간, 사람마다 8(넘으면 가장 오래된 것을 닫는다) · 전체 256(넘으면 503). 패널마다 게이트웨이
  MCP 세션 하나를 열어 두고 유휴 10분이면 닫는다(게이트웨이 SDK 에 세션 유휴 만료가 없다). 게이트웨이를 재기동해 세션을 잃으면(404) 한 번만 다시
  연다 — 그 호출은 실행되지 않았다. 패널 PAT 는 남은 수명이 2분 아래면 다시 찍는다. 내려갈 때 열린 세션을 닫는다.
- **감사** — 포털 `panel_open` · `panel_call` · `panel_confirm` · `panel_close` 에 앱 · 도구 · 주소 · 크기 · 성패 · ms 만 싣는다(인자 본문 없음 —
  변이로 확인). 성패 판정은 `judge`(평문 결과를 받게 raw)이고 돌려주는 것은 CallToolResult 그대로다.
- **open-link 허용 출처** = 박스 `PANEL_LINK_ORIGINS` ∪ 그 앱 플랫폼의 external-url 타일 출처(이 사람에게 보이는 것). CSP 바깥 출처는 리소스
  `_meta.ui.csp`(connectDomains · resourceDomains 만) ∩ 박스 `PANEL_ALLOWED_ORIGINS` — 둘 다 기본은 비었다.
- **화면** — 패널이 스스로 다른 문서로 가면(두 번째 load) 접는다. sandbox · CSP 로는 자기 탐색을 막지 못해 주소로 자료를 빼낼 수 있는 길이라(B7 보강),
  가는 요청은 이미 나간 뒤다 — 마지막 막이는 박스 출구다. 여는 중에 접히면 늦게 온 열기 답의 세션을 닫는다(셋을 한꺼번에 열 때의 경합 — 시험이
  잡았다). 기록에서 온 포인터는 저절로 열지 않는다. 입력은 브라우저 사본에만(4 KB 까지), 결과 · `_meta` 는 그 탭의 메모리에만 있다.
- **첫 쓰기 확인은 한꺼번에 온 쓰기 여럿을 하나로 푼다** — 패널이 쓰기 둘을 잇달아 보내면 확인 창이 하나만 뜨고, 허용하면 둘 다 한 번씩 다시 부른다.
  포털은 기다리는 확인 토큰을 여럿(최근 8개) 쥐고 그 가운데 하나로 세션을 허용한 뒤 나머지를 지운다(뒤에 온 확인은 no_pending_confirm 이고 화면은 그대로
  다시 부른다). 처음엔 토큰을 하나만 쥐어 뒤의 쓰기가 영영 기다리는 꼴이었다(자기 검토에서 찾았다).
- **`feat:panels` 는 CAEG 의 `*` 에 든다** — CAEG 가 지금의 파일럿 소속이다(09-11 결정 '지금 만드는 것은 모두 CAEG 것 — 다 같이 쓴다'). 다른 소속은
  개별 허가로만 받는다. 켜는 것은 박스 손잡이라 손잡이를 켜기 전에는 아무도 패널을 보지 않는다.

### 남은 위험(1단계에서 받아들인 것)

- **CSP 밖의 길** — WebRTC(RTCPeerConnection) · DNS 미리 찾기는 CSP 가 덮지 않는다. 패널 앱이 제 데이터를 바깥으로 보내는 길이 남는다 — 패널 앱(사내
  앱)이 이미 가진 데이터이고, 포털 쿠키 · 다른 앱 도구에는 닿지 못한다. 마지막 막이는 박스 출구(사내 프록시)다.
- **같은 프로세스** — 브라우저가 출처 없는 iframe 을 탭과 같은 프로세스에 두면 패널의 끝없는 루프가 탭을 멈춘다. 닫기 단추가 듣지 않으면 탭을 닫는다
  (B7 '무거운 패널'). 다른 출처 프록시(B-3 (나))로 옮기면 나아진다.

### SimFlow 가정(답이 오면 이것만 본다)
