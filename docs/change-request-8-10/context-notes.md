# 8·9·10차 변경 요청 — 결정 기록

## D-1. 범위와 제외 (2026-10-08)
총정리의 #1~#20 을 한다. 제외 — 7-1(전역 업로드 상한 0, 요청서가 보내지 않기를 권함) · 7-8(ODB 가 SSO 를 켠 뒤) · #18(#2 가 들어가 불필요).
요청서 §4(외부 팀)·§5(요청자가 정할 것)는 대상이 아니다. 사용자 지시: "좀전에 수정한 내용은 제외" — 심의 엔진 작업과 겹치는 것은 #1 뿐이다(D-2).

## D-2. #1 이 엔진 요청 4-3 을 대체한다
엔진 요청서 4-3 은 "부서 Claim 이 열리면 `department → affiliation` 매핑" 이었고 `docs/delib-engine-feedback` D-10 으로 "꺼진 채로, 소속이 빈
사람을 로그인 때 채운다" 로 잡았었다. 10차 §2 가 같은 문제를 더 정확히 요청했다 — 그쪽을 따르고 4-3 구현 단위는 돌리지 않는다.
- **키는 지금 있는 Claim 이다.** 운영 ADFS 는 `CompId`·`DeptId` 를 이미 준다(이름·부서명 Claim 은 아직 없다) — 부서 Claim 을 기다릴 이유가 없다.
- **최초 INSERT 때만 적용한다.** 로그인 때마다 빈 소속을 채우면 관리자가 일부러 비워 둔 사람을 다시 채운다. 기존 16명은 관리자가 지정한다(요청서 §5 ①).
- **매핑 표는 박스 파일에 둔다.** Claim 값(회사·부서 코드)은 사내 식별자라 추적 파일에 적지 않는다 — `access.local.yaml`(#7 의 오버레이)의
  `sso_affiliation_map` 으로 읽고, 추적 파일에는 지어낸 값의 예시만 둔다. 소속 id 가 표에 없는 행은 읽을 때 소리 내 버린다.
- **기본 소속(ⓐ)은 대안으로 함께 넣는다** — 매핑이 안 맞을 때만 쓰이고 기본은 빈 값이다. 전권 소속(`grants: ["*"]`)을 기본 소속으로 주면
  ADFS 를 통과한 누구나 전권이다 — 막지는 않되 기동 때와 관리자 화면(배선 설정)에 경고를 띄운다.

## D-3. 관리자는 원장만 — 개발 박스의 mock 관리자
`is_admin` 을 원장 그룹(과 #5 의 고정 목록)으로만 판정하고, 토큰이 들고 온 `portal-admin` 은 그룹에서도 뺀다. mock·oidc-mock 박스는 관리자를
IdP 그룹으로 받아 왔으므로 원장에 행이 없으면 관리자를 잃는다 — 시험은 원장을 시드하고, dev 박스는 `PORTAL_ADMIN_EMAILS` 로 잇는다.
게이트웨이는 하위로 넘기는 그룹에서 `portal-admin` 을 빼고, 포털 `/internal/access/entitlements` 응답의 `is_admin` 이 참일 때만 붙인다.

## D-4. smart-twin-mcp — 없어진 서비스가 아니다. 설정된 박스에서만 등재한다 (#11 의 6-a 답)
SmartTwinMCP 는 살아 있는 서비스다 — dev 는 `127.0.0.1:5013` 에서 듣고 있고 게이트웨이에 도구 18종이 붙어 있다(2026-10-07 실호출).
cae00 에 `:5013` 을 듣는 프로세스가 없는 것은 그 박스에 **띄운 적이 없어서**다. 그래서 요청의 (6-b)대로 조건부 등재로 바꾸되, 요청서의 필터
("직전 config 의 옛 기본값은 이어받지 않는다")를 그대로 넣으면 env 없이 기본 주소로 도는 **dev 에서 도구 18종이 사라진다.**
정한 것: 등재 조건은 `SMARTTWIN_MCP_URL`(env) 또는 직전 config 의 **기본값이 아닌** 주소. dev 는 `provision.env` 에 `SMARTTWIN_MCP_URL` 을 적는다.
포털 update-all 의 기대 목록도 같은 조건을 본다. 생략은 조용히 넘기지 않고 '켜려면' 과 함께 찍는다.

## D-5. arp — 두 리포를 같은 배포로 (#10)
게이트웨이는 `ARP_BASE` 와 `ARP_TOKEN` 이 둘 다 있을 때만 등재하고, 포털 update-all 은 같은 조건으로 기대한다. 토큰 모양은 ARP 회신 전이라
`Authorization: Bearer` 로 둔다(쿼리 방식이면 odb-hub 분기를 따라 바꾼다).

## D-6. ARP·ODB 라우트 (#4)
- 7-1 은 하지 않는다 — 전역 상한을 풀면 버퍼링이 켜진 다른 경로의 본문이 95% 찬 `/` 파티션의 `/tmp` 에 쌓인다. 7-2 의 `aireadyportal` arm 에
  `client_max_body_size 0` 을 넣어 ARP 만 푼다.
- 7-3·7-4·7-5 는 한 커밋. 플랫폼 id `arp` 와 게이트웨이 키 `arp` 는 그대로다(바꾸면 `plat:arp` 가 걸린 전원이 막힌다).
- 7-8(odb-hub 핸드오프)은 ODB 가 `PORTAL_JWKS_URL` 을 켠 뒤 따로 한다.
- 배포하는 순간 타일이 콜백으로 토큰을 보낸다 — push 는 하되 cae00 반영 시각은 요청자가 ARP 와 맞춘다.

## D-7. #21 — 지금은 그대로 두고, RA 의 홈 부서 보장이 확인되면 포털도 뺀다 (부록 B 를 받고 고쳐 씀)
처음엔 "의도다 — 게이트웨이가 지우는 것은 서비스 계정의 부서이고 포털이 싣는 것은 그 사람이 고른 부서" 라고 답했다. 부록 B(9차 §6)의 사실로
절반만 맞다. 연결 9건은 **전부** workspace 를 갖고 있는데 고른 것이 아니라 등록할 때 자동으로 채워진 값이다(`connections.py` 의
`_pick_default_workspace` — 조직 먼저, 조직 멤버십이 없으면 개인함). 위임 방식에서는 화면이 "부서는 RA 에서 정한다" 고 말하고 고르는 칸을 숨기므로,
포털만 **보이지도 바꿀 수도 없는 값**을 계속 싣는 셈이고, 같은 사람의 호출이 길에 따라 다른 부서로 간다(게이트웨이 경유는 RA 의 홈 부서, 포털의
PPT 가져오기는 저장된 값).
끝 상태는 게이트웨이와 맞추는 것이다 — 위임 방식에서는 포털도 싣지 않고 RA 가 정한다(sso-delegation 의 처음 결정과 같다).
**지금 바로 빼지 않는 이유** — RA 가 "헤더가 없으면 홈 부서" 를 보장하는지 확인되지 않았고(요청서 §4·§5 ③), 저장된 값은 '조직 먼저' 규칙으로
고른 것이라 RA 의 홈이 개인함인 사람을 조직함으로 보내 주고 있다. 지금 빼면 그 사람들의 PPT 가 개인함으로 가거나 400 이 된다.
그래서 이번에는 동작을 바꾸지 않고 그 자리에 사정을 주석으로 남긴다. `personal-*` 로 저장된 2명은 헤더로 풀 수 없다 — 홈이 개인함이라 빼도
개인함이다. RA 쪽에서 조직을 배정해야 한다(요청서 §4 RA).

## D-8. 게이트웨이 NO_PROXY — 클라이언트마다 고치지 않고 기동 때 환경을 세운다 (#2)
`AsyncClient` 를 만드는 자리가 10곳이고 MCP SDK 가 안에서 만드는 클라이언트는 손이 닿지 않는다. 설정을 읽은 직후 백엔드·위임·REST·포털 주소의
호스트를 모아 `NO_PROXY`·`no_proxy` 에 **더한다**(있던 값은 지우지 않는다) — 그 뒤에 만들어지는 클라이언트 전부가 따른다.
레지스트리로 뒤늦게 발견되는 앱도 같은 함수로 더한다. 무엇을 더했는지는 기동 로그에 호스트 이름으로 남긴다(주소는 남기지 않는다).

## D-9. 부록 B 는 뒤늦게 왔다 — 구현이 먼저 나갔고, 원문과 대조는 검토 단계에서 한다
처음 받은 요청서는 5만 자에서 잘려 9차 §4·§5·§6 원문(부록 B)이 없었다. #2·#3·#12·#19 구현 단위는 본문(§1) 서술로 먼저 나갔고, 부록 B 는
그 뒤에 왔다(요청 파일 끝에 붙였다). 원문이 더 정한 것은 셋이다.
- #12 — 스니펫과 자리가 정해져 있다(§1f 가 닫히는 `fi` 직후, `RA_HOST`·`ARP_HOST` 만, `export NO_PROXY no_proxy="$NO_PROXY"`). 구현이 다르면 맞춘다.
- #2 — `os.environ` 유도가 MCP SDK(`streamable_http`)가 안에서 만드는 클라이언트까지 덮는지 요청자가 확인하지 못했다. 구현 단위가 클라이언트가
  만들어지는 자리와 시점을 전부 적게 했다 — 덮지 못하는 자리가 있으면 그 자리에는 `trust_env=False` 를 쓴다.
- **CIDR 는 쓰지 않는다**(9차 §5) — httpx 0.28.1 은 `NO_PROXY` 의 CIDR 를 한 주소로만 읽어 대역이 우회되지 않는다(요청자 실측). 유도는 전부
  호스트·주소 그대로 하고, `check-egress.sh`(#19)가 `NO_PROXY` 안의 CIDR 항목을 "동작하지 않는 값" 으로 경고한다.
#18 은 원문도 "(3)이면 이 자리가 필요 없다" 고 적어 하지 않는다.

## D-10. 게이트웨이 몫이 요청서 diff 와 다르게 간 곳 (2026-10-08, 구현 결과)
- **#6** — 요청서는 `_base` 에서 `portal-admin` 을 빼라고 했다. 실제로는 **하위로 넘기는 그룹에서만** 빼고, 포털에 소속을 물을 때 보내는 로그인 그룹은
  그대로 둔다. 먼저 빼고 물으면 게이트웨이만 새것이고 포털이 옛것인 동안, 관리자를 IdP 그룹으로 받는 박스(dev 가 그렇다)가 도구 열쇠를 잃는다.
  그래서 포털의 `is_admin` 은 **원장만** 봐야 한다 — 질의로 온 그룹에서 유도하면 토큰에 박힌 표지를 포털의 판정인 것처럼 되붙이게 된다.
  `portal-admin` 을 실제로 읽는 하위 백엔드는 지금 없다(dev 기준 — cae00 의 `allowed_groups` 는 배포 전에 한 번 확인한다).
- **#2** — 부록 B 의 스니펫보다 넓다. 백엔드·위임 주소 외에 REST 사이트, 포털(api·jwks·폐기 목록), 레지스트리 주소도 모은다(게이트웨이가 실제로 부르는
  곳이다). 있던 순서를 지키고(정렬하지 않는다), 한쪽 철자만 있으면 다른 쪽이 그 값을 이어받고, `*` 하나뿐이면 건드리지 않는다. MCP SDK 가 안에서
  만드는 클라이언트도 이 환경을 따르는 것을 확인했다 — `trust_env=False` 가 필요한 자리는 없었다.
- **#17** — 선택 사항(상주 세션이 죽어 있어도 신원 호출은 단발 세션으로 바로 나간다)까지 넣었다.
- **#11** — 등재 조건은 요청서 diff 그대로다(직전 config 의 기본값 아닌 주소는 이어받는다). 더한 것은 생략 줄이고, dev 는 재프로비저닝 **전에** `provision.env` 에 `SMARTTWIN_MCP_URL` 한 줄이 있어야 한다(박스 파일이라 커밋에는 없다).
- **#8** — 접두는 환경변수 이름 꼴만 받고, 잘못된 쌍은 자리와 키만 알린다(쌍점 뒤는 찍지 않는다 — 비밀이 붙어 왔을 수 있다).

## D-11. #15 는 사번만 본다 — LoginId 는 넣지 않았다 (2026-10-08, 구현 결과)
요청서 제목은 "사번·LoginId 로도" 지만 diff 는 사번뿐이다. LoginId 가 사람마다 하나이고 바뀌지 않는다는 근거가 없어(계정 재발급·법인 이동) 넣지 않았다.
사번 없이 LoginId 만 오는 로그인이 실제로 보이면 다시 연다.

## D-12. 포털 몫이 요청서 diff 와 다르게 간 곳 (2026-10-08, 구현 결과)
- **#1** — 매핑 표는 `access.yaml` 이 아니라 박스 파일(`access.local.yaml`)에서만 읽는다(D-2). Claim 이름은 정확한 속성 키가 먼저이고, 짧은 이름(`CompId`)은
  그 Assertion 에 같은 끝 마디가 하나뿐일 때만 맞는다. 기본 소속은 정책에 있는 소속일 때만 쓰이고, 전권 소속이면 기동 로그와 배선 설정에 경고가 남는다.
  자동 지정의 흔적은 접속 이력의 로그인 줄에 남는다(`sso:aff:map` · `sso:aff:default`). 가입 줄을 못 쓴 실패는 이제 경고로 남는다(종전: 삼킴).
- **#7** — 박스 파일이 **재기동 뒤 첫 읽기에** 깨져 있으면 추적 파일로 돌아가지 않고 요청마다 실패한다. 돌아가면 박스 전용 백엔드가 표에서 빠지고 게이트웨이는
  표에 없는 백엔드를 전체 공개로 본다 — 조용히 열리느니 멈춘다. 도는 중에 깨지면 직전 정책을 지키고 배선 설정에 사유가 뜬다. 박스 파일은 추적된 플랫폼을
  통째로 바꾸지 못한다(검토에서 확정 — 타일·백엔드가 표에서 빠져 전체 공개가 되던 것).
- **#6** — PAT 발급 자리 셋(개인 토큰·절차·챗)에서 관리자 표지와 권한 키를 빼고 박는다. 포털 응답에 `is_admin` 이 생겼고 원장(과 고정 목록)만 본다.
- **#5** — 지정·해제는 저장소 잠금 안에서 한 번에 판정한다(두 관리자가 서로를 동시에 해제하는 경합). 고정 목록에 있는 사람의 해제는 409 로 거절한다(떼어도
  관리자라서). 활성 관리자가 0명이면 기동 로그·`/health/ready`·update-all §6 이 알린다.
- **#15** — 정지된 사번이면 브라우저에 JSON 403 이 아니라 로그인 화면으로 돌려보낸다(다른 콜백 실패와 같은 처리).
- **#14** — 응답에 앱별 회수 결과(`app_revocations`)가 실린다 — 성공과 실패가 똑같이 생기지 않게.
- **#3·#12** — 요청서의 두 줄을 그대로 쓰지 않았다. apptainer 는 명시한 값이 있으면 호스트 값을 물려주지 않아(실측), 소문자만 둔 박스에서 빈 값이 넘어간다.
  `NO_PROXY`·`no_proxy`·`RA_HOST`·`ARP_HOST` 의 합집합을 두 철자 모두에 넘기고, `start.sh` 를 update-all 밖에서 불러도 같게 했다.
- **#9** — knox-bridge 가 빠진 것은 **보고만** 한다. 재프로비저닝이 그 키를 만들 수 없어, 방아쇠로 두면 매 실행 게이트웨이·에이전트서버만 헛돈다.
- **#10·#11** — 옛 항목(토큰 없는 arp · 기본 주소의 smart-twin-mcp)이 남은 박스는 update-all 이 한 번 재프로비저닝해 걷는다(검토에서 확정 — 안 그러면 가짜 DOWN 이
  그대로 남는다). `ARP_TOKEN` 을 적으면 스스로 재프로비저닝한다.
