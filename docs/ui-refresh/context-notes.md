# 포털 UI 개선 — 결정과 이유

**D-1 리뷰 방법(2026-10-02).** 실 DB 를 안 건드리게 임시 포털을 빈 포트에 띄웠다 — `AUTH_PROVIDER=mock`·`SERVE_FRONTEND=1`·저장소 경로 전부
임시(메모리 'verify-permission-ui-temp-portal' 의 레시피). 시드 대화(표·목록·코드블록 답변) 하나를 넣고, Python playwright(SignalForge
venv 에 있다 — 포털 venv 에는 없다)로 11개 경로를 찍었다. ⚠ 첫 로그인 업데이트 팝업이 모든 화면을 덮으므로 '확인' 을 눌러 닫은 뒤 찍는다.
다섯 관점이 각자 추가 캡처·계측(scrollWidth, 계산된 스타일, 대비 계산)을 하고, 누락 점검이 높은 심각도 주장 다섯을 다시 확인했다(전부 맞음).
캡처는 리포에 넣지 않았다(사내 화면) — 단계 0 이 같은 세트를 시험으로 만든다.

**D-2 강조색 — 채움과 글자를 가른다.** `#1428a0` 은 흰 글자를 얹으면 11.4:1 로 좋지만, 어두운 배경 위 **글자**로는 1.66:1, **채움**으로도
버튼-배경 대비가 약 1.5:1 이라 비텍스트 3:1 에 못 미친다(버튼이 배경에 묻힌다). 글자·링크·선택·포커스는 이미 91곳에서 쓰는 `#98a8ff`
(8.4:1), 주 버튼 채움은 `#3b5bdb`(흰 글자 5.7:1, 배경과 3.3:1). 브랜드 블루는 로고·마크에만 남긴다. 사내 브랜드 지침이 채움 색을
`#1428a0` 으로 못박는다면 이 결정은 뒤집는다 — 그때는 버튼에 밝은 테두리를 더해 비텍스트 대비를 확보한다.

**D-3 대화상자는 Radix 대신 네이티브 `<dialog>`.** 스타일 관점은 Radix(Dialog·Menu·Tabs)를 제안했고, 누락 점검은 네이티브를 권했다.
`showModal()` 은 의존성 없이 배경 inert(포커스 가둠)·Esc·포커스 복귀·top layer 를 준다. top layer 는 z-index 10단계 난립과 '조상 transform 이
position:fixed 를 깬다' 는 이 리포의 기존 함정(챗 그림 오버레이)도 함께 없앤다. 빌드는 dev 에서 하고 dist 만 나르므로 의존성 자체는
막히지 않지만, 쓸 이유가 줄면 안 쓴다. Menu 는 직접 구현이 부담되면 그때 Radix 를 다시 본다.

**D-4 폭 우선순위는 960~1536px.** 사내 엔지니어 포털이고 CAE 도구 옆 반화면, 1920 모니터 150%(=1280px)·125%(=1536px) 배율이 흔하다.
헤더가 깨지는 곳(관리자 1340px 미만, 일반 1060px 미만)이 정확히 이 구간이라 데스크톱 문제가 모바일보다 먼저다. 390px 대응을 얼마나
할지는 접속 원장의 UA 열(access_log)로 실제 비율을 본 뒤 정한다 — 헤더만 고쳐도 본문 넘침은 /tokens 하나뿐이었다.

**D-5 글꼴은 번들.** cae00 은 사내 TLS 프록시 뒤라 런타임 CDN 이 위험하고, 빌드는 dev 에서 하고 dist 를 나른다. 그래서 글꼴은 빌드 산출물
(woff2)에 들어가야 한다. Pretendard(OFL) 기본. 사내 라이선스 글꼴(예: SamsungOne Korean)을 쓸 수 있으면 그쪽 — 사용자 결정으로 남긴다.
번들하면 개발 캡처와 사용자 화면이 같은 글꼴이 되어 시각 회귀도 결정적이 된다.

**D-6 단계 0(안전망)을 맨 앞에.** 프론트에 시험이 0개다. 전역 CSS 와 404곳의 인라인 스타일을 바꾸면 어디가 무너졌는지 볼 방법이 없다.
픽셀 비교만으로는 '흰 패널' 같은 결함을 기준선에 박제할 수 있어서, 가로 넘침·밝은 배경·미정의 변수 세 단언을 따로 둔다.

**D-7 리뷰의 한계 — 관리자 화면, Linux 글꼴.** 다섯 관점은 portal-admin 으로 봤다. 기본 권한 사용자는 헤더 항목이 적어 덜 깨지고(1060px
까지 버팀), 대신 /access 가 '권한 없음 · 요청' 26줄의 벽이다. 캡처의 글꼴은 dev 박스(DejaVu + Noto CJK)라 Windows 사용자의 맑은 고딕
화면과 다르다. 단계 0 의 캡처 세트를 세 권한 층으로 나누고, 타이포 판정은 글꼴 번들(D-5) 뒤에 다시 한다.

**D-8 하지 않는 것.** 전면 재작성·UI 프레임워크 교체(챗 화면은 이미 수준이 높다 — 토큰 치환만), 라이트 테마, 정식 SLO, 모바일 전용
레이아웃. 화면 문구 정리는 하되 기능 동작은 바꾸지 않는다(타일 열기 동작 통일은 예외 — 절반은 같은 탭, 절반은 새 탭이라 사용자가 길을 잃는다).

**D-9 픽셀 기준선은 리포에 넣지 않는다(2026-10-02, 단계 0).** 결함 단언(가로 넘침·밝은 패널·마크다운 기호·헤더 줄바꿈)을 시험으로 두고, 캡처는
`frontend/e2e/.shots`(gitignore)에 남겨 사람이 전후를 본다. 이유 셋 — 개편 중에는 기준선이 매 커밋 바뀌어 픽셀 비교가 소음이 된다, 기준선이
'흰 패널' 같은 결함을 박제할 수 있다(D-6), 사내 화면 캡처를 공개 리포에 올리지 않는다. Playwright 는 1.60.0 고정 — dev 박스에 이미 받은
chromium-1223 과 짝이라 브라우저를 새로 받지 않는다. 미정의 CSS 변수는 화면 점검이 아니라 `pnpm build`(check-css-vars)와 백엔드 시험에서 막는다.

**D-10 결정 대기 셋은 권장안으로 진행(2026-10-02).** 사용자가 '전반적으로 세련되게, 하나씩' 으로 진행을 맡겼다. 글꼴 Pretendard 번들,
주 버튼 #3b5bdb, 데스크톱 우선(모바일은 가로 넘침 0 까지). 셋 다 tokens.css 한 줄로 바꿀 수 있게 해 두었다.

**D-11 SSO 실패 리다이렉트는 단계 4 로 미룬다(2026-10-02).** 운영 SSO 가 이틀 전 열렸고, 요청자는 ACS 의 JSON 오류 본문(예: InvalidNameIDPolicy)을
보고 원인을 찾았다. 리다이렉트로 바꾸면 그 단서가 화면에서 사라진다 — 로그인 화면 재설계(단계 4) 때 '자세히' 로 원인을 함께 보이게 묶어서 한다.

**D-12 헤더에서 '리스크 심사' 를 뺐다(2026-10-02).** 그 화면은 스스로 '앱 창을 여는 역할만 한다' 고 말하고 같은 앱이 /apps 타일에 있다.
/risk 딥링크는 그대로다. 업데이트 이력(10-02)으로 사용자에게 알렸다.

**D-13 회귀 검토는 단계마다 임시 포털로(2026-10-02).** 단계 1·2 의 전역 변경(줄 간격·버튼 배경·keep-all·폼 기본값·포커스 링)은 자동 점검(경로 단위)
밖의 상태로 번진다 — 선택기·조직도·심의 옵션·절차 상세·관리 표. 세 관점(챗 화면·페이지·헤더 접근성)이 각자 임시 포털(포트 분리, 저장소 임시)을
띄워 '이전 빌드 vs 지금 빌드' 를 같은 클릭으로 비교하고, 검증자가 다시 재현했다. 확인된 것 18건을 고쳤다(2f96d44·4482370). 교훈 —
① 전역 기본값은 :where + :not([class]) 로 '아무것도 안 정한 것' 에만 ② 포커스 같은 의사 클래스도 :where 안에 넣어야 명시도 0 이다
③ 번들에서 globals.css 가 컴포넌트 CSS 뒤에 오므로(main.tsx 가 App 을 먼저 import) 같은 명시도면 전역이 이긴다.

**D-14 활동 레일의 '현재 전문가' 를 입력창 알약으로(2026-10-02).** 레일은 '누구와 대화 중인지·바꾸는 길' 을 대화 시작 뒤에도 닫히지 않게
하려고 늘 떠 있었다. 같은 목적을 입력창 도구 줄의 전문가 알약(이름·색·×·선택기·Thinking 충돌 경고)이 더 가까운 자리에서 한다.
레일은 활동이 있을 때만. 열 폭은 '넓게' 라는 종전 결정을 지키고 글 블록만 46rem 으로 묶었다(표·그림은 넓게).

**D-15 SSO 실패는 로그인 화면 + '자세히'(2026-10-02, D-11 의 이행).** 콜백(OIDC·SAML ACS)의 AuthError 를 `/login?error=sso&detail=<원인 1000자>`
로 302. 원인은 서버 로그(WARNING, hwax.auth)에도 남겨, 화면에서 사라져도 운영자가 찾는다. 300자로 자르니 '받은 클레임' 목록이 잘려 시험이
잡았다 — 1000자. 요청자가 ACS JSON 본문으로 원인을 찾던 단서(D-11)는 '자세히' 접힘에 그대로 있다.

**D-16 토큰 화면은 탭 셋, 탭은 주소에(2026-10-02).** 성격이 다른 셋(내 토큰·허브에 보일 앱·외부 연결)을 쌓아 '내 토큰' 이 맨 아래에 묻혔다.
`?tab=` 에 남겨 안내문이 바로 그 탭을 연다 — RA 연결 없음 안내(챗·절차)가 `/tokens?tab=connect` 를 가리킨다. 방금 발급한 토큰은 컴포넌트 상태라
탭을 오가도 남는다(화면을 떠나면 사라지는 것은 종전과 같다). 탭 원형(components/ui/Tabs)은 APG 자동 활성(화살표로 옮기면 연다).
⚠ 이 화면 파일을 prettier 로 통째 다시 접지 않는다 — `test_setup_bat` 가 TokenPage 소스에서 Desktop 조각 호출을 **한 줄 문자열로** 찾아
자리표시자(`<사용자>`)를 확인한다. 접혀서 그 시험이 깨졌다(9297178). 이 리포 파일 다수가 prettier 폭으로 쓰이지 않아, 통째 포맷은 무관한 줄까지 바꾼다.

**D-17 회의록 화자 이름은 명부의 가벼운 호출로(2026-10-02).** 서버 저장 심의는 발언에 키만 있다. 이름을 저장 경로에 새로 싣는 대신 전문가 명부
(light, 세션 1회 캐시 — 조직도가 이미 쓰는 것)에서 찾는다. 못 찾으면 키 그대로 — 이름이 틀리게 보이는 것보다 키가 보이는 쪽이 낫다.
색은 종전대로 키로 뽑는다(같은 사람이 심의 안에서 같은 색).

**D-18 저장된 심의의 진행 표시는 '일어난 단계만 완료'(2026-10-02).** 복원본에는 stage·outcome 이 없어 현재 단계를 못 찾고(-1) 모든 점이 '할 일' 이었다.
결정문이 있으면 끝난 심의로 보고, 일어났다고 알 수 있는 것만 남긴다 — 쉬운 설명은 본문이 있을 때, 보고는 보고서 번호가 있을 때.
없는 단계를 '완료' 로 칠하면 거짓말이다.

**D-19 관련도 3단계(2026-10-02).** recommend 점수는 상대값이라 '최상위 대비 %' 는 1등이 늘 100% 였다 — 맞는 사람이 없을 때도. 비율 0.8/0.5 로
높음·보통·낮음, 서버가 low_confidence 면 전부 낮음(위의 경고문과 같은 말을 한다). 추천 근거(why — 섹션 수·어휘 매칭률)는 진단용이라 툴팁으로.

**D-20 배선 설정은 관리 영역 + 헤더 건수, manual 은 '확인함'(2026-10-02).** 상자의 존재 이유가 '안 본 곳에 적은 것은 안 적은 것' 이라 단순히 관리
화면으로 옮기면 그 이유를 거스른다 — 그래서 헤더 '관리' 옆에 남은 건수를 늘 띄운다(세션 1회 + 확인함 때. 확인이 2초 걸릴 수 있어 화면 이동마다 안 묻는다).
manual 항목은 포털이 확인할 수 없어 영원히 남았다 — users.sqlite `setup_acks`(누가·언제)에 확인함, 되돌리기 가능. check 가 있는 항목은 확인함을
받지 않는다(404) — 고쳐지면 저절로 사라지는데 사람이 '됐다' 로 덮으면 상자가 거짓말을 한다.

**D-21 업데이트 '본 날짜' 는 서버와 브라우저 중 늦은 쪽(2026-10-02).** users.changelog_seen(앞으로만 간다 — 옛 탭이 늦게 옛 날짜를 적어도 안 되돌아간다).
서버를 못 묻거나 원장에 행이 없으면 브라우저 값으로 산다. 화면 시험은 '브라우저 기록을 지워도 서버 값으로 판정' 을 두 갈래로 단언한다(서버 값이
최신이면 처음 온 사람 경로를 안 탄다 = 브라우저에 latest 를 안 적는다).

**D-22 대화상자는 네이티브 dialog, 배경 div 는 안에 그대로(2026-10-02).** showModal 이 포커스 가둠·뒤 화면 inert·Esc·포커스 복귀·top layer 를
준다. 일곱 대화상자의 배경·카드 CSS 는 그대로 두고 틀만 바꿨다(diff 가 들여쓰기만). 닫기는 **레이아웃 단계**에서 — DOM 에서 떼기 전이어야
브라우저가 연 버튼에 포커스를 돌려준다. Chrome 은 Esc 를 연달아 누르면 cancel 없이 닫으므로 close 이벤트로도 상태를 맞춘다.
조직도 위 심층 보기는 top layer 순서로 맨 위만 Esc 를 받는다(종전: window 리스너 둘을 캡처 단계에서 끊어 막았다).

**D-23 회귀 하나 — 배경과 서랍을 같은 층으로 묶었다(2026-10-02, 47d8c11).** z 토큰화(2f96d44)가 배경 110·서랍 120 을 둘 다 --z-drawer 로 만들어,
DOM 뒤에 오는 배경이 좁은 화면의 사이드바를 덮고 클릭을 가로챘다. 경로 단위 점검은 '열기만' 해서 못 봤고, 저장된 심의를 390px 에서 실제로
누르는 시험이 잡았다 — 상태(서랍 열림)까지 가는 시험이 있어야 겹침 회귀가 보인다. --z-backdrop 110 을 따로 두었다.

**D-24 이모지 아이콘은 화면 장식만 걷었다(2026-10-02).** ⚠·✓·✕ 같은 글자 기호(글꼴이 그리고 뜻이 글자와 같다), 주석·LLM 지시문 속 기호는 둔다.
