- 코드 수정 요청 6건 — 작업 폴더는 노드 디스크에 두고, 업로드와 로그만 356대 모두에 붙은 `/data`(NFS)로 옮기는 안.

## 왜 실패하나

- **업로드** — `backend/job_submit_api.py` 153–159 `UPLOAD_DIR = SHARED_BASE/slurm_uploads` · 644 저장 · 857–873 잡 시작 때 계산 노드에서 `cp "<UPLOAD_DIR>/<파일>" "$SLURM_SUBMIT_DIR/input/<파일>"`. 계산 노드에 그 파일이 없어 실패할 것으로 본다(코드로 확인, 실측 아님).
- **로그** — 같은 파일 778–779 `#SBATCH --output` · `--error` 를 `SHARED_BASE/logs/%j.*` 로 → 계산 노드 디스크에 쓰인다. `backend/job_logs_api.py` 119 는 헤드의 같은 경로를 읽어 로그 보기에 안 나온다. 같은 꼴 — `backend/app.py` 935 · `backend/lsdyna_submit_api.py` 261.
- **폴더 없는 노드** — Slurm 은 스크립트보다 먼저 `--output` 파일을 연다. 폴더가 없으면 시작 전에 죽는다(신호 53). 스크립트 안 `mkdir` 로 못 막는다.
- **조용한 물러남** — 153–159 가 공유 폴더를 못 만들면 헤드 로컬 `/tmp` 로 물러난다. 6월 실행 계정이 바뀐 뒤 파일을 올리는 제출은 모두 500 이었다. 11-26 22:31 폴더를 만들어 제출 단계만 풀었다.
