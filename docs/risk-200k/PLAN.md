# 리스크 심사를 20만 토큰 창에서 — 지식카드 누락 0 · 멈춤 0 (계획, 2026-10-20)

> 사용자 요청(10-20) — "0.2m 을 염두에 두고, 이 사이즈라도 모든 지식카드가 누락없이 잘 검토가 되도록 하는 방안" ·
> "거절이 아니라 여러번 핑퐁을 치더라도 다 고려해야지". 체크리스트 [checklist.md](checklist.md) · 결정과 까닭 [context-notes.md](context-notes.md)(W-D1~).
> 이 계획은 재설계 D-22('작은 창 박스를 위한 장치를 만들지 않는다 — 창이 모자라면 잡을 멈춘다')를 뒤집는다. 1M 박스의 동작은 바꾸지 않는다.

## 0. 끝났다고 말할 기준

| # | 기준 | 판정 |
|---|---|---|
| G1 | **누락 0** — 범위 안 셀(전문가 × 단위)마다 그 전문가의 카드가 전부 **전문으로** 한 번 이상 모델에 실렸다 | 원장(커버리지)으로 증명한다. 제목만 실린 것은 세지 않는다. 승인된 거르기로 뺀 셀은 종전대로 따로 센다 |
| G2 | **멈춤 0** — 크기 때문에 잡이 `ctx_too_small` 로 서지 않는다 | 카드 · 단위 · 요약 · 패널 근거 모두. 창보다 큰 것은 나눠 여러 번 부르고 합친다 |
| G3 | **품질** — 같은 대상을 1M 과 20만(나눠 부르기)으로 돌려 결과가 같다고 볼 만하다 | 걸림(FAIL · WARNING) 판정 일치율 · 인용 대조 통과율 · 쟁점 수. 기준값은 W0 측정 뒤 사용자와 정한다(초안: 걸림 일치 95% 이상) |
| G4 | **비용을 미리 말한다** | 잡을 열 때 호출 수 어림(1M 대비 배수)을 보이고, 끝에 실제 수를 적는다 |

## 1. 지금 20만 창에서 새는 곳 (실측)

표본은 dev AIDataHub 전문가 796명 가운데 무작위 30명 + 2명(카드 5,716장)이다. 엔진의 `normalize_card` · `render_card` 로
실제와 똑같이 펼쳐 쟀다(읽기만). 창 값은 엔진 `card_review.limits()` 의 계산값이고, 20만은 Claude 길 기본(출력 32K)으로 셈했다.

| | 1M | 20만 |
|---|---|---|
| 전문가 한 명의 카드 전문 합 | 중앙값 244만 자 · 최대 3,559만 자 | 같다 |
| 가장 긴 카드 한 장 | 중앙값 14.4만 자 · 최대 51.7만 자 | 같다 |
| 카드 한 장이 넘으면 안 되는 한계(판정 · 훑기) | 84.5만 · 81.7만 자 | 13.2만 · 12.6만 자 |
| 한계를 넘는 카드 | 0장 | **143장(2.5%)** |
| 그런 카드가 있어 잡이 멈추는 전문가 | 0명 | **19명 / 32명(59%)** |
| 입력 결손 셀에 전문으로 싣는 카드 몫 | 138,117자 | **24,648자** — 32명 중 31명이 넘는다 |
| 훑기 호출(목록 한 쪽 기준, 32명 합) | 470 | 2,120(4.5배) |
| 셀 하나의 판정 호출(조각 포함 어림) | 중앙값 26 · 최대 519 | 중앙값 65 · 최대 1,469(2.6배 · 최대 4.9배) |

새는 곳은 다섯이다.

| # | 자리 | 지금 동작 | 결과 |
|---|---|---|---|
| L1 | 한계보다 긴 카드(훑기 · 판정) | 계획의 `oversize` → 앱이 잡을 `ctx_too_small` 로 멈춘다(D-22) | 그 전문가의 **검토 전체가 서지 않는다** |
| L2 | 카드 밖 호출의 배경 카드 · 입력 결손 셀의 카드 | 남은 몫만큼만 전문, 나머지는 **제목만**(`bg_dropped` 로 셈) | 대부분의 카드가 제목으로만 실린다 |
| L3 | 단위 본문이 창을 넘는다 | 계획의 `oversize.units` → 잡 멈춤 | 드물지만 멈춘다(운영 단위 크기는 W0 에서 잰다) |
| L4 | 종합 요약의 행이 창을 넘는다 | `over_budget` → `ctx_too_small` 보류 | 보고서가 서지 않는다 |
| L5 | 쟁점 패널 근거 | 인용된 카드 절 칸 13,436자(1M 77,929) · 좌석 자기 카드 3,500자 · 자유 조회 3,500자 | 인용이 많은 쟁점에서 카드 절이 빠진다(빠진 줄은 셈) |

판정 단계는 원래 점검 카드 전부를 모든 살아 있는 단위에 대본다(빠진 카드 재질의까지 있다). 20만에서 **판정 자체가 카드를
빠뜨리지는 않는다** — 긴 카드에서 멈추는 것(L1)이 문제다.

## 2. 방안 — 원칙은 하나다: 넘치면 나눠 여러 번 부르고, 합칠 때 빠짐을 센다

### A. 카드 조각 — L1 (엔진 · 앱)
- 한계(셀 종류별 '한 장 자리')를 넘는 카드는 **절 경계에서 조각**으로 나눈다. 한 절이 혼자 넘으면 문단 → 문장 경계로 더
  나누고 앞뒤 한두 문장을 겹친다. 경계는 결정적이다(같은 카드면 같은 조각 — 다시 돌기 · 접두 캐시가 산다).
- 조각마다 **카드 틀**을 싣는다 — 카드 머리 줄 · 제목 · 전체 절 목차 · '이 조각은 §3~§5(3/7)'. 모델이 카드 전체의 모양을 안다.
- 조각은 묶음 안에서 카드처럼 다룬다(별칭 `K12.1`, `K12.2` …). 절 번호는 원래 것을 그대로 둬 **인용 대조가 바뀌지 않는다**
  (문단으로 나눈 절은 `§3` 의 원문 위치로 대조한다).
- 카드 단위 결과로 합친다 — 해당 여부는 '어느 조각이든 해당', 판정은 가장 무거운 것, 인용은 조각들의 것을 모은다.
- **조각끼리 갈리면 한 번 더 핑퐁** — 한 조각은 FAIL 인데 다른 조각이 그것을 반박하는 절(OK 의 근거)을 가졌으면, 두 조각에서
  인용된 절만 모아 그 카드 하나를 다시 판정한다(통합 재판정). 절이 서로 다른 조각에 있어 생기는 맥락 손실을 메운다.
- **나누기 · 부르기 · 합치기 · 통합 재판정은 엔진의 run 안에서 한다**(W-D11 고침, 10-20). 계획은 그 카드를 혼자 한 묶음(`chunked`)으로
  내고, 앱은 원래 카드를 그대로 보내 카드 한 장의 행을 받는다 — 앱의 원장 · 불변식(카드 하나 = 행 하나)이 바뀌지 않는다.
  조각마다 `status{chunk, of}`, 재판정은 `status{step: reconcile}` 이 흐른다. 조각 하나가 끝내 실패하면 그 오류로 끝내고(반쯤 합치지
  않는다), 판정 행 없이 끝난 조각이 있으면 그 카드를 빠진 카드로 낸다.

### B. 배경 · 입력 결손을 쪽으로 — L2 (엔진 · 앱)
- 카드 밖 호출과 입력 결손 호출은 제목으로 내리지 않고 **카드 쪽**으로 나눠 쪽마다 한 번씩 부른다(훑기에 걸린 카드가 앞 쪽).
  각 카드는 정확히 한 쪽에 전문으로 실린다. 다른 쪽 카드의 **제목 목록**은 쪽마다 함께 실어 모델이 전체를 안다.
- 쪽이 둘 이상이면 셀마다 **합치기 한 번**을 더 부른다 — 쪽별 지적을 모아 겹친 것을 묶고(메커니즘 · 부품 · 인용 기준),
  인용을 다 남긴다. 합치기는 새 지적을 만들지 않고 있는 것만 정리한다(검증 가능 — 출력의 인용이 입력 지적의 인용 안이다).

### C. 단위를 쪽으로 — L3 (엔진 · 앱)
- 단위 본문이 '단위 자리' 를 넘으면 변경 줄 기준으로 쪽을 나누고(앞뒤 문맥 줄 겹침), 단위 머리(부품 · 영역 · 변경 요약)는 쪽마다 싣는다.
- 카드 × 단위 쪽마다 판정하고 카드 × 단위 결과로 합친다(어느 쪽이든 해당 → 해당, 인용 줄은 원래 `[c:…]` 그대로).
- W0 에서 운영 단위 크기를 재 보고, 넘는 단위가 없으면 이 몫은 시험 · 가드만 두고 뒤로 미룬다.

### D. 요약을 계층으로 — L4 (엔진 · 앱)
- 행이 요약 몫을 넘으면 메커니즘 · 부품으로 무리를 지어 무리마다 부분 요약을 받고(map), 부분 요약들로 최종 요약을 받는다(reduce).
- '꼭 다룰 행'(`must_cover`)은 무리를 가로질러 추적한다 — 최종 요약의 risk · conflict 줄이 모든 꼭 다룰 행을 덮는지 코드로 견주고,
  빠졌으면 그 행만 실어 한 번 더 부른다.

### E. 패널 근거를 빠짐없이 — L5 (앱 · 엔진)
- **E1 근거 압축(필수)** — 패널 전에 인용된 카드마다 원장에서 **결정적으로** 한 줄을 만든다(카드 · 절 · 판정 · 인용 원문 · 까닭 —
  LLM 을 부르지 않는다). 인용된 카드는 전부 이 줄로 실리고, 칸이 남는 만큼 절 전문을 더한다(D-57 의 번갈아 차례를 따른다).
  카드가 '빠지는' 일은 없고 '전문이 아니라 인용으로만 실리는' 카드만 생긴다 — 그 수를 셈한다.
- **E2 좌석의 다시 읽기(선택 — 사용자 결정)** — GLM 길은 좌석 자유 조회에 `card_section(record_id, sid)` 를 열어 좌석이 필요한 절의
  전문을 직접 읽게 한다(도구 예산 안). Claude 길은 자유 조회가 없으니 근거를 쪽으로 나눠 라운드마다 다른 쪽을 싣는 방식을 따로 본다.
- 좌석 자기 카드(질문 검색 3,500자)는 쟁점 패널에서는 E1 이 인용 카드를 이미 실으므로 둔다.

### F. 커버리지 원장 — G1 의 증명 (앱)
- 셀마다 카드마다 '전문으로 실린 호출'(조각 · 쪽 번호)을 적는다. 잡을 닫을 때 불변식 하나를 더한다 —
  **범위 안 살아 있는 셀에서 전문 노출 0인 카드 = 0**. 어기면 `completed` 가 아니라 그 목록을 단 `partial` 이다(조용히 끝나지 않는다).
- 전문가 보고서와 종합 보고서에 '누락 0 증명' 줄(카드 수 · 전문 노출 수 · 조각 · 쪽 · 통합 재판정 수)을 싣는다.

### G. 비용 · 시간
- 늘어나는 호출 — 판정은 셀당 중앙값 2.6배(최대 4.9배), 훑기 4.5배, 쪽 나누기 · 합치기 · 통합 재판정이 더해진다.
- 줄이는 길 — ① 프롬프트 차례가 [당신]→[카드]→[단위]→[지시] 라 같은 묶음을 다른 단위에 댈 때 앞부분이 같다. 조각 경계를
  결정적으로 두면 vLLM 접두 캐시가 산다. ② 동시 수는 용량 측정(`docs/llm-pool/capacity.md`)으로 정한다.
  ③ 거르기(승인된 표)가 셀 수를 줄인다 — 그대로 쓴다.
- 미리 말한다 — 잡을 열 때 `calls_estimate` 를 20만 계획(조각 · 쪽 포함)으로 셈해 1M 대비 배수와 함께 보인다. 카드가 아주 많은
  전문가(표본의 material-twin-analyst — 2,693장 · 3,559만 자)는 어림을 따로 보이고 확인을 받는다.
- Claude 길이 20만 모델이면 호출이 사람 속도의 워크플로로 간다(주인마다 동시 8). 시간이 크게 늘어 W0 에서 길을 먼저 정한다.

### H. 검증
- 엔진 — 조각 경계 결정성 · 틀 줄 · 인용 대조, 쪽 나누기 커버리지(모든 카드가 정확히 한 쪽), 요약 계층의 꼭 다룰 행 추적. 변이로 시험을 확인한다.
- 앱 — 합치기 규칙(해당 · 판정 · 인용), 통합 재판정 방아쇠, 커버리지 불변식, `ctx_too_small` 보류가 크기 때문에는 서지 않음.
- 배선 리허설(`HWAXRisk/backend/tests/synth/rehearsal_d.py`)을 20만 설정(가짜 LLM 창 200,000)으로 끝까지 — 실제 카드 길이 분포로
  만든 합성 팩(긴 카드 · 많은 카드 전문가 포함).
- 실측 A/B — cae00 에서 같은 대상을 1M(지금 GLM)과 20만(`LLM_CONTEXT_TOKENS=200000` 을 준 임시 에이전트 서버)으로 돌려 G3 를 잰다.
