# 5차 변경 요청 — 결정과 이유

**D-1 이름 헤더는 UTF-8 바이트가 아니라 퍼센트 인코딩(2026-10-01).** 요청서 1-a 는 `display_name.encode("utf-8")` 를 제안하고
"ste 의 수신 디코딩에 의존한다 — 판단을 넘긴다" 고 적었다. ste 는 `request.headers.get("x-heax-user-name")` 로 읽는데 Starlette 는
헤더 바이트를 **latin-1** 로 푼다 — UTF-8 바이트를 보내면 500 은 멎지만 ste 원장에 **깨진 이름**이 남는다. 우리 스택은 이미 비ASCII
헤더를 퍼센트 인코딩으로 나른다(게이트웨이 `x-hwax-user`·`x-hwax-groups`). 같은 규칙으로 포털은 **출력 가능한 ASCII 는 그대로 두고**
비ASCII 와 `%` 만 인코딩하고, ste 는 `unquote` 한다. 옛 판 ste 가 남아 있는 동안에도 ASCII 이름은 그대로라 바뀌는 것이 없다.

한글 이름은 포털이 먼저 갱신되고 ste 가 아직이면 (500 이 아니라) **인코딩된 채로** 계정이 만들어진다. ste 는 이름을 **처음 만들 때만**
쓰므로 다시 로그인한다고 저절로 바로잡히지 않는다 — 그래서 ste `ensure_sso_user` 에 자가 치유를 넣었다: 저장된 이름에 `%` 가 있고
그것을 되푼 값이 지금 들어온 이름과 **같을 때만** 고쳐 쓴다. 사람이 ste 에서 바꾼 이름은 그 조건에 안 걸려 건드리지 않는다(시험 고정).

**D-2 1-b 는 그대로 넣는다.** 인코딩을 고치면 그 자리의 UnicodeEncodeError 는 더 안 나지만, 헤더에 들어가는 다른 값이 비ASCII 가
되는 날 같은 500 이 된다. "조용히 빈 토큰을 돌려주지 않는다" 는 이 파일의 약속을 지키는 방어선이다 — 시험이 따로 고정한다.

**D-3 권한 표 구멍은 시험만으로는 cae00 을 못 지킨다.** CI 는 dev 에서 돈다 — dev 게이트웨이 백엔드는 이미 전부 표에 있고
(실측 17개), 구멍(simflow·plm-defect·knox-bridge)은 cae00 에만 있는 백엔드였다. 그래서 시험(고정 목록 + 닿으면 실제 `/health`)에 더해
update-all §6 이 **그 박스의 실제 백엔드**를 게이트웨이 정책과 대조해 빠진 것을 fail 로 낸다(표에 없으면 아무나 쓰거나 아무도 못 쓴다 —
보안이라 경고가 아니라 실패). 요청서가 표에 없다고 짚은 `heax_registry`·`portal`·`rest` 는 gateway_config.json 의 **설정 절**이지
백엔드가 아니다 — `/health` 의 backends 에 안 나온다.

**D-4 대조 상대는 게이트웨이 캐시가 아니라 포털의 지금 표(2026-10-01).** 게이트웨이는 정책을 60초마다 받아 둔다. update-all 이 방금
access.yaml 을 받아 온 실행에서 게이트웨이 `/health`(시크릿)의 `access_policy` 와 대조하면 옛 캐시로 빨개질 수 있다. 그래서 백엔드 목록은
게이트웨이 무인증 `/health` 에서, 표는 포털 `/internal/access/policy`(게이트웨이와 같은 공유 시크릿, `curl -K -`)에서 받는다. '게이트웨이가
표를 실었는가' 는 바로 위의 `access_policy_loaded` 점검이 따로 본다. 못 읽으면 ⚠(초록 아님), 구멍이면 ✗.

**D-5 dist 표식 불일치도 멈춘다 — 끄는 손잡이 없음(2026-10-01).** 요청서는 '표식 없음' 만 짚었지만, 표식이 HEAD 와 다른 dist 를 올리면
받는 쪽 게이트가 어차피 ✗ 로 막는다 — 올리는 쪽에서 멈추는 편이 원인에 가깝다. `build-all-to-drive.sh portal` 은 빌드부터 해 이 상태가
안 생기고, 손으로 `images-to-drive.sh` 만 돌릴 때는 다시 빌드하면 된다. 그래서 우회 옵션은 두지 않았다.

**D-6 IdP 메타데이터 검증은 기본 켬(2026-10-01).** 요청자(cae00)는 파일 경로를 써서 영향이 없다. URL 을 쓰는 박스가 사내 CA 면
메타데이터를 못 받아 SAML 로그인이 실패한다 — 그때의 정석은 `SSL_CERT_FILE` 이고(urllib 기본 컨텍스트가 읽는다),
`SAML_IDP_METADATA_VALIDATE_CERT=false` 는 최후 수단으로만 남긴다.

**D-7 경고는 전부 끝에서 다시 센다(2026-10-01).** '매핑된 서비스 없음' 만 `bad` 로 바꾸면 끝 요약에 안 남아 여전히 수백 줄 사이에 묻힌다.
`bad` 가 `WARN_ITEMS` 에 적고 끝에서 건수와 함께 다시 낸다(성공·실패 어느 끝에서든). 종료코드는 그대로다 — `bad` 는 FAIL 을 안 건드린다.
