> 받는 분 — MatNexus · TestScope 개발 · 운영 팀(두 시스템이 같은 팀이라 한 장으로 묶었다). 보내는 쪽 — HWAX 포털(MCP 게이트웨이를 맡은 쪽).
> 건네는 사람 — 사용자. 함께 건넬 것 — 공통 계약 [../contract.md](../contract.md). 고친 날 2026-11-27(처음). 숫자는 운영 박스 기록에서 옮겼고 날짜를 붙였다.

## 0. 무엇 · 왜

HWAX 포털의 MCP 게이트웨이에는 운영 박스 기준 백엔드 35 · 도구 1,984개가 모이고(11-26), 그 가운데 약 1,200개가 사내 앱 도구다. 웹 챗 · 심의 좌석 · 개인 Claude 는
도구를 이름 · 설명 · 인자 스키마만 보고 고르고 부른다. 그 셋이 산문 · 빈칸이면 2,000개 속에서 잘못 고르고, 인자를 지어내고, 읽기 도구를 쓰기로 막는다.

두 시스템은 합쳐 도구 약 230개로 **게이트웨이 백엔드 도구의 약 12%** 다(MatNexus 6.6% · TestScope 5.1%). 물성과 시험 장비라는 이름이 다른 앱(재료 · 시험 쪽)과
겹치기 쉬워, 설명과 인자 설명이 고르기의 정밀도를 가른다.

## 4. 프로토콜 — stateless · 두 세대

- **TestScope** — 옛 사본(v0.62.0)이 이미 SDK 2.x 라 두 세대를 같은 자리에서 낼 것으로 본다. 운영 판(v0.65.x)도 2.x 인지와, 세션을 쥐는 설정이 남았는지만 알려 주세요.
  모델이 읽어야 할 오류는 `ToolError` 로(P3 — 2.x 는 일반 예외를 「Error executing tool …」 으로 가린다).
- **MatNexus** — 1단계(먼저)는 서버가 세션을 쥐지 않는 것이다(P1). Python SDK 1.x(FastMCP)면 생성자에 `stateless_http=True` 한 줄, TypeScript SDK 면 streamable HTTP
  전송의 세션 id 생성기를 비운다. 2단계는 SDK 2.x(`mcp>=2.3`, Python 3.11 이상)로 두 세대를 같은 자리에서(P2) — TestScope 와 같은 판으로 맞추면 팀 안에서 한 벌이다.
- 서버 발 알림 · sampling · elicitation 을 쓰고 있으면 알려 주세요(1단계에서 버려진다). 게이트웨이는 옛 세대 앱도 계속 부른다.

## 5. 로드맵 — R1 · R2 · R3

- **R1 이벤트** — TestScope 의 검토함 새 항목 · 기종 요청, MatNexus 의 물성 등록 · 바뀜을 「바뀐 것 목록」 읽기 도구(커서 · 시각 · 종류 · id)로 내 주세요. 이름은
  `<앱>.<대상>.<일>` 꼴(예 `testscope.review.created` — 이름은 앱이 정한다).
- **R2 길 안내** — TestScope 는 서버 지침의 길 표(ROUTING)를 그대로 보내 주면 된다. MatNexus 는 대표 업무 둘 ~ 다섯을 「목적 · 차례 · 입구 도구 · 확인할 쓰기」 로.
- **R3 앱 입구** — TestScope 는 `get_guide` 로 알고 있다(맞는지만). MatNexus 는 처음 부를 도구 하나를 정해 알려 주세요.
