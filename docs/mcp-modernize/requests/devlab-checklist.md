# 개발실 체크리스트에 — MCP 계약 · stateless · 로드맵(요청)

> 받는 분 — 둘이다. **1절 몫은 중계 MCP 의 주인(운영 쪽** — 검증 서버 앞에 운영 쪽이 지은 중계, 게이트웨이 백엔드 `devlab-checklist`). 이 몫은 받은 편지함 7차 절의
> 「이 박스 몫」 으로도 읽힌다. **2절 몫은 원 서버(PCB 체크리스트 검증 서버) 담당**이다. 보내는 쪽 — HWAX 포털(MCP 게이트웨이를 맡은 쪽). 건네는 사람 — 사용자.
> 함께 건넬 것 — 공통 계약 [../contract.md](../contract.md). 고친 날 2026-11-27(처음). 숫자는 운영 박스 기록에서 옮겼고 날짜를 붙였다.

## 0. 무엇 · 왜

HWAX 포털의 MCP 게이트웨이에는 운영 박스 기준 백엔드 35 · 도구 1,984개가 모이고(11-26), 그 가운데 약 1,200개가 사내 앱 도구다. 웹 챗 · 심의 좌석 · 개인 Claude 는
도구를 이름 · 설명 · 인자 스키마만 보고 고르고 부른다. 그 셋이 산문 · 빈칸이면 2,000개 속에서 잘못 고르고, 인자를 지어내고, 읽기 도구를 쓰기로 막는다.

개발실 체크리스트는 중계 MCP 가 원 서버의 REST 를 감싸는 꼴이다. 계약(표지 · 인자 설명 · 결과 꼴)은 중계에서 내지만, 결과 꼴과 부작용은 원 서버가 정한다. 그래서 둘에게
나눠 청한다.

### 1-3. 프로토콜 — stateless · 두 세대

- **1단계(먼저)** — 중계가 세션을 쥐지 않는다(P1). Python SDK 1.x(FastMCP)면 생성자에 `stateless_http=True` 한 줄. 제출처럼 여러 호출에 걸친 상태는 작업 id 를 도구
  인자로 받는다. 서버 발 알림을 쓰고 있으면 알려 주세요(1단계에서 버려진다).
- **2단계** — SDK 2.x(`mcp>=2.3`, Python 3.11 이상)로 두 세대를 같은 자리에서(P2). 운영 박스의 Python 3.11 여부는 받은 편지함 7차 MQ-8 이 함께 본다. 모델이 읽어야 할
  오류(원 서버의 500 · 시간 초과)는 `ToolError` 로(P3 — 2.x 는 일반 예외를 가린다).

### 1-4. 로드맵

- **R1 이벤트(값진 몫)** — 검증 제출 끝 · 실패를 「바뀐 것 목록」 읽기 도구(커서 · 시각 · 종류 · id)로. 이름은 `<앱>.<대상>.<일>` 꼴(예 `devlab.check.finished` — 이름은
  주인이 정한다). 큰 보드도 사람이 다시 묻지 않아도 끝이 온다.
- **R2 길 안내** — 보드 제출 → 상태 → 결과 읽기 → 위반 그림의 차례를 「목적 · 차례 · 입구 도구 · 확인할 쓰기」 로.
- **R3 앱 입구** — 처음 부를 도구 하나(체크리스트 · 규칙 목록 조회 류).
- **도구 영역** — 아홉이 속할 영역 키 하나를 알려 주면 게이트웨이에 넣는다(HG-30).

## 2. 원 서버(PCB 체크리스트 검증 서버 담당)

중계가 위 계약을 내려면 원 서버의 답이 먼저인 것들이다. 내용은 11-24 요청 모음 3-3 그대로이고 여기 다시 쓰지 않았다 — MCP 쪽에서 무엇이 기다리는지만 잇는다.

| 원 서버 번호 | 중계에서 기다리는 것 |
|---|---|
| RR-01 응답 스키마 | C7 결과 꼴 — 판정 · 항목 · 근거 필드 |
| RR-02 체크리스트 · 규칙 목록 API | R3 입구 · C3 enum(규칙 · 체크리스트 이름의 닫힌 집합) |
| RR-03 가벼운 상태 확인 | 중계의 상태 도구 · 게이트웨이 스모크 |
| RR-04 상태 여러 값 | C3 enum · C4 경계 |
| RQ-09 `resolve-checklists` 의 부작용 | C6 표지 — 답이 오면 읽기로 열지 정한다 |
| RQ-04 로그인 없이 결과 · 제출자 | 출력 위생 |
| RQ-12 ~ RQ-16 큰 보드 제출 500 · 30초 한도 | C8 · R1 — 제출과 결과 읽기를 나누는 꼴 |
