# PLM 결함 검색에 — 주인 확인부터 · MCP 계약 · stateless(요청)

> 받는 분 — **아직 모른다.** 게이트웨이 백엔드 `plm-defect`(시장 불량 원천 후보)의 개발 · 운영 담당을 사용자가 먼저 찾는다. 찾으면 이 글과 공통 계약
> [../contract.md](../contract.md) 를 함께 건넨다. 보내는 쪽 — HWAX 포털(MCP 게이트웨이를 맡은 쪽). 고친 날 2026-11-27(처음).

## 0. 무엇 · 왜

HWAX 포털의 MCP 게이트웨이에는 운영 박스 기준 백엔드 35 · 도구 1,984개가 모이고(11-26), 그 가운데 약 1,200개가 사내 앱 도구다. 웹 챗 · 심의 좌석 · 개인 Claude 는
도구를 이름 · 설명 · 인자 스키마만 보고 고르고 부른다. 그 셋이 산문 · 빈칸이면 2,000개 속에서 잘못 고르고, 인자를 지어내고, 읽기 도구를 쓰기로 막는다.

PLM 결함 검색은 MX 백서 LLM 위키가 시장 불량 원천으로 쓰려는 후보다. 주인을 모르는 채로는 계약 · 판 · 바뀜을 맞출 곳이 없다.

## 2. 청할 것 — 주인이 정해지면

1. **주인 · 판** — 담당과 판(커밋 · 판 번호)을 알려 주세요.
2. **공통 계약** — 특히 C6 표지(검색 · 상세 · 유사 셋은 `readOnlyHint=True`일 것으로 보인다 — 맞는지), C2 인자 설명, C7 결과 꼴(결함 사례 칸을 반환 타입 모델로),
   C8 정직한 한도(잘랐으면 `truncated` · `total`), 출력 위생(결과에 사람 실명 · 메일을 싣지 않는다).
3. **프로토콜** — 1단계는 서버가 세션을 쥐지 않는 것이다(P1 — Python SDK 1.x 면 `FastMCP(..., stateless_http=True)` 한 줄, TypeScript SDK 면 세션 id 생성기를 비운다).
   2단계는 SDK 2.x(`mcp>=2.3`, Python 3.11 이상)로 2026-07-28 새 세대와 옛 세대를 같은 자리에서(P2) · 모델이 읽어야 할 오류는 `ToolError` 로(P3). 게이트웨이는 옛 세대
   앱도 계속 부른다.
4. **로드맵** — 새 결함 사례 적재를 「바뀐 것 목록」 읽기 도구로(R1 — MX 백서 위키가 새 원천을 받는 때가 된다) · 대표 업무 둘 ~ 다섯(R2) · 처음 부를 도구 하나(R3).

## 3. 이미 보낸 것과 잇기

없다(주인을 몰라 보낸 적이 없다). MX 백서 위키 쪽 기록은 `../../mxwp-wiki/` 에 있다.

## 4. 답하는 꼴

항목마다 한 줄 — `C6 | 할 차례 | <판>에서 | (비고)`. 상태는 「됨 · 할 차례 · 안 함(까닭)」. P1 ~ P3 · C1 ~ C9 · R1 ~ R3 를 다 적는다. 수는 게이트웨이 품질 카드가 잰다.
