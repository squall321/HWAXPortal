# PLM 검색 에이전트에 — MCP 계약 · stateless · 로드맵(요청)

> 받는 분 — PLM 검색 에이전트 개발 · 운영 담당(게이트웨이 백엔드 `plm-search-agent`). 보내는 쪽 — HWAX 포털(MCP 게이트웨이를 맡은 쪽). 건네는 사람 — 사용자.
> 함께 건넬 것 — 공통 계약 [../contract.md](../contract.md). 고친 날 2026-11-27(처음). 숫자는 운영 박스 기록에서 옮겼고 날짜를 붙였다.
> 개인정보 가림 범위(PL-03 · PL-10)는 사용자 결정이 먼저라 이 글에 싣지 않았다(11-24 요청 모음 4절).

## 0. 무엇 · 왜

HWAX 포털의 MCP 게이트웨이에는 운영 박스 기준 백엔드 35 · 도구 1,984개가 모이고(11-26), 그 가운데 약 1,200개가 사내 앱 도구다. 웹 챗 · 심의 좌석 · 개인 Claude 는
도구를 이름 · 설명 · 인자 스키마만 보고 고르고 부른다. 그 셋이 산문 · 빈칸이면 2,000개 속에서 잘못 고르고, 인자를 지어내고, 읽기 도구를 쓰기로 막는다.

PLM 검색 에이전트는 유사 사례를 찾는 검색이라, 결과가 얼마나 믿을 만한지를 결과 칸으로 말해 주지 않으면 모델이 엉뚱한 결과를 그대로 근거로 쓴다(PL-02). 필터 값이
닫힌 어휘인데 스키마에 없어 늘 0건이 나는 것(PL-01)도 계약으로 막을 수 있다.

## 2. 공통 계약 — 이 앱에 특히 해당하는 것과 차례

| 차례 | 항목 | 이 앱에서 | 카드 칸 |
|---|---|---|---|

## 3. 프로토콜 — stateless · 두 세대

- **1단계(먼저)** — 서버가 세션을 쥐지 않는다(P1). Python SDK 1.x(FastMCP)면 생성자에 `stateless_http=True` 한 줄, TypeScript SDK 면 streamable HTTP 전송의 세션 id
  생성기를 비운다. 서버 발 알림 · sampling · elicitation 을 쓰고 있으면 알려 주세요(1단계에서 버려진다).
- **2단계** — Python SDK 2.x(`mcp>=2.3`, Python 3.11 이상)로 2026-07-28 새 세대와 옛 세대를 같은 자리에서(P2). 2.x 는 인자 설명을 `Field(description=)` 에서만 읽는다.
  모델이 읽어야 할 오류는 `ToolError` 로(P3).
- 게이트웨이는 옛 세대 앱도 계속 부른다 — 2단계를 서두르지 않아도 끊기는 것은 없다.

## 4. 로드맵 — R1 · R2 · R3

- **R1 이벤트** — 색인을 다시 지었을 때를 「바뀐 것 목록」 읽기 도구로(커서 · 시각 · 종류). 바뀜이 드물면 「안 함(까닭)」 으로 답해도 된다.
- **R2 길 안내** — 대표 업무 둘 ~ 다섯(예 — 증상 문장으로 유사 사례 → 묶음 대표 건 → 사례 읽기)을 「목적 · 차례 · 입구 도구 · 확인할 쓰기」 로.
- **R3 앱 입구** — 처음 부를 때 먼저 부를 도구 하나.

## 5. 이미 보낸 것과 잇기

11-24 요청 모음 3-9 — PL-01 · PL-02 · PL-04 ~ PL-08. 4절 PL-03 · PL-10(개인정보 가림)은 사용자 결정 뒤. 여기 다시 쓰지 않았다.

## 6. 답하는 꼴

항목마다 한 줄 — `C3 | 할 차례 | <판>에서 | (비고)`. 상태는 「됨 · 할 차례 · 안 함(까닭)」. P1 ~ P3 · C1 ~ C9 · R1 ~ R3 를 다 적는다. 수는 게이트웨이 품질 카드가 잰다 —
판(커밋 · 판 번호)만 알려 주면 된다.
