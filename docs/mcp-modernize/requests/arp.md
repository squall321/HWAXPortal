# ARP(AI Ready Portal)에 — MCP 계약 · stateless · 로드맵(요청)

> 받는 분 — ARP 개발 · 운영 담당. 보내는 쪽 — HWAX 포털(MCP 게이트웨이를 맡은 쪽). 건네는 사람 — 사용자.
> 함께 건넬 것 — 공통 계약 [../contract.md](../contract.md). 고친 날 2026-11-27(처음). 숫자는 운영 박스 기록에서 옮겼고 날짜를 붙였다.

## 0. 무엇 · 왜

HWAX 포털의 MCP 게이트웨이에는 운영 박스 기준 백엔드 35 · 도구 1,984개가 모이고(11-26), 그 가운데 약 1,200개가 사내 앱 도구다. 웹 챗 · 심의 좌석 · 개인 Claude 는
도구를 이름 · 설명 · 인자 스키마만 보고 고르고 부른다. 그 셋이 산문 · 빈칸이면 2,000개 속에서 잘못 고르고, 인자를 지어내고, 읽기 도구를 쓰기로 막는다.

ARP 는 해석 실측(낙하 등) 근거를 내는 앱이라 숫자 칸 하나의 단위가 결론을 바꾼다 — 낙하 높이에 단위가 없어 모델이 cm 를 mm 로 읽은 일이 있었다(AR-9). 이 글은 공통 계약
가운데 그런 정밀도 문제를 스키마로 옮기는 몫을 적는다.

## 3. 프로토콜 — stateless · 두 세대

- **1단계(먼저)** — 서버가 세션을 쥐지 않는다(P1). Python SDK 1.x(FastMCP)면 생성자에 `stateless_http=True` 한 줄, TypeScript SDK 면 streamable HTTP 전송의 세션 id
  생성기를 비운다. 올리기처럼 여러 호출에 걸친 상태는 서버가 낸 id(handle)를 도구 인자로 받는다. 서버 발 알림 · sampling · elicitation 을 쓰고 있으면 알려 주세요.
- **2단계** — Python SDK 2.x(`mcp>=2.3`, Python 3.11 이상)로 2026-07-28 새 세대와 옛 세대를 같은 자리에서(P2). 2.x 는 인자 설명을 `Field(description=)` 에서만 읽는다.
  모델이 읽어야 할 오류는 `ToolError` 로(P3).
- 게이트웨이는 옛 세대 앱도 계속 부른다 — 2단계를 서두르지 않아도 끊기는 것은 없다.

## 4. 로드맵 — R1 · R2 · R3

- **R1 이벤트** — 새 해석 결과 등록 · 올리기 끝을 「바뀐 것 목록」 읽기 도구(커서 · 시각 · 종류 · id)로 내 주세요. 이름은 `<앱>.<대상>.<일>` 꼴(예
  `arp.analysis.created` — 이름은 앱이 정한다).
- **R2 길 안내** — 가장 필요한 앱의 하나다. 대표 업무 둘 ~ 다섯(예 — 모델 찾기 → 해석 목록 → 결과 읽기 → 결함 쪽 다음 호출)을 「목적 · 차례 · 입구 도구 · 확인할 쓰기」 로
  보내 주세요. HWAX 운영자 정의의 빈 대표 도구 칸을 채운다(ARO-3 의 「다음 호출 안내」 와 같은 뜻).
- **R3 앱 입구** — 처음 부를 때 먼저 부를 도구 하나를 정해 알려 주세요.

## 6. 답하는 꼴

항목마다 한 줄 — `C7 | 할 차례 | <판>에서 | (비고)`. 상태는 「됨 · 할 차례 · 안 함(까닭)」. P1 ~ P3 · C1 ~ C9 · R1 ~ R3 를 다 적는다. 수는 게이트웨이 품질 카드가 잰다 —
판(커밋 · 판 번호)만 알려 주면 된다.
