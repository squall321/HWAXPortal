> 받는 분 — SimFlow 개발 · 운영 담당. 보내는 쪽 — HWAX 포털(MCP 게이트웨이를 맡은 쪽). 건네는 사람 — 사용자.
> 함께 건넬 것 — 공통 계약 [../contract.md](../contract.md). 고친 날 2026-11-27(처음). 숫자는 운영 박스 기록에서 옮겼고 날짜를 붙였다.

## 0. 무엇 · 왜

HWAX 포털의 MCP 게이트웨이에는 운영 박스 기준 백엔드 35 · 도구 1,984개가 모이고(11-26), 그 가운데 약 1,200개가 사내 앱 도구다. 웹 챗 · 심의 좌석 · 개인 Claude 는
도구를 이름 · 설명 · 인자 스키마만 보고 고르고 부른다. 그 셋이 산문 · 빈칸이면 2,000개 속에서 잘못 고르고, 인자를 지어내고, 읽기 도구를 쓰기로 막는다.

SimFlow 는 해석 워크플로를 돌리는 앱이고 화면 패널(MCP Apps) 여섯을 낸다. 오래 도는 일이 있어 잡 끝 알림(이벤트)의 첫 대상이고, 패널 도구의 설명 문구가 모델의 호출
차례를 직접 바꾼다(PA-04 — 「묻지 않아도 먼저 호출」).

## 3. 프로토콜 — stateless · 두 세대

- **1단계(먼저)** — 서버가 세션을 쥐지 않는다(P1). Python SDK 1.x(FastMCP)면 생성자에 `stateless_http=True` 한 줄, TypeScript SDK 면 streamable HTTP 전송의 세션 id
  생성기를 비운다. 잡 · 올리기처럼 여러 호출에 걸친 상태는 서버가 낸 id(handle)를 도구 인자로 받는다. 잡 진행을 대기 스트림의 서버 발 알림으로 보내고 있다면 1단계에서
  버려진다 — 그 경우 알려 주세요(상태 읽기 도구 · 아래 R1 로 옮긴다).
- **2단계** — Python SDK 2.x(`mcp>=2.3`, Python 3.11 이상)로 2026-07-28 새 세대와 옛 세대를 같은 자리에서(P2). 2.x 는 인자 설명을 `Field(description=)` 에서만 읽는다.
  모델이 읽어야 할 오류는 `ToolError` 로(P3). 오래 도는 일을 위한 Tasks 확장은 SDK 구현을 지켜보는 중이다 — 지금은 상태 읽기 도구로 충분하다.
- 게이트웨이는 옛 세대 앱도 계속 부른다 — 2단계를 서두르지 않아도 끊기는 것은 없다.

## 4. 로드맵 — R1 · R2 · R3

- **R1 이벤트(가장 값진 앱의 하나)** — 워크플로 잡 끝 · 실패를 「바뀐 것 목록」 읽기 도구(커서 · 시각 · 종류 · id)로 내 주세요. 이름은 `<앱>.<대상>.<일>` 꼴(예
  `simflow.job.finished` — 이름은 앱이 정한다). 게이트웨이가 커서로 묻고 `io.modelcontextprotocol/events` 로 다시 낸다 — 사람이 잡을 다시 묻지 않아도 끝이 온다.
- **R2 길 안내** — 대표 업무 둘 ~ 다섯(예 — 워크플로 고르기 → 입력 올리기 → 제출 → 상태 → 결과)을 「목적 · 차례 · 입구 도구 · 확인할 쓰기」 로. 패널을 먼저 여는
  차례도 여기에 적는다.
- **R3 앱 입구** — 처음 부를 때 먼저 부를 도구 하나를 정해 알려 주세요.

## 6. 답하는 꼴

항목마다 한 줄 — `C6 | 할 차례 | <판>에서 | (비고)`. 상태는 「됨 · 할 차례 · 안 함(까닭)」. P1 ~ P3 · C1 ~ C9 · R1 ~ R3 를 다 적는다. 수는 게이트웨이 품질 카드가 잰다 —
판(커밋 · 판 번호)만 알려 주면 된다.
