# StandardPlatform 과 데이터허브 다섯에 — MCP 계약 · stateless · 로드맵(요청)

> 받는 분 — ① StandardPlatform(틀) 개발 · 운영 담당(Datahub 플랫폼) ② 허브 관리자 넷(불량 추적 FailureTrace · CAE그룹 · 실장 MountSol · NC 개발 NCDev).
> 보내는 쪽 — HWAX 포털(MCP 게이트웨이를 맡은 쪽). 건네는 사람 — 사용자. 함께 건넬 것 — 공통 계약 [../contract.md](../contract.md).
> 고친 날 2026-11-27(처음). 숫자는 운영 박스 기록에서 옮겼고 날짜를 붙였다.

## 0. 무엇 · 왜

HWAX 포털의 MCP 게이트웨이에는 운영 박스 기준 백엔드 35 · 도구 1,984개가 모이고(11-26), 그 가운데 약 1,200개가 사내 앱 도구다. 웹 챗 · 심의 좌석 · 개인 Claude 는
도구를 이름 · 설명 · 인자 스키마만 보고 고르고 부른다. 그 셋이 산문 · 빈칸이면 2,000개 속에서 잘못 고르고, 인자를 지어내고, 읽기 도구를 쓰기로 막는다.
게이트웨이 쪽은 검색 보정 · 읽기 목록 · 가림으로 받쳐 왔지만, 그 보정은 앱 쪽의 빈 곳을 가리고 판이 바뀔 때마다 다시 고쳐야 한다.

같은 틀로 띄운 데이터허브 다섯은 도구 약 580개로 **게이트웨이 백엔드 도구의 약 30%** 다 — 가장 큰 덩어리다. 그래서 틀(StandardPlatform)에서 한 번 고치면 다섯
설치가 함께 맞는다. 이 글은 공통 계약(프로토콜 셋 · 도구 계약 아홉 · 로드맵 셋) 가운데 이 틀과 허브에 특히 해당하는 것과 고칠 차례를 적는다.

## 4. 프로토콜 — stateless · 두 세대

- **1단계(먼저)** — 서버가 세션을 쥐지 않는다(P1). SDK 1.x 그대로 `FastMCP(..., stateless_http=True)` 한 줄이다. 재기동 · 여러 대로 늘리기에 붙어 있던 쪽이 끊기지
  않는다. 서버 발 알림 · sampling · elicitation 을 대기 스트림으로 보내던 것은 버려진다 — 쓰고 있으면 알려 주세요.
- **함께 볼 것(dev 사본 0.4.105 기준)** — `_install_identity` 는 접속마다 안내문을 사람 눈으로 다시 만든다. SDK 1.x 의 stateless 는 **요청마다**
  `create_initialization_options` 를 부르므로 이 갈고리가 요청마다 돈다. 자기소개는 토큰별 캐시(`PROFILE_TTL`)가 받치지만 식으면 요청마다 다시 읽고, 전역
  `instructions` 를 바꾸는 꼴이라 동시 요청에서 다른 토큰의 안내문이 섞일 틈이 넓어진다. 1단계 때 함께 봐 주세요. 요청마다 토큰을 잡는 `_RememberToken` 은
  stateless 와 맞는다.
- **2단계** — SDK 2.x(`mcp>=2.3`, Python 3.11 이상)로 옮기면 2026-07-28 새 세대(세션 · initialize 없음)와 옛 세대를 같은 자리에서 낸다(P2). 새 세대에는 initialize 가
  없으므로 위 안내문 갈고리는 2.x 이행 안내에 맞춰 옮겨야 한다. C2(Field 설명)와 함께 옮기면 한 번에 끝난다.
- 게이트웨이는 옛 세대 앱도 계속 부른다 — 2단계를 서두르지 않아도 끊기는 것은 없다.

## 5. 로드맵 — R1 · R2 · R3

- **R1 이벤트** — 코어 거울 받기(배치 작업) 끝 · 객체 바뀜 · 정의 제안 적용처럼 새 데이터가 생기는 때를 「바뀐 것 목록」 읽기 도구 하나(커서 · 시각 · 종류 · id)로
  내 주세요. 게이트웨이가 커서로 묻고 `io.modelcontextprotocol/events` 로 다시 낸다. 이름은 `<앱>.<대상>.<일>` 꼴(예 — 받기 끝이면 `<slug>.ingest.finished`, 이름은 틀이
  정한다). 틀에서 내면 다섯 설치가 함께 낸다.
- **R2 길 안내** — 대표 업무 둘 ~ 다섯을 「목적 · 차례 · 입구 도구 · 확인할 쓰기」 로 보내 주세요. 씨앗은 HWAX 쪽 정본 허브 운영자 정의의 차례다 — 이름 · 코드는
  `object_resolve` 로 먼저 풀고 후보가 여럿이면 묻는다 → 개수는 `objects_list` 의 total 이나 `objects_summary` 로 → 이어짐은 `graph_neighbors` → 다른 허브로 건널 때는
  앞 허브의 id 를 쓰지 않고 key 로 다시 resolve. 맞는지 · 빠진 업무가 있는지 알려 주세요.
- **R3 앱 입구** — 처음 부를 때 먼저 부를 도구 하나. HWAX 는 지금 `object_resolve` 를 입구로 쓴다. 자기소개(`whoami` 류)를 입구로 하려면 가벼워야 한다(DP-07).

## 7. 답하는 꼴

항목마다 한 줄 — `C6 | 할 차례 | 0.4.1xx 판에서 | (비고)`. 상태는 「됨 · 할 차례 · 안 함(까닭)」 셋 가운데 하나다. P1 ~ P3 · C1 ~ C9 · R1 ~ R3 를 다 적고, 허브 관리자
몫(3절)은 설치마다 따로 적는다. 도구 수 · 인자 설명 비율 · 표지 비율은 게이트웨이 품질 카드가 잰다 — 판(SP 판 번호 · 커밋)만 알려 주면 된다.
