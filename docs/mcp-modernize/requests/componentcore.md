# ComponentCore 에 — MCP 계약 · stateless · 로드맵(요청)

> 받는 분 — ComponentCore 개발 · 운영 담당. 보내는 쪽 — HWAX 포털(MCP 게이트웨이를 맡은 쪽). 건네는 사람 — 사용자.
> 함께 건넬 것 — 공통 계약 [../contract.md](../contract.md). 고친 날 2026-11-27(처음). 숫자는 운영 박스 기록에서 옮겼고 날짜를 붙였다.

## 0. 무엇 · 왜

HWAX 포털의 MCP 게이트웨이에는 운영 박스 기준 백엔드 35 · 도구 1,984개가 모이고(11-26), 그 가운데 약 1,200개가 사내 앱 도구다. 웹 챗 · 심의 좌석 · 개인 Claude 는
도구를 이름 · 설명 · 인자 스키마만 보고 고르고 부른다. 그 셋이 산문 · 빈칸이면 2,000개 속에서 잘못 고르고, 인자를 지어내고, 읽기 도구를 쓰기로 막는다.

ComponentCore 는 도구 183개로 **사내 단일 앱 가운데 가장 크고, 게이트웨이 백엔드 도구의 약 9.4%** 다. 183개 안에서도 모델은 같은 낱말(조회 · 검색 · 목록)을 단 도구
여럿 가운데 하나를 골라야 하므로, 설명의 「언제 쓰나 · 언제 형제 도구를 쓰나」 와 인자 설명이 정밀도를 가른다.

## 2. 공통 계약 — 이 앱에 특히 해당하는 것과 차례

| 차례 | 항목 | 이 앱에서 | 카드 칸 |
|---|---|---|---|
| 1 | C6 표지 | 183개 전부에 `readOnlyHint`. 표지가 없으면 게이트웨이는 확인된 읽기 목록에 없는 도구를 자동 실행(분석 루틴 단계 · 심의 좌석)에서 막는다 — 지금 이 앱의 읽기 도구 대부분이 그 경우일 수 있다. 바꾸는 도구는 `readOnlyHint=False`, 지우기 · 덮어쓰기는 `destructiveHint=True` | `ro_annotated_ratio` 1.0 |
| 2 | C1 설명의 꼴 | 첫 줄에 무엇 한 문장 → 언제 쓰나 · 언제 형제 도구를 쓰나(형제 이름으로) → 돌려주는 꼴 · 한도 · 쪽. 400 ~ 1,500자. 183개라 형제 안내가 가장 값지다 | `desc_lt100` · `desc_gt1000` · `desc_shared_other_app` |
| 3 | C2 인자 설명 | 모든 인자에 설명 · 단위 · 범위 · 기본값의 뜻 — 스키마에(`Annotated[…, Field(description=…)]`) | `arg_described_ratio` |
| 4 | C3 · C4 | 부품 분류 · 상태처럼 닫힌 낱말은 enum, `limit` · `page` 에 최소 · 최대 | `enum_args` · `numeric_bounded_ratio` |
| 5 | C7 · C8 | 구조 있는 결과는 반환 타입을 모델로(실제 필드가 있는 `outputSchema`). 잘랐으면 `truncated` · `total` · 다음 쪽 손잡이 | `output_schema_real` · `audit.over_50k` |
| — | C9 이름 | 앱 사이 흔한 이름(`search` · `list_jobs`)에 앱 접두를 스스로 달지 않는다 — 겹치면 게이트웨이가 붙인다 | `prefixed` |

## 3. 프로토콜 — stateless · 두 세대

- **1단계(먼저)** — 서버가 세션을 쥐지 않는다(P1). Python SDK 1.x(FastMCP)면 생성자에 `stateless_http=True` 한 줄, TypeScript SDK 면 streamable HTTP 전송의 세션 id
  생성기를 비운다. 세션에 기대던 상태가 있으면 서버가 낸 handle 을 도구 인자로 받는다. 서버 발 알림 · sampling · elicitation 을 쓰고 있으면 알려 주세요(1단계에서 버려진다).
- **2단계** — Python SDK 2.x(`mcp>=2.3`, Python 3.11 이상)로 옮기면 2026-07-28 새 세대(세션 · initialize 없음)와 옛 세대를 같은 자리에서 낸다(P2). 2.x 는 인자 설명을
  `Field(description=)` 에서만 읽으므로 C2 와 함께 옮기면 한 번에 끝난다. 모델이 읽어야 할 오류는 `ToolError` 로(P3 — 일반 예외는 가려진다).
- 게이트웨이는 옛 세대 앱도 계속 부른다 — 2단계를 서두르지 않아도 끊기는 것은 없다.

## 4. 로드맵 — R1 · R2 · R3

- **R1 이벤트** — 데이터 소스 받기가 끝날 때(CCO-2 의 「마지막 결과」) 같은 새 데이터의 때를 「바뀐 것 목록」 읽기 도구(커서 · 시각 · 종류 · id)로 내 주세요. 이름은
  `<앱>.<대상>.<일>` 꼴(예 `componentcore.datasource.finished` — 이름은 앱이 정한다). 게이트웨이가 묻고 다시 낸다.
- **R2 길 안내** — 183개 가운데 대표 업무 둘 ~ 다섯을 「목적 · 차례 · 입구 도구 · 확인할 쓰기」 로 보내 주세요. HWAX 쪽에는 이 앱의 차례 씨앗이 없다 — 가장 값진 답이다.
- **R3 앱 입구** — 처음 부를 때 먼저 부를 도구 하나(`get_guide` · `next_step` 류)를 정해 알려 주세요.

## 5. 이미 보낸 것과 잇기

## 6. 답하는 꼴

항목마다 한 줄 — `C6 | 할 차례 | <판>에서 | (비고)`. 상태는 「됨 · 할 차례 · 안 함(까닭)」. P1 ~ P3 · C1 ~ C9 · R1 ~ R3 를 다 적는다. 수는 게이트웨이 품질 카드가 잰다 —
판(커밋 · 판 번호)만 알려 주면 된다.
