# 결정 기록 — 챗 안의 Report Archive

> 계획은 [PLAN.md](PLAN.md), 체크리스트는 [checklist.md](checklist.md). 덧붙이기만 한다.

## 2026-11-26 — 시작

**RC-1 링크 접두는 화면에서 고친다.**
- 에이전트 서버에서 도구 결과를 바꾸면 새 답만 고쳐지고, LLM 이 보는 글도 달라진다.
- RA 는 고칠 수 없다(커밋 금지).
- 화면은 이미 `raLink.ts` 에 같은 바꿈을 들고 있다. 포털 화면에는 `/w/` 로 시작하는 경로가 없어서(App.tsx 라우트) 겹치지 않는다.

**RC-2 소속의 정본은 RA 의 홈 부서다.**
- 사용자가 말한 것이 「나의 report archive 조직」이다.
- 포털의 SSO 부서 이름은 쓰지 않는다. RA 도 이 값을 힌트로만 쓴다(「문자열로 맞추면 권한이 틀린다」 — MeRead `sso_dept_name` 주석).
- `memberships[0]` 은 옛 부서일 수 있어 쓰지 않는다(RA 주석 그대로).

**RC-3 위계는 `parent_slug` 사슬이다.**
- RA `/api/workspaces` 를 그 사람 명의로 읽어 홈 부서에서 위로 올라간다.
- 개인 공간은 빼고, 순환이 있거나 노드가 빠지면 거기서 멈추고, 최대 8단까지만 올라간다.
- 화면 표기는 끝의 두 단(그룹 › 파트)만 보이고, 전체 사슬은 마우스를 올리면 보인다.

**RC-4 조회 축은 게시판, 기간은 최근 2주다.**
- RA `list_boards` 설명이 「조직 단위로 찾으려면 게시판」이라고 적는다. 작성자 소속(`author_org`)과는 다른 축이다.
- 제시어에 게시판 slug 를 함께 적어 LLM 이 `board` 칸을 짐작하지 않게 한다.
- 2주는 기본값이다. 사용자가 바꾸라고 하면 바꾼다.

**RC-5 못 받으면 조용히 빠진다.**
- RA 연결 없음 · 홈 부서 없음 · RA 실패는 모두 `{home: null, reason}` 이고 200 이다.
- 첫 화면을 막거나 오류를 띄우지 않는다. 까닭은 서버 로그와 `reason` 에 남긴다.

**RC-6 한 탭에 한 번만 묻는다.**
- 첫 화면은 `/` 로 올 때마다 다시 그려진다.
- 그때마다 RA 를 두 번 부르지 않도록 `fetchInteractionStatus` 와 같은 꼴로 약속을 나눠 쓴다.
