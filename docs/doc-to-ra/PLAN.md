## 1. 지금 — 무엇이 있고 무엇이 비었나

출처(파일 · 줄)는 research.md 에 있다. 여기는 요점만 적는다.

### 1-1. RA 의 목표 형식

| 항목 | 꼴 |
|---|---|
| 보고서 | `title` · `report_date` · `tags` · `pages[]` · `report_type_id` · `entity_ids` · 쪽 설정(`page_width_px` · 슬라이드 비율 안내선 등). 첫 쪽의 `template_id` · `template_version` 과 같아야 한다 |
| 쪽(ReportPage) | `template_id` · `template_version` · `name` · `extra_blocks:[{id, type, props, layout}]` · `content:{블록 id: 내용}` · `blocks_order`(정본) · `block_sections` |
| 배치 | **12칸 격자 + 행** — `{row, col_span 1–12, row_span(8px 단위), col_offset, auto_fit}`, 한 행의 col_span 합 ≤ 12. 겹침 · 절대 좌표 · 담는 그릇 위젯이 없다 |
| 위젯 | 40종 — heading(1~3) · rich_text(줄마다 TipTap HTML 의 일부 태그 + 같은 글, 깊이 0~5) · bulleted_list · key_value · table(열 형식 · 병합 · 칸 스타일 · 머리 행) · chart(**막대 · 꺾은선만**) · pie · scatter · heatmap · tree · network · image · attachment · video · doc_viewer · equation(LaTeX) · card 등 |
| 리소스 | `POST /api/files` → `file_id`(UUID). 블록은 `file_id` 로만 가리킨다. 기본 25MB(CAD 200MB · 동영상 1GB). 아무 블록도 안 가리키는 파일은 유예 뒤 지운다 |
| 검증 | 저장할 때 위젯마다 내용 스키마(jsonschema)로. 정적 스키마 파일은 없고 `GET /api/widgets`(props 스키마 · `schema_version`)와 실행 중 OpenAPI 뿐이다 |

### 1-2. RA 로 넣는 길 셋

### 1-3. 지금 변환기 셋과 버리는 것

| | RA `/api/imports/pptx` | AIDH `convert_file` | PC 도우미(DRM 문서) |
|---|---|---|---|
| 형식 | PPTX 만(python-pptx) | DOCX · XLSX · PPTX · PDF | PPT · Word · PDF(Excel 없음) |

| 표 | 첫 행이 머리 · 열은 전부 글 · 병합은 복제 | 머리 · 행 | 마크다운 표 |

| 그림 | 그대로 올린다(**EMF 도** — 브라우저가 못 연다) | **자리만**(내용 0 · 뽑은 그림은 임시 폴더에 남는다) | 슬라이드 PNG(≤12장, 너비 1280px) |
| 발표자 노트 | **말없이 버린다** | 표시 줄 뒤에 글 | `> 발표자 노트:` 줄 |

| Word · Excel | 없다 | Excel 은 값만(수식 · 차트 · 그림을 버린다) | — |

그래서 오늘의 'Report Archive 로 보내기' 는 가져오기가 위치를 버리고, ai-draft 가 남은 배치마저 다시 깐다. 그림은 아무도 읽지 않는다 —
RA 안에는 그림을 모델에 보내는 곳이 없다.

### 1-4. VLM — 이미 쓰는 것

에이전트 서버 `vision.py` 는 챗 LLM(stcx Qwen3.8-Flash-Next — 그림 탐침을 통과하면)을 먼저 쓰고, 아니면 GLM(`VLLM_*`)을 쓴다. 공학 그림 판독 지시가
있다 — 그림 종류 · 축 · 단위 · 범례 · 읽히는 수치 전부(최대 · 최소 · 위치) · 글은 그대로 · 못 읽으면 「판독 불가」 · 지어내지 않는다. 판독은
sha256 으로 캐시하고, 그림은 8MiB · 12장까지, 생각은 끄고 부른다.

### 1-5. 사내 온톨로지 — 둘이다

| | StandardPlatform(SP) | RA 자체 엔티티 |
|---|---|---|
| 무엇 | 사내 공통 틀의 온톨로지 메타모델 — `plm_project` · `plm_task`(key = 과제코드 · 과제명 · 시험 종류 등) · `plm_model`(key = 모델명 · 개정 등) · 부서 · 담당 관계 | 보고서에 다는 축 7(모델명 · 부품명 · BOM Code · 개발 단계 · 불량 종류 · 신뢰성 시험 · 시뮬레이션 종류) · 별칭 · 관계 · 외부 연결(`object_links`) · **자동 태깅 제안 큐**(확실한 것은 바로 붙이고, 애매한 것은 사람이 수락 · 기각) |
| 정본 | SP 허브(Core API · `core:read` 토큰 · 증분 수신) | RA DB |
| 지금 | StepForge 가 수신 키트를 옮겨 두었다(`core/sp_core.py` · 자체 정의 `stepforge-core.json`). **cae00 허브에는 아직 안 붙었다**(주소 · 토큰 — 사람 몫) | 쓰는 중 |

## 2. 목표 — 무엇이 '잘' 인가

1. **원문을 잃지 않는다** — 원본의 글 · 숫자 · 표 칸이 결과에 그대로 있다. 없으면 '버린 것' 목록에 까닭과 함께 있다(무음 누락 0).
2. **구조를 살린다** — 제목 · 목록 깊이 · 표(병합 · 머리 행 · 숫자 열) · 차트(값까지) · 노트 · 링크 · 슬라이드 배치를 RA 위젯과 격자로 옮긴다.
3. **그림을 읽는다** — 그림 · 그림으로 박힌 차트 · 그림 속 글을 VLM 이 읽어 판독문으로 붙인다. 원문과 갈라 '모델 판독' 이라고 표시한다.
4. **사내 온톨로지에 잇는다** — 과제 · 모델 · 프로젝트 · 부서를 찾아 근거 구절과 함께 후보로 내고, 사람이 확정한다.
5. **RA 에서 바로 고칠 수 있다** — 결과는 RA 편집기에서 손볼 수 있는 보통 보고서다. 슬라이드를 그림 한 장으로 뭉뚱그리지 않는다.
6. **되짚을 수 있다** — 블록마다 원본 위치(슬라이드 · 도형 · 칸 범위)와 만든 쪽(파서 · 모델 · 지시문의 판)을 남긴다.

숫자 기준은 §10 에 제안했다(사람이 정한다).

## 3. 원칙

- **원문 유지 + 모델 보강** — 모델은 원본 글을 고쳐 쓰지 않는다. 판독 · 요약 · 분류는 덧붙이고 표시한다(10-23 의 제안을 원칙으로 삼는다).
- **정해진 일은 코드, 판단만 모델** — 파싱 · 표 · 차트 값 · 배치는 코드가 원본 XML 에서 한다. 모델은 「이 글상자는 저 그림의 설명인가」 같은 애매한
  판단과 그림 읽기만 맡는다. 답은 고른 범위(주어진 id · 원문 구절) 안에서만 받고 Pydantic 모델로 묶는다.
- **버린 것은 말한다** — 변환 보고서(블록 수 · 버린 것과 까닭 · 모델이 쓴 것 목록)를 결과와 함께 낸다.
- **변환과 배달을 나눈다** — 변환기는 RA 패키지(JSON + 리소스)를 만들 뿐 RA 자격을 쥐지 않는다. RA 에 넣는 일은 사용자 명의를 이미 다루는 쪽(포털)이
  한다. 포털 '보내기' 의 원칙(포털은 배달만 한다)과 같다.
- **RA 는 API 로만** — RA 리포는 고치지 않는다(이 리포의 규칙). RA 쪽에 필요한 것은 요청서로 보낸다.
- **사내망 밖으로 나가지 않는다** — 문서 · 모델 · VLM 이 모두 사내(dev · cae00 · stcx)에서 돈다. 기록에는 문서 글을 남기지 않는다.

## 4. 구조 — 단계와 중간 표현

```
받기 → 해부 → 그리기 → 읽기(VLM) → 짜기(코드 · LLM) → 잇기(온톨로지) → 검증 → 포장 → 배달(포털 → RA) → 사람 검토
 S0     S1      S2         S3              S4                 S5             S6      S7          S8              S9
```

| 단계 | 하는 일 | 주로 쓰는 것 |
|---|---|---|
| S0 받기 | 원본(PPTX · DOCX · XLSX · PDF) 또는 PC 도우미 묶음(`hwax-doc/1` 글 + 슬라이드 PNG) · 지문(sha256) · 형식 판별(마법 바이트) | — |
| S1 해부 | 원본 → **중간 표현(IR)**. 쪽(슬라이드 · 절 · 시트)마다 요소(제목 · 글 · 목록 · 표 · 그림 · 차트 · SmartArt · 수식 · 노트 · 링크)와 원본 위치 · 기하(EMU 상자) · 서식 런 | Docling + 형식별 보강(python-pptx · openpyxl · python-docx 로 Docling 이 놓치는 것 — 차트 XML 값 · 노트 · SmartArt · 수식 · 병합 · 기하) |
| S2 그리기 | 슬라이드 · 쪽 그림(LibreOffice → PDF → PNG) · EMF/WMF → PNG · 차트 그림 | LibreOffice(헤드리스) · 한글 글꼴 |
| S3 읽기 | 그림 판독 · 그림으로 박힌 차트의 값 · 그림 속 글(한국어) · SmartArt 그림 | VLM(stcx Qwen 또는 GLM) · 판독 캐시 |
| S4 짜기 | IR → RA 블록. 위젯 고르기 · 서식 → 허용 태그 · 표 열 형식 · 차트 → chart/pie/scatter · 배치 → 12칸 격자(§6). 애매한 판단만 LLM | 코드 + Pydantic 계약 + LLM(구조화 출력) |
| S5 잇기 | 과제코드 · 모델명 · 과제명 · 부서를 찾아 후보 + 근거 구절 · RA 엔티티 후보 | SP 거울 · RA 엔티티 조회 · LLM(후보 중에서 고르기만) |
| S6 검증 | 글 회계(원본 글이 전부 어딘가에 있나) · 숫자 대조 · 그림 회계 · RA 스키마 · 격자 합 | 코드 |
| S7 포장 | **RA 패키지** — `report.json`(draft_v1 꼴 — 리소스 자리는 `res://` 자리표) + `resources/` + `conversion.json`(변환 보고서 · 블록별 출처) | — |
| S8 배달 | 리소스를 사용자 명의로 `/api/files` 에 올려 `file_id` 로 바꾸고 엄격 생성(`POST /api/reports`) — 배치를 지킨다 | 포털(사용자의 RA 연결) |

**중간 표현(IR)** — Docling 을 쓰면 `DoclingDocument`(글 · 표 · 그림 · 묶음 · 출처)에 **보강 층**(형식별 추가 정보 · 판독 · 온톨로지 후보 · 회계)을
얹는다. 요소마다 안정 id(`s3.e12`)와 원본 위치를 둔다. 글 회계와 「이 블록은 어디서 왔나」 가 여기서 나온다. 패키지는 RA 인스턴스와 무관하다 —
dev RA 에도 cae00 RA 에도 같은 패키지를 넣을 수 있고, 평가와 재현이 이 파일로 된다.

## 6. 배치 옮기기 — 슬라이드 좌표 → 12칸 격자

RA 에는 겹침도 절대 좌표도 없다. 다음 규칙은 결정적이라 시험할 수 있다.

1. 내용 도형만 쓴다(배경 · 장식선 · 쪽 번호는 뺀다). 묶음은 펼쳐 절대 좌표로 둔다.
2. 위에서부터 세로로 겹치는(높이의 절반 이상) 도형을 한 행으로 모은다.
3. 행 안에서는 왼쪽부터 — `col_offset` = 앞 도형 끝과의 틈 × 12, `col_span` = 너비 × 12(반올림 · 최소 1). 합이 12 를 넘으면 가장 넓은 것부터 줄인다.
4. `row_span` = 높이(쪽 너비 기준으로 환산한 px) ÷ 8.
5. 그림 위에 얹힌 글상자(설명 · 화살표 글)는 그 그림의 caption 으로 둔다(애매한 것만 LLM 이 고른다). 그 밖의 겹침은 다음 행으로 내리고 경고한다.
6. 쪽마다 원본 슬라이드 그림을 블록 하나로 둘지는 §12.

Word 는 흐름 그대로(행 하나에 블록 하나, 그림 · 표는 너비 비례)이고, Excel 은 시트마다 표가 중심이다.

## 7. 기술 선택 — M0 에서 재고 정한다

| 자리 | 첫 후보 | 대체재 | M0 에서 재는 것 |
|---|---|---|---|
| 해부 | **Docling 2.9x**(사내망만으로 돈다 · DOCX · PPTX · XLSX · PDF · 출처 정보) | 형식별 직접(python-pptx · python-docx · openpyxl — AIDH 와 RA 가 이미 쓴다) · MarkItDown(가볍지만 구조가 약하다) · Unstructured | 금 표본에서 글 회계 · 표 · 차트 · 노트 · 기하(PPTX 에서 상자가 나오나)가 얼마나 나오나 · 쪽당 시간(CPU/GPU) · SIF 크기 · 모델까지의 라이선스 |
| 그리기 | LibreOffice 헤드리스 + 한글 글꼴 | 원본이 PDF 면 pypdfium2 | 슬라이드 그림이 원본과 같나(글꼴 · 도형 · EMF) |
| 그림 읽기 | 이미 쓰는 VLM(stcx Qwen · GLM) — 판독 지시를 이어 쓰고 넓힌다 | Docling 의 그림 설명(OpenAI 호환 원격 VLM 을 부를 수 있는지 확인) | 판독 유용성 · 지어낸 수치 · 장당 시간 · 챗과의 부하 |
| 구조화 출력 | **Pydantic AI**(타입 있는 출력 · 검증 재시도 · OpenAI 호환 공급자 → 우리 vLLM) | vLLM `response_format: json_schema` 직접 · Instructor · LangChain `with_structured_output`(에이전트 서버가 쓰는 것) | 우리 GLM · Qwen 에서 `NativeOutput`(json_schema) · `ToolOutput` 이 스키마를 지키는 비율(목표 ≥ 99%) · 지연 · 비스트리밍 |
| 그림 속 글 | VLM(한국어) | Docling OCR(EasyOCR · RapidOCR) · Tesseract kor | 그림 속 한국어 글 |
| 온톨로지 | SP 수신 키트(StepForge `core/sp_core.py` 꼴) + RA 엔티티 API · MCP | StepForge 에 묻기(`find_plm_task`) | 허브가 붙기 전에는 가짜 허브로 |

Pydantic 모델은 **어느 도구를 쓰든 계약**이다 — RA 위젯 내용(우리가 내는 것) · IR · 판독 결과 · 온톨로지 후보. RA 스키마가 바뀌면 계약 시험이
먼저 깨지게 한다(§13).

## 8. 온톨로지 잇기

- **SP 거울** — 변환기가 작은 거울을 둔다(SP 수신 키트 · 수신 규칙 열하나 · `core:read` 토큰은 파일로만). StepForge 에 묻지 않는 까닭은 StepForge 가
  떠 있어야만 변환이 되는 것을 피하려서다(§12 에서 뒤집을 수 있다).
- **찾기** — ① 과제코드 · 모델명 꼴(SP 의 모델명 해석 규칙)을 글자 그대로 찾는다 ② 과제명 · 부서명은 유사도로 찾는다 ③ 애매한 것만 LLM 이 **후보 key 중에서**
  고르고 근거 구절을 원문에서 그대로 인용한다(구절이 원문에 있는지는 코드가 본다).
- **RA 에 넣는 자리** — 세 군데에 넣는다.
  - 첫 쪽 맨 위 `key_value`(「연결된 과제 · 모델」 — 보이고 고칠 수 있다)
  - `tags`(`과제:<코드>` 등)
  - RA 엔티티 — RA 어휘에 이미 있는 값은 `entity_ids` 로 단다. 없는 값은 RA 의 제안 큐에 맡긴다(확실한 것은 RA 가 바로 붙이고, 애매한 것은 사람이 수락한다).
  - SP key 를 RA 엔티티의 별칭 · 외부 연결로 다는 것은 RA 주인과 합의할 일이다(§12).
- **개정** — 문서 제목 · 꼬리말의 개정 표기(Rev · 차수)를 속성으로 남긴다. 말은 StepForge 의 `cad_revision` 과 맞춘다.

## 9. 어디에 두나 — 새 HEAX 앱 「DocForge」(가칭)

| 안 | 장점 | 단점 |
|---|---|---|
| **새 HEAX 앱(권장)** — StepForge 와 같은 꼴(FastAPI + MCP streamable-http + 잡 러너 + 원장 + SP 거울) | 무거운 의존성(Docling 모델 · LibreOffice · 글꼴)을 한 SIF 에 가둔다 · 게이트웨이 MCP 에 저절로 실린다 · 잡 진행률 | 새 리포 · 새 배포 |
| AIDH `convert_file` 확장 | 형식별 파서가 이미 있다 | 남의 리포 · 목적이 지식카드 · 임베더와 GPU 를 나눈다 |
| 포털 백엔드 안 | 배선이 짧다 | 포털이 무거워진다(모델 · LibreOffice) |
| RA 안 | 목표 형식 옆 | RA 리포는 고치지 않는다 |

배선은 셋이다.

- **포털 업로드** — 목적지 「Report Archive — 정밀 변환」(pptx · docx · xlsx · pdf). 포털이 DocForge 잡을 띄우고(서비스 토큰) 진행을 패널에 보인다.
  패키지를 받아 사용자 명의로 RA 에 넣고(S8), 대화에 알림을 남긴다(업로드 근거 — docs/chat-ppt PP-D3).
- **MCP(게이트웨이)** — `docforge_convert` · `docforge_status` · `docforge_package`(요약 · 경고 · 미리보기). MCP 에서 RA 에 넣는 길은 §12 에서 정한다
  (포털이 넣어 주는 도구 대 RA 의 패키지 가져오기).
- **'이 대화에서 분석'** — DocForge 의 IR(판독 포함)로 바꿀 수 있다(M4).

## 10. 평가

- **금 표본** — 사내 실문서 40건과 DRM 5건(PC 도우미)이다. 리포 밖(cae00 의 DocForge 개발 데이터 폴더 — M0 는 cae00 에서, DF-D9)에만 두고 리포에는 넣지 않는다.

## 13. 위험 · 한계

- **RA 계약이 자주 바뀐다** — v0.167 이고, 쪽 안의 칸은 마이그레이션 없이 늘었으며, 규칙 파일과 스키마가 두 곳에서 어긋난다. `GET /api/widgets` 의
  `schema_version` 을 보고, 우리가 내는 위젯만 Pydantic 으로 둔다. dev RA 에 계약 시험을 두고, 낯선 판이면 크게 알리고 멈춘다.
- **RA 는 손대지 않는다** — 필요한 것(패키지 가져오기 · 엔티티 합의 · 큰 원본 첨부 상한)은 요청서로 보낸다.
- **Docling 의 PPTX 는 XML 을 그대로 읽는 해부라 얕을 수 있다** — 형식별 보강으로 메운다. 어디까지 메울지는 M0 이 정한다.
- **폐쇄망** — Docling 모델 무게 · LibreOffice · 한글 글꼴을 SIF 에 굽는다. SIF 가 수 GB 라 Drive 올리기가 길다(30분 한도 · HEAXHub 지문 목록 함정).
- **GPU** — dev GPU 는 AIDH · dev vLLM 과 나눠 쓴다. cae00 GPU 는 모른다 → CPU 로도 돌 수 있게 한다(쪽당 시간은 M0 에서 잰다).
- **VLM 부하** — stcx Qwen 은 챗 모델이다. 큰 덱 하나가 그림 수백 장을 보낼 수 있다 → 동시 수 상한 · 챗 먼저 · 판독 캐시.
- **모델이 지어낸다** — 판독 수치는 표시하고, 표 · 차트에는 '확인 필요' 로만 넣는다. 구조화는 고른 범위 안에서만 받는다.
- **DRM** — 서버는 문서를 못 연다. PC 도우미는 슬라이드 12장까지이고 그림 · 차트 값이 없다 → 낮은 충실도로 표시한다(M4 에서 도우미를 넓힐 수 있다).
- **크기** — 포털 정문은 10GB 지만 RA 파일은 기본 25MB 다. 큰 원본 첨부 · 큰 그림은 줄이거나 경고한다.
- **한국어** — 글꼴 · 그림 속 글 · 섞인 글자.
- **보안** — 문서 글은 기록에 남기지 않는다. 임시 파일은 지운다(AIDH 는 뽑은 그림을 임시 폴더에 남긴다 — 따라 하지 않는다). 권한은 RA 와 같은 소속 규칙을 따른다.
