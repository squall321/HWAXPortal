# 챗·심의 그림 인식 — 결정과 까닭

**CV-D1 진단과 사용자 결정(2026-10-15).** 요청 — "image_url이 content배열에 들어가 있는지 봐줘 … 모델을 바꿨는데도." 진단 — 들어가 있지 않다(PLAN 1절의 세 자리). 그래서 모델을 바꿔도 소용이 없었다. 결정 — 범위는 챗 이미지 + 도구 그림, 차례는 M3 끝나고 바로.

**CV-D2 도구 그림의 URL 치환은 버리지 않고 그 위에 얹는다.** 지금의 치환(base64 → 파일 + 글자 URL)은 절단 상한·문맥 낭비를 막고 화면에 그림을 띄우려는 장치다(`app.py` 주석). 모델이 그림을 보게 하더라도 화면 렌더와 기록은 그 장치에 기대므로, 비전이 켜진 박스에서만 같은 그림을 다음 턴의 `image_url` 조각으로 **더** 싣는다.

**CV-D3 서버가 먼저다.** 탐침이 거절을 보이면 HWAX 를 고쳐도 그림은 읽히지 않는다. 그래서 cae00 탐침 결과를 시작 조건으로 둔다(LLM 서버 둘 계획에서 비전 모델을 어디에 둘지와 함께 본다).
