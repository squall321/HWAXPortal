# 챗·심의에서 그림을 모델이 보게 — 계획

> 사용자 요청(2026-10-15): "GLM연결에 대한 /v1/chat/completions에 지금 image_url이 content배열에 들어가 있는지 봐줘 이미지 인식이 안되는 상황이거든 모델을 바꿨는데도." 결정 — 범위는 **챗에 올린 이미지 + 도구가 만든 그림** 둘 다, 차례는 **리스크 심사 M3 를 올린 바로 뒤**.

## 1. 진단(10-15)

HWAX → GLM 의 `/v1/chat/completions` 에 `content` 배열의 `image_url` 이 **어디에도 없다**. 그래서 모델을 바꿔도 그림을 못 읽는다.

- 챗 첨부 입력이 이미지 확장자를 받지 않는다(`frontend/src/components/chat/Composer.tsx` 의 `accept`). 올린 파일은 LLM 메시지가 아니라 앱 '목적지' 로 간다.
- 에이전트 서버가 GLM 에 보내는 메시지는 문자열이다(`HWAXAgentServer/app.py` 의 `ChatOpenAI`). 다중모달 조각을 짓는 곳이 없다.
- 도구가 만든 그림(AIDataHub `captured.images` base64 · MCP `ImageContent`)은 파일로 저장되고 모델에는 '생성된 이미지 URL — 답변에 ![](url) 로 포함하세요' 라는 **글자 URL** 만 간다(`app.py` `_stash_artifacts` · 도구 결과 정규화). 화면 렌더용 장치이고 모델은 그림을 보지 않는다.
- 서버 쪽 확인 — `HWAXAgentServer/scripts/llm_vision_probe.py`(빨간 그림 한 장을 `[text, image_url(data URL)]` 로 직접 보낸다). dev 의 텍스트 모델은 `is not a multimodal model` 로 거절한다. **cae00 에서 돌려 GLM 이 그림을 받는지 먼저 본다** — 받지 않으면 HWAX 를 고쳐도 소용없고 서버(모델·vLLM 인자)부터다.

## 2. 무엇을 하나

1. **챗 이미지** — 챗 입력이 이미지(png · jpg · webp · gif)를 받고(붙여넣기 포함), 포털이 그것을 에이전트 서버 챗 요청에 실어 보낸다. 에이전트 서버는 그 턴의 사용자 메시지를 `[{"type":"text",…}, {"type":"image_url","image_url":{"url":"data:image/…;base64,…"}}]` 로 짓는다.
2. **도구 그림** — 도구가 낸 그림을 다음 모델 턴에 `image_url` 조각으로도 싣는다(화면용 URL 치환은 그대로). 한 턴의 그림 수·크기 상한을 둔다(넘친 것은 'N장 중 M장만 보였다' 를 모델과 화면에 알린다 — 조용히 버리지 않는다).
3. **켜고 끄기** — 서버가 그림을 받는지는 박스마다 다르다. 에이전트 서버 설정 `LLM_VISION`(기본: 기동 때 `/v1/models`·탐침으로 판정, 손으로 고정 가능) — 꺼져 있으면 지금처럼 글자 URL 만 보내고, 사용자가 그림을 올리면 '이 서버의 모델은 그림을 읽지 못한다' 를 알린다.
4. **크기** — data URL 은 토큰을 먹는다. 긴 변을 줄여(예: 1,568px) 보내고 원본은 아티팩트로 남긴다.
5. **심의** — 좌석·의장에게도 같은 규칙(근거에 그림이 있으면 실을지는 심의 옵션으로 — 기본 끔, 좌석 수만큼 그림이 곱해진다).

## 3. 열린 물음(시작할 때)

1. cae00 탐침 결과 — GLM 서버가 그림을 받는가(받지 않으면 비전 모델을 어느 서버에 둘지 — LLM 서버 둘 계획과 같이 본다).
2. 그림 크기·장수 상한의 기본값.
