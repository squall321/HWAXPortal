# 소속·허가 기반 접근 — 결정 기록

## D-1. 전달은 합성 그룹(feat:·plat:) — 게이트웨이·에이전트서버를 새 개념 없이 태운다
끝까지 흐르는 인가 수단이 groups 하나다(PLAN 조사). 권한을 새 필드로 만들면 포털→에이전트서버→
게이트웨이 세 층을 모두 새로 배선해야 하지만, 합성 그룹으로 얹으면 게이트웨이의 기존 allowed_groups
겹침 판정이 그대로 먹는다(tools/list·call 둘 다). 에이전트서버에만 entitlements 필드를 따로 준다 —
트리거 판정(심의·Thinking)은 그쪽이 쥐고 있고, '권한 정보를 안 보낸 옛 호출'과 '권한이 없는 사람'을
구분해야 해서다.

## D-2. 권한은 요청마다 저장소에서 계산한다 — JWT·PAT 에 박힌 그룹을 믿지 않는다
세션 JWT 8시간·PAT 최대 100년에 그룹이 박혀 있어, 권한을 거둬도 그만큼 남는다. 포털은 요청마다
사용자 행(소속·개별 허가)과 정책 파일로 다시 계산한다. 게이트웨이도 PAT 호출자의 권한을 포털에서
짧은 캐시로 받아 쓴다. 관리자 여부(portal-admin)는 종전대로 로그인 때 값이다(거두려면 재로그인).

## D-3. 함의 — 전문가 기능은 AI 데이터 허브 위에서 돈다
심의·Thinking·전문가 챗은 좌석 발굴·역할·지식카드를 AI 데이터 허브 도구(recommend_agents·
get_agent_session·agent_search)로 한다. 이 기능만 주고 허브를 안 주면 기능이 조용히 부서진다.
기능 정의에 implies 를 두고, 내 권한 페이지는 '전문가 심의에 포함'처럼 이유를 적는다.

## D-4. 게이트웨이 정책은 포털에서 받아 온다 — 정본은 access.yaml 하나
게이트웨이 리포에 정책 파일을 따로 두면(tool_areas.json 선례) 포털 표와 두 곳이 된다. 게이트웨이는
어차피 PAT 호출자의 현재 권한을 포털에 물어야 하므로(D-2), 백엔드별 필요 권한도 같은 통로
(/internal/*, GATEWAY_SHARED_TOKEN)로 받는다. 받은 값은 디스크에 캐시해 포털이 잠깐 죽어도 직전
정책으로 돈다. gateway_config.json 의 allowed_groups 는 provision 이 다시 쓰며 날아가서 쓰지 않는다.

## D-5. 포털 챗 가드는 명시 모드만 — delib_opts 는 일반 챗에도 늘 실린다
처음엔 delib_opts 가 있으면 심의 권한을 요구했다. 프론트는 일반 챗에도 delib_opts(search_sources 를
담아)를 늘 싣는다 — 기본 권한 사용자의 모든 챗이 403 이 됐다(프론트 배선 중 발견, ec73088).
심의 트리거는 에이전트서버가, 도구(웹 검색·지정 앱)는 게이트웨이가 권한으로 거르므로 포털은
Thinking·전문가 지정만 본다. 같은 판정을 세 곳에 두면 한 곳이 틀릴 때 알아채기 어렵다.

## D-6. 원장 읽기도 잠근다 — 요청마다 계산하자 드러난 동시성 결함
UserStore 는 sqlite 연결 하나를 스레드풀이 나눠 쓰며 쓰기만 잠갔다. 전에는 get() 이 로그인·/auth/me
에서만 돌아 드러나지 않았는데, 권한을 요청마다 계산하자 모든 요청이 동시에 get() 을 불러
'bad parameter or other API misuse'·열 개수 불일치로 500 이 났다(브라우저 E2E 중, 1c8184d).
쓰기 안에서 get() 을 부르므로 재진입 잠금(RLock).

## D-7. 전문가 풀 엔드포인트는 막지 않는다 — 도구 카탈로그가 같은 응답에 실린다
챗 시작 패널의 앱·도구 고르기가 /agent/deliberate/experts 응답의 tools 를 쓴다. 엔드포인트를 막으면
기본 권한 사용자가 도구 고르기까지 잃는다. 심의·전문가 대화 권한이 없으면 전문가 목록만 비운다.

## D-8. 그룹 헤더 없는 GW_TOKEN 호출은 내부 서비스 — 사람 권한 정책을 받지 않는다
에이전트서버는 사용자 호출에 늘 그룹 헤더를 싣는다(빈 값이라도). 헤더 자체가 없는 GW_TOKEN 호출은
사용자를 대리하지 않는 내부 서비스라, 표시 그룹(gateway:service)으로 포털 정책에서 뺀다 — 정책
이전과 같은 시야. GW_TOKEN 보유자는 원래 그룹 헤더를 마음대로 실을 수 있어 새 구멍이 아니다.
PAT 경로는 이 값을 싣지 못한다(검증된 PAT 그룹으로 갈아 끼울 때 뺀다).

## D-9. 배포 때 챙길 것 — 기존 사용자·서비스 PAT·mock SSO
- 권한 모델을 켜면 소속 없는 기존 사용자는 일반 챗만 쓴다. 사용자 관리의 '소속 없는 활성 사용자 →
  모두 이 소속으로'로 한 번에 옮긴다(관리자·비활성 계정은 대상에서 뺀다). 자동으로 CAEG 를 주지
  않은 이유 — 다른 그룹(자주검증·실장솔루션) 사람이 섞여 있을 수 있다.
- HWAXRisk 는 포털 PAT(HWAXRISK_PORTAL_PAT)로 게이트웨이를 부른다. 그 PAT 계정이 CAEG 이거나
  관리자여야 도구가 보인다(게이트웨이가 그 계정의 지금 권한을 쓴다).
- mock SSO 버튼은 누구나 portal-admin 으로 만든다 — 켜 둔 박스에서는 권한 모델이 의미가 없다.
