# 소속·허가 기반 접근 — 계획

## 사용자가 말한 것 (2026-09-11)

소속에 따라 쓸 수 있는 에이전트·웹이 달라야 한다. 지금 만드는 것은 모두 **CAEG** 것이라 CAEG 는
다 같이 쓴다. 그 밖은 **허가 기반**으로 에이전트 기능이나 특정 플랫폼을 쓴다. 전체 플랫폼 각각에
대해 **내가 쓸 수 있는지** 확인하는 화면. 권한이 없으면 **심의 같은 메뉴는 아예 안 보이게**.

## 조사로 확정된 사실 (2026-09-11, 네 리포)

- 끝까지 흐르는 인가 수단은 **groups 하나**다 — 포털 로그인 JWT → 에이전트서버 요청 본문 →
  게이트웨이 `X-HWAX-Groups` → 백엔드별 `allowed_groups`(겹치면 통과, 비었으면 공개).
  게이트웨이는 tools/list 와 tools/call 을 **둘 다** 거른다(gateway.py:1276·1332).
- dev 에서는 아무것도 막지 않는다 — 존재하는 그룹은 `portal-admin` 하나, 타일의 `required_role`
  0건, 게이트웨이 16개 백엔드 `allowed_groups` 전부 빈 값. **mock SSO 버튼은 누구나 portal-admin**.
- 소속(부서)은 자유 텍스트(users.department)이고 어떤 인가 판단에도 쓰이지 않는다. `CAEG` 그룹은 없다.
- 관리자 화면(/admin/users)은 승인 때 `[]` 또는 `['portal-admin']` 만 준다. 그룹·부서를 나중에 고칠
  API 가 없다(user_store.set_groups 는 부르는 곳이 없다). SSO 사용자는 저장된 그룹을 아예 안 쓴다.
- 그룹은 세션 JWT(8시간)·리프레시·PAT(최대 100년)에 **박혀** 있다 — 권한을 거둬도 다시 로그인
  하거나 PAT 가 끝날 때까지 남는다.
- 메뉴는 '사용자 관리'(portal-admin)와 '리스크 심사'(타일 유무)만 가려진다. 라우트는 로그인만 본다.
  심의 입구는 메뉴 말고도 여섯 곳이다 — 슬래시 명령(ChatDock 포함)·/deliberate 자동 접두·이어하기·
  넘기기(ExportBar)·Thinking 토글·MCP(deliberate_start).
- 백엔드에서 그룹을 보는 곳은 업로드뿐이다. 챗·심의·Thinking·전문가·VOC·카탈로그는 막지 않는다.
- 이름이 층마다 다르다 — 포털 타일 `report-archive` / 게이트웨이 `reportarchive` / HEAXHub `hwax_risk`.
- HEAXHub 는 자기 권한 모델(visibility private|team|department|company + 접근표)이 따로 있고 포털
  그룹을 받지 않는다. 게이트웨이는 HEAXHub 를 관리자로 폴링해 그쪽 가시성이 MCP 에 안 걸린다.
- 외부 URL 플랫폼(ARP·ODB·SPDM)은 포털이 타일을 숨길 수만 있고 막을 수는 없다.

## 제안 모델

**권한 키** — 두 종류.
- 플랫폼 `plat:<id>` — 정본 플랫폼 표 하나가 포털 타일 id ↔ 게이트웨이 백엔드 키 ↔ HEAXHub 앱 ↔
  HE팀 페르소나를 잇는다(지금 층마다 이름이 다르다).
- 기능 `feat:<id>` — 심의(deliberation)·Thinking·전문가 챗(HE팀 포함)·업로드·API 토큰(MCP 개인 연결)·
  웹 검색 등. 기능마다 **입구(화면·명령)**와 **강제 지점(백엔드)**을 표에 같이 적는다.

**허가 계산 — 서버에서, 요청마다.** 유효 권한 = 소속 기본 허가 ∪ 사용자별 추가 허가 ∪ (관리자면
전부). 소속 기본값은 정책 파일(`backend/config/access.yaml`, git 추적)에 — `CAEG: 전부`. 사용자별
추가 허가·소속은 사용자 저장소에. JWT 에 박힌 groups 를 믿지 않고 요청마다 저장소에서 계산한다
(권한을 거두면 바로 먹는다). PAT 도 같은 계산을 탄다.

**전달 — 합성 그룹.** 계산 결과를 `plat:*`·`feat:*` 그룹으로 만들어 기존 groups 에 얹는다. 에이전트
서버·게이트웨이는 코드 변경 없이 그대로 받는다 — 게이트웨이 백엔드의 `allowed_groups` 에
`plat:stepforge` 같은 값을 넣으면 tools/list·call 이 둘 다 걸린다. 게이트웨이 정책은 git 추적 파일로
(tool_areas.json 선례) — 지금 gateway_config.json 은 provision 이 다시 만들어 손으로 넣은 값이 날아간다.

**화면.**
- `/auth/me` 가 계산된 권한을 준다. 메뉴·라우트·입구(슬래시 명령·넘기기·Thinking 토글·타일)가 그걸로
  **숨는다** — 비활성으로 두지 않는다(사용자 요구).
- **내 권한** 페이지 — 모든 플랫폼·기능을 한 표로: 쓸 수 있음/없음, 왜(소속 기본·개별 허가·관리자),
  없으면 누구에게 요청하는지.
- 관리자 화면 — 사용자별 소속 지정·추가 허가 체크, 소속별 기본 허가 보기.

**강제(숨기기만으로는 안 된다).** 포털 `/agent/chat`(심의 접두·thinking·delib_opts)·`/agent/deliberate/*`·
업로드·PAT 발급을 권한으로 막고, 게이트웨이 `hwax-deliberation` 백엔드에 `feat:deliberation` 을 건다
(Claude·PAT 로 MCP 를 직접 쓰는 사람도 막히게).

## 단계

- **A** 정책 파일·플랫폼/기능 표·소속 저장·권한 계산·`/auth/me`·합성 그룹 전달
- **B** 관리자 화면 — 소속·개별 허가 편집
- **C** 메뉴·라우트·입구 숨김 + 포털 백엔드 강제
- **D** 게이트웨이 정책 파일(allowed_groups) — MCP 도구·심의 MCP 까지
- **E** 내 권한 페이지
- **다음** HEAXHub 직접 접속 권한 연동 · 외부 URL 플랫폼 · nginx auth_request · 심의 잡 소유자 범위

## 결정 (사용자, 2026-09-11)

1. **소속은 관리자가 지정한다.** 사용자는 자기 소속을 못 바꾼다(권한을 스스로 올리는 길이 된다).
   SSO 가 붙으면 AD 부서 속성으로 처음 값을 채우고 관리자 지정이 우선한다(이번엔 저장 칸만).
2. **CAEG 밖 기본값은 일반 챗만.** 로그인·일반 챗·업데이트·내 권한 페이지는 누구나. 심의·Thinking·
   전문가/HE팀 챗·각 플랫폼(앱 타일·MCP 도구)·업로드·API 토큰은 허가가 있어야 보이고 쓸 수 있다.
3. **허가는 둘 다** — 관리자가 직접 켜고, 사용자가 내 권한 페이지에서 요청하면 관리자가 승인한다.
4. **이번 범위는 포털·챗·MCP.** 게이트웨이 MCP 도구(Claude·PAT 직접 연결 포함)까지 막는다.
   HEAXHub 앱 화면 직접 접속·외부 URL 플랫폼(ARP·ODB)은 다음 단계.

## 주의

- **mock SSO 가 누구나 portal-admin 으로 만든다** — 권한 모델을 올려도 이 버튼이 살아 있으면 모두가
  관리자다. dev·데모 박스 설정을 함께 정해야 한다.
- 에이전트서버 `/chat` 은 인증이 없고 본문의 groups 를 믿는다(127.0.0.1 바인딩이 유일한 보호).
  권한 강제는 포털과 게이트웨이에서 하고, 에이전트서버는 받은 권한으로 한 번 더 막는다(방어 심층).
