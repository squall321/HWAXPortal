# 웨어러블 로스터 — 포털 쪽 결정 · 까닭

## WR-1 무엇이 '예산 막힘' 이었나(11-13)

- 사용자가 "예산 막혀서 안 되던 것들" 가운데 「논문 전문 → 지식카드 저작」을 골랐다. 기록상 막힘은 둘이었다 — PaperAuthor 전문 저작(편당 약 $4, P2 배치가
  예산 기준으로 멈춤)과 ExpertAgents OI-011(웨어러블 보강 카드 검증이 주간 한도 429 로 실패). 중계 받는 폴더(cae00 업로드)는 비어 있어 PaperAuthor 로
  돌릴 논문이 없었고, 사용자가 이어서 웨어러블 로스터 카드를 서브에이전트로 만들라고 지시했다.
- 그래서 `claude -p` 헤드리스 배치(PaperAuthor) 대신 이 세션의 워크플로 서브에이전트로 ExpertAgents 규약(09 · 07 · 08)을 그대로 따른다.

## WR-2 근거 원천 — 사용자 결정 '코퍼스 전부'

- ExpertAgents 07 §3.1 은 libgen · sci-hub 사본을 예외 없이 금지한다. PaperDownloader 는 오픈액세스 실패 시 sci-hub · libgen 으로 받고 논문별 출처를 남기지
  않는다. OpenAlex 로 DOI 마다 공개본인지 확인할 수 있다고(dev 에서 동작 확인) 선택지를 냈고, 사용자가 '코퍼스 전부' 를 골랐다. 이 로스터에 한한 결정으로
  ExpertAgents context-notes 에 남겼다.

## WR-3 분류 · 겹침

- id 첫 마디가 분류여야 하는 규칙 때문에 로스터 접두 19개를 분류로 신설했다(사용자 결정). 포털 조직도는 도메인 = id 첫 마디라 라벨만 더하면 된다.
- 기존 전문가와 완전히 겹치는 로스터 자리는 만들지 않는다(사용자 결정). 판정은 클러스터 계획 에이전트가 기존 expert.yaml 을 읽고 한다.

## WR-4 대기 루프가 자기 자신을 기다렸다

- 색인 완료를 `until ! pgrep -f build_index.py` 로 기다렸는데, 그 셸 자신의 명령줄에 `build_index.py` 가 있어 pgrep 이 늘 자신을 찾았다(끝난 지 오래인데 '실행 중').
  기다릴 때는 결과 파일(로그의 완료 줄)을 본다. `pgrep -f` 의 판정 문자열은 기다리는 셸의 명령줄에도 들어간다.
