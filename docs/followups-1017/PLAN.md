## 3. 묶음과 순서

끝난 리포부터 올린다(시험 → push → dev 반영 → 필요하면 Drive). 시험 스위트는 한 번에 하나만 돌린다(dev 메모리).

- **묶음 A — 보안 · 자료 보호 · 리뷰 결함**(오늘): 게이트웨이(G1 · G2) → 포털 스크립트(P1 · P4 · P5 · P6 · P8 · P9 · 결정 25) →
  리스크 백업(결정 2) → 지식 리포 묶음(결정 3) → 데이터허브(결정 4 · 24 · H1 · H1-b · H2 · H3 · H4) → 에이전트 서버(A1 · A2 · A3) →
  HEAXHub(X1 · X2 · X3 · X4 · 결정 16 일부) → MXWP · KooRemapper(결정 16 · K1) → 사내 IP 킷(결정 1) → 문서(P2 · P3 · P7 · 결정 기록).
- **묶음 B — 기능**(여러 날): 토큰 읽기 · 쓰기(5) → 허브 앱 개방(7) · 같은 소속 심의 열람(6) · 그림 인식(10) · 도구 검색 재측정(21) ·
  stcx 권한 확인(8 — DynaForge 요청서) · T1 절차(11).
- **사람 몫**: 옛 사본 삭제 확인(17) · cae00 의 stash 삭제 · PG 시한 · 리스크 백업 키 · 데이터허브 바인드 확인 · stcx LLM 잡 만료(11-14 전 `llmctl.sh rolling`).
