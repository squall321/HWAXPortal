  재는 동안 다른 변수가 섞인다. 페르소나 연결(E5-4)처럼 틀린 줄만 버린다. 게이트웨이도 M3 에서 같아야 한다 — 그쪽 해석이 예외를 내면 덧씌우기 전체를 버려

**OF-6 규칙은 앱 이름 없는 한 줄 + 도구 설명 표지(챗 로드에만)다.** 시스템 프롬프트는 사람마다 같아야 앞부분 캐시가 산다(W-3). 사람마다 보이는 앱이 달라(권한 ·
끈 앱) 규칙에 앱 이름을 적으면 그 사람에게 없는 도구를 가리키거나, 사람마다 글이 달라진다. 그래서 규칙은 '온톨로지 입구 표지가 달린 도구로 먼저' 라는 일반
글이고, 앱마다의 표시는 그 사람에게 보이는 도구의 설명에 단다. 표지는 챗 로드(`_prep_tool(chat=True)` — `app.py:4525`)에만 단다 — 라벨을 붙이는
`_tag_tool_app`(`app.py:2636-2645`)은 공용 래퍼라 심의 · 리스크 심사 로드(`deliberation.py:2373`)도 타고, 리스크 좌석 후보에 이미 `list_tasks` · `find_plm_task`
가 든다(반대 검토 5). 규칙에 'id · key 를 쥔 뒷걸음은 다시 풀지 않는다' 를 넣은 것은 HA-28(상태 기다림)과 같은 객체 다시 보기에서 쓸데없는 왕복을 막으려는 것이다.

**OF-7 게이트웨이 손잡이 `onto_first` 는 기본 끔 · 질의가 앱을 부를 때만 · 코어 질문에는 걸지 않는다.** 개인 Claude 는 서버 지침에 자리가 없다(가장 긴 조합 2,031자 ·

'앱을 부를 때만' 은 (가)의 뜻 그대로다 — 이미 쓰는 플랫폼 안에서만 입구를 올린다. 코어 질문에 걸면 (나)가 된다. 기본 끔이면 순위가 바이트까지 같아야 한다는
E-7 의 규칙을 지키고, `/search-eval` 이 꺼진 손잡이를 `+` 판으로 저절로 잰다(`gateway.py:3086-3100`). 새 가중치는 `_TUNING_WEIGHTS` · `_TUNING_FALLBACK`
(`:3227-3229`)에 더하고 보정 없는 점수(`base` — `:3622`)에는 넣지 않는다. 게이트웨이가 내는 도구 설명에 표지를 다는 것은 첫 판에서 하지 않는다 — 설명은 검색 점수에

**OF-8 심의는 미리보기를 권한다(사용자 결정 대기 — PLAN §10-3).**

  행의 과제 key · 이름은 결정문의 근거 목록과 RA 보고서에 실린다 — 뜻은 사람이 고른 심의만큼 연다(반대 검토 6 — 처음 판은 'PG-21 그대로' 라고만 적었다).

이웃 줄을 고쳐 병합이 부딪친다. 손잡이 · 가중치 칸만 더하고 설명은 README 코어 어휘표 절 · 코드 주석에 적었다(병합 뒤 `_doc` 에 한 줄 더할 일).

**OF-20 미리보기 — 닻은 포털이 M1 규칙으로 확인한 과제, 정본의 exact 는 그 key 일 때만.** 브라우저는 확인 상태를 보낼 수 없고(M1 — 422), 에이전트 서버는
심의를 열 때에만 주제를 확인한다. 그래서 창구가 M1 과 같은 풀이(`heaxstep_forge_find_plm_task` · 50행 · full)를 그 사람의 PAT 로 불러 같은 규칙(key 가
글자 그대로 같은 활성 행 하나)으로 확인한다(`subject.confirm_rows` — 형제 원문 `delib_subject.confirm` 과 판정을 견주는 시험). 확인하지 못하면 허브를 부르지
않는다. 정본의 `object_resolve` 가 exact 여도 그 객체의 key 가 닻과 다르면(별칭 · 이름으로 맞은 다른 객체) 고르지 않는다(mismatch) — 틀린 대상의 길을
하나 더 막는다. 읽기 확인은 닫힌 쪽이다 — 두 이름이 이 박스 지도에서 정본 백엔드 것이고 `routine_read` 에 있어야 한다(`routine_read` 가 없는 옛 게이트웨이도
부르지 않는다). 이웃 타입 인자는 어휘표 types 의 값에서 focus 를 뺀 것이지만 SP 는 시작점 타입을 늘 다시 넣는다 — 그래서 행은 어휘표 타입 전부(plm_task 포함 —
앞 · 뒤 과제)이고, 닻과 바로 이은 노드만이다(판정 · 기록 · 인사이트 타입과 이웃의 이웃은 행이 아니다). 근거는 호출 하나에 한 항목 — 주제 과제를 고르면 풀이
호출의 항목, 이웃 행을 고르면 이웃 호출의 항목(화면 차례, '[포털이 줄인 행 — 도구 원문이 아니다]' 머리). 화면은 VOC 칸의 `vf-*` 클래스를 그대로 써 새 색 ·
인라인 스타일이 없다. 기준일 심의는 칸을 그리지 않고 앞서 고른 것도 싣지 않는다. 두 화면에는 리스크 · 봉인 입구가 없고, 창구가 리스크 심사 계열 의장을
422 로 거절한다. M2 contracts §1(3)의 '주제가 갈 길이 없다' 는 '엔진이 옮기는 길은 없다 · 사람이 고른 근거는 예외' 로 고쳤다(PLAN §5.2 · OF-8).
