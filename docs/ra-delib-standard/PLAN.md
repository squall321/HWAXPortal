# 심의 보고서 RA 제출 표준화 — 형식 하나 · 시스템 공간에 확인 후 게시(2026-11-26)

> 체크리스트는 [checklist.md](checklist.md), 결정과 까닭은 [context-notes.md](context-notes.md), 운영 박스 사람 몫은 [server-setup.md](server-setup.md).

## 요청과 결정

사용자 요청(11-26): RA 최신을 받아 보니 심의한 보고서를 제출하는 길이 따로 생긴 것 같으니, 잘 파악해서 심의 보고서 제출도 표준화해 달라.

**파악한 것(RA `04a147e` v0.188.0, 원문 대조).**

- RA 코드 · 릴리스 노트에 심의만 받는 전용 길은 없다.
- 사용자가 본 것은 v0.180.0 의 「시스템 연계」 묶음이다.
  - **시스템 양식(수신 게시판):** 올라오면 바로 게시된다. HTML 양식 + `create_report_from_format` 전용이다.
  - **시스템 공간 `sys-<시스템>`:** 그 시스템의 결과가 모이는 게시판이다. 부서 단위로 「게시 가능」 · 「열람만」을 연다.
  - **AI 가 게시판을 골라 올리기:** 미리보기와 확인 토큰을 거쳐 사람이 확인한 뒤 게시한다.
  - **시스템 계정:** 사람 없이 올릴 때만 쓴다. 사람이 AI 로 올리는 우리 경우에는 필요 없다고 RA 가 적었다.
- 형식 등록 `POST /api/templates/register` → `sys.<system>.<kind>` 는 v0.176.0 부터 있다.

**우리 쪽 지금 모습.** 심의 보고서를 RA 에 저장하는 길이 다섯이다.

| 길 | 형식을 고르는 곳 |
|---|---|
| 엔진 심의 | 박스 파일 |
| `/보고서` | 박스 파일 |
| Claude 워크플로 | 코드에 박음 |
| 분석 루틴 | 박스 파일 |
| 리스크 종합 보고서 | 리스크 앱 손잡이 |

`"deliberation"` 이 코드 네 곳에 박혀 있고, 다섯 길 모두 개인 공간 초안으로만 남는다.

**사용자 결정(11-26, 둘 다 권장안).**

1. **목적지:** 심의 보고서는 RA 시스템 공간(`sys-hwax`)에 **사람이 확인한 뒤** 게시한다. 11-21 게시 관문 결정(확인 없이 게시하지 않는다)을 그대로 지킨다.
2. **형식:** 엔진 심의(웹 · MCP) · Claude 워크플로 · 리스크 심사 보고서는 등록 형식 `sys.hwax.deliberation` 하나를 쓴다. 고르는 곳은 박스 파일 한
   곳이다. `/보고서` · 분석 루틴은 지금 그대로 둔다.

## 설계

**박스 파일 한 곳.** `infra/ra-formats.local.json` 의 `deliberation` 줄에 `board`(시스템 공간 slug)를 더한다.

```json
{"deliberation": {"template_id": "sys.hwax.deliberation", "template_version": 1, "board": "sys-hwax"}}
```

- 에이전트 서버 · 게이트웨이의 읽기는 줄의 모르는 칸을 무시하므로 지금 동작이 그대로다.
- 파일이 없거나 `board` 가 없으면 지금처럼 초안까지만 간다. 게시 단추도 뜨지 않는다.

**게시 — 포털이 그 사람 명의로.**

| 창구 | 하는 일 |
|---|---|
| `GET /agent/ra/post-target` | 이 박스의 심의 게시판(없으면 null) |
| `GET /agent/ra/reports/{id}/post-preview` | RA `POST /api/mounts/preview` — 그 게시판 이름 · 볼 사람 수 · 이미 게시됐나 · 못 올리는 까닭 |
| `POST /agent/ra/reports/{id}/post` | 세션이면 CSRF. 미리보기를 다시 받아 확인 토큰과 함께 RA `POST /api/mounts` |

- 게시판은 박스 파일에서만 온다. 화면이 고르지 않는다.
- 심의 결과 카드에 「시스템 공간에 올리기」 단추를 둔다. 누르면 미리보기(게시판 이름 · N명 · 「게시 뒤에는 작성자가 직접 내릴 수 없다」)를
  보여 주고, 확인하면 게시한다.

**형식 통일.**

- **엔진(웹 · MCP):** 이미 박스 파일이다. 바꿀 것이 없다.
- **리스크 종합 보고서:** 포털 `risk_report.py` 는 재료의 형식이 기본값 `deliberation` 일 때만 박스 형식으로 바꾼다. 앱 손잡이로 일부러 다른 틀을
  고른 경우는 그대로 둔다.
- **Claude 워크플로:** 게이트웨이 읽기 도구 `ra_report_format` 로 형식 · 게시판을 받는다. 도구가 없으면 `deliberation`/1 로 돈다. 게시판이 있으면
  저장 뒤 RA 표준 흐름(`preview_publish` → 사람 확인 → `publish_report`)을 안내한다. 게이트웨이의 `invoke_tool` 거절 목록은 직접 호출을 막지
  않는다.
- **등록 스크립트:** `ra-register-format.py --use --board <slug>` 가 박스 파일에 게시판까지 쓴다.

## 운영 박스 사람 몫

[server-setup.md](server-setup.md) 를 본다. 차례는 이렇다.

1. RA 판이 0.180 이상인지 확인한다.
2. RA 시스템 관리자가 시스템 공간 `sys-hwax` 를 만들고 부서를 「게시 가능」으로 등록한다.
3. 형식을 최상위 조직 소유로 등록하고 박스 파일에 쓴다. RA 는 소유 부서 트리 밖 사람에게 그 형식을 보이지 않는다.
4. 포털 · 게이트웨이를 재기동한다.

## 범위 밖

- RA 리포는 고치지 않는다.
- HTML 양식(`create_report_from_format`)과 수신 게시판 자동 게시는 쓰지 않는다(결정 1).
- 시스템 계정은 쓰지 않는다. 사람이 AI 로 올리는 길이라서다.
