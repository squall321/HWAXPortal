# 결정 기록 — 심의 보고서 RA 제출 표준화

> 계획은 [PLAN.md](PLAN.md), 체크리스트는 [checklist.md](checklist.md). 덧붙이기만 한다.

## 2026-11-26 — 파악과 결정

**RS-1 RA 에 심의 전용 길은 없다.**
- RA `04a147e`(v0.188.0)를 `--ff-only` 로 받았다. dev RA 는 이 작업 트리로 떠 있지 않았고, 커밋은 만들지 않았다.
- 코드 · 릴리스 노트 · 가이드 어디에도 심의나 「제출」 전용 길은 없다. 사용자가 본 것은 v0.180.0 「시스템 연계」 묶음으로 본다.
- 묶음의 내용은 시스템 양식(수신 게시판 — HTML 양식 + from-format 전용, 확인 없이 게시) · 시스템 공간 `sys-<시스템>` · AI 의 게시판 지정 게시(미리보기 + 10분 확인 토큰) · 시스템 계정이다.
- v0.187 · v0.188 은 RA → SP 지식 연계라 들어오는 길이 아니다.

**RS-2 사용자 결정(11-26) — 시스템 공간에 확인 후 게시 · 심의 형식 하나(둘 다 권장안).**
- 자동 게시(수신 게시판)를 고르지 않았다. 그래서 11-21 게시 관문(L21-4 B1 — `create_report_from_format` 은 확인 없이 게시하므로 막는다)은 그대로다.
- `/보고서` · 분석 루틴은 형식을 바꾸지 않는다.

**RS-3 게시는 포털이 그 사람 명의로 하고, 게시판은 박스 파일에서만 온다.**
- RA `POST /api/mounts` 는 `X-Client: mcp` 일 때만 확인 토큰을 요구한다(사람이 화면에서 누르는 게시는 한 번에).
- 포털은 사람이 카드에서 미리보기를 보고 확인을 누른 뒤에만 부르고, 그때 받은 확인 토큰도 함께 보낸다(어느 길로 읽혀도 맞게).
- 화면이 게시판을 고르지 않는다. 고르게 하면 「AI 가 상위 부문을 고른다」와 같은 실수를 화면이 할 수 있다.

**RS-4 박스 파일은 새로 만들지 않고 `deliberation` 줄에 `board` 칸을 더한다.**
- 에이전트 서버 `ra_formats.py` · 게이트웨이 `_ra_formats_load` 는 줄의 `template_id` · `template_version` 만 읽고 나머지 칸은 무시한다.
- 그래서 칸을 더해도 두 쪽 동작이 바이트까지 같다. 파일이 없으면 지금과 같다.

**RS-5 리스크 보고서는 재료가 기본값일 때만 바꾼다.**
- 리스크 앱 손잡이 `HWAXRISK_RA_REPORT_TEMPLATE` 는 그 앱이 정본이라고 적혀 있다.
- 손잡이를 일부러 다른 틀로 바꾼 박스를 덮지 않도록, 재료의 형식 id 가 기본 `deliberation` 일 때만 박스 형식으로 바꾼다.
- 블록 id 넷(background · results · recommendation · minutes)은 등록 형식 정의 `infra/ra/formats/deliberation.json` 과 같다.

**RS-6 워크플로는 게이트웨이 읽기 도구로 받는다.**
- 워크플로는 사용자 PC 에서 돌아 박스 파일을 못 읽는다.
- `ra_report_format` 이라는 이름은 심의 좌석 자유 조회 접두(`_FREE_ALLOW`)에 걸리지 않는다. 좌석에 새 길을 열지 않는다(D-18 의 교훈 — 게이트웨이 로컬 읽기 도구 이름).
- 게이트웨이 `_INVOKE_DENY_EXACT` 의 `publish_report` 는 `invoke_tool` 경유만 막는다. 사람의 Claude Code 가 직접 부르는 게시는 RA 의 확인 토큰 흐름을 그대로 탄다.

**RS-7 형식 소유는 최상위 조직이어야 전사가 쓴다.**
- RA 는 그 사람이 소유 부서 트리(조상 · 자손)의 멤버일 때만 형식을 보인다(`templates/services.py` `is_visible_to_user`). 안 보이면 ai-draft 가 404 다.
- 시스템 공간의 부서 등록은 이 판정에 들지 않는 것으로 읽었다(멤버 행만 본다). 그래서 소유를 시스템 공간으로 두면 안 된다.
- 운영 등록 때 소유를 최상위 조직으로 둔다(server-setup). 실호출로는 확인하지 않았다.

## 2026-11-26 — 지으며 정한 것

**RS-8 결과 카드는 그리면서 포털에 묻지 않는다.**
- 처음에는 카드가 그려질 때 `/agent/ra/post-target` 을 물었다. 브라우저 시험(`test_wda_deck_in_browser` — WD-D78 「그리는 동안 포털에 묻지 않는다」)이 잡았다.
- 앱 머리(`AppHeader`, 모든 화면 공통)가 RA 권한이 있는 사람에게 한 탭에 한 번 미리 묻고, 카드는 그 답을 기다리기만 한다(`knownPostBoard`).
- 첫 화면에서 카드가 앱 머리보다 먼저 그려져도 단추를 잃지 않게, 묻기가 시작될 때까지 기다린다. 묻지 않는 곳(권한 없음 · 시험 장치)에서는 카드가 스스로 묻지 않고 단추를 숨긴다.

**RS-9 게이트웨이 도구가 'report' 검색 순위에 낀다.**
- `ra_report_format` 은 이름에 report 가 있어 「report digest」 같은 검색에서 앞쪽에 선다(게이트웨이 E9 시험의 순위 2 → 3).
- 읽기만 하는 작은 도구라 그대로 둔다. 순위가 문제가 되면 검색 튜닝 덧씌우기로 낮춘다.

**RS-10 리스크 형식 바꾸기는 박스 줄이 있을 때만.**
- 처음 고침은 박스 파일이 없을 때도 기본 v1 로 덮어, 앱이 `deliberation` v2 를 실어 와도 v1 이 될 수 있었다. 박스 줄이 있을 때만 바꾸게 고쳤고 변이 시험이 잡는다.

**RS-11 시험과 반영.**
- 포털 전체 회귀 5,960 통과(실패 둘은 위 RS-8 과 시험 글귀 — 고친 뒤 해당 시험 · 화면 묶음 시험 336 통과) · 게이트웨이 전체 1,255 통과 · 변이 둘(확인 토큰 빠짐 · 박스 없을 때 덮기)을 시험이 잡았다.
- 게이트웨이는 `c27a2f9` 로 합쳐 올렸다. 포털 · 게이트웨이 dev 재기동은 사용자에게 묻는다(켜지는 것은 이번 변경뿐 — 다른 세션의 미반영 커밋 없음).
