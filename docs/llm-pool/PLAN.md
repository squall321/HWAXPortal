# LLM 서버 둘을 자원 보고 나눠 쓰기 — 계획

> 사용자 결정(2026-10-15): 두 서버(…136 · …137)에 **같은 모델**을 올리고, **자원 상황을 보고** 덜 바쁜 쪽으로 보낸다. 차례는 **리스크 심사 M3 를 올린 바로 뒤**다.
> 내부 IP·포트·키는 추적 파일에 적지 않는다 — 실제 주소는 `infra/.env` 에만.

## 1. 지금

HWAX 의 LLM 호출은 전부 서버 하나(…137 의 vLLM, GLM-5.2 · 1M 창)로 간다. 주소의 정본은 포털 `infra/.env` 의 `LLM_BASE_URL` 이고, 서비스마다 자기 `.env` 에 사본을 든다(에이전트 서버 `VLLM_BASE_URL` · AIDataHub `LLM_BASE_URL` · MXWhitePaper 등). 설정 킷은 '없는 키만 더한다' 라서 정본을 바꿔도 이미 적힌 사본은 바뀌지 않는다.

## 2. 모양 — 자원 보는 라우터 하나

```
에이전트 서버 · AIDataHub · …  ──▶  LLM 라우터(OpenAI 호환 /v1)  ──▶  vLLM …136
                                         │ /metrics 를 몇 초마다         └▶ vLLM …137
```

- **고르는 기준** — 서버마다 vLLM `/metrics` 의 도는 요청 수(`num_requests_running`) · 대기 수(`num_requests_waiting`) · KV 캐시 사용률을 몇 초마다 읽고, 요청마다 '대기 + 도는 수' 가 적은 쪽(같으면 KV 여유가 큰 쪽)으로 보낸다.
- **캐시 붙임(선호)** — 같은 대화·같은 전문가의 연속 호출은 가능하면 같은 서버로 보낸다(요청 머리의 붙임 열쇠 — 대화 id · 카드 대조의 전문가 키). vLLM 접두 캐시가 같은 카드 묶음을 다시 읽는 비용을 줄인다. 붙인 서버가 상대보다 확실히 바쁘면(문턱) 떨어뜨린다.
- **장애 넘김** — 응답이 없거나 `/metrics` 를 못 읽는 서버는 잠시 뺀다. 연결 실패(아직 아무것도 안 보낸 요청)는 다른 서버로 한 번 다시 보낸다. 이미 흐르기 시작한 스트림은 다시 보내지 않는다(중복 생성 금지).
- **그대로 통과** — `/v1/chat/completions` 의 스트리밍(SSE) · `/v1/models`(두 서버의 모델·창이 같은지 확인하고 하나로 답 — 다르면 기동 경고), 그 밖의 경로는 그대로.
- **보이기** — 라우터 `/health` 와 `/stats`(서버별 수 · 붙임 적중 · 넘김 수), update-all §6 에 한 줄.

## 3. 같이 바꾸는 것

- **동시 수** — 처리량이 두 배라 카드 대조 관문(`CARD_REVIEW_CONCURRENCY` 8 → 16)·심의 동시 수를 올린다. 리스크 앱 워커·시간 한도 사슬 시험(P3-3)을 함께 맞춘다.
- **주소 바꾸기** — 정본을 라우터로 바꾸면 사본들을 함께 바꾸는 update-all 단계(백업 · 바뀐 파일 목록 · 되돌리기 한 줄)를 둔다. 반대 길(라우터를 지금 주소에 두고 vLLM 을 옆 포트로)도 있다 — GPU 서버를 우리가 관리하면 클라이언트를 하나도 안 고친다(열린 물음 1).

## 4. 열린 물음(시작할 때 사용자에게)

2. …136 의 vLLM 이 …137 과 같은 모델·같은 창(1M)·같은 기동 인자로 뜨는가 — 다르면 엔진의 예산 셈이 어긋난다.
