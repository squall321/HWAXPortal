# 서버(cae00)에서 할 일 — 리스크 심사 M0-b 탐침(운영 LLM 실측)

> 대상: cae00 운영자 · **대조 시점 2026-10-12** · 보낸 쪽: dev(이 리포 `docs/risk-review-redesign/`).
> 쓰는 것 — HWAXAgentServer `412edde` 이후의 `scripts/m0b_probe.py`(탐침)와 포털의 카드 대조 중계(`0f66999` 이후). 둘 다 평소 `update-all` 로 들어온다. 탐침은 파일만 있으면 되고 서버를 다시 띄울 필요가 없다.
> dev 에서는 로컬 vLLM(qwen 16K)에 10회 돌려 응답 칸 읽기와 창 초과 거절(HTTP 400 `This model's maximum context length is 16384 tokens …` → `context_overflow`)을 확인했다. 포털 중계로 팩을 받는 길은 시험(가짜 중계)으로만 봤다.
> 명령은 각 리포 루트에서 돈다(cae00 은 `~/Projects/<Repo>`). 근거는 줄 번호가 아니라 **출력 문구**로 가리킨다.
> 이 박스의 지금 상태는 이 문서가 알지 못한다. 그래서 확인마다 재는 명령을 적었다.
> (10-15 덧붙임) M3 의 보강 팔 셋(`--extra agree·merged·summary`, 탐침 판 `m0b-2`)은 `server-setup-m3.md` 3절이다. 이 문서의 걸음은 그대로 쓴다.

## 0. 한눈에

M2(카드 대조)는 아직 재 본 적 없는 값 위에 서 있다 — 호출 하나가 몇 초 걸리나, 글자 몇 자가 토큰 하나인가, `max_tokens` 를 안 보낼 때 GLM 이 출력을 어디서 끊나, 창을 넘으면 어떤 문구로 거절하나, 카드 몇 장을 한 호출에 실어야 빠뜨리지 않나. 탐침이 이것을 운영 LLM(GLM-5.2, 1,048,576 토큰 창)에 직접 물어 잰다.

- 하는 일 — 에이전트 서버 리포의 `scripts/m0b_probe.py` 하나를 돌린다. 에이전트 서버와 같은 `.env`·같은 LLM 설정으로 카드 대조 프롬프트를 GLM 에 **한 번에 하나씩** 보낸다(기본 64회). 결과는 수만 남긴다.
- 바뀌는 것 — 없다. 서버 재기동·설정·DB·잡 원장을 건드리지 않고 포트를 열지 않는다. 쓰는 파일은 `--out` 으로 준 결과 파일 하나다.
- 걸리는 시간 — 호출 하나가 30초면 약 30분, 5분이면 약 5시간이다. 실제 속도는 진행 줄의 '남은 어림' 이 알려 준다. **심의가 돌지 않을 때** 시작한다.
- 사람이 할 일 — 돌리기 전 확인(1절), 전문가 고르기와 dry run(2절), 끝나면 요약 블록과 결과 파일을 dev 에 보내기(3절).

## 2. 돌리기

### 2-1. 전문가 고르기

verdict 호출은 전문가의 **점검 카드**(종류 design-rule·standard-summary·failure-case)를 묶어 싣는다. 탐침은 묶음 장수 1·4·8·K_out 넷을 견주고, 1백만 토큰 창에서 K_out 은 19장이다. dev 코퍼스의 기구 전문가는 카드 30장 남짓에 점검 카드가 13장 안팎이라 한 명으로는 19장 묶음을 채우지 못한다. 그래서 **같은 분야 전문가 둘을 쉼표로** 준다(카드를 합치고 역할은 첫 전문가 것을 쓴다).

- 권하는 짝 — `mech-drop-impact,mech-psa-bonding`(dev 에서 각각 점검 카드 13장).
- 다른 짝을 고르려면 Claude 에서 `browse_experts(domain='mech')` 처럼 조직도를 보고 같은 분야 둘을 고른다.
- cae00 코퍼스가 dev 와 다를 수 있다. dry run 의 `[팩]` 줄이 실제 장수를 말한다 — 합친 점검 카드가 19장 이상이면 된다. 40장을 넘으면 회차마다 묶음이 덜 겹쳐 더 좋다.

### 2-2. 토큰을 셸에만 넣는다

```bash
read -rs HWAX_PROBE_PAT && export HWAX_PROBE_PAT
```

토큰을 붙여 넣고 Enter 를 친다. 화면에 보이지 않고 셸 기록(history)에 남지 않는다. 파일이나 명령 인자에 적지 않는다 — 탐침은 토큰을 인자로 받지 않고 이 환경변수에서만 읽는다. 탐침은 시작할 때 포털 중계(`/agent/card-review/pack`)로 카드를 받는 데만 쓴다.

### 2-3. dry run — LLM 을 부르지 않고 계획만 본다

```bash
cd ~/Projects/HWAXAgentServer
.venv/bin/python scripts/m0b_probe.py --agent mech-drop-impact,mech-psa-bonding --dry-run
```

LLM 에는 창 크기 조회(`/v1/models`)만 하고 생성 호출은 하지 않는다. 카드를 받는 데 보통 1분이 안 걸린다. 출력에서 아래 줄을 본다.

| 줄 | 기대 | 다르면 |
|---|---|---|
| `[LLM] 모델 … · 키 있음(값은 찍지 않는다)` | 운영 모델 이름(GLM-5.2 계열) | 에이전트 서버 `.env` 의 `VLLM_BASE_URL`·`VLLM_MODEL`·`VLLM_API_KEY` 를 본다 |
| `[창] 1,048,576 토큰 · 출처 server` | 출처가 `server` 이고 `K_out 19` | 출처가 `env`·`fallback` 이거나 `다시 묻는 중` 이면 실제 실행이 멈춘다 — LLM 서버가 닿는지, 키가 맞는지 본다 |
| `[팩] … 카드 N장(점검 M·배경 …)` 과 `… 의 카드를 합쳤다` | M 이 19 이상 | `⚠ 점검 카드가 M장이라 K 팔 kout(…)` 이 나오면 같은 분야 전문가를 하나 더 준다 |
| `[계획] 호출 64회(동시 1)` 아래 팔 표 | `k1`·`k4`·`k8`·`kout`·`sweep`·`offcard`·`cache-cold`·`cache-repeat`·`cache-repair`·`overflow` | `⚠` 로 시작하는 줄을 읽는다 |
| `입력 추정 합 … 토큰 · 호출 하나 30초면 약 …, 5분이면 약 …` | 걸릴 시간의 범위 | — |
| `[부하] … delib_active 0, delib_queued 0, review_active 0` | 전부 0 | 끝난 뒤 돌린다 |
| `[프록시] 이 셸에 … 가 있다` | 없거나, 있어도 LLM 이 닿는다 | 2-6 의 `llm_unreachable` 줄 |
| `[dry-run] LLM 을 부르지 않았다` | 마지막 줄 | — |

`멈춤 —` 으로 시작하는 줄이 나오면 2-6 을 본다.

### 2-4. 돌리기

SSH 가 끊겨도 돌도록 `nohup` 으로 띄우고, 결과는 리포 밖(홈)에 쓴다.

```bash
cd ~/Projects/HWAXAgentServer
OUT=~/m0b-$(date +%m%d-%H%M).jsonl
nohup .venv/bin/python scripts/m0b_probe.py --agent mech-drop-impact,mech-psa-bonding --out "$OUT" > "${OUT%.jsonl}.log" 2>&1 &
echo "pid $!  결과 $OUT"
unset HWAX_PROBE_PAT
tail -f "${OUT%.jsonl}.log"
```

띄운 뒤 곧바로 `unset` 해도 된다 — 탐침은 띄울 때의 환경을 이미 가지고 있다. `pid` 는 적어 둔다(2-5). `tail -f` 는 Ctrl-C 로 빠져나와도 탐침에는 아무 일이 없다.

진행 줄은 호출마다 하나다.

```text
[ 3/64] verdict k8           fwd  k=8   · 41,234자 · 41.2초 · 토큰 30,123→2,100 · stop · 빠짐 0/8 · 못읽음 0 · 남은 어림 1:02:00
```

팔 이름·변형·묶음 장수, 프롬프트 글자 수, 걸린 초, 입력→출력 토큰, `finish_reason`, 빠진 행/기대 행, 못 읽은 원소, 남은 시간 어림이다. 끝에서 두 번째 `cache-*` 셋과 마지막 `overflow` 는 일부러 큰 호출이다(아래).

부하와 시간.

- 호출은 한 번에 하나다(동시 1). 기본 64회 — verdict 네 팔 × 12회차, sweep·offcard 각 6회, 접두 캐시 셋, 창 초과 하나.
- 큰 호출은 넷이다. 접두 캐시 셋은 단위를 20만 자로 채운 같은 글을 세 번 보내 두 번째부터 빨라지는지 본다. 창 초과 하나는 창의 1.1배(수 MB)를 한 번 보낸다. 서버가 곧바로 거절하는 것이 정상이고(진행 줄 `오류 context_overflow(HTTP 400)` 처럼), 혹시 받아들여도 600초에서 끊는다.
- 시작할 때 `/health` 에 심의나 카드 대조가 돌고 있으면 탐침이 스스로 시작하지 않는다. 도는 중에 누가 심의를 시작하면 멈추지 않고 그 호출에 표시해 둔다(요약의 `다른 심의·검토가 돌던 호출`).
- 탐침이 공유 LLM 을 쓰는 동안 챗·심의의 첫 응답이 조금 늦을 수 있다.

### 2-5. 멈추기와 다시 내기

- 끝나기 전에 멈추려면 `kill <pid>` 를 보낸다(`kill -INT` 도 같다). 도는 호출 하나를 접고, 거기까지의 요약을 로그에 찍고, 결과 파일 끝에 summary 줄을 쓴다.
- `kill -9` 나 박스 재부팅으로 끝났으면 요약이 없다. 결과 파일에서 다시 낸다(LLM 을 부르지 않는다).

```bash
.venv/bin/python scripts/m0b_probe.py --summarize "$OUT"
```

- 다시 돌릴 때는 다른 `--out` 이름을 준다. 있는 파일은 덮지 않고 멈춘다.
- 종료 코드 — 0 끝까지 돌았다, 2 시작 전에 멈췄다(`멈춤 —` 문구), 3 다른 일이 돌아 시작하지 않았다, 4 잇단 실패 3회로 멈췄다, 130 `kill`·Ctrl-C 로 멈췄다.

### 2-6. 멈춤 문구와 할 일

| 문구 | 뜻 | 할 일 |
|---|---|---|
| `--agent 는 포털 PAT 가 필요하다` | `HWAX_PROBE_PAT` 가 비었다 | 2-2 |
| `팩을 받지 못했다 — HTTP 401 — PAT 가 틀렸거나 만료됐다` | 토큰이 틀렸거나 만료·폐기됐다 | '개인 토큰' 페이지에서 다시 받는다 |
| `팩을 받지 못했다 — HTTP 403` | 그 계정에 전문가 심의 권한이 없다 | 포털 '내 권한' 에서 요청하거나 권한 있는 계정의 토큰을 쓴다 |
| `HTTP 404 agent_not_found` | 전문가 키가 없다 | 키 철자를 본다 |
| `HTTP 404 agent_outdated` · `포털 중계 … 에 닿지 못했다` | 에이전트 서버나 포털이 카드 대조 전의 판이거나 떠 있지 않다 | 1절 확인 2, update-all |
| `HTTP 429 review_busy` · `engine_busy` | 카드를 받을 자리가 잠시 없다 | 1분 뒤 다시 |
| `HTTP 502 card_list_…` · `card_fetch_failed` · `HTTP 503 tools_unavailable` | AIDataHub·게이트웨이에서 카드를 다 받지 못했다(일부만 든 팩은 쓰지 않는다) | 잠시 뒤 다시. 이어지면 dev 에 문구를 보낸다 |
| `카드가 0장이다` · `점검 카드(checkable)가 0장이다` | 그 전문가로는 잴 것이 없다 | 다른 전문가 |
| `LLM 서버에 창 크기를 묻지 못했다` · `창 크기를 알려 주지 않았고` | 창을 모른 채로는 K_out·창 초과를 잴 수 없다 | LLM 서버가 닿는지, `.env` 의 주소·키를 본다 |
| `에이전트 서버에서 다른 일이 돈다` | 심의·카드 대조가 돈다 | 끝난 뒤 다시. 급하면 dev 와 상의해 `--allow-busy` |
| `… 가 이미 있다 — 덮지 않는다` | 같은 `--out` 이 있다 | 다른 이름 |
| `잇단 실패 3회(llm_unreachable …)` | LLM 에 닿지 않는다 | LLM 서버 상태를 본다. dry run 에 `[프록시]` 줄이 있었으면 그 셸의 프록시 변수가 사내 LLM 주소를 가로채는지(`NO_PROXY`) 본다 |
| `잇단 실패 3회(llm_timeout …)` | LLM 이 1,800초 안에 답하지 않는다 | LLM 이 바쁜지 본다. dev 에 알린다 |

## 3. 결과 보내기

dev 에 셋을 보낸다.

1. **요약 블록** — 로그 끝의 `===== M0-b 탐침 요약 — 이 블록을 그대로 붙여 보낸다 =====` 부터 `===== 요약 끝 =====` 까지를 그대로 붙인다. 로그가 없으면 2-5 의 `--summarize` 가 같은 블록을 다시 낸다.
2. **결과 파일** `$OUT`(JSONL) — 첫 줄이 meta(모델·창·예산·팩 수·계획), 호출마다 한 줄, 끝 줄이 summary 다. 카드·단위 원문, LLM 키, 포털 토큰은 들어 있지 않다. 수와 해시, 전문가 키, 모델 이름, LLM 주소(호스트까지), 오류 발췌(200자와 원래 길이)만 있다. 리포에 커밋하지 않는다.
3. 로그 앞머리의 `[LLM]`·`[창]`·`[팩]`·`[계획]` 줄(meta 에도 있지만 사람이 읽기 쉽다).

요약 블록의 줄마다 dev 가 다시 정하는 값은 이렇다.

| 요약 줄 | 재는 것 | M2 가 지금 거는 값 |
|---|---|---|
| `[호출 초]` 의 verdict·sweep·offcard p50·p95 | 호출 시간 | 5분 가정(PLAN 6절) — 앱 셀 벽시계·동의 문턱·전원 1회 벽시계 |
| `[글자/토큰]` 의 중앙값·`엔진 추정÷실제` | 글자/토큰 비 | 1.05(엔진의 최악값)·거절 문턱 |
| `[출력]` 의 `length …/…`·`가장 긴 출력 … 토큰` | `max_tokens` 를 안 보낼 때의 출력 상한 | 16,000 토큰 가정 → K_out 19·쪽당 단위 64·카드 밖 14건 |
| `[출력]` 의 `finish_reason 실림`·`token_usage 실림` | 응답에 두 칸이 오나 | 안 오면 절단·토큰을 '모름' 으로 둔다 |
| `[출력]` 의 `<think>` | 본문에 추론이 섞이나 | 파서가 늘 뗀다 |
| `[K 팔 · 종류별 행]` 의 빠진행·못읽음·보충필요 | 묶음 장수별 정확도 | `CARD_REVIEW_K` 8 |
| `[창 초과]` 의 상태·분류·발췌 | 창 초과 거절의 모양 | 400 이고 추정이 창의 85% 이상이면 `context_overflow` |
| `[접두 캐시]` 의 처음·같은 글·보충 꼴 | 같은 머리의 글을 다시 보낼 때 빨라지나 | 없다고 보고 보충 시도 상한 3 |

## 4. 지우기

- `unset HWAX_PROBE_PAT`(2-4 에서 했으면 끝났다). 이 탐침만을 위해 받은 토큰이면 포털 '개인 토큰' 페이지에서 폐기한다.
- 탐침은 서버·설정·DB·잡 원장을 바꾸지 않았다. 남는 것은 결과 파일과 로그 둘이다. dev 가 받았다고 하면 지운다.

```bash
rm "$OUT" "${OUT%.jsonl}.log"
```

## 5. 손잡이 (전부 선택 — 안 주면 기본값)

| 인자 | 기본 | 무엇 |
|---|---|---|
| `--reps` | 12 | verdict 팔마다의 회차. sweep·offcard 는 그 절반 |
| `--k-arms` | `1,4,8,kout` | verdict 묶음 장수. `kout` 은 그 창의 K_out |
| `--max-calls` | 100 | LLM 호출 상한. 넘으면 회차 꼬리부터 버리고 몇 회를 버렸는지 말한다(캐시 셋·창 초과는 남긴다) |
| `--skip` | 없음 | 뺄 것을 쉼표로 — `sweep`·`offcard`·`cache`·`overflow` |
| `--unit-file` | 합성 단위 | 검토 단위 JSON. M0-d 로 실제 과제의 단위가 생기면 리스크 앱이 내보낸 단위(하나나 목록)를 준다. 합성 단위는 작아서 호출이 실제보다 짧게 나올 수 있다 — 접두 캐시 셋의 첫 호출(20만 자)이 큰 단위의 시간을 대신 보여 준다 |
| `--portal` | `http://127.0.0.1:8723` | 포털 백엔드 주소 |
| `--env-file` | 리포 루트의 `.env` | 에이전트 서버 `.env`. 서버가 읽는 규칙(start.sh)과 같게 읽는다 |
| `--allow-busy` | 꺼짐 | 심의·카드 대조가 돌아도 강행한다(재는 초에 줄 기다림이 섞인다) |
