이대로 구현하면 완결 표기와 커버리지 수치가 '안 본 것' 을 '본 것' 으로 세는 길이 여럿 남는다. 가장 무거운 것은 셋이다 — 후속 단계(교차·메커니즘·쟁점·표본)가 한 번도 안 돌았거나 낡았어도 '없다' 꼴 조건이 공허하게 참이 되어 C3 가 서는 것, 사람이 넘긴 칸(계약 C-18 의 skipped — pending 에서도 갈 수 있다)이 잔여 목록에 없어 맨 C3 로 사라지는 것, C1·C2·C2(closed) 에는 잔여 표기가 아예 없어 회로 110명이 아무것도 못 본 채 '심층 완료' 가 서는 것이다. 숫자 쪽은 '카드 판정 N/N' 이 종결 조건과 같은 식이라 늘 100% 이고, 검증률의 분모가 '있던 행' 이며, 메커니즘 '검토함' 은 자기 신고 한 줄로 닫히고, 놓침률·뒤집힘률은 정의가 문서마다 다르거나 표본 설계와 분모가 안 맞는다. 반대로 판정 행 집합 회계(별칭 닫힌 집합 → 빠진 카드 재질의)와 '해당 없음' 의 단일 문은 견고해서, 형식 붕괴·절단·지어낸 별칭이 reviewed 로 새는 길은 찾지 못했다. 고칠 것은 대부분 WP4 의 완결 판정과 WP3b 의 집계 정의에 몰려 있고 새 표는 하나(`rr_post_runs`)면 된다.

빼거나 미루자는 것 5건.

- '카드 판정 / 기대'(rv.cards · review.cards.judged/expected)를 지표와 C3-2 조건으로 싣는 것 — reviewed 의 종결 조건과 같은 식이라 늘 100% 이고 정보가 없다. 보고서에 실리면 '카드 전부를 대조했다' 로 읽힌다(X1-03).
- '노출 전수(exposed/expected)' 비율 한 줄 — 수를 내는 함수가 어느 설계서에도 없고, 구현하면 훑기 800자 목록만 본 셀과 입력 결손 셀까지 노출로 세게 된다(X1-10).
- 첫 출시에서 '해당 없음' 자동 필터와 다회차 표본 확대(59 → 93 → 124, 층 재개방, 회차 상한) — WP2 §8 결정 3 의 권고가 이미 '첫 실제 타깃은 필터를 끈다' 다. 필터가 꺼져 있으면 na_irrelevant 가 0 이라 이 기계는 죽은 코드이고, 켜는 순간 X1-12 · X1-13 · X1-17 의 구멍이 한꺼번에 열린다.
- 메커니즘 칸을 `m.seen` 목록으로 닫는 길(considered 자격 ⓐ) — 증거가 없는 자기 신고가 C3-6 을 채운다. 사냥 호출과 증거 수준이 맞지 않는다(X1-08).
- 새 흐름 타깃에서 `C2(closed)` 로 닫는 길 — 잔여 표기가 C3 에만 있어, Tier C 245명과 입력 결손 영역을 안 본 채 '닫힘' 으로 저장된다(X1-02).

## 가로지르기 — 배포 중간 상태

막음 1 · 큼 10 · 작음 5 — 전문 `reference/problems-x2-rollout.md`

이행 코드 자체는 원자적이고 옛 타깃·옛 잡은 기본값(`flow`·`mode` = 'panels') 덕에 옛 흐름에 그대로 남아, 스키마가 자료를 망치는 길은 찾지 못했다. 깨지는 곳은 그 둘레다 — 비우기 신호는 적힌 대로는 배포 창을 열지 못하고(미룸 판정의 재료가 git 실패 코드이고 수명이 update-all·쟁점 패널보다 짧다), heax 물음(P2)은 '심의 중이라 미룸' 을 배포 실패(exit 1)로 만든다. 섞인 판의 문지기가 `run` 의 첫 프레임과 `/health` 둘뿐이라 단발 JSON 호출과 뒤에 붙는 호출 종류는 보류 대신 실패로 떨어지고, 같은 v4 안의 옛 SIF 나 WP2 만 나간 판에서는 새 흐름의 잡·타깃이 옛 패널 경로로 조용히 돈다. 리스크 앱이 cae00 에 닿는 Drive 길·뜬 판의 식별·박스별 스위치·옛 타깃을 새 흐름으로 넘기는 길이 어느 4절·절차서에도 없어 cae00 시범이 기댈 자리가 비어 있다. '이행 안전 묶음(R3)' 과 'v4 통합 DDL + 문지기' 를 맨 앞 걸음으로 못 박으면 나머지는 걸음 순서 조정으로 풀린다(메모 파일 /tmp/claude-1000/-home-koopark-claude-HWAXPortal/0565039f-7220-44a9-9ec5-fbcb80c6651f/scratchpad/rr-redesign/problems-x2-rollout.md 에 같은 내용이 있다).

빼거나 미루자는 것 6건.

- 표본 재검토용 제공자 'cell_audit' 와 cells.run_check — WP3b 가 주지 않겠다고 못 박은 접점이고, 제공자 한 건 = 호출 한 번이라는 모양에 셀 하나의 다회 호출이 맞지 않는다(X4-02).
- 단위 5개 이하에서 훑기를 건너뛰는 few_units 규칙(그리고 snap·filter_off 의 훑기 생략) — 훑기는 전문가당 1~2호출인데 그 답(k)을 noinput 카드·offcard 배경 카드·card_vocab 세 곳이 읽는다(X4-06).
- 메커니즘 격자의 자격 ⓑ(카드의 메커니즘 태그)와 교차 호출 카드 우선순위 ⓑ — 카드에 메커니즘 태그가 없다(03-cards). 읽을 것이 없는 조건이다(X4-09).
- 잡 사슬의 '다음 Tier 자동 시작' — 대표 15명 시범이 동의 없이 전원 실행으로 번지고 Tier 마다 후속·쟁점이 돈다(X4-11).
- 새 흐름(cells) 타깃을 만들 때의 좌석 승계(apply_carry_over) 호출 — 새 흐름은 전원을 다시 보는데 승계가 좌석을 carried 로 닫으면 롤업이 그 행을 못 닫는다(X4-17).
- 필터를 끄는 손잡이 둘 가운데 하나(HWAXRISK_ROUTE_FILTER=off 와 HWAXRISK_REVIEW_SWEEP=off) — 같은 일을 WP2 와 WP3b 두 곳에서 하고, 한쪽만 끄면 훑기는 도는데 답은 안 쓰이는 상태가 된다.
