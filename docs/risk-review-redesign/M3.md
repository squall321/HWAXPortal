## 1. 무엇을 하나

PLAN 3절 M3 에 D-33(호출 줄이기 — 거르기를 M4 에서 당김)·D-34·D-35 를 얹은 것이다. 걸음 이름은 상세 계획의 것이다(`C3-` = 리스크 앱 셀 확장, `S3-` = 리스크 앱 쟁점·종합, `E3-` = 에이전트 서버, `P3-` = 포털).

- 리스크 앱 셀 확장(`m3-cells`) — 전원 포함(입력 결손 문 열기·보류 해제), 입력 결손 호출 배선, 실패 셀 처분, 거르기(코드 신호·훑기 판단·표본·넓힘), 걸린 카드만 이중 판정과 1순위 보정, 근거 꾸러미 실호출, 359명 규모.
- 리스크 앱 쟁점·종합(`m3-synthesis`) — 스키마 v5, 택소노미 1.2 와 메커니즘 → 영역 배정표, 등록부 병합, 쟁점 선정·패널, 잡 사슬, 완결 판정, 영역 요약·종합 보고서, 도구 둘.
- 에이전트 서버(`m3-engine-ops` E) — `noinput`·`summary` 종류, 긴 문서 검색, 판정 틀의 `mech`, 훑기의 결손 블록, 관문 8/4 와 `/drain`·`/health`, 챗 첫 조각 지연 계측, M0-b 보강.
- 포털(`m3-engine-ops` P) — 중계 경계와 `DelibOpts.started_by`, update-all 비우기, 시간 한도 사슬, 절차서.
- 게이트웨이 코드는 바꾸지 않는다.

나갈 기준은 PLAN 그대로다(cae00 실제 타깃 1건, 359명 전원 — 회로 110명은 입력 결손 두 질문이고 보고서가 그 사실을 적는다).

1. 모든 셀이 종결이거나 사유 있는 `failed` 다. 그 수와 사유가 종합 보고서 머리에 있다.
2. 전문가 보고서가 359편이다.
3. 쟁점 패널이 상한 안에서 전부 끝났고 상한 밖은 '미토의 쟁점' 으로 보고서에 있다.
4. 영역 요약 15건과 종합 보고서가 있고 그 수치가 완결 판정과 같다.
5. 완결 표기가 잔여(입력 결손·실패·사람 넘김·미토의·2차 영향 미실행·결손 사냥 미실행)를 달고 나온다. 잔여가 있으면 맨 `C3` 로 적히지 않는다.
6. 도는 중에 update-all 한 번이 비우기로 지나가고 심사가 이어 돈다. 챗 첫 응답 지연이 평소의 2배 안이다.

- **리스크 앱은 통합 가지 `m3` 와 꾸러미별 하위 가지 `m3-cells`·`m3-synth` 에서 짓는다.** 하위 가지마다 따로 워크트리를 쓰고(작업 디렉터리를 나눠 쓰지 않는다), 걸음이 끝나면 `m3` 에 합치고 다른 쪽이 날마다 rebase 한다. v5 는 단계 D 전에는 push 하지 않는다(PLAN 4절 C-2). HWAXRisk `context-notes.md` 에 'v5 는 재설계 M3 몫, 가지 `m3`, 블록 주인은 S3-1' 을 먼저 적는다. `frontend/` 는 다른 세션 몫이라 응답 필드까지만 한다.
- **에이전트 서버·포털은 단계 B 끝(포털 비우기는 단계 C 끝)에 main 으로 올린다.** 업데이트 이력은 올릴 때마다 함께 쓴다(엔진·포털은 B·C 끝, 리스크 앱은 D 끝 — 사용자 체감과 기술 둘 다).

### 3.1 나란히 가는 것과 차례를 지켜야 하는 것

**나란히.** 리포 셋(에이전트 서버 · 포털 · 리스크 앱)은 4절 계약과 엔진이 낸 계약 예제로만 묶이므로 나란히 간다. 엔진 안에서는 `card_review.py` 갈래(E3-1~E3-6)와 `review_gate.py`·`app.py` 갈래(E3-7~E3-9)가 나란하다. 리스크 앱 안에서는 두 꾸러미가 하위 가지 둘로 나란하다 — 에이전트는 꾸러미당 하나, 리스크 앱에 동시에 둘까지다(B 층 C3-12 는 새 파일이 많지만 `review_runner`·`units` 를 건드리므로 셀 쪽 에이전트가 한다).

### 3.3 단계 D 리허설에서 보는 것

하네스는 HWAXRisk `backend/tests/synth/rehearsal_d.py` 를 넓힌 하나다(M2 의 일곱 점검은 기본으로 그대로 돌고, M3 국면은 플래그로 더한다 — #54). 빈 포트·스크래치 디렉터리에 가짜 LLM(1M 창)·임시 에이전트 서버·임시 포털·리스크 앱을 띄운다. 하네스는 절대경로를 쓰고 `pkill -f` 를 쓰지 않으며, 끝에 실 저장소(9009·8723·실 원장)의 크기·mtime·fd 무접촉을 단언한다(D-31).

1. **전원 규모** — 합성 로스터 359명(영역 15 · 회로 110 · 카드 0장 3) × 단위 4~6 을 실제 배선으로 끝까지. 거름·표본·넓힘(가짜 LLM 이 표본 하나에 FAIL)·입력 결손 정산 네 줄·처분(다시·넘김)·카드 0장의 `role_only`·`search_only`. 명단은 줄이지 않고, 한 시간을 넘으면 단위만 줄인다. 7,180셀 전부는 가짜 엔진 통합 시험(C3-11, `RR_FULL=1`)이 본다.
2. **관문** — 사람이 띄운 가짜 심의 하나(`started_by` 없음)가 돌면 서버 limit 이 4, 쟁점 패널(`started_by:"app"`)만 돌면 8 이다. 앱 워커가 서버 limit 을 넘겨 뜨지 않는다.
3. **update-all 흉내 중 비우기** — `lib/review-drain.sh` 를 `HWAX_AGENT_URL=<임시>` 로 적재해 `1h` 절과 끝맺음을 떼어 부르고, 그 사이 임시 포털·에이전트 서버·리스크 앱을 차례로 내렸다 올린다. 깃발이 선 뒤 새로 시작한 호출 0(포털 감사 `card_review_run_start` 시각), `charged` 합 0, 잡 `completed`, 깃발 파일이 지워짐. 심의 국면(`delib_active=1` + 장부의 '재기동 건너뜀')이면 끝맺음이 `scope=panels until_idle` 이고 카드 대조는 이어 돌며, 심의가 끝나면 줄인 `grace_s` 뒤 깃발이 풀린다. 카드 대조 8건이 자리를 쥔 동안 챗 첫 조각이 `/health.load.chat` 의 `review` 고리에 들고 `slow` 가 선다(가짜 LLM `--capacity`).
4. **쟁점 패널** — 사슬이 쟁점 패널 2건 이상을 실제 엔진으로 돈다(가짜 LLM 의 심의 대본이 FAIL 을 낸다). 대본으로 결정문을 파싱할 수 있게 못 만들면 쟁점 단계만 dev 7B 로 한 번 돌린다(M1 이 쓴 길 — 판정의 질은 보지 않고 프레임과 사슬만 본다). 그 SSE 를 긁어 C14 의 `issue_panel_*.sse` 로 남긴다.
5. **종합 보고서** — 종합 잡이 영역 요약 15 + 종합 1 을 돌고 보고서 판이 넷(`reviews_partial`·`reviews_closed`·`issues_closed`·`synth_done`) 선다. 보고서 머리의 수 == 같은 때의 `closure.cell_counts`. 요약 하나를 `over_budget` 으로 만들면 그 영역이 `code_only(ctx_too_small)` 이고 보고서가 크게 적는다.
6. **포털 대화** — 카드 대조·`noinput`·`summary` 가 만든 대화 **0**. 쟁점 패널은 종전 패널 길(`POST /agent/conversations`)이라 대화 수 == 쟁점 패널 수다(#54). `save_report` 0 이라 RA 초안이 생기지 않는다.
7. **재기동 이어 돌기** — 셀이 도는 중 리스크 앱 SIGTERM·SIGKILL, 에이전트 서버 재기동 — 차감·보류 없이 이어 돈다. 쟁점 패널이 도는 중 SIGKILL — 쟁점이 `queued` 로 돌아오고 사람이 재개하면 끝까지 간다(자동 재개는 M4).
8. **판 올림** — 리허설 도중 엔진의 `summary` 판만 올려 다시 계획해도 셀 지문이 그대로다(#37).

리허설이 표 모양을 바꾸라고 하면 v5 를 고친다(push 전이다). 그 뒤 `PUSHED_DDL_SHA256[5]` 를 굳히고, dev 인스턴스 교체는 `apptainer instance list` 출력에서 이름을 확인하고 내리며 다시 올리는 것은 허브에 맡긴다. 교체는 dev 에 살아 있는 검토 잡이 없을 때다.

### 4.3 `GET /card-review/limits` 에 더하는 것

```json
{"api_rev": "cr-1",
 "kinds": ["sweep", "verdict", "offcard", "noinput", "summary"],
 "cell_kinds": ["sweep", "verdict", "offcard", "noinput"],
 "llm_max_tokens": 32768, "max_tokens_source": "card_review|delib|none",
 "unit_body_max": 99402,
 "verdict":  {"…M2 칸…", "mech_max": 13762},
 "offcard":  {"…M2 칸…", "longdoc_max": 82575},
 "noinput":  {"p", "fixed", "body", "role_max", "digest_max", "known_max", "mech_max", "hint_max", "unit_body_max", "card_budget", "items_max": 15},
 "summary":  {"p", "fixed", "body", "hint_max", "blocks_max", "line_max": 400, "narrative_max": 2520, "cover_max": 18, "cover_hard_max": 54},
 "runnable": {"sweep": true, "verdict": true, "offcard": true, "noinput": true, "summary": true},
 "search":   {"timeout_s": 60},
 "limits_rev_by_kind": {"sweep": "…", "verdict": "…", "offcard": "…", "noinput": "…", "summary": "…"},
 "prompt_rev": {"sweep": "cr-sweep-2", "verdict": "cr-verdict-2", "offcard": "cr-offcard-2", "noinput": "cr-noinput-1", "summary": "cr-summary-2"}}
```

- 수치는 1M 창 · `CARD_REVIEW_MAX_TOKENS` 미설정(출력 몫 16,000 토큰 가정)의 어림이다. 실제 값은 엔진 계약 예제 `limits_1m.json` 이 못 박는다. 식은 m3-engine-ops E3-1 이다 — `narrative_max = int(rows_out × 0.25)`, `cover_max = max(1, (rows_out − narrative_max − 300) // 400)`, `cover_hard_max = cover_max × (1 + CARD_REVIEW_PARSE_RETRIES)`, `items_max = max(1, (rows_out − 800) // 600)`, `rows_out = OUTCAP × 0.6 × 1.05`. 낮은 고정 천장은 없다.
- `ctx_too_small` 은 `cell_kinds` 가운데 하나라도 못 돌 때만 선다. `runnable.summary=false` 인 박스는 셀 일을 멈추지 않고 요약만 코드 조립본(`code_only(ctx_too_small)`)으로 낸다.
- 최상위 `unit_body_max` 는 단위를 싣는 종류(`verdict`·`offcard`·`noinput`) 가운데 작은 값이다.
- `verdict.k = max(1, min(CARD_REVIEW_K, k_out))` 다. 1M 창·출력 상한 미설정이면 `k_out` 19 라 K 는 19 를 넘지 못한다(D-35). K·출력 상한·`ROW_CHARS`·새 상수는 `limits_rev` 에 들고, 관문 손잡이는 들지 않는다.

### 4.4 `POST /card-review/run` — 새 종류와 틀

요청은 M2.md 4.3 의 모양이고 다음만 다르다. 선언하지 않은 칸은 지금처럼 422 `unknown_fields` 다. 포털 중계는 본문을 통째로 넘기고 신원 칸 넷만 덮어쓴다(새 경로 없음).

#### 4.4.1 `sweep` 의 결손 블록(`cr-sweep-2`)

- 입력 결손 전문가의 훑기에 `extra.missing[{kind, note}]`(전문가 단위 결손)를 싣는다. 엔진은 [결측] 블록과 한 문장('결측 입력이 와도 무관한 단위만 no 다. 결측 때문에 가릴 수 없으면 maybe 다')을 더한다. 결손 없는 요청의 프롬프트는 그 문장 하나 말고 글자까지 같다.
- 다른 종류에 `extra.missing` 을 보내면 422 `bad_request` 다(단위 결손은 `unit.missing` 이다 — 둘을 섞지 않는다).
- 앱은 `meta.prompt_rev.sweep` 이 `cr-sweep-2` 이상인 답일 때만 입력 결손 전문가의 셀을 거른다(cells a-2).

#### 4.4.2 `noinput`(`cr-noinput-1`)

- 요청 — `kind:"noinput"`, `variant:null`, `cards` = 그 전문가의 카드 전부(점검·배경, 훑기 `k` 에 걸린 것 먼저, 나머지 팩 순서), `digest` = 전 카드 제목, `unit` = `review_payload` 출력에 `unit.missing[{kind:'ecad', note:<영역 실마리 — input-gap.v1.json>}]`, `extra.mechanisms`. `unit.missing` 이 비면 422 `bad_request`. 본문 몫을 넘는 카드 꼬리는 엔진이 제목으로 내리고 `meta.bg_dropped` 로 센다.
- 행(JSON Lines).

```
{"t":"q1","impact":"yes|no|unknown","title":"…","mech":"메커니즘 코드 또는 free","mech_free":"…","path":"…","l":["L03"],"k":"K05","cq":"…","sev":"경미|중대|치명","why":"…"}
{"t":"q2","item":"확인할 항목(없으면 \"\")","needs":"필요한 데이터","k":"K07","l":["L03"],"why":"…"}
{"t":"more","more":"yes|no"}
{"t":"inj","at":"…","text":"…"}
```

- 엔진 검사 — `q1`·`q2`·`more` 가 각각 한 줄 이상 없으면 `missing` 이고 보충한다. `impact=yes` 인데 `l` 이 비면 `checks.refs="missing"`(표지만). 전문이 실린 카드의 `cq` 는 원문에 대조한다(보충 사유). 제목만 실린 카드면 `checks.quote="digest_only"`. `mech` 가 목록 밖이면 `free` + `mech_free`. `q1` 이 `items_max` 를 넘으면 앞을 남기고 `quality.dropped_over_cap`. `q1` 줄 수가 `items_max` 이거나 `more=yes` 면 `quality.maybe_more=true`. `meta.basis="noinput"`.
- 앱 — `maybe_more` 면 받은 `q1.title` 을 `extra.known` 에 실어 최대 3번 다시 묻는다(카드 밖의 되묻기와 같은 규칙). `l` 은 그 단위의 줄, `k` 는 실은 별칭이어야 하고 `cq` 는 얼린 원문으로 다시 대조한다. 정산은 아래 표다(cells 3.6 — 셀 상태는 앱이 정한다).

| q1 | q2 | 셀 | `extras_json.noinput.outcome` |
|---|---|---|---|
| `impact='yes'` 가 하나라도 | 무엇이든 | `reviewed`(`basis='noinput'`) | `impact` |
| `yes` 없고 `unknown` 있음 | 무엇이든 | `no_input` | `unknown` |
| 전부 `no` | 항목 ≥ 1 | `no_input` | `request` |
| 전부 `no` | 항목 0(까닭만) | `reviewed`(`basis='noinput'`) | `none` |

- 받은 행은 `extras_json.noinput{q1[], q2[], outcome}` 과 호출 원장 `result_gz` 에 둔다. `rr_card_verdicts` 에는 쓰지 않는다. `q1 yes` 줄이 finding 후보다(`source_kind='card_review'`, 메커니즘은 `mech`, 정책 `hold`). `q2` 는 보고서의 '입력이 오면 확인할 것' 이다.
- 엔진이 `noinput` 을 모르면(`limits.kinds` 에 없음) 앱은 호출을 내지 않고 잡을 `agent_outdated`(300초 자동 재개)로 멈춘다(#35).

#### 4.4.3 `verdict` 의 `mech`(`cr-verdict-2`)

- `verdict` 요청이 `extra.mechanisms` 를 받으면 [메커니즘 목록] 블록(몫 `verdict.mech_max` = P 의 5%, 1.2 의 52종이면 약 1,500자)을 싣는다. 변형(`fwd`·`rev`·`solo`)과 상관없다.
- `v` 줄에 `mech`·`mech_free` 를 더한다. **WARNING·FAIL 줄에만 필수**이고 OK·na 줄은 비워도 된다. 목록 밖이면 `free` + `mech_free`. 걸렸는데 비면 `checks.mech="missing"` 표지만 남기고 보충하지 않는다. 메커니즘 목록 없이 온 verdict 요청은 지금처럼 돈다(칸은 비고 표지 `no_list`).
- 앱 — finding 의 메커니즘은 실효 행(단독 재질의가 있으면 그것, 없으면 묶음 판정)의 `mech` 다(`solo.get("mech") or eff.get("mech")`). 비거나 `free` 면 `cells` 대상에서만 `mechanism_detail='unclassified'` 이고 클러스터 키 세부 자리에 `'unclassified~' + free_key`(`mech_free` 를 NFKC·소문자·공백·구두점 제거한 앞 24자, 그것도 비면 `'card~' + (card_id or record_id)`)를 넣는다. `family_key` 에도 같은 규칙. 배정표의 소유 ∪ 관련 밖이면 표지 `mech_out_of_domain`(판정은 바꾸지 않는다).

#### 4.4.4 `offcard` 의 긴 문서 검색(`cr-offcard-2`)

- `extra.search{queries[1~3]}`(하나당 600자, 넘으면 끊고 `meta.search.req_cut`). 앱은 **카드 0장 전문가(`card_basis='none'`)에게만** 보낸다. 엔진은 LLM 전에 `status{step:"search"}` 를 내고 검색어마다 `agent_search(agent_type, q, mode=hybrid)` 를 동시에(각 `CARD_REVIEW_SEARCH_TIMEOUT_S`) 부른다. 도구는 사용자 PAT 만 쓴다(서비스 계정으로 내려가지 않는다).
- 적중의 `snippet`(절 본문 전체)을 `D01…` 로 싣는다. 몫 `offcard.longdoc_max`(본문 몫의 25%)를 순위 순으로 채우고 넘는 적중은 끊어 `clipped:true`·`orig_chars` 를 적는다. 점수는 임계로 쓰지 않는다.
- `meta.search{state, queries, hits_n, scope_n, used[{alias, record_id, section_id, title, chars, orig_chars, clipped}], note}` — `state ∈ ok · empty_scope · no_hits · failed`. 앞의 셋은 '물어봤다', `failed` 만 '못 물었다' 다. `f` 줄의 `src` 가 `D` 별칭이면 `q` 를 그 발췌에 대조한다. `basis` 는 실은 발췌가 있으면 `search_only`, 없으면 `role_only` 다.

#### 4.4.5 `summary`(`cr-summary-2` — 3라운드 반대 검토 뒤, 4.14)

- 요청 — `{kind:"summary", variant:null, target_key, expert:null, summary{scope{kind: domain|target, key, label}, rows[{ref:'reg:<cluster_key>', text}], must_cover['reg:…'], blocks[{name, title, text}]}, expect}`. `expert` 가 있는 summary 와 `summary` 칸이 있는 다른 종류는 422 `bad_request`, 빈 `rows` 도 422 다. 엔진이 `rows` 에 `R001…` 별칭을 매기고 결과 줄에 되돌린 `refs` 를 싣는다. `rows`·`blocks` 의 글은 «» 안에 그리고 안쪽 «» 를 지운다(앞 단계 LLM 글의 2차 주입 위생).
- 행(JSON Lines) — `head`(정확히 한 줄) · `risk` · `conflict`(`r` 둘 이상) · `gain` · `watch` · `ask` · `para`(한 줄 이상, 합 `narrative_max` 안 — 넘으면 `checks.long` 표지만) · `inj`. 앱이 객체(`headline`·`key_risks[]`·`conflicts[]`·`gains[]`·`watch[]`·`info_requests[]`·`narrative`)로 옮긴다.
- 검사 — 모르는 별칭은 지우고 `checks.refs="unknown_alias"`, `r` 이 비면(ask 제외) `checks.refs="missing"`. 수치가 `rows`·`blocks` 에 없으면 `checks.nums_unsourced`(표지만). `must_cover` 가운데 `risk`·`conflict` 어디에도 없는 별칭이 `missing` 이고 그것만 보충한다. 시도를 다 써도 남은 `missing` 은 결과에 그대로 실린다.
- 크기 — 조립이 `p_hard` 를 넘으면 LLM 0회로 422 `over_budget{need, have, part}`(다시 쪼개지 않는다), `summary.p` 를 넘고 `p_hard` 안이면 돌고 `meta.soft_over=true`. `must_cover` 가 `cover_hard_max` 를 넘으면 422 `cover_too_large`.
- 앱 — `rows` 는 그 범위의 등록부 행 **전부**(영역 요약은 `merged.domains` 에 그 영역이 있는 행, 종합은 주의 A 전부와 B 상위), 한 줄은 m3-synthesis 3.10 의 꼴(400자 안). `must_cover` 는 주의 A 를 우선순위 순으로 `cover_max` 까지, 넘는 A 는 코드 표에만 두고 '서술은 A 상위 N건 — 나머지 M건은 표' 를 보고서에 적는다. 엔진의 `missing`·`nums_unsourced` 가 남으면 지적을 실어 한 번 다시 묻고 그래도면 `code_only(checks_failed)`. `meta.basis="rows"`.

#### 4.4.6 프레임

M2.md 4.3 의 프레임 그대로이고 `status{step:"search"}` 하나가 는다. `result.meta` 에 `search{…}`(offcard), `basis ∈ cards · background · role_only · search_only · noinput · rows`, `checks.mech`·`checks.quote`·`checks.refs`·`checks.nums_unsourced`·`checks.long` 이 는다.

### 4.7 비우기 계약(update-all 동안)

**`/health` 에 더하는 것.** 기존 `delib_active`·`delib_queued` 는 이름도 뜻도 그대로다(재기동 미룸 판정 — 리스크 앱 패널도 센다). 카드 대조는 거기 세지 않는다.

```json
{"delib_active": 0, "delib_queued": 0, "review_active": 3,
 "draining": false,
 "drain": {"on": false, "scope": null, "until": null, "until_idle": null, "hold": false, "by": null, "reason": null, "set_at": null},
 "capabilities": ["card_review", "drain"],
 "card_review": {"…M2 칸…", "kinds": ["sweep", "verdict", "offcard", "noinput", "summary"], "limit": 8, "limit_reason": "normal|delib_human|draining", "delib_human": 0},
 "load": {"chat": {"active": 1, "window": 50, "ttft_ms": {"idle": {"n": 50, "p50": 2100, "p95": 6100}, "review": {"n": 31, "p50": 3900, "p95": 11800}}, "ratio_p50": 1.86, "slow": false, "slow_since": null}}}
```

- `card_review.delib_human` 은 `started_by` 가 `app` 이 아닌 도는 심의 수이고, 관문은 그것이 1 이상일 때만 절반이다(#26).
- `draining`(범위 `all`)이면 `card_review.limit=0`·`limit_reason="draining"` 이고 새 run·pack(요약 포함)은 1초 안에 `error{review_busy, reason:"draining"} → done` 이다(LLM 을 부르지 않는다).
- `load.chat.ttft_ms` 는 챗 턴의 첫 `on_chat_model_start` 에서 첫 스트림 조각까지다(도구 왕복 제외, E3-9). `slow` 는 두 고리가 다 10턴 이상이고 `review.p50 > 2 × idle.p50` 일 때 참이고, 참으로 바뀌면 엔진 로그에 한 줄을 낸다.

**`/drain`.** `POST /drain {on, scope: all|panels, ttl_s | until_idle{grace_s, max_s}, hold?, by, reason, force?}` · `GET /drain`. `hold` 깃발은 `hold` 아닌 요청으로 안 바뀐다(409 `drain_held`). 수명은 늘리기만 한다. `until_idle` 은 심의 합이 처음 0 이 된 때부터 `grace_s` 뒤에 풀리고, 그 전에 심의가 다시 서면 시계를 지우며, 어떤 경우에도 `max_s` 를 넘기지 않는다. 판정은 읽을 때 한다. 깨진 파일은 '꺼짐' 으로 읽고 지운다. 인증은 없다(루프백). **포털은 `/drain` 을 중계하지 않는다.**

### 4.8 관문 셈과 일일 상한(#26 · #27)

- 포털 `DelibOpts` 에 `started_by: Literal["human","app"] | None` 을 선언한다(선언하지 않은 키는 조용히 버려진다 — 그러면 표지가 사라져 관문이 보수 쪽인 절반으로 간다). 리스크 앱 `runner.build_delib_opts` 가 러너가 편성한 모든 패널(쟁점·옛 흐름 coverage)에 `started_by:"app"` 을 싣는다. 엔진은 심의 기록에 그 값을 두고, 관문의 절반 판정만 `started_by ≠ app` 인 도는 심의(분리 태스크 + MCP 잡)로 센다. `delib_active`·`delib_queued`·update-all 의 미룸 판정은 그대로 전부 센다.
- 표지는 스스로 밝히는 값이다. 잘못 달아도 카드 대조 동시 수가 4 대신 8 이 될 뿐이라 검증하지 않는다.
- 하루 패널 상한(`HWAXRISK_DAILY_PANEL_CAP` 24)은 `kind='coverage'` 패널만 센다(`runner._panels_today`). `mode='issues'` 잡은 `daily_cap` 으로 멈추지 않는다. 과제당 쟁점 상한(24/48)만 따른다.

### 4.9 거르기 · 표본 · 이중 판정(리스크 앱 두 꾸러미 사이)

- **분류.** m3-cells 3.2 의 열 줄 결정표 그대로다(처음 맞는 줄 — `filter_off` · `rank1` · `global_unit` · `no_cards` · `input_gap`(결손 블록 없는 훑기) · `widened`·`filter_off`(넓힘·대상 전체 끔) · `handoff` · `tier_a_pending` · 두 신호가 다 무관이면 거름(표본 해시 아래면 `audit`) · 그 밖 검토). 모르면 검토다. 분류는 훑기 바로 뒤 한 번이고, 같은 원장·같은 손잡이면 재기동해도 같은 셀이 걸러지고 같은 셀이 표본이 된다. `route_json` 에 두 신호·규칙·`routing_rev` 를 얼린다.
- **코드 신호.** 단위 줄의 `code` → `change-routing.v1.json` 의 `codes`(정확 일치 또는 끝 `*` 접두) → 없으면 `change_kinds` → 메커니즘 → `mech-owners.v1.json` 의 소유 ∪ 관련 → 영역, 그리고 부품 역할 → 영역(더하기만). 풀리지 않는 줄이 하나라도 있으면 관련이 아닌 영역 전부가 `unknown`. `mechanisms: []` 는 '설계 변경이 아니다'(관련도 모름도 아니다). 읽는 함수는 `taxonomy.mech_owners()` · `domains_for(codes)` · `mechanisms_of(domain)` · `mech_owners_meta()` 다. 불변식 — 택소노미 active 코드마다 배정표 한 행·소유 1개 이상, 15개 영역이 전부 어느 행엔가 나온다, 한 행에서 소유와 관련이 겹치지 않는다.
- **승인 문(#40).** `mech-owners.v1.json` 의 `review_status` 와 `change-routing.v1.json` 의 `status` 가 **둘 다** `approved` 가 아니면 코드 신호는 전 영역 `unknown` 이고 거르기가 일어나지 않는다. 잡은 만들 때의 승인 여부를 `routing_approved` 로 얼린다 — 승인 커밋은 다음 잡부터 듣는다.
- **표본·그림자·넓힘(#42).** 즉시 표본 `sample_score('filter_audit', T, u, a) < audit_pct/100`, 잡 끝 보충 표본 `n_audit = max(ceil(audit_pct% × N_filtered), min(N_filtered, 59))` + 영역마다 1건(채운 뒤에야 `completed` — 사슬보다 먼저). 1순위 셀의 `would_filter` 는 그림자로 적는다. 결과 넷 `risk_miss · relevance_miss · undetermined · kept`(`review_verify.audit_outcome`). `risk_miss` 가 나오면 그 영역을 그 대상에서 넓히고(거른 셀 전부 다시 연다), 셋째 영역에서 대상 전체 거르기를 끈다. 넓힘은 저장하지 않고 원장에서 유도한다. 늦게 온 넘김(`h` 줄)은 이미 걸러진 (단위, 영역) 셀을 다시 연다.
- **이중 판정(#31).** `flagged` — 셀 · 묶음마다 fwd 실효(빠진 카드 재질의 뒤)가 FAIL·WARNING 인 별칭이 둘 이상이면 그 별칭만 실은 rev 한 번, 하나면 rev 없이 단독 재질의가 두 번째 판정이다. `_Cell.dual_decks` 는 별칭 집합 `dual_aliases` 로 바꾼다. 1순위 셀(`dual_calib='tier_a'`)은 묶음 전체를 rev 한다(보정 모집단, 약 +225 호출).
- **무작위 뒤집기 자동 켬(#32).** 대상의 1순위 셀이 다 종결된 때(분류 8번 줄이 풀리는 때와 같다) 보정 모집단의 '걸림 없음 → 걸림' 비율(fwd 실효가 OK·na 인데 rev 가 FAIL·WARNING 인 카드 / fwd 실효가 OK·na 인 카드)이 `DUAL_NEG_TRIGGER`(5%)를 넘으면, 그 대상에서 그 뒤에 rev 를 정하는 1순위 밖 셀의 걸림 없는 묶음 가운데 `sample_score('dual_neg', T, u, a, deck) < dual_neg_pct/100` 인 것을 rev 한다. 켜짐은 원장에서 유도하고(저장하지 않는다) 한 번 켜지면 그 대상에서 꺼지지 않는다. 이미 정산된 셀은 다시 돌리지 않는다. 셀마다 `sample_json.dual_neg{on, picked}` 를 적고 보고서·품질이 켜진 때와 그 뒤 셀 수를 싣는다. 1순위가 범위에 없어 보정을 못 잰 잡은 켜지지 않고 '미측정' 으로 적는다.
- **보이기.** 거른 셀은 보고서 표에 '거름 — 까닭' 한 줄로 남고(조용히 빼지 않는다), 비율은 `risk_miss / 표본`(정확 이항 95% 상한)과 보수 상한 `(risk_miss + undetermined) / 표본` 둘을 싣는다. '음성 → 걸림' 뒤집힘은 보정 모집단(과 켜졌으면 무작위 표본)으로만 말하고 그 밖은 '미측정' 이다.

### 4.10 완결 몫 — 셀 셈에서 잔여까지

- **셀 몫(cells → synthesis).** `review_cells.closure_cells(store, target_key)` 의 모양은 m3-cells 3.10 그대로다(`grid` · `by_state` · `by_basis` · `failed{open, by_code}` · `skipped{n, experts, by_note}` · `filtered{n, would_filter, by_domain, audit{…, floor_met, upper95, upper95_conservative}, shadow, widened, off}` · `no_input{experts, cells, by_outcome}` · `undetermined{rows, cells}` · `out_of_scope_pending` · `invariants[]`). GROUP BY 라 폴링에도 쓴다. 나갈 기준 1 의 코드 판정이 `by_state.pending + running == 0 and invariants == []` 다. 롤업 사유 문자열은 4.1 의 것이고 완결 판정이 그것으로 깊이·strong 분모를 가른다.
- **완결(synthesis).** `registry.close_level` 은 문지기다 — `flow='cells'` 면 `closure.close_level_cells`, 아니면 지금 본문(`_close_level_panels`). 레벨 어휘는 넓히지 않는다. C1 = 단위 ≥ 1 · 미배정 0 · 격자 완전 · 요구 영역의 1순위 대표 셀 전부 닫힘. C2 = C1 + Tier B 범위 닫힘 + 영역별 깊이(**실제로 검토한 전문가만** — `active` 는 거르지 않은 셀이 있고 입력 결손이 아닌 전문가, `have` 는 그 가운데 `basis='cards'` 인 `reviewed` 셀이 있고 셀이 다 닫힌 전문가, `need = active if active < 3 else max(3, ceil(0.3·active))`) + 쟁점 신선 + P1 열림 0. C3 = C2 + 격자 전부 닫힘 + 넘김이 '거르지 않고 입력 결손도 아닌 셀' 의 5% 이하 + 쟁점 열림 0 + 마지막 보고서 판 신선 + 막음 잔여 0 이거나 전부 유효하게 확인. 저장 레벨은 내려가지 않고 `level_current`·`regressed` 로 알린다.
- **잔여.** 모든 레벨에 그 범위의 잔여를 붙인다. '막음' 은 확인 전에 저장 레벨이 `C2(closed)`·`C3` 로 오르지 않는다는 뜻이다.

| item | 세는 것 | 막음 |
|---|---|---|
| `input_gap` | `no_input` 셀과 그 전문가 수·영역(영역 전원이 결손이면 영역 이름까지) | 막음 |
| `failed` | `failed` 셀(사유별) | 막음 |
| `skipped` | 사람이 넘긴 셀 + (영역 × 단위)마다 넘김이 그 칸의 절반을 넘은 곳 | 막음 |
| `issues_untried` | 쟁점 `untried_cap`·`inconclusive`·`skipped`(P1·`held_fail` 따로, '전문가 N명이 FAIL 로 봤으나 미토의') | 막음 |
| `filtered` | 거른 셀과 표본 결과 | 표기. 표본 바닥을 못 채웠거나 놓침 상한이 5% 를 넘거나 거르기가 꺼졌다 켜졌으면 막음 |
| `unit_excluded` | 제외 단위 가운데 `capture_partial`·`partial_scope`·`source_drift`(그 밖은 수만) | 막음 |
| `quality` | `review_quality.compute` 의 기준 밖 항목 + 셀 기준 strong 0.7 미달 | 막음 |
| `undetermined` | 적용 판정 가운데 `unknown`·`undetermined` 행의 비율(X1-15) | 20% 를 넘으면 막음, 아니면 표기(#52 — 사용자 확인 대기) |
| `no_cards` | 카드 0장 전문가와 그 basis(`role_only`·`search_only`·`search_failed`) | 표기(#38) |
| `cross_not_run` | M3 에서는 늘 있다 — 넘김 줄 수와 (영역 → 영역) 쌍 수 | 표기 |
| `mech_not_run` | M3 에서는 늘 있다 — 셀의 메커니즘 신고 표 | 표기 |

- 확인으로 넘길 수 **없는** 것 — 미배정 변경, 격자 결손, `pending`·`running` 셀, `reviewed` 셀의 카드 판정 누락, 전문가 보고서 누락, 쟁점 `queued`·`planned`·`running`, 후속 낡음(`chain_stale`). 이것들은 레벨 조건에서 거짓으로 걸리고 표기에 붙는다.
- 표기 `level_label = "<레벨>" + ("(" + 잔여 표기를 ' · ' 로 + ")" if 잔여 else "")`. `cells` 대상에는 `cross_not_run`·`mech_not_run` 이 늘 있으므로 **맨 `C3` 는 M3 에서 나오지 않는다** — 최선은 `C3(2차 영향 미실행 · 결손 사냥 미실행)` 이다. 보고서 제목·진행판·MCP 가 이 문자열을 쓴다.
- 확인(ack)은 막음 잔여 한 종류씩, 사유 필수(300자 안), 확인 시점의 `basis_hash` 를 함께 받고 다르면 409. **소유자·관리자만, 웹·REST 만**이다(편집자 403, MCP 쓰기 도구 없음).
- 캐시 — `closure.refresh` 가 병합·쟁점 해결·셀 처분·확인·보고서 조립 뒤에 `rr_targets.closure_json`·`level_label`·`closure_at` 을 쓴다. 진행판과 MCP 는 캐시를 읽고 `GET …/closure?fresh=1` 만 다시 센다. 보고서의 모든 수는 같은 호출 안의 `closure.cell_counts` 한 벌에서 나오고 그 값이 `rr_reports.counts_json` 이다.
- **사슬.** 검토 잡 `completed` 뒤 `chain.on_reviews_closed` — 마감 범위(`cells` 대상 기본 C3 = 격자 전부)에 열린 셀이 남았으면 병합·`closure.refresh`·코드 조립 판(`reviews_partial`)만, 다 닫혔으면 판(`reviews_closed`) 뒤 쟁점 선정 → `issues` 잡(없으면 `synth`) → `synth` 잡. 다음 잡 생성은 앞 잡의 전이와 다른 트랜잭션이고 `chain.sweep`(30초 틱)이 끊긴 사슬을 메운다. 자격 검사로 행을 만들지 않는 일은 없다(자격이 없으면 `queued` + `error`). `issues` 잡이 `failed` 여도 남은 쟁점을 `untried_cap(engine_fail)` 로 옮기고 `synth` 를 잇는다. 사람이 취소하면 잇지 않는다.

### 4.14 반대 검토 2라운드 뒤 고친 모양(10-14, D-40)

반대 검토 4라운드 뒤(엔진 `4d569e8..1feec22`, D-42) 바꾼 것.

- **별칭표 `ENUM_ALIASES`**(대소문자를 접고 공백을 모두 뺀 뒤 맞춘다 · 원래 말은 줄의 `checks.alias` 에 `"필드:말"` 로) — 별칭은 강제가 아니라 모델의 명시적 뜻이다. rel → no: none · irrelevant · not relevant · n/a · 없음 · 무관 · 해당 없음 / rel → yes: relevant · likely · 해당. impact → no: rel 과 같은 일곱 / impact → yes: likely · relevant · 해당 · 있음. judgement → OK: pass · passed · 통과 · 문제없음 / WARNING: warn · 경고 / FAIL: failed · 실패 / na: n/a · 해당 없음(적용 안 됨은 OK 가 아니라 그 필드의 na 다). 표는 엔진 README 계약 절에 있고 시험이 코드와 맞댄다.

달력으로는 단계 A~D 가 M2 의 두 배 남짓이다(걸음 51 대 30여). cae00 단계 E 는 M0-b(보강 팔 1~2시간 더) · M0-d · 파일럿 · 전원 실주행(동시 8·호출 5분이면 셀 일 3~4일, 배정표 승인 전이면 약 7일) · 쟁점 패널(대상 안에서 한 줄 — 24건이면 반나절~하루, P1 48건이면 하루~이틀) · 종합(한 시간 남짓)이다. 호출 시간이 가정의 3배면 셀 일이 3배다.
