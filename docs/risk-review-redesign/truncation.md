# 글자 잘림 해소 — 1백만 토큰 기준 (M1, 2026-10-10~11)

> 사용자 지침(2026-10-10) — "glm 5.2 1백만 토큰 가정한 시나리오로 전부 해줘 하다보면 글자 잘려서 생겼다는 문제가 대부분임."
> 1차 조사 원본(351곳)은 [reference/truncation-inventory.md](reference/truncation-inventory.md) 에 있다. 이 문서는 무엇을 어떻게 바꿨고 무엇을 일부러 남겼는지의 요약이다.

## 원칙

- **창에서 유도한다.** 작은 창 시절에 박은 고정 상한(글자·건수·줄)은 모델 창에서 몫을 나눠 정한다. 운영(cae00, GLM-5.2 · 1,048,576 토큰)에서는 상한이 사실상 풀리고, dev(16K)에서는 종전 값이 바닥으로 남는다.
- **환경변수는 낮출 때만 쓴다.** `.env` 에 값을 적으면 그 값이 천장으로 걸린다. 적지 않으면 창에서 유도한다. 낡은 설정 한 줄이 넓은 창을 도로 좁히지 않게, cae00 절차서가 적힌 줄을 찾아 보게 한다.
- **남는 절단은 조용하지 않다.** 잘랐으면 원문 길이를 표식에 넣고(`…[N자 중 앞 M자]`), 화면 카드·원장·경고로 남긴다.
- **바깥 한도는 쪽으로 나눈다.** 우리가 정할 수 없는 한도(Claude Code 의 MCP 결과 상한 등)는 잘라 버리지 않고 쪽을 나눠 다음 쪽을 안내한다.

## 1백만 토큰 창에서 몫이 얼마나 되나 (엔진 계산값)

| 몫 | 16K(dev) | 128K | 1,048,576(cae00) |
|---|---|---|---|
| 좌석 사전 근거(`/health` 의 `evid_budget`) | 2,000자 | 20,067자 | 389,648자 |
| 좌석이 받는 직전 라운드 | 48,000자 | 48,000자 | 193,850자 |

나머지 몫(지식카드·자유 조회 결과·지정 도구 결과·이어하기 결정문·사람 의견·의장 전사·챗 이력)도 같은 방식으로 창에서 나눈다.

## 바꾼 것 (리포별 대표)

- **심의 엔진(HWAXAgentServer)** — 다음 라운드로 넘기는 발언 값당 700자·라운드 합 48,000자, 좌석이 직접 조회한 결과 호출당 900자·합 3,500자, 지정 도구 결과 도구당 2,000자·합 5,000자, 지식카드 한 줄 700자·좌석 합 3,500자, 이어하기 결정문 8,000자, 사람 의견 2,000자, 깨진 좌석 JSON 2,000자, 기록용 발언·RA 회의록 12,000자, 후처리(요약·쉬운 설명·심판)의 입력 상한을 창에서 유도하거나 원문을 보존하게 바꿨다. 챗→심의 맥락과 챗 이력은 최근 것부터 담는다. 챗 도구 결과가 여러 건 쌓여 창을 넘으면 오래된 결과부터 원문 길이를 적고 줄인 뒤 알린다.
- **리스크 앱(HWAXRisk)** — 브리프 크기를 웹 경로는 엔진이 알려 주는 근거 예산에서 정한다. 좌석 발언을 2,000자로 받던 것을 원문(`say_full`)으로 받는다. 변경 목록의 전체 건수와 잘린 줄 수를 남긴다. 잡 메모·오류 문구·의장 글의 칸을 자르지 않는다.
- **포털(HWAXPortal)** — 중계·대화 저장·Word 내보내기·심의 파이프라인 JS 의 상한을 엔진이 보내는 크기에 맞췄다.
- **게이트웨이(HWAXMcpGateway)** — Claude 가 받는 도구 결과를 자르지 않는다. 응답 캐시에는 바이트 상한을 두어 큰 결과는 캐시하지 않고 그대로 돌려준다.
- **AIDataHub** — 검색 결과의 스니펫·절 수·top_k 상한을 풀고, 재정렬 입력은 모델 한도(8,192토큰)에 맞춰 스레드에서 돌린다.

## 일부러 남긴 한도

| 한도 | 까닭 | 어떻게 다루나 |
|---|---|---|
| Claude Code 의 MCP 결과 상한(약 25,000토큰) | 받는 쪽(Claude Code)의 한도다 | `deliberate_*` 도구는 쪽을 나눈다(`DELIB_MCP_PAGE_CHARS`, 기본 25,000자). 리스크 앱의 스냅샷·등록부·인용 조회도 `offset` 으로 다음 쪽을 준다 |
| Claude Code 보충 회차의 리스크 브리프(11,000자·12건·항목 2,000자) | 워크플로가 브리프를 LLM 출력으로 옮겨 적어야 받는다 — 크게 보내면 실패로 바뀐다 | 옛 크기로 두고 잘린 것은 브리프 안·응답·패널 품질에 표시한다. 팀이 쓰는 주 경로(Claude 에서 엔진 직접 호출)는 1백만 토큰을 그대로 쓴다 |
| 근거 항목 120건·항목 150,000자 | 포털 요청 모델·프론트와 같은 값이어야 한다는 계약이 있다 | 합계 예산으로 막고, 빠진 항목은 키와 함께 카드로 알린다 |
| 임베딩 모델 입력(e5-base 512토큰) · 재정렬 모델(8,192토큰) | 모델 자체의 한도다 | 그 한도 안으로 넣고 넘은 것을 경고로 남긴다 |
| AIDataHub 기록 요약 500자 | 문서화된 스키마 규칙이다 | 둔다 |
| 포털 메시지 한 칸 4,194,304자 | 요청 크기 보호 | 1백만 토큰 창보다 크다 |

## 미룬 것

- 교차심문의 '다른 전문가 한 줄 입장' 160자, 조회 서명 1,200자, 좌석 도구 스키마 예산 — M2 에서 좌석 프롬프트를 다시 짤 때 본다.
- 숫자 손잡이를 죌 때(라운드 2~8 등) 알리는 카드 — 카드 종류를 새로 둬야 한다.
- AIDataHub 4단계 이하 절의 색인 단위 — 전 기록 재동기화·재임베딩이 필요해 사용자 결정으로 미룬다(지금은 경고만).
- 좌석 초안 작성(`draft_agent`)의 출력 상한 900토큰 — 심의 경로가 아니다.
