# 챗 자기검증 — 결정과 까닭

> 계획 [PLAN.md](PLAN.md) · 체크리스트 [checklist.md](checklist.md).

**SC-D1 사용자 결정 셋(2026-10-23).** ① 검증한 답만 본문에(초안은 '생각 중' 칸) ② 같은 챗 모델이 검증(GLM 에 짐을 더하지 않는다 — 10-17
결정) ③ 항상, 근거도 수치도 없는 짧은 답만 건너뜀.

**SC-D2 열다섯 군데를 고치지 않고 턴을 감싼다(10-23).** 챗 한 턴(`_agent_stream_turn`)은 글을 내는 자리가 열다섯이다(스트리밍 조각 ·
비스트리밍 완결 · 빈 응답 구제 · 마무리 문구 · 대체 발췌 …). 자리마다 '검증이면 생각 칸으로' 를 넣으면 하나만 빠져도 초안이 본문에 섞인다.
감싸개가 우리가 만든 SSE 프레임을 읽어 token 을 reasoning 으로 바꾸고 result · done · meta 를 붙잡는다 — 새 자리가 생겨도 저절로 따른다.
근거 블록은 안쪽이 초안에 붙이지 않고(`box`) 감싸개가 고친 답으로 다시 센다(초안의 '출처 없는 수치' 를 검토자가 지웠으면 경고도 사라져야 한다).

**SC-D3 검토자는 생각을 끈다(기본, 10-23).** 챗 서버(stcx Qwen)는 생각을 켠 채(xhigh) 돈다. 같은 설정으로 검토하면 턴이 두 배를 훌쩍 넘는다
— 사용자가 받아들인 것은 '조금 느려져도' 다. 검토는 정해 둔 다섯 가지를 근거와 견주는 일이라 지시 목록으로 버틴다고 봤다. 켜려면
`CHAT_SELF_CHECK_THINK=1`(그때 생각 글도 '생각' 칸으로 흐른다). 끄는 값(`chat_template_kwargs.enable_thinking=false`)이 넘김 묶음
(`RunnableWithFallbacks`)을 지나 챗 서버에 닿는 것은 실제 기동 경로 시험(가짜 서버 — 생각을 켠 요청이면 생각 글을 낸다)으로 봤다.

**SC-D4 건너뛰기는 이번 턴의 근거만 본다(10-23).** 조회 · 붙인 문서 · 올린 그림이 없고, 400자 미만이고, 대조할 수치(소수 · 100 이상)가 없을 때만
건너뛴다. 처음엔 앞 대화의 그림도 넣었는데, 그러면 오래전에 그림을 올린 대화의 '고마워' 까지 검증해 느려질 뿐이다. 앞 대화의 그림을 묻는
답은 대개 수치가 있거나 길어 어차피 검증한다.

**SC-D5 몫은 넘칠 때만 나누고, 쓰지 않는 몫은 넘치는 쪽으로(10-23).** 첫 구현은 고정 비율(조회 결과 55% · 문서 25% · 앞 대화 20%)이라
문서도 앞 대화도 없는 턴에서 조회 결과가 창의 55% 에서 잘렸다(16K 창 시험에서 입력 6,799 토큰 — 창의 절반도 안 썼다). 제 몫 안에 드는
쪽은 다 주고 남는 몫을 넘치는 쪽에 비율대로 다시 나눈다(`_sc_shares`, 드는 쪽이 없어질 때까지). 앞 대화는 최근 것부터 담는다.

**SC-D6 고친 답은 '생각' 칸에 다시 흘리지 않는다(10-23).** 화면은 result 를 받으면 본문을 그 글로 바꾼다. 검토자 글을 통째로 '생각' 칸에 흘리면
펼쳤을 때 고친 답이 본문과 두 번 보인다. `[답]` 표지 앞(판정 · 고친 점)까지만 흘리고, 뒤는 상태줄 '고친 답을 쓰는 중' 으로 바꾼다. 표지가
조각 경계에 걸칠 수 있어 끝 두 자를 다음 조각까지 쥔다(한 자씩 · 두 자씩 … 쪼갠 시험).

**SC-D7 고친 답은 다 쓴 뒤 한꺼번에 낸다(10-23).** 흘려 보내면 첫 글자가 빨리 보이지만, 가드(끊김 · 지나치게 짧음 · 그림 잃음)는 끝에서야
알고, 그때 초안으로 되돌리면 화면의 본문이 통째로 바뀐다. '검증한 답만 본문에'(SC-D1 ①)를 지키려면 다 본 뒤에 낸다. 대가로 검증 동안 본문이
빈다 — '생각 중' 칸과 상태줄이 진행을 보인다.

**SC-D8 시험 환경은 자기검증을 끈다(10-23).** 챗 턴 시험들이 LLM 호출 수 · 흘린 글을 그대로 센다. 루트 conftest 가 `CHAT_SELF_CHECK=0` 을
두고, 자기검증 시험이 제 손으로 켠다. 기본값이 켬이라는 것은 따로 시험한다(`test_기본은_켬이고_0_만_끈다`).

**SC-D9 화면 자리(10-23).** 고쳤다 · 검증하지 못했다는 답을 읽는 사람이 알아야 할 일이라 답 아래에 늘 보인다(펼치면 무엇을 왜). 고칠 것
없음 · 생략은 소음이라 모델 표시 옆(마우스를 올려야 보이는 줄)에 둔다. 검증 못 함(suspect)에는 검토자가 짚은 곳을 '반영하지 않음' 으로
함께 보인다 — 고친 답은 버렸어도 짚은 점은 쓸모가 있을 수 있다.

**SC-D10 검토자 호출도 이 턴의 모델 호출로 센다(10-23).** 모델 표시(C3)는 '이 답을 낸 모델(호출 수)' 이다. 검토자도 답을 바꾼 호출이라
`meta.models` 에 더한다. 실패한 호출은 세지 않는다.

**SC-D11 '고쳤다' 는데 바뀐 글자가 없으면 ok(10-23).** 판정만 '고침' 이고 답이 초안과 같으면 고친 곳 목록은 사실과 다르다. 판정은 굵게 ·
띄어쓰기가 섞여도 읽고(`**고침**` · `고칠 것 없음` · `고침 없음`), 꼴 밖이면 unreadable 로 초안을 낸다.
