# 챗 자기검증 — 답을 근거와 대조해 한 번 고친 뒤 낸다 (2026-10-23)

> 체크리스트 [checklist.md](checklist.md) · 결정 [context-notes.md](context-notes.md). 대상은 HWAXAgentServer(챗 한 턴)와 HWAXPortal 화면(검증 표시).

## 1. 무엇 · 왜

사용자 요청(10-23) — 포털 챗으로 대화할 때 늘 자기검증을 해서 답의 완성도를 높이고 싶다(조금 느려져도). 지금 있는 검증은 **근거 블록**
하나다 — 코드가 답의 수치를 이번 턴 조회 결과와 대조해 출처 없는 값을 경고로 붙인다. 표시만 하고 답을 고치지는 않는다.

## 2. 사용자 결정(10-23)

1. **검증한 답만 본문에** — 초안은 접히는 '생각 중' 칸에 흐르고(진행이 보인다), 본문에는 검증을 거친 답만 나온다. 아래에 '검증 — 고친 것 N곳'.
2. **같은 챗 모델이 검증한다** — 10-17 결정(챗은 stcx · 심의는 GLM)대로 GLM 에 짐을 더하지 않는다.
3. **항상** — 근거(조회 · 붙인 문서 · 그림)도 수치도 없는 짧은 답(인사 등)만 건너뛰고 '검증 생략' 이라고 적는다.

## 3. 바꾸는 것

| # | 무엇 | 어디 |
|---|---|---|
| S1 | 챗 한 턴을 감싼다 — 초안 글(token)은 '생각 중' 칸(reasoning)으로 돌리고, 결과 · 끝 · meta 는 붙잡는다. 초안이 끝나면 검증 → 고친 답을 본문(token)으로 → 근거 블록은 **고친 답**으로 다시 셈 → meta 에 `self_check` → 결과 · 끝. 오류 · 조기 종료 길은 초안을 본문으로 그대로 흘린다 | 에이전트 `_agent_stream` · `_agent_stream_turn(box)` |
| S2 | 검토자 호출 하나 — 질문 · 초안 · 이번 턴 조회 결과 · 붙인 문서 · 앞 대화(최근) · 코드 대조(출처 없는 수치)를 이 턴의 창 안에 싣고, 다섯 가지를 본다(빠진 물음 · 근거 없는 수치/사실 · 근거와 어긋남 · 계산/단위 · 빠뜨린 조회 결과). 고칠 곳만 고치고 나머지는 그대로. 창은 고친 답을 쓸 몫(초안의 1.3배 + 1,024)을 먼저 떼고, 넘치면 조회 결과 55% · 문서 25% · 앞 대화 20%(쓰지 않는 몫은 넘치는 쪽으로, SC-D5). 검토자는 생각을 끈다(SC-D3). 판정 · 고친 점은 '생각' 칸에 흐르고 고친 답은 본문으로만(SC-D6) | 에이전트 `_self_check_messages` · `_self_check_stream` |
| S3 | 지킴 — 검토자 답을 못 읽거나 · 고친 답이 비었거나 지나치게 짧거나 · 초안의 그림 링크를 잃었거나 · 출력 상한에서 끊겼거나 · 호출이 실패하면 초안을 그대로 내고 까닭을 meta 에 적는다(고칠 점은 보인다) | 에이전트 |
| S4 | 화면 — 고쳤으면 답 아래에 '검증에서 N곳을 고쳤습니다'(펼치면 목록), 검증 못 함은 답 아래에 늘 '검증하지 못해 초안을 그대로 보였습니다' + 까닭 + 검토자가 짚은 곳. 고칠 것 없음 · 생략은 모델 표시 옆에 '검증 ✓' · '검증 생략'(SC-D9) | 포털 `MessageList` · `types/chat` |
| S5 | 손잡이 — `CHAT_SELF_CHECK`(기본 1 · 0 이면 종전 그대로) · `CHAT_SELF_CHECK_THINK`(검토자 생각, 기본 0 — 빠르게) | 에이전트 env |

## 4. 하지 않는 것

- **보강 조회** — 검토자가 '조회가 더 필요하다' 고 보면 도구를 다시 부르는 것. 훨씬 느려 다음 단계로 둔다. 지금은 근거가 없으면 '근거 없음' 으로 표시만 한다.
- 띵킹 · 심의 — 그쪽은 따로 된 구조(좌석 · 의장 · 품질 점검)가 있다. 일반 챗(전문가 지정 챗 포함)만.
- 조회한 자료 자체의 오류 — 검토자는 근거와 답을 견줄 뿐이다.

## 5. 확인

가짜 LLM 으로 감싸개 · 지킴 · 생략 · 오류 길 · 근거 블록 재계산 · 검토자 입력(예산 · 잘림 표지) · 끄기 · 실제 챗 한 턴(가짜 LLM 서버 두 호출) · 변이 ·
에이전트 전체. 화면은 브라우저 시험(검증 표시). 검증 품질 자체(고친 것이 맞나)는 실모델이 있어야 잰다 — dev 에는 지금 그림 · 챗 모델이 없다.
