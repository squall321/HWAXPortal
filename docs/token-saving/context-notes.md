**TS-1 검토(2026-11-02 KST, 읽기만) — 설계안 v1.0 은 대부분 맞게 읽었지만 이미 있는 것을 여럿 놓쳤다.** P1 보기 머리는 E-4(10-31)로 이미 지어져 PC 설정 한 줄이면
된다. P5(리스크 앱 `risk_create_diff` · `risk_get_diff(summary)`) · P9 · R7(WDA 렌더 · TTS) · P7(WDA 마크다운 → docx) · 보고서 → 발표자료('발표자료로' 11-01)는

틀린 주장 셋 — `_RESP_CACHE` 는 큰 결과(1 MB 넘음)를 넣지 않아 손잡이 저장소로 못 쓴다 · P2 의 '그 사람의 PAT 로 다시 부른다' 는 MCP 잡에 맞지 않는다(사람 ·
그룹 · 소속 머리만 넘어온다) · `status_wait` 이 아니라 `review_task_next` 가 본뜰 꼴이다.

**TS-2 '1/10' 은 설계안 숫자로도 나오지 않는다.** 효과 합 52.3%p(남는 몫 약 1/2) — 겹침을 빼면 더 작다. 가장 큰 지렛대는 목록 밖이다 — Claude 가 좌석 · 판단 과제마다
직접 도는 워크플로(`infra/pipeline/hwax-deliberate.js` · `hwax-risk-claude.js`)를 서버 엔진(GLM)으로 돌리는 것. 그래서 순서를 PC 설정(P1) → 작은 코드(P3 · P4a ·
search_tools 압축) → cae00 측정 → 중간(P2 · P4b) → 나머지로 둔다.

**TS-3 게이트웨이 공통 결과 줄이기(P4b)는 연결 머리로 고를 때만 한다.** `via=pat` 로 가르면 개인 PAT 로 도는 서버 쪽 길(루틴 · 리스크 앱 · MXWP 위키)까지 줄어든
결과를 받는다. 엔진(GW_TOKEN) · 챗 · 절차 · 패널은 늘 그대로. 출력 스키마가 있는 도구는 `structuredContent` 도 함께 줄여야 Claude Code 가 받는다. 검증 근거에는
전체 결과를 남긴다.

**TS-4 심의 결과 요약(P4a)의 기본은 full 이다.** 루틴의 심의 단계가 결정문을 쪽마다 다 읽는다(`../HWAXAgentServer/routine.py:1769-1782`) — 기본을 바꾸면 루틴이 말없이
요약만 받는다.
