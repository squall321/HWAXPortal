# 보고서에 도구 그림 싣기 — 계획

> 체크리스트 [checklist.md](checklist.md) · 결정 [context-notes.md](context-notes.md)(RF-1 ~).

사용자 신고(2026-11-02 KST) — StepForge · DynaForge 도구가 낸 그림이 인사이트에서 쓴 보고서에 한 장도 들어가지 않는다. 웹 챗은 도구 그림을
에이전트 서버의 `ARTIFACT_DIR/<sha256 앞 20자>.<확장자>` 에 두고 `/agent/artifacts/…` 로 보이는데, `/보고서` 와 심의 RA 보고서는 대화 · 심의의
**글만** 블록으로 만들어 그림이 포털 상대 주소를 가리키는 마크다운 글자로 RA 에 들어간다(RA 에서는 깨진 글이다). 포털이 RA 에 그 사람 명의로
그림을 올리는 창구를 둘 연다 — 게이트웨이(개인 Claude)가 부르는 `POST /agent/figures/to-report`(그 보고서의 쪽 끝에 그림 칸 하나)와, 에이전트
서버가 보고서를 만들기 **전에** 그림만 올려 file id 를 받는 `POST /agent/figures/upload`. RA 에 올리는 코드는 DocForge 배달의 것을 `RaSession`
하나로 떼어 같이 쓴다. 에이전트 서버는 `/보고서` · 심의 보고서의 블록에서 그림 줄(마크다운 그림 · 맨 주소)을 찾아 그 사람의 PAT 로 올리고,
그 자리를 `[그림 N — 설명]` 으로, 올리지 못한 그림은 `[그림 — 올리지 못함: 까닭]` 으로 바꾼 뒤, 그림 칸을 보고서를 만드는 같은 호출의
`extra_blocks` 에 싣고 몇 장이 들어갔는지 결과에 센다. 사람 토큰이 없는 길(MCP 로 연 심의)은 서비스 자격으로 올리지 않고 까닭을 남긴다.

## PC 에서 쓰는 법 — 표 칸 그림이 든 docx(긴급 11-02 '표칸그림 필요해', RF-19 ~ RF-23)

개인 Claude 가 보고서를 PC 에서 Word(docx)로 낼 때의 차례다. 변환기는 PC 에서 혼자 도는 한 파일(`infra/pc-kit/hwax-md2docx.py`)이고 Python 3.9+ 와
`pip install python-docx` 만 있으면 된다(webp 그림은 Pillow, svg 그림은 cairosvg 도 — 없으면 그렇게 말하고 멈춘다).

1. **변환기 받기** — 게이트웨이 `kit_get` 을 부르면 `curl -fsS -o hwax-md2docx.py "<주소>"` 한 줄이 나온다(주소는 1시간). 보고서 폴더에서 돌린다.
2. **그림 받기** — 도구 결과 끝의 `그림 저장 — fig_…` 를 `figure_get(ref)` 로 부르면 curl 한 줄이 나온다(`<도구>-<ref>.<확장자>` 로 받는다). md 폴더나
   따로 둔 그림 폴더(`--fig-dir`)에 받는다. 받지 않아도 환경 변수 `HWAX_GATEWAY_PAT`(내 PAT) · `HWAX_PORTAL_BASE`(`https://<포털 호스트>`)를 두면
   변환기가 없는 ref 를 받아 md 옆에 둔다.
3. **md 에 쓰기** — 그림은 어디에나 `![캡션](fig_…)` 또는 `![캡션](경로)` 다. 줄에 홀로 두면 본문 폭 그림과 아래 캡션, 문단 · 목록 안이면 줄 안
   그림, **표 칸 안이면 그 칸의 그림**(그 열 폭에 맞추고 캡션도 같은 칸에 — 한 칸에 여럿도, 앞뒤 글도 그대로)이다. 경로는 md 기준 상대 · `H:/…` ·
   `H:\…` · `\\서버\공유\…` 이고, 빈칸이 있으면 `<…>` 로 감싸도 된다.
4. **돌리기** — `python hwax-md2docx.py 보고서.md -o 보고서.docx --fig-dir 그림폴더`. 끝 줄 `그림 표기 N · docx 그림 N · 표 칸 안 M` 의 두 N 이
   같으면 다 들어갔다. 없는 그림이 있으면 줄마다 알리고 docx 를 쓰지 않는다(종료 2 — `--allow-missing` 이면 빨간 `[그림 없음: …]` 으로 쓴다).
   수가 어긋나면 종료 3 이다(그 docx 는 쓰지 않는다).
