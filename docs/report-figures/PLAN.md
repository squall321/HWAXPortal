# 보고서에 도구 그림 싣기 — 계획

> 체크리스트 [checklist.md](checklist.md) · 결정 [context-notes.md](context-notes.md)(RF-1 ~).

사용자 신고(2026-11-02 KST) — StepForge · DynaForge 도구가 낸 그림이 인사이트에서 쓴 보고서에 한 장도 들어가지 않는다. 웹 챗은 도구 그림을
에이전트 서버의 `ARTIFACT_DIR/<sha256 앞 20자>.<확장자>` 에 두고 `/agent/artifacts/…` 로 보이는데, `/보고서` 와 심의 RA 보고서는 대화 · 심의의
**글만** 블록으로 만들어 그림이 포털 상대 주소를 가리키는 마크다운 글자로 RA 에 들어간다(RA 에서는 깨진 글이다). 포털이 RA 에 그 사람 명의로
그림을 올리는 창구를 둘 연다 — 게이트웨이(개인 Claude)가 부르는 `POST /agent/figures/to-report`(그 보고서의 쪽 끝에 그림 칸 하나)와, 에이전트
서버가 보고서를 만들기 **전에** 그림만 올려 file id 를 받는 `POST /agent/figures/upload`. RA 에 올리는 코드는 DocForge 배달의 것을 `RaSession`
하나로 떼어 같이 쓴다. 에이전트 서버는 `/보고서` · 심의 보고서의 블록에서 그림 줄(마크다운 그림 · 맨 주소)을 찾아 그 사람의 PAT 로 올리고,
그 자리를 `[그림 N — 설명]` 으로, 올리지 못한 그림은 `[그림 — 올리지 못함: 까닭]` 으로 바꾼 뒤, 그림 칸을 보고서를 만드는 같은 호출의
`extra_blocks` 에 싣고 몇 장이 들어갔는지 결과에 센다. 사람 토큰이 없는 길(MCP 로 연 심의)은 서비스 자격으로 올리지 않고 까닭을 남긴다.
