> 받은 것 — 「HWAX 개선 아이디어 — 운영·관측·검색」(2026-10-15, @박용진). 사용자 지시(2026-10-16) — "하기 의견을 분석하고 반영할수 있는것도 해".
> 판정의 근거는 2026-10-16 의 HWAXPortal · HWAXAgentServer · HWAXMcpGateway · AIDataHub main 이다. 문서가 든 사실(파일·숫자)은 모두 지금 코드와 맞았다.

## 2. 항목별

### 1. 상시 상태판 — Gatus

- **맞는 근거.** `docs/gotchas.md` 의 조용한 고장(signalforge 포트 · LLM 백엔드 · Drive `latest/`)에 더해, **2026-10-16 아침의 실례**가 있다 — dev 박스 메모리가 바닥나 earlyoom 이 python 프로세스를 내렸고 포털 백엔드와 게이트웨이가 꺼졌다. 포털 인스턴스는 '떠 있음' 으로 남아 `start.sh` 가 그냥 지나갔다(안의 백엔드만 죽었다). 사람이 손으로 보기 전까지 아무도 몰랐다.
- **조정 — 경보 길.** 포털의 메일은 `console · smtp · graph` 셋 중 하나다(`backend/app/config.py`). cae00 이 SMTP 면 Gatus 의 이메일 경보를 그대로 쓴다. Graph 면 Gatus 가 직접 못 보낸다 — 경보를 포털에 맡기면 포털이 죽었을 때 경보도 죽으므로, 그때는 작은 독립 발신기(Graph 자격을 읽는 스크립트)를 둔다. 어느 쪽인지 정해 주셔야 한다.
- **걸음.** ① `services.yaml` · `routes.env` 에서 Gatus 설정을 만드는 생성기(`gen-nginx-conf.sh` 와 같은 '한 줄 → 유도'). ② 검사 — 서비스마다 health(매니페스트의 url 전부 — 포털처럼 리스너가 둘이면 둘 다), 게이트웨이 `/health` 의 도구 수와 백엔드, LLM 라우터 `/health`(`[BODY].models.match == true`), 에이전트 서버의 도는 심의. 스크립트가 필요한 검사(`mcp-smoke.py` · Drive `latest/` 나이)는 주기 스크립트가 Gatus 외부 엔드포인트로 밀어 넣는다(2단계). ③ 이미지는 dev 에서 굽고 Drive 로 옮긴다(searxng 와 같은 길). ④ 매니페스트 항목은 기본 꺼짐 — `infra/.env` 의 한 줄로 켠다. ⑤ 포트는 `docs/PORT-MAP.md` 에 올린다. 검사용 PAT 는 읽기 전용 그룹으로 따로 발급한다(사람).

### 2. 호출 추적 — Phoenix

- **맞는 근거.** 토큰 집계가 카드 대조에만 있고, 챗·심의는 호출 단위 기록이 없다. LLM 서버가 둘이 되면 '어느 서버에서 얼마나 기다렸나' 가 더 필요하다(라우터 `/stats` 는 지금 순간만 본다).
- **뒤로 미루는 까닭.** 트레이스에는 프롬프트 원문(지식카드 · 설계 변경)이 남는다. 보존 기간 · 열람자 · 운영자를 먼저 정해야 한다. 또 에이전트 서버에 새 패키지(OpenInference)가 들어가는데, cae00 은 인터넷이 없어 패키지 반입 길(오프라인 휠)도 함께 정해야 한다. 정해 주시면 env 가 있을 때만 켜지는 20줄 남짓의 연결과 Phoenix 인스턴스를 짓는다.

### 3. LLM 풀 용량 측정 — GuideLLM

- **맞는 근거.** LP-D7 이 동시 수를 사람이 정하게 했는데 정할 데이터가 없다. 이 측정이 그 데이터다.
- **걸음.** ① 실제 심의 전사(`delib-runs`)와 카드 대조 기록에서 프롬프트·출력 **길이 분포만** 뽑는다(본문은 꺼내지 않는다). ② GuideLLM 을 이미지로 굽고(dev, 인터넷) 실행 스크립트 하나 — 서버 하나 직결 대 라우터 경유, 붙임 문턱 `LLM_ROUTER_STICKY_SLACK` 켬·끔. ③ 결과를 `docs/llm-pool` 에 표로 남기고 세 값(관문 · 리스크 워커 · 포털 중계)의 권장 조합을 적는다. 측정 자체는 cae00 에서 사람이 심의 없는 때 돌린다 — GPU 를 차지한다.

### 4. 의미 기반 도구 검색

- **맞는 근거.** 게이트웨이 `_search_tools` 는 부분문자열 점수와 손으로 늘리는 동의어 사전(`_SYN`)이다. 도구는 9월 실측 468개, 오늘 dev 게이트웨이 397개(백엔드 일부가 빠진 상태)로 G2 의 착수 기준(~300+)을 넘었다.
- **걸음.** 평가셋을 **먼저** 만든다 — 문서에 남은 오배정 사례와 '하고 싶은 일 → 정답 도구' 쌍(초안은 도구 설명에서 만들고 사람이 고친다). 지금 방식의 1위·5위 적중을 잰 뒤, AIDataHub `/api/embed` 색인 + RRF(지금 점수 · 임베딩 순위 · 호출 수 작은 가중)를 env 옵션으로 넣고 같은 평가셋으로 견준다. 임베더가 죽으면 지금 방식으로 떨어진다. 임계값은 쓰지 않고 순위만 쓴다(e5 코사인 함정).

### 5. 한국어 검색 평가셋과 형태소 색인

- **맞는 근거.** AIDataHub 전문 검색은 `to_tsvector('simple', …)` 다(`search_svc.py` — 형태소를 모른다). 임베더 평가는 8월에 12질의 한 번뿐이다.
- **걸음.** 바꾸기 전에 재는 판부터 — 카드에서 짧은 질의를 자동으로 만들어 원 카드의 순위를 보는 평가셋(수백 개, 도메인 고르게)과 지금 검색의 기준선(어휘 · 의미 · 하이브리드, 지연 포함). 그 다음 비교(pg_bigm · Kiwi · bge-m3 · KURE-v1 · 재정렬기)는 실 DB 가 아니라 사본에서 한다 — pg_bigm 은 Postgres 이미지를 다시 굽고, 임베더를 바꾸면 전 코퍼스 재색인과 GPU 메모리가 든다.

### 6. 도구 인자 설명 점수판

- **맞는 근거.** `docs/procedures/gaps/hub-arg-descriptions.yaml` — 인자 1,348개 중 설명 15개(1%).
- **걸음.** 게이트웨이가 재집계할 때 앱별로 `inputSchema.properties[].description` 이 있는 비율과 단위·범위 낱말이 든 비율을 세어 `/tools-map` 에 앱별 점수와 가장 나쁜 도구 다섯을 싣고, 새 앱이 기준 아래면 기동 로그에 경고 한 줄(막지 않는다). 기준 모델은 LaminateAnalyzerMCP 의 '각 필드 description 에 단위와 유효 범위' 다.

## 3. 순서

결정이 필요 없는 것부터 — **6 → 1(검사·화면, 경보는 결정 뒤) → 3(도구 · 절차서) → 4(평가셋 먼저) → 5(기준선 먼저) → 2(결정 뒤)**. 문서가 권한 순서(1 → 3 → 6 → 2 → 4·5)에서 6 을 앞으로 당긴 것은 사람의 결정이 하나도 필요 없고 4 의 색인 재료가 되기 때문이다.

## 4. 열린 물음(사용자)

1. 상태판과 추적을 누가 운영하고, 경보 메일을 누가 받나.
2. cae00 의 포털 메일은 SMTP 인가 Graph 인가(Gatus 경보 길이 갈린다).
3. 추적에 남는 프롬프트 원문의 보존 기간과 열람자.
4. 용량 측정을 돌릴 시간(심의가 없는 때).
