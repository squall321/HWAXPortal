# 전문가 페르소나 챗 — 쓸 수 있게 만들기

## 사용자가 말한 것 (2026-09-09)

1. "전문가를 페르소나로 해서 챗을 하는 건 할 수 있는데 **사용이 조금 어려운 상태**인 것 같다."
2. "오른쪽에 뜨는 상태 바 아래 정도에 **현재 페르소나를 띄워 주고** 그걸 **수동으로 고르게도**
   해 주면 좋을 것 같다."
3. "페르소나 기반 대답은 **그 페르소나 말풍선을 띄워 주는 건 어떠냐, 심의할 때처럼**."

## 왜 어려웠나 — 실측

| 마찰 | 지금 |
|---|---|
| **고르는 자리가 하나뿐이다** | 랜딩의 '🎛 전문가·도구 고르고 시작' 칩뿐. `ChatPage` 가 `empty` 일 때만 그린다 — 대화가 시작되면 사라진다 |
| **대화 중엔 바꿀 수 없다** | 컴포저 칩의 `×` 는 **해제**만 한다. 다시 고르려면 새 대화를 열어야 한다 |
| **누구인지 안 보인다** | 칩이 `👤 sim-drop-impact` 처럼 **기계 키**를 띄운다. 사람 이름(`세트 낙하·충격 해석 전문가`)이 아니다 |
| **골라도 티가 안 난다** | 답변이 일반 챗과 똑같은 말풍선이다. 그 전문가가 답했다는 표시가 없다 |
| **'/전문가' 검색이 죽은 채널** | 서버가 `agents` SSE 이벤트로 구조화 목록을 보내는데 `chat.api.ts` 의 `dispatch` 에 case 가 없어 **조용히 버려진다.** 텍스트만 보이고 고를 수 없다 |
| 오른쪽 레일이 사라진다 | `ActivityPanel` 이 `if (!msg \|\| items.length === 0) return null` — 활동이 없으면 패널 자체가 없다 |

지연은 문제가 아니다 — 전문가 조회는 데운 뒤 **0.36~0.64초**다(첫 호출만 임베더 콜드로 50초).

## 만들 것

### ① 오른쪽 레일에 '현재 전문가' (사용자 제안 2)

`ActivityPanel` 의 상태 바(`act-head`) **바로 아래**에 한 칸을 둔다.

- 지정돼 있으면 — 아바타·**사람 이름**·도메인, 그리고 `바꾸기`
- 없으면 — "일반 어시스턴트" 와 `전문가 고르기`
- **활동이 없어도 보인다.** 지금은 패널이 통째로 사라지는데, 이 칸은 대화가 있으면 항상 있다

### ② 거기서 바로 고르기 (사용자 제안 2)

레일에서 여는 가벼운 선택기. 검색 + 추천 + 최근 고른 사람. `StartPicker` 를 그대로 쓰지
않는 이유는 그것이 전문가·앱·도구를 한꺼번에 고르는 큰 패널이라, "전문가만 바꾸고 싶다" 에는
과하기 때문이다. 조회는 같은 API(`/deliberate/experts`)를 쓴다.

### ③ 페르소나 말풍선 (사용자 제안 3)

심의 회의록의 발언 버블(`dv-turn`: 아바타 + 이름 + 색 테두리 버블)을 챗에 가져온다.
같은 사람은 심의에서도 챗에서도 같은 색이어야 하므로 `colorOf`/`initialOf` 를 공용 모듈로
빼서 **양쪽이 같은 함수를 쓴다**.

말풍선을 그리려면 그 메시지가 **누구의 답인지**를 알아야 한다. 지금은 대화 상태
(`pinnedAgent`)에만 있어서 새로고침하면 사라진다 → 메시지에 `persona{key,name}` 을 실어
저장한다.

### ④ '/전문가' 검색 결과를 고를 수 있게

죽어 있던 `agents` 이벤트를 프론트가 소비해 `ToolCatalogBlock` 처럼 **메시지 안 카드**로
그린다. 도구는 이미 그 대우를 받는데 전문가만 못 받고 있었다.

## 원칙

- **서버 계약을 바꾸지 않는다.** `pinned_agent` 는 그대로 `agent_type` 키다. 사람 이름은
  화면 표시용으로만 들고 다닌다.
- **이미 있는 것을 재사용한다.** 버블은 심의 것, 조회는 `/deliberate/experts`, 카드 패턴은
  `ToolCatalogBlock`, 토글 관용구는 `SourcePanel`/`ThinkPanel`.
- 색은 한 사람에 하나 — 심의와 챗이 어긋나면 같은 사람으로 안 읽힌다.

## 범위 밖

- 전문가를 여러 명 동시에 두는 것(그건 띵킹 모드와 심의가 하는 일이다)
- 전문가 편집·생성(AIDataHub 관리 화면의 일)
