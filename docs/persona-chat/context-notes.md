# 전문가 페르소나 챗 — 작업 노트

왜 그렇게 했는지. 다음 사람이 같은 판단을 다시 내리지 않도록.

## D-1. 색은 **원래 이름**으로 뽑는다 (`personaColor.ts`)

심의 회의록(`DelibView`)과 챗 말풍선이 같은 사람을 같은 색으로 그려야 같은 사람으로
읽힌다. 그래서 `colorOf`/`initialOf` 를 `DelibView` 안에서 꺼내 공용 모듈로 옮겼다.

⚠ **`shortName()` 결과로 색을 뽑으면 안 된다.** 심의 turn 의 `persona` 는 서버가 준
원래 이름(`… 전문가 (… Expert)`)이고 챗은 축약형을 보여 준다. 축약형으로 해시하면 같은
사람이 두 화면에서 다른 색이 된다. 표시만 줄이고 해시는 원본으로 한다.

## D-2. 이름 축약 — 정규식으로는 못 자른다

카탈로그 이름은 `한국어 이름 (English Name)` 꼴인데 **괄호가 중첩된다**.

```
지문 센서(초음파·광학) 전문가 (Fingerprint Sensor (Ultrasonic & Optical) Expert)
```

`\([^)]*\)$` 류는 첫 `)` 에서 멈춰 엉뚱하게 자른다(같은 함정으로 `test_grounding.py`
가 한 번 터졌다). 뒤에서부터 깊이를 세어 짝을 찾고, **괄호 안에 한글이 없을 때만** 뗀다 —
`지문 센서(초음파·광학)` 처럼 이름의 일부인 한글 괄호는 남겨야 한다.

## D-3. '누가 답했나'는 **보낼 때** 메시지에 찍는다

`Message.persona = {key, name}` 를 전송 시점(`sendMessage`)에 stamp 한다. 대화 상태
(`pinnedAgent`)만 보고 그리면 두 가지가 깨진다 — ① 나중에 전문가를 바꾸면 **과거 답까지**
그 사람 것으로 보이고, ② 새로고침하면 아예 사라진다. 스토어에도 같이 영속한다.

서버 계약은 그대로다. 나가는 것은 `pinned_agent`(=`agent_type`) 하나이고, 사람 이름은
화면 표시용으로만 들고 다닌다(`Conversation.pinnedAgentName`).

## D-4. 도메인 라벨은 프론트에 있다 — 정본이 없어서다

`list_agent_domains` 는 **코드와 인원만** 준다(`sw 408`, `xd 122` …). 사람이 읽는 이름이
어디에도 없어서 `personaCatalog.ts` 의 `DOMAIN_LABEL` 에 붙였다. 모르는 코드는 코드
그대로 보여 주므로 새 도메인이 생겨도 화면은 안 깨진다.

나중에 AIDataHub 가 도메인 이름을 주기 시작하면 이 맵을 지우고 그걸 쓰면 된다.

## D-5. 그룹은 **2명 이상일 때만** 세운다

키 둘째 세그먼트로 묶는데(`sw-app-*` → `app`), 전부 세우면 `sw` 하나에 그룹이 150개가
되어 조직도가 아니라 목록이 된다. 2명 미만은 `개별` 로 모은다. 실측: `sw` 408명 →
`app 33 · camera 12 · audio 7 …` + 개별.

## D-6. 조직도 연결선은 **루트→레일**까지만 그린다

카드가 줄바꿈되면 카드마다 위로 뻗는 줄기는 둘째 줄부터 허공을 가리킨다(CSS 로 행을
알 수 없다). 루트에서 내려온 세로줄 + 그리드 상단 가로 레일까지만 그리고 카드 줄기는
포기했다. 왼쪽 트리는 `border-left` + `::before` 로 진짜 계보선을 그린다.

## D-7. 전창은 `createPortal(…, document.body)`

`Lightbox` 와 같은 이유다 — 조상에 `transform` 이 있으면 `position: fixed` 가 뷰포트가
아니라 그 조상 기준이 된다. 챗 카드에 호버 `translateY` 가 있어 실제로 걸린다.
[[hwax-chat-figure-render]] 에 같은 함정이 기록돼 있다.

## D-8. 상세 로드는 늦게 온 응답을 버려야 한다

`/catalog/agent` 는 콜드에 6~11초다(감사 실측, 웜 0.23초). 연달아 누르면 도착 순서대로
덮어써서 **선택한 사람과 다른 사람의 설명**이 뜬다 — 그걸 보고 고르면 틀린 판단을 하고도
모른다. `selKeyRef` 로 지금 선택과 같을 때만 반영한다. `StartPicker` 에도 같은 결함이
있어 같이 고쳤다.

⚠ `setSel((cur) => { … 부수효과 … })` 로 풀면 안 된다 — 갱신 함수는 순수해야 하고
StrictMode 에서 두 번 돌아간다. ref 로 따로 둔다.

## D-9. 띵킹과 지정 전문가는 **서로를 무효화하는데 둘 다 켜진 것처럼 보였다**

서버 디스패처가 `is_thinking(...) or req.thinking` 을 먼저 보므로 띵킹이 이긴다. 화면은
둘 다 켠 상태로 보여 주고 아무 말도 안 했다(감사 during-F3). 레일에 그때만 뜨는 한 줄을
넣었다. **동작은 안 바꿨다** — 어느 쪽이 이겨야 하는지는 별개 결정이다.

## D-10. 검증은 임시 vite 진입점 + 실데이터로

포털이 로그인을 요구해 챗 화면을 직접 못 본다. `frontend/probe.html` + `src/__probe.tsx`
를 만들고 `window.fetch` 를 가로채 **게이트웨이에서 뽑은 실제 781명**을 먹였다
(`list_agents(compact)` → jq). 그렇게 해서 잡은 것 —

- 긴 이름에 `해제` 버튼이 세로로 찌그러짐 → `flex: none` + 이름 `ellipsis`
- 중첩 괄호에서 축약이 안 먹음 (D-2)
- 정적 HTML 하네스로는 하나도 안 나왔을 것들이다

확인 후 진입점은 지웠다. 다음에 챗 UI 를 고칠 때 같은 방법을 쓴다.
