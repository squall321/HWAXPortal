# 7차 변경 요청 — 결정과 이유

**D-1 설정 이름·기본값은 요청서 그대로(2026-10-02).** 요청자가 같은 diff 를 cae00 에 얹어 운영 로그인을 확인했다 — 이름이 같아야
update-all 이 박스 패치를 stash 로 치운 뒤 같은 `.env` 값이 정식 코드에 그대로 먹는다. 기본 참은 종전 동작(NameIDPolicy 를 요구해야 하는
IdP 도 흔하다). ⚠ **순서** — `.env` 두 줄을 update-all **전에** 넣는다. 반대로 하면 update-all 이 패치를 치우고 기본값(참)으로 재기동한
순간부터 `.env` 를 고칠 때까지 운영 로그인이 다시 InvalidNameIDPolicy 다. 옛 코드는 모르는 SAML_* 환경변수를 무시하므로 먼저 넣어도 안전하다.

**D-2 SLO 는 블록을 통째로 뺀다(2026-10-02).** `url` 만 비우면 python3-saml 이 빈 주소로 그대로 광고한다(요청자 실측). 메타데이터
`validate_metadata` 는 블록이 없어도 통과한다(시험 고정). `/auth/saml/sls` 501 스텁은 그대로 둔다 — 광고하지 않으면 IdP 가 보내지 않는다.

**D-3 6차 D-4 의 전제가 틀렸다(2026-10-02).** 'ADFS 가 NameIDPolicy 를 가리지 않는다' 는 9월 측정이 인증 **전**(로그인 폼이 오는지)만 본 것이었다.
ADFS 는 ACS 경로처럼 NameIDPolicy 도 인증 **뒤** 토큰 발급 단계에서 판정한다. 같은 성질을 4차에서 ACS 로 겪었다 — IdP 가 '요청에서
요구한 것' 은 인증 전 측정으로 판정하지 않는다.
