# 운영 현황 — 결정 기록

**OD-1 조사(2026-11-02 KST, 읽기만) — 이용 통계는 지금 있는 원장만으로 관리자 첫 화면을 지을 수 있고, 날마다 접는 표가 있어야 기록이 남는다.**
원천은 포털 안 원장(접속 · 챗 감사 · 사용자 · 대화 · 절차/루틴 · PAT) · 게이트웨이 `audit.jsonl` · 에이전트 서버 MCP 심의 원장 · 리스크 앱 호출 원장이다.
오래 남지 않는 것 넷(챗 · 심의 토큰 · 턴 종류 · 엔진 호출의 사람 · 허브 앱 열기)과 사라지는 원천(만료 PAT 삭제 · 대화 삭제 · nginx 14일 · 검색 기록 · 호출 추적
30일) 때문에 M2 의 접기 표가 필요하다. 포털 컨테이너는 다른 서비스의 파일을 열지 못하므로 게이트웨이 · 에이전트 서버에 공유 비밀 창구를 둔다
(`/search-log` 와 같은 꼴). 사람별 줄은 관리자 그룹으로 막는다 — CAEG 가 `"*"` 를 쥐어 `feat:` 키는 사실상 모두에게 열린다.

**OD-2 조사(같은 날) — LLM 서버 상태는 지금 읽히고, GPU 잡 · 하드웨어는 접근 확인 · 다른 팀 승인이 먼저다.** vLLM 0.23.0 의 `/metrics` · `/health` · `/version` 은
API 키가 지키지 않는다(키는 `/v1` 아래만). cae00 의 묶음 nginx(Qwen 18700 · GLM 18800)는 아무 한 대로 보내므로 서버 · 복제본마다 직접 묻는다. Slurm 잡 표는
사람 없는 `ssh stcx` 가 되는지가 먼저고(미확인 — 받은 편지함 Q8), SmartTwinMCP 의 Slurm ssh 별칭은 문서끼리 가리키는 곳이 어긋나 재사용하지 않는다.
GPU 사용률 · 온도 · 전력은 어느 리포도 읽지 않는다 — stcx 는 노드 관리자, GLM 은 운영 팀의 승인을 사용자를 거쳐 받는다. 수집기는 포털 백엔드가 아니라 호스트
쪽 작은 서비스다(`portal.sif` 에 ssh 가 없고, 에이전트 서버는 심의 중 재기동이 미뤄진다).

**OD-3 근거 없는 수치는 계획에 옮기지 않는다.** 토큰 절감 설계안 v1.0 의 'GLM 서버당 동시 34건에 1건당 201 tok/s' · '학습과 겹치면 6 tok/s' 는 리포 어디에도 근거가
없었다. 근거가 있는 값은 GLM 요청당 약 116 tok/s(`docs/chat-depth-context/request.md:100`) · Qwen 복제본 하나가 동시 8 에 779 · 32 에 1,212 tok/s
(`docs/chat-llm-stcx/server-setup.md:264-265`)다. GLM 의 지금 모델 · 창도 문서끼리 다르다(10-20 '20만' · 10-22 두 서버가 300K · 1M) — 화면은 늘 살아 있는 값을 읽는다.

**OD-4 사용자 결정(2026-11-02 KST) — 합계도 관리자만 · LLM/GPU 는 호스트 수집기.** 이용 통계는 사람별 줄과 합계 모두 관리자 화면에만 둔다(나중에 넓힐 수 있다).
LLM/GPU 현황은 cae00 의 작은 호스트 수집기(기본 꺼짐) + 관리자 화면으로 짓는다 — Slurm 잡 표 · 기록 · GPU 하드웨어를 담을 수 있고 포털 갱신으로 끊기지 않는다.
나머지 기본값(사람별 집계 400일 · k = 5 · 사람별 LLM 토큰은 M3 에서 다시 묻는다 · 허브 앱 열기는 HEAXHub 세션 몫)은 계획서 권장 그대로 두고, 바꿀 일이 생기면 묻는다.

**OD-5 이용 통계 M1 은 원장을 읽기 전용으로 따로 열어 스레드에서 센다(2026-11-02 KST, 가지 `wt1102/usage-stats`).** 저장소 객체(app.state)의 연결 · 잠금을
빌리지 않고 설정의 경로 다섯(`agent_audit_log_path` · `user_store_path` · `token_store_path` · `conv_store_path` · `procedures_store_path` — 레지스트리
`infra/services.yaml` 의 그 자리)을 `mode=ro` 로 연다(`backend/app/usage_stats.py`). 세는 동안 이벤트 루프에서 부르는 감사 쓰기가 파이썬 잠금에 막히지 않고,
읽기가 없는 원장을 만들거나 쓰지 못한다(seat_review_harvest 와 같은 길). 라우트 `GET /auth/admin/usage`(`backend/app/auth/routes/usage.py`)는 셈을
`asyncio.to_thread` 로 넘긴다. 새 저장소 · 경로가 없어 conftest 격리는 그대로다. `agent_audit` 의 ts 색인(`agent_audit_ts`)은 `AuditLog` 가 열 때 건다 —
시험이 감사 · 접속 읽기 전부의 계획에 표 전체 훑기가 없음을 본다. 사건 갈래 · 챗 오류 까닭은 SQLite JSON 함수를 쓴다 — 없는 빌드면 그 칸만 error 로 낸다.

**OD-6 기간은 오늘(KST)을 끝으로 한 N 일(1 ~ 400, 기본 30)이고, 범위 밖 값은 거절하지 않고 붙잡아 맞춘 뒤 응답에 적는다(range.clamped).** 날은 고정
UTC+9 로 가른다(서울은 서머타임이 없다). 주는 월요일에 시작한다. 원장의 첫 줄보다 앞선 날 · 주 · 달은 null 이다(기록 전 — 0 이 아니다). 기간 앞뒤에
걸치거나 아직 끝나지 않았거나 원장이 그 중간에 시작한 주 · 달은 partial 이고, null 칸은 partial 이 아니다(화면 검토에서 고침). 지금 상태를 세는
칸(계정 상태 · 소속 · 살아 있는 PAT · 외부 연결)은 기간과 무관하다고 note 가 말한다.

**OD-7 시험 · 서비스 계정은 설정 하나(`USAGE_EXCLUDE_ACCOUNTS`, 기본 비어 있음)로 모든 칸에서 빼고, 화면이 무엇을 뺐는지 말한다.** 쉼표 · 대소문자 무시이고
이메일과 주체(감사 principal · 대화 owner_sub · PAT sub)로 견준다 — 이 포털은 로컬 · SSO 모두 주체가 이메일이다. 시험 · 서비스 둘로 나누지 않았다(박스마다
관리자가 적는 짧은 목록이다). dev 의 시험 신원(`backend/tests/conftest.py` 머리)은 dev 의 `backend/.env` 에 적는다 — 추적 파일에는 적지 않는다. 자동 SSO
예열(detail=primer)은 접속 원장의 모든 읽기에서 늘 뺀다. 싣지 않는 것은 IP · UA · 연결 ID · 감사 meta 의 글(상류 사유 · 예외 · 파일 이름) · 대화 제목 · 메시지 ·
부서 · 부서 코드다. 챗 오류는 정해진 까닭 낱말(`[a-z0-9_]{1,40}`)이나 에이전트 서버 HTTP 상태(`agent_<번호>`)만 세고 그 밖은 unknown 이다.

**OD-8 로그인 기준 DAU 는 계획서가 쓴 것보다 더 적게 센다 — 세션은 8시간에 끊기지 않는다.** PLAN §2.2 는 '로그인 한 번이 8시간 세션' 이라 했지만, 10-15
부터 `/auth/refresh` 가 refresh 토큰도 새로 내 쓰는 동안 세션이 이어지고 8시간(`JWT_REFRESH_TTL`)은 쉬는 상한이다. 며칠씩 다시 로그인하지 않는 사람이 있다.
화면 note 가 그렇게 말하고(시간은 설정에서 읽는다), 실제 쓰임에 더 가까운 수로 '챗을 쓴 사람' 을 함께 보인다. 원천을 가로지른 DAU 는 M2 다.

**OD-9 M1 은 합계만 낸다 — 사람별 줄은 없다.** 사람별 이용은 관리자 '접속 이력' 이 이미 보인다. 소속 칸은 관리자만 보더라도 k = 5 를 지킨다(OD-4 가 남긴
기본값) — 계정이 5명 미만인 칸은 '소속 없음' 도 같은 규칙으로 '기타' 에 접고 접힌 소속 수만 적는다. 다른 사람 속성 축(도구×소속 등)은 M1 에 없다.

**OD-10 완주율은 끝난 실행 가운데 done 의 몫이다.** 아직 도는 실행(절차 queued · running · gated, 루틴 queued · running · waiting)은 분모에서 뺀다. 루틴의
interrupted 는 원장이 끝난 시각을 적는 쪽이라 끝난 것으로 센다(이어서로 되살아날 수 있다). 끝난 실행이 없으면 비율도 null 이다.

**OD-11 화면은 한 계열 막대 · 표 · 수 타일뿐이다(차트 라이브러리 없음, `/admin/usage`).** 두 계열을 한 그림에 겹치지 않는다 — 범례 · 둘째 색이 필요 없게
하고, 오류 수는 타일 · 까닭 표로 낸다. 막대 색은 새 토큰 `--chart-1`(= `--primary-hover`)이다. dataviz 검사(카드 표면 `--surface-1` 위 OKLCH L 0.48–0.67 ·
대비 3:1 이상)를 지난 값이다 — `--primary` 는 대비 2.98:1 로 모자라고, `--accent-fg` 는 너무 밝아 마우스가 올라간 막대(`--chart-1-hover`)에만 쓴다. hex 는
늘지 않았다(90). 기록 전은 띠, 일부만인 주는 흐리게 그리고, 그림마다 '표로 보기' 를 두며 화살표 키로도 값을 본다. 기간이 해를 넘으면 그림 끝 날짜에 해를
붙이고, MAU 표는 원장 전 달을 한 줄로 접는다.

**OD-12 M2 가 게이트웨이 · 에이전트 서버에 바라는 것.** ① 게이트웨이 `GET /usage-rollup?since&until`(공유 비밀 — `/search-log` 꼴이라 포털은
`tool_search_review._gateway()` 를 그대로 쓴다). KST 날 × 백엔드 × 도구 × via(gw-token · chat · procedure · pat · mcp-app) × ok 마다 호출 수 · 오류 수 ·
ms p50/p95 · chars 합, 사람(caller 소문자 메일)별 날마다 호출 수를 낸다. 상태 묻기 도구는 따로 표시하고, 접두가 바뀐 이름(E-2)은 원래 이름으로 접고, 칸이
생긴 날(via · ip · caller 09-29 · chars 10-10)을 응답에 싣는다. 무기한 audit.jsonl 을 묻기마다 훑지 않게 그쪽도 날마다 접어 둔다. ② 에이전트 서버도 같은
꼴의 창구 — 심의 잡(종류 · 상태 · 웹/MCP · 걸린 시간 · 좌석 · 라운드 · RA 보고서 유무 · 사람 · 소속)과 루틴 · 카드 대조의 날마다 수, (M3 결정 뒤) 턴 · 잡마다
LLM 토큰 · 모델이다. 둘 다 옛 판이면 404 → 포털은 '그쪽 판이 낡았다' 로 보인다. ③ 포털의 날마다 접는 표(`usage_daily` · `usage_actor_daily`)는 M1 셈을
하루 창으로 다시 불러 채울 수 있다(칸마다 기간으로 자른다). '지금 상태' 칸(살아 있는 PAT · 연결 · 권한)은 날마다 찍어 두는 따로 셈이다(PLAN 2단계 나).
