## 1. 판정

- **이용 통계 — 된다.** 새로 적지 않아도 관리자용 첫 화면(M1)을 지을 수 있다. 다만 네 가지는 지금 어디에도 오래 남지 않는다 — LLM 토큰 수(리스크 앱 밖), 챗 턴의 종류(챗 · 심의 · 띵킹 · 루틴), 엔진 호출의 사람, 허브 앱 열기. 그리고 사라지는 원천이 있다(만료 PAT 삭제 · 대화 삭제 · nginx 14일 · 검색 기록과 호출 추적 30일). 그래서 포털이 **날마다 접어 두는 집계표**가 필요하다.
- **LLM/GPU 현황 — 반은 된다.**
  - LLM 서버 상태(모델 · 창 · 도는/기다리는 요청 · KV 캐시 · 처리 속도 · 지연 · 오류)는 cae00 에서 지금 열쇠 없이 읽힌다 — vLLM `/metrics` · `/health` · `/version` 은 키를 묻지 않는다(GLM 두 대 · stcx Qwen 복제본 10).
  - stcx(356대)의 GPU 잡(Slurm) 표는 cae00 에서 사람 없이 `ssh stcx` 가 되는지가 먼저다(미확인).
  - GPU 사용률 · 메모리 · 온도 · 전력은 지금 아무 리포도 읽지 않는다. stcx 는 노드 관리자, GLM 은 그 서버를 운영하는 팀의 승인이 있어야 한다.

### 2.2 지표

1단계 — 지금 있는 것으로(값 · 비용).

- 계정 — 상태 · 소속별, 주마다 새 계정(S).
- 로그인 — 날마다 로그인 수 · 실패 · 로그인한 사람 수(DAU · WAU · MAU — 로그인 한 번이 8시간 세션이라 실제 사용보다 적게 센다), SSO 대 로컬(S). 자동 SSO 예열(`detail=primer`, 45분마다)은 뺀다.
- 타일 진입 — 서비스별 진입 수 · 사람 수(S). 허브 앱 요청은 nginx 14일 안에서만(M).
- 챗 · 심의 · 루틴 · 절차 — 날마다 챗 턴 · 쓴 사람 · 오류 까닭, 심의(웹 · MCP · 종류 · 걸린 시간 · 상태), 루틴(실행기 · 상태), 절차 실행(출처 · 완료율)(S).
- MCP 도구 — 앱 · 도구 · 날짜별 호출, 누가 불렀나(개인 Claude · 포털 챗 · 엔진 · 패널), 많이 쓰는 도구 · 실패율(앱 쪽 대 관문 쪽) · p50/p95 · 캐시 적중 · 큰 응답(M+L — 게이트웨이 창구 필요). 상태 묻기 도구(`deliberate_status` 등)는 따로 센다.
- 개인 Claude — 주마다 쓴 사람 · 만료 · 잘못된 토큰 실패(M+L).
- PAT — 살아 있는 수 · 주마다 발급(날마다 찍어 둔다 — 만료 행이 지워지므로)(S).
- 도구 검색 — 날마다 검색 · 검색 뒤 성공(M).
- RA 초안 — 사람 · 날짜별(M).
- LLM 토큰 — **리스크 심사만**(모델 · 날짜 · 요청자)(L).
- 권한 요청 · 외부 연결 — 기능별 수요 · 승인까지 걸린 때(S).

2단계 — 새로 적어야.

- (가) 포털 중계가 턴마다 종류 · 답한 모델(`answered_by` · 에이전트의 `meta.models`)을 `chat_done` 에 싣는다 — 포털만, 작다.
- (나) 날마다 PAT · 외부 연결 · 권한 수를 찍어 둔다.
- (다) 에이전트 서버가 턴 · 잡마다 LLM 토큰 · 모델 · 호출 수를 남긴다(흘려 받는 챗은 `stream_usage` 가 필요 — GLM · vLLM 이 스트림에 usage 를 주는지 먼저 본다).
- (라) 게이트웨이가 PAT 종류(개인 · 교환된 자식 · 패널)를 달고, 엔진 호출이 잡의 주인을 싣는다.
- (마) 허브가 `/authz` 에 (사람, 앱, 날) 한 줄 · SSO 로그인 감사 · Caddy `trusted_proxies` — HEAXHub 세션 몫.

### 2.3 공개 범위 · 가림

- **사람별 줄은 관리자만**(`require_role(ADMIN_GROUP)` — 접속 이력 · 전체 PAT 와 같은 문). `feat:` 키로 막지 않는다 — CAEG 가 `"*"` 를 쥐어 모든 키가 열리고(`backend/app/access/policy.py:119-127` · `backend/config/access.yaml:22-26`), 관리자 말고 다른 역할(예 소속 책임자)이 없다.
- 합계를 누가 보나는 사용자 결정이다(§4) — 관리자만 · 로그인한 모두에게 회사 합계 · 내 이용만 보기.
- 소속 · 도구×소속처럼 사람 수가 적은 칸은 5명 미만이면 '기타' 로 접는다(k = 5).
- 통계 화면에 싣지 않는 것 — ip(접속 이력에만), 질의 · 메시지 글, 부서 코드.

### 2.4 구조

- **M1** — 포털 안 원장들(같은 프로세스)을 읽을 때 셈한다. `agent_audit` 에 ts 색인을 더한다.
- **M2** — 날마다 접는 표 `usage_daily(day, source, metric, dims, value)` · `usage_actor_daily(day, email, source, n, 그때의 소속)` 를 **`agent_audit.sqlite` 안에** 둔다(접속 이력 D-3 와 같은 파일 — 이미 등록된 자료 칸 · 이미 백업된다). 포털 lifespan 작업이 끝난 KST 날을 접고, 앞 이틀을 다시 접고, 기동 때 밀린 날을 채운다(sqlite 일은 이벤트 루프 밖에서).
- **다른 서비스 읽기** — 포털 컨테이너는 게이트웨이 · 에이전트 서버 파일을 열 수 없다(`infra/scripts/start.sh:103-106` 의 바인드). 그래서 게이트웨이에 공유 비밀로 묻는 `GET /usage-rollup?since&until`(`/search-log` 와 같은 꼴 — `backend/app/auth/routes/tool_search_review.py:41-62` 의 `_gateway()` 를 그대로 쓴다)과 에이전트 서버의 같은 창구를 새로 둔다. 옛 판이면 404 → '그쪽 판이 낡았다' 로 보인다.
- 날은 KST 로 가른다(게이트웨이는 UTC 로 적는다). 사람은 소문자 메일로 잇는다. 경로는 설정 · 등록부로만(절대경로 금지).
- 화면 — 관리자 메뉴에 `/admin/usage`. 차트 라이브러리가 없고 hex 색 래칫이 있어 인라인 SVG + CSS 토큰으로 그린다.

주의 — cae00 의 묶음 주소(Qwen 18700 · GLM 18800)로 물으면 아무 한 대의 숫자만 온다. 서버 · 복제본마다 따로 묻는다. 에이전트 서버가 보는 것은 HWAX 몫뿐이다 — 다른 서비스(AIDataHub · SignalForge 등)도 GLM 을 바로 부른다.

### 3.2 화면 — 관리자 `/admin/llm-status`

- 머리 — 수집기 상태와 원천마다 마지막으로 읽은 때.
- 서버 카드(GLM-1 · GLM-2 · Qwen 묶음 + 복제본 10줄 · 라우터를 켰으면 라우터 · dev 에서는 dev vLLM) — 모델 · 살아 있나(까닭) · vLLM 판 · 창(서버끼리 다르면 표지) · 도는/기다리는 요청(1시간 · 24시간 작은 그래프) · KV 캐시 % · 입력/출력 토큰 초당 · 첫 토큰 · 끝까지 · 줄 선 시간 p50/p95(≈ — 히스토그램 어림) · 오류 · 끊김 · 선점 · 앞부분 캐시 적중 %.
- '지금 쓰는 일' — 에이전트 서버 `/health` 의 심의 · 좌석 · 루틴 · 카드 대조 · 챗 턴(HWAX 몫이라고 적는다).
- GPU 잡(stcx Slurm) — 잡 번호 · 이름 · 노드 · 파티션 · GPU 수 · 상태(기다리는 까닭) · 지난 때와 한도 · 남은 때(3일 안이면 경고 — Qwen 잡은 30일 한도로 11-15 께 끝난다) · 그 복제본 포트의 살아 있음.
- GPU 하드웨어 — 원천이 있으면 GPU 마다 사용률 · 메모리 · 온도 · 전력. 없으면 '모름 — <무엇이 필요한가>' 한 줄.

### 3.3 구조

- **호스트 쪽 작은 수집기**(기본 꺼짐) — `infra/llm-status/collector.py`(표준 라이브러리만 · `status-push.py` 꼴) · 매니페스트 `if_env: LLM_STATUS` · 루프백 포트(허브 앱 포트 풀 9100~9999 밖). 포털 백엔드가 아닌 까닭 — `portal.sif` 에 ssh 가 없고 포털은 갱신마다 다시 뜬다. 에이전트 서버가 아닌 까닭 — 심의가 도는 동안 재기동이 미뤄지고 복제본 포트를 못 본다.
- 묻는 주기 — HTTP 대상 · 에이전트 `/health` 15초(대상마다 연결 3초 · 읽기 5초 — 한 대가 걸려도 다른 대상을 세우지 않는다), Slurm 60초(한 번의 ssh · BatchMode · 정해진 읽기 명령), GPU 60초(원천이 있을 때).
- 저장 — `infra/.state/llm-status/` 의 sqlite(폴더 700 · 파일 600), 15초 표본 48시간 · 5분 접기 35일(30일 잡 주기를 덮는다). 카운터가 다시 0 이 되면 빈칸(음수 속도를 만들지 않는다).
- 포털 — 관리자 `GET /auth/admin/llm-status` · `/series` 가 수집기를 대신 묻는다(설정 없음 503 · 안 닿음 502 → '수집기가 답하지 않는다'). 값마다 `{value, at, source, error}` 이고 세 번 못 읽으면 낡음 표지. 설정된 대상은 숨기지 않는다.
- 비밀 — 수집기가 `infra/.env` 의 키를 스스로 읽는다(명령줄 · 환경 · 브라우저에 싣지 않는다 — 라우터 규칙 LP-D11). 추적 파일에는 설정 키만(내부 주소 없음).
- 라우터의 지표 해석기는 손대지 않는다(라우터 지문에 들어 바꾸면 라우터가 다시 뜬다) — `infra/llm-status/` 에 넓은 해석기를 두고, 같은 견본으로 라우터 해석기와 결과가 같은지 시험한다.

4. LLM/GPU 현황 — (가) 호스트 수집기(권장 — Slurm 표 · 기록 · GPU 를 담을 수 있다) (나) 포털 백엔드 안 HTTP 만(작지만 Slurm 표 · 기록이 없다).
