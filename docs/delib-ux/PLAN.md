# 심의 UX 7건 — 계획

## 사용자가 말한 것 (2026-09-11)

1. 심의 전문가 선택도 **분야별 분류**로 보이게(챗 조직도처럼).
2. 도구를 **영역별**로 분류 — CAD 직접 제어 / 시뮬레이션 / VOC 등.
3. 토론이 잘 안 되면 **한 번 돌고 전문가 로스터를 다시 고르게**.
4. 처음 질문이 부족하면 **몇 번 더 물어** 메커니즘 분석 최소 정보를 채우게.
5. **VOC 만 먼저 돌려** 놓고 거기서 보강하거나 골라서 진행.
6. 심의가 끝나면 **누가 누구에게 어떤 의견을 줬는지 지식 그래프**.
7. 이어하기에서 **앞 내용이 효과적으로 정리되어 들어가는지 꼭 확인**.

승인된 순서 — ①화이트리스트 → ②반박 구조 → ③좌석 조직도 → ④도구 분류 →
⑤VOC 먼저 → ⑥되묻기.

## 조사로 확정된 사실 (workflow wzwfyg500, 6 렌즈)

### ⑦이 이미 깨져 있다 — 여기서 시작한다

포털 백엔드 `DelibOpts`(backend/app/agent/routes.py:59-98)에 **선언 안 된 키는
`model_dump(exclude_none=True)` 에서 조용히 사라진다.** 같은 함정에 네 개가 빠져 있다.

| 키 | 프론트 | 백엔드 선언 | 결과 |
|---|---|---|---|
| `non_negotiables` | 보냄(ChatContext.tsx:647) | **없음** | 양보 불가 조항 드롭 — 이전 결정이 소리 없이 되돌아간다 |
| `stop_after_round` | 패널에 있음(DelibOptsPanel.tsx:49) | **없음** | 1라운드 체크포인트가 **죽은 토글** |
| `rounds_so_far` | 안 보냄 | 없음 | 회차마다 회의록이 "1R 초기입장"으로 되돌아간다 |
| `append_to_report_id` | 안 보냄 | 없음 | 회차마다 RA 보고서가 새 건으로 흩어진다 |

엔진(`deliberation.py`)은 넷 다 구현돼 있다. **MCP 경로로는 살아 있고 웹에서만 죽는다** —
그래서 눈에 안 띄었다. 주석에 "⚠ 종전 미선언이라 웹 경로에서 조용히 버려졌다" 가 이미
두 번 적혀 있는데도 같은 자리에 네 개가 더 있었다.

⚠ `stop_after_round` 는 **두 겹**이다 — `delibOptsToWire`(chatStore.ts:234-247) 화이트리스트와
백엔드 모델 둘 다 통과해야 한다. `continueDeliberation` 이 쓰는 `extraDelibOpts` 는
`delibOptsToWire` 를 우회하므로 백엔드만 고치면 된다(ChatContext.tsx:546).

### 나머지 여섯의 출발점

- **③ 로스터 재선택** — 체크포인트는 엔진·JS 에 **이미 있다**(deliberation.py:2775-2786,
  hwax-deliberate.js:355-367). 웹 배선만 끊겼다. 단 **좌석을 빼는 경로는 엔진에 없다**
  (추가만 다섯 곳) — 의도된 설계다(context-notes.md:61).
- **⑥ 지식 그래프** — 반박 관계가 LLM 스키마에 **이미 있다**(`rebut=[{target,quote,counter,basis}]`).
  서버 메모리에서만 살고 `_item_text` 가 산문으로 평탄화해 저장한다. mermaid 렌더는 완비.
- **① 좌석 조직도** — 챗 조직도와 **같은 엔드포인트·같은 타입**(`ExpertsResponse.pool`).
  `personaCatalog.ts` 의 `buildTree/groupsOf/domainLabel` 과 `.pv-*` CSS 76규칙을 그대로 쓴다.
- **② 도구 분류** — 지금 축은 소유 앱 하나뿐. 앱과 영역이 실제로 어긋난다(StepForge 81 =
  CAD 54 + 전처리 10 + 재료 6 + 잡 11; '시뮬레이션'은 앱 4개에 흩어짐).
- **⑤ VOC** — 25종 살아 있고 심의가 이미 쓴다. 단 **질문에 불량 단어가 있을 때만** 켜지는
  조건부 환기다(deliberation.py:2291). 없는 건 '먼저 돌리는 단계'와 '사람이 고르는 UI'.
- **④ 되묻기** — 아예 없다. 선례 둘 — 업로드 목적지 UI(UploadRouter.tsx),
  AIDataHub `_scan_missing` + `{status:'incomplete', ask_user, suggestions}`(mcp_write_svc.py:29-166).

## 원칙

- **이미 있는 것을 켠다.** 엔진에 있는데 웹에서 죽은 것이 넷이다. 새로 짓기 전에 켠다.
- **화이트리스트 두 겹을 항상 같이 본다.** 이 리포의 반복 사고 유형이다. 새 키를 넣을 때마다
  `delibOptsToWire` + 백엔드 `DelibOpts` 를 짝으로 확인한다.
- **분류가 판단 근거를 지우면 안 된다.** 좌석을 분야로 접으면 관련도 %가 사라진다 —
  candidates 를 머지해 배지로 살려야 한다.
- **좌석은 빼지 않는다.** 이전 발언을 방어·수정할 당사자가 사라지기 때문이다. 재선택은
  '추가'와 '다음 회차 구성'으로 푼다.

## 범위 밖

- 진행 중인 심의를 멈췄다 같은 잡에서 재개하는 것(in-place resume) — 체크포인트는 스트림을
  끝내고 이어하기는 새 호출이다. 그 구조를 바꾸지 않는다.
- 도구 분류를 `gateway_config.json` 에 두는 것 — gitignore 라 `--force` 재생성에 날아간다.
