# 상호작용 데이터 수집 · DB화 · 활용 — 이용자의 챗 · 심의 · 개인 Claude(MCP) 기록을 모아 쓴다

> 할 일 [checklist.md](checklist.md) · 결정과 까닭 [context-notes.md](context-notes.md).

사용자 요청(2026-11-24): 「모든 이용자가 했던 채팅이나 Claude MCP 로 나눈 데이터를 수집해 DB 화하고 활용」 — 「최대한 많이, 예외 없이」.
Claude 대화 원문은 구조상 우리에게 오지 않으므로 「사람이 스스로 MCP 로 보내게」 한다.

## 1. 목표와 하지 않는 것

**목표** — 이 생태계에서 사람과 AI 가 주고받은 모든 것을 한 원장에 모으고(원문), 가린 가공층을 얹어, 아래 여섯 가지에 쓴다.

1. 도구 검색 · 라우팅 평가셋 — 「실제 질문 → 결국 성공한 도구」 쌍이 저절로 쌓인다(지금은 사람이 150쌍을 손으로 맞춘다).
2. 모델 · 심의 A/B 재생 평가셋 — Qwen · GLM · Claude 교체, 심의 품질 손잡이(T1 · T3 · 앵커 …)를 실제 질문으로 비교한다(측정 ① · ② 가 막힌 까닭).
3. 실패 지도 — 도구를 못 찾음 · 자기검증이 고침 · 확인 카드 거절 · 근거 없는 답 · 도구 오류를 플랫폼마다 센다 → 각 플랫폼에 고칠 것을 근거와 함께 청한다.
4. 지식 승격 — 되풀이되는 질문과 좋은 답을 지식카드 · FAQ 후보 큐에 올리고 사람이 승인하면 AIDataHub 에 들인다(과제 인사이트 그래프와 잇는다).
5. 수요 지도 — 어느 앱 · 주제 · 소속이 무엇을 묻는지, 답할 도구가 없는 질문이 무엇인지.
6. 본인 기록 — 각자 자기 기록 전체(웹 · MCP · 공유한 Claude 대화)를 한곳에서 찾아본다.

**하지 않는 것(이번 계획)** — 모은 데이터로 모델을 미세조정하지 않는다(별도 승인). 원문을 dev 로 꺼내지 않는다 — 원문은 운영 박스(cae00) 안에만 둔다
(실데이터 고리는 cae00 에서 닫는다). 수집이 호출을 느리게 하거나 실패하게 하지 않는다.

## 4. 구조 — 세 층

```
 [S1 · S2 · S6 포털]  [S3 · S4 게이트웨이 스풀]  [S5 에이전트 서버 잡 원장]  [S7 리스크 앱]  [S8 공유 도구 · PC 훅]
          └──────────────────────┬──────────────────────────────────────────────────────┘
                     ① 원장층 — 포털 수집기(ingest) → PostgreSQL DB `hwax_interactions`(원문 · 무기한)
                                 │  밤 배치(GLM · BGE-M3)
                     ② 가공층 — 가림 · 가명 · 요지 · 주제 · 앱 · 의도 · 결과 신호 · 임베딩
                                 │
                     ③ 활용층 — 내 기록 · 분석가 화면 · 집계 화면 · 평가셋 내보내기 · 지식 후보 큐
```

### 4-1. 원장층(원문)

- **저장소** — AIDataHub 가 띄우는 PostgreSQL 인스턴스에 **따로 된 DB `hwax_interactions`**(주인은 포털). 같은 인스턴스를 쓰되 DB 를 나눠, AIDataHub 의
  덤프 · 조각 동기화(dev → cae00 병합)에 절대 섞이지 않게 한다. 백업은 이 박스의 `backup-local.sh` 에 대상으로 더한다(Drive 로 내보내지 않는다).
- **한 줄 = 한 사건(event)** — 공통 칸: `id` · `ts` · `surface`(web_chat · web_delib · think · routine · procedure · mcp_call · tool_search · delib_job · risk ·
  shared_claude) · `actor`(사람 이메일 — PAT sub · 세션 sub) · `affiliation`(그때의 소속) · `client`(브라우저 · Claude Code · Claude Desktop · 앱 이름) ·
  `conv_id` · `turn_id` · `corr`(게이트웨이 연결 ID) · `app` · `tool` · `model` · `status` · `ms` · `tokens_in/out` · 본문 칸(`input` · `output` — JSONB 또는 글) ·
  `meta`(JSONB) · `source_ref`(원래 저장소의 id — 되짚기 · 중복 막기).
- **겹치기 막기** — 웹 챗이 부른 도구는 게이트웨이도 본다. `corr` · `source_ref` 로 한 사건을 한 번만 세고, 게이트웨이 줄에는 `via`(pat · panel · procedure ·
  routine · agent)를 남겨 「사람의 개인 Claude」 와 「포털이 대신 부른 것」 을 가른다.
- **비밀은 원문이어도 남기지 않는다** — 수집 전에 칸 이름(authorization · token · api_key · password · secret · cookie …)과 값 꼴(Bearer · PAT · JWT · 키 꼴)로
  지운다(`<가림:token>`). 원문 저장(IX-2)의 예외가 아니라 그 전제다 — 비밀이 원장에 들어가면 열람 권한이 곧 자격 탈취가 된다.
- **큰 것** — 결과 원문은 한 줄 상한(기본 1 MB, 손잡이)까지 넣고, 넘으면 앞부분 · 크기 · sha256 을 남긴다. 그림은 base64 를 넣지 않고 게이트웨이 그림 보관소
  ref 를 남긴다(그림 보관 기한 7일 — 무기한으로 남길지는 M3 에서 정한다).
- **수집이 호출을 막지 않는다** — 게이트웨이는 호출 끝에서 로컬 스풀 파일(JSONL, 크기 회전)에 한 줄 덧붙이기만 하고, 포털 수집기가 스풀을 가져간다. 포털이
  내려가 있어도 스풀에 쌓였다가 나중에 들어간다. 스풀이 넘치거나 수집이 멈추면 상태판 · update-all ✗ 로 알린다(무음 실패 금지).

### 4-2. 공유한 Claude 대화(IX-3)

- **MCP 도구 `share_conversation`**(게이트웨이 로컬 도구) — 사람이 「이 대화 공유해」 하면 Claude 가 부른다. 받는 것 — 대화 제목 · 메시지 목록(역할 · 글) ·
  사람의 한 줄 동의(도구 설명에 「사람이 공유하라고 한 때만 부른다」). Claude 가 다시 적어 보내는 글이라 긴 대화는 빠질 수 있다 — 그래서 아래 훅을 함께 둔다.
  지금 `save_conversation`(심의 워크플로가 대화 저장소에 쓰는 것)은 그대로 두고, 그것도 원장에 S1 으로 들어온다.
- **PC 킷 훅**(Claude Code) — 토큰 페이지의 설정 배치가 고를 수 있게 설치한다(기본 끔 — 사람이 켠다).
  - 명령 한 줄 `/hwax-share`(Claude Code 사용자 명령) — 지금 세션의 기록 파일(`~/.claude/projects/<…>/<세션>.jsonl`)을 원문 그대로 포털에 올린다.
  - 선택 — 세션 끝마다 자동 올리기(`SessionEnd` 훅). 켜고 끄기는 사람 몫.
  - 올리는 곳 — 포털 `POST /interactions/share`(그 사람 PAT · 이 기능 권한). 같은 세션을 다시 올리면 덮어쓴다(세션 id 로 하나).
  - 올리기 전 가림 — 위 비밀 가림을 PC 쪽에서도 한 번(토큰이 기록에 남는 경우가 있다).
- Claude Desktop 은 훅이 없어 도구 길만 쓴다.

### 4-3. 가공층(가린 사본)

- 밤 배치(GLM — 띵킹 · 심의가 없는 때, 동시 수 손잡이) — 사건마다 ① 개인정보 가림(게이트웨이 · 에이전트 서버의 가림 규칙 재사용 — HG-21 · HG-22 고친 것)
  ② 요지 한두 줄 ③ 주제 · 앱 · 의도(조회 · 해석 · 비교 · 작성 · 운영) ④ 결과 신호(성공 · 도구 못 찾음 · 도구 오류 · 자기검증 고침 · 확인 거절 · 근거 없음 · 사람이
  다시 물음) ⑤ BGE-M3 임베딩(요지).
- 사람은 가명(이메일의 키 해시 — 키는 박스 비밀)으로, 소속은 5명 이상 묶음으로만(OD-9 과 같은 k).
- 가공본은 원문 id 를 가리켜, 본인이 지우기를 청하면 원문 · 가공본 · 임베딩을 한 번에 지운다.

### 4-4. 활용층

| 화면 · 산출 | 누가 | 무엇 |
|---|---|---|
| 내 기록 | 본인(모든 사용자) | 내 웹 챗 · MCP 호출 · 공유한 Claude 대화를 한 줄로 · 검색 · 지우기 청구 |
| 분석가 화면 | `feat:interaction-analyst`(개별 허가 · `grant_only` — 「전부」 · 관리자 전권에 딸려 오지 않는다) | 원문 검색 · 거름(출처 · 앱 · 기간 · 결과 신호) · 원문 열기마다 감사 행 |
| 집계 화면 | 관리자 · 분석가 | 주제 · 앱 · 결과 신호 · 수요 지도(가공층만 — 원문 없음) |
| 평가셋 내보내기 | 분석가 | 도구 검색 정답 후보 · A/B 재생 질문 묶음(가린 본) — 게이트웨이 `search-eval` · 심의 측정 러너가 받는 꼴 |
| 지식 후보 큐 | 분석가가 올리고 전문가 · 운영자가 승인 | 되풀이 질문 + 좋은 답 → 지식카드 · FAQ 초안 → 승인되면 AIDataHub |
| 실패 지도 보고 | 분석가 | 플랫폼마다 실패 신호 상위 → 그 플랫폼 세션에 보낼 요청서 초안 |

## 5. 알림 · 동의 — 수집 사실을 숨기지 않는다

- 토큰 페이지 · 웹 챗 첫 화면 · 게이트웨이 `initialize` 의 instructions · `share_conversation` 설명에 「이 포털을 거친 대화 · 도구 호출은 기록되어 품질 개선과
  지식 정리에 쓰인다 · 원문은 본인과 지정 분석가만 본다 · 지우기를 청할 수 있다」 를 적는다.
- 회사 개인정보 · 보안 규정과 맞는지는 **사람이 확인한다**(이 계획의 전제 — M1 을 cae00 에서 켜기 전에).
