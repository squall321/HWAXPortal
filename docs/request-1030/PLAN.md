## 어떻게 하나

사용자 지시 「울트라 코드로 꼼꼼히」 · 「서브에이전트 많이 나눠서」 · 「중간중간 진행상황」 을 이어 받는다.

1. **설계(높음 넷)** — HA-27 · HA-28 · HA-29 · HA-30 은 코드를 깊게 읽는 설계 에이전트가 먼저 안을 낸다. 셋이 같은 도구 래퍼(`_cap_tool.capped`)를 지나므로 맞물림을 함께 본다.
2. **구현** — 행(또는 같은 자리를 만지는 행 묶음)마다 형제 워크트리(`<Repo>-wt-1030-<행>`, 가지 `wt1030/<행>`)에서 고친다. 워크트리에서는 그 행의 시험만 돌린다(dev 메모리 — 시험 스위트는 한 번에 하나).
3. **블랙박스 시험** — 구현을 보지 않고 요청서 행과 설계만 읽은 에이전트가 시험을 따로 쓴다. 맞대 보고 어긋나면 누가 맞는지 가린다.
4. **합치기** — 가지를 main 에 차례로 합치고, 리포마다 전체 회귀를 한 번에 하나씩 돌린다(회귀 도중 커밋 금지).
5. **반대 검토** — 고친 것마다 반박하려는 검토자를 붙이고, 확인된 것만 고친다. 고침은 변이 시험으로 시험이 실제로 잡는지 본다.
6. **올리기** — 리포마다 끝난 것부터 push, 화면을 고쳤으면 빌드 + Drive, 업데이트 이력, cae00 안내(`server-setup.md`), CLAUDE.md 문서 표.
