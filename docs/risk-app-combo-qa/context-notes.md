# 리스크 심사 앱 조합 QA — 결정 기록

**RQ-1 조사(2026-11-01) — 앱을 바꿔 볼 수 있는 자리는 엔진의 `apps` 하나다.** 리스크 앱 패널은 잡마다 앱을 고르지 못하고 늘 세 어댑터를 싣는다.
모든 리스크 좌석에는 끌 수 없는 keep set 이 붙는다. 그래서 QA 는 리스크 앱의 패널이 아니라 엔진 `deliberate_start(job='risk-review', apps=…)` 로
조합을 바꿔 돌리고, 결과를 조합 과제에 패널 결과로 들여 판정 · 셈을 앱의 장부 위에서 한다. 카드 대조(셀 흐름)는 도구를 부르지 않아 앱 조합의
영향이 원천 종류 · B층 · 쟁점 패널에만 닿는다 — 이번 QA 는 패널 길(조회 범위)만 잰다. 원천 종류 조합(셀 흐름)을 재는 실험은 GLM 으로 따로 할
수 있다(조사안의 Part S — 이번 범위 밖). 조용한 넓힘(좁힌 풀이 도구 1개 이하 · 도구 지도 실패 → 전체 범위)은 그 실행을 무효로 본다.

**RQ-2 사용자 결정 넷(2026-11-01).** ① 모델 — Claude Sonnet(실제 Claude 심사에 쓸 급과 같아야 결과가 들어맞는다 — Haiku 결론이 Sonnet · Opus 에
맞는다는 보장이 없다). ② 규모 — 작게 시작(실제 변경 3 × 조합 6 × 반복 2, 기준 3, 1라운드로 고른 뒤 기준과 상위 둘만 3라운드). ③ 제품 반영 —
앱 정책 칸(필수 + 변경 종류별 조건부)을 함께 짓는다. ④ 정답 — 도메인 담당자가 QA 과제의 라벨로 판정하고, QA 과제는 코퍼스에서 뺀다.

**RQ-3 '방법만 해 둔다'(사용자 11-01 — "cae00 에서 할거니까 방법만 해둬").** dev 에서는 QA 를 돌리지 않고 cae00 이 따를 방법(PLAN)만 쓴다.
앱 정책 칸(RQ-2 ③)도 지금 짓지 않고 결과가 나온 뒤 dev 에서 짓는다 — 기본값을 정할 근거가 그 결과이고, '방법만' 이 지금의 범위라서다. 바로
지어야 하면 사용자가 말한다(그때 기본값은 지금의 세 어댑터).

**RQ-4 격리 — 조합마다 QA 과제 하나.** 같은 과제에서 대상을 새로 열면 옛 대상이 밀리고 결과가 이어지며, 같은 대상에 조합을 쌓으면 등록부 병합이
조합을 섞는다. 그래서 조합마다 과제를 나누고 `corpus_excluded=1` 로 다른 심사의 선례 · 지표 · 학습에서 뺀다. 강제 재시도는 앞 판정을 지우므로
제자리 다시 돌리기를 하지 않고 먼저 내보낸다.

**RQ-5 원 자료는 cae00 에만.** 실행 기록 · 전사 · 판정에는 설계 · 사람 이름 · 실제 제품이 든다. 이 리포는 공개라 익명 합계(앱별 재현율 · 고유 수 ·
결론)만 사용자를 거쳐 옮긴다. RA 에는 쓰지 않는다(리스크 앱의 RA 쓰기가 cae00 에 서지 않았다).
