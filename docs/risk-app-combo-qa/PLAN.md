## 0. 한 줄

실제 변경 셋을 고정된 근거 · 좌석으로 두고 **앱 조합만 바꿔** 같은 심의를 되풀이한다. 사람이 '실제 리스크' 라고 판정한 것을 기준으로
조합마다 찾은 수 · 그 앱만 찾은 것 · 앱을 뺐을 때 줄어드는 몫을 반복 간 흔들림과 견줘, 앱을 **필수 · 조건부(변경 종류별) · 뺌** 으로 가른다.

## 3. cae00 에서 돌리는 차례

1. **준비(읽기만)** — 리스크 앱이 `2460cd0` 이상인가 · 에이전트 서버 `EXTERNAL_LLM_ENABLED` · 게이트웨이에 `risk_*` · `review_task_*` 도구가 뜨는가
   (HWAXRisk `scripts/rr_gateway_check.py` — 소스가 아니라 `tools/list` 로 본다) · 돌릴 사람의 포털 PAT 가 리스크 앱에 등록됐는가 · 상자 점검
   `infra/scripts/risk-review-inventory.sh`.
   - `EXTERNAL_LLM_ENABLED` 가 꺼져 있으면(기본) `docs/risk-review-redesign/server-setup-m3.md` 8절대로 켠다 — 사람이 하고, 켠 뒤 에이전트 서버 재기동.
   - 돌릴 사람의 리스크 앱 자격 — 앱 화면 설정의 포털 PAT 줄(또는 `GET /api/me`)에서 등록 출처가 게이트웨이 교환이고 청중에 `mcp-gateway` · `step-forge`
     가 다 있는지 본다(없으면 위임 캡처의 REST 다리가 닫힌다 — RK-02, 화면이 까닭을 말한다). 실제 변경 캡처는 웹 화면으로 해도 된다.
   - 이 일을 이어받는 cae00 세션의 출발점 — 이 PLAN · [checklist](checklist.md) · 받은 편지함 `docs/cae00-inbox/2026-11-01.md` Q1 · Q2.
2. **대상 캡처(M0-d — 사람)** — 1절의 조건대로 실제 변경 3쌍. 과제 만들기 → 원천 등록(StepForge · DynaForge · KooRemapper · ODB) → 두 판
   스냅샷 → 비교 대상 열기. 조합 과제(2절 격리)마다 같은 스냅샷이 서도록 같은 원천으로 연다(같은 주인이면 두 과제 사이 비교도 된다).
3. **실행 기록 만들기** — 한 줄에 한 실행: 대상 · 조합(앱 목록) · 반복 번호 · 모델 · 얼린 브리프 해시 · 팩 해시 · 게이트웨이 도구 지도 해시 ·
   시작 · 끝 시각 · 잡 id. 기록은 cae00 에만 둔다(설계 · 이름이 든다).
4. **돌리기** — 실행마다 `deliberate_start(job='risk-review', evidence=<얼린 브리프>, personas=<좌석 6>, apps=<조합>, voc='off',
   save_report=false, stop_after_round=1, llm=외부 응답자 + 반출 동의)` → 그 사람의 Claude Code(Sonnet)가 외부 응답자 워크플로로 과제를 집어 답한다.
   **유효성** — '앱 범위 제한 불가 — 전체 범위로' 카드가 뜬 실행(1절 조용한 넓힘)은 버리고 다시 돈다. 좌석별 조회 성공(`tool_calls_ok`)을 적는다.
5. **결과 모으기** — 결정문의 리스크 명세를 조합 과제의 대상에 패널 결과로 들인다(`risk_submit_panel_result`) — 그래야 finding · 등록부 묶음 ·
   라벨이 그 조합 과제에 선다. 들이기 전에 원문을 `GET /export` 로 남긴다.
6. **판정(도메인 담당자 — 사용자 결정)** — 조합들을 합친 묶음(같은 리스크는 `cluster_key` = 메커니즘 · 세부 · 대상 부품 키 · 변경 종류로 맞대고,
   부품 키가 원천마다 다르면 `family_key` + 부품 이름으로)마다 '실제 리스크인가' 를 판정해 그 조합 과제의 finding 에 라벨로 남긴다
   (`POST /findings/{id}/labels` — source `expert_review`, outcome `confirmed` · `refuted`). 셀 묶음 중대 이상 · 기각 아님 · 끊긴 인용 없음 ·
   경험칙보다 위인 것만 판정 대상으로 올린다(판정 짐을 줄인다).
7. **셈** — 조합별로 —
   - **실제 리스크 재현율** = 그 조합이 찾은 판정 '실제' 묶음 수 / 모든 조합이 찾은 '실제' 묶음 합집합.
   - **앱별 고유 실제 리스크** = 그 앱이 든 조합만 찾은 '실제' 묶음 — 인용으로 앱에 매긴다(`tool:<호출>` → `rr_panel_calls.tool` → 게이트웨이
     `/tools-map` 의 앱, `p:` · `e:` → `rr_ir_nodes.source_kind`, `tool:b-` → B층, `voc:` · `paper:` → E10).
   - **뺐을 때 줄어드는 몫** = A1 대비 A2 ~ A4 의 재현율 차 — **잡음 바닥**(A1 반복끼리의 차) 보다 클 때만 센다.
   - 근거 없는 묶음 수 · 앱별 호출 성공률 · 비용(과제 수 · 시간).
8. **결론 규칙**
   - **필수** — 빼면 실제 리스크 재현율이 잡음 바닥보다 크게 떨어지는 대상이 **둘 이상**이거나, 그 앱이 없으면 도메인 좌석이 서지 않는다
     (예 StepForge 없으면 mech · xd 좌석이 대표 하나로 준다).
   - **조건부** — 그 앱의 고유 실제 리스크가 한 변경 종류에 몰린다 → 비교의 변경 종류를 열쇠로 붙인다(예 재료 교체 → MaterialTwin, 보드 변경 → ODB).
   - **뺌** — 고유 실제 리스크가 없고 비용 · 잡음만 늘린다.
   - keep set 은 끌 수 없어 A0 대 A1 로만 보인다(빼는 판단 대상이 아니다).
9. **보고** — 원 자료(과제 · `/export` · 잡 id · 전사 · 실행 기록 · 판정)는 cae00 에만 둔다. 셈과 결론은 cae00 의 스크래치 마크다운 한 편으로 쓰고,
   **익명 합계만**(앱별 재현율 · 고유 수 · 결론) 사용자를 거쳐 이 폴더에 옮긴다 — 이 리포는 공개다. RA 에는 쓰지 않는다(리스크 앱의 RA 쓰기가
   cae00 에 아직 서지 않았다 — RK-01 은 M4).

## 4. 비용 어림(Sonnet)

- 1라운드 고르기 — 6석 × 1라운드 ≈ 판단 호출 6 ~ 12 + 조회 과제 ≤ 24 → 실행 하나에 과제 약 20 ~ 35. 3 대상 × (조합 5 × 2 + 기준 3) = 39 실행 →
  과제 약 800 ~ 1,400.
- 3라운드 — (기준 + 상위 둘) × 3 대상 × 2 ~ 3 반복 ≈ 21 실행 × 과제 약 50 ~ 140 → 약 1,000 ~ 3,000.
- 합계 과제 약 2,000 ~ 4,500. 워크플로 한 번의 상한(약 800 에이전트) 때문에 여러 번 나눠 돌린다. 시작 전에 사용자에게 이 어림을 한 번 더 보인다.

## 5. 앱 정책 칸(제품 — 사용자 결정 '함께 짓는다', 결과가 나온 뒤 dev 에서)

- **무엇** — 리스크 앱 과제(또는 대상)에 앱 정책 `{mandatory: [앱…], conditional: [{change_kind, apps}], optional: [앱…]}` 을 둔다. 패널을 계획할 때
  `apps` = 필수 ∪ (그 비교의 변경 종류에 걸린 조건부) ∪ (사람이 고른 선택)으로 푼다. 기본값은 지금 세 어댑터다.
- **엔진** — `deliberate_start` 의 `apps` 상한 3 을 늘리거나(어댑터만으로 세 자리가 찬다) 어댑터를 따로 세는 칸을 둔다. keep set 은 그대로.
- **채우기** — 3절 8의 결론(필수 · 조건부)을 기본값으로 넣는다. 결론 전에는 짓지 않는다 — '방법만 해 둔다'(사용자 11-01). 결과가 오면 dev 에서
  리스크 앱 · 에이전트 서버를 고치고 SIF · Drive 로 cae00 에 보낸다(cae00 은 SIF 를 짓지 못한다).

## 6. 함정

- **조용한 넓힘**(1절) — 그 실행은 '조합' 이 아니라 '전체 범위' 다. 카드로 가려 버린다.
- **결과가 알려진 옛 쌍의 누수** — `as_of` 는 지식 검색만 거르고 keep set 의 VOC 는 `apps` 로 못 끈다 — 뒤의 현장 정보가 샐 수 있어 그 쌍은 따로 읽는다.
- **Claude 는 온도를 못 고른다** — 반복이 필요한 까닭이다(GLM 은 0).
- **반출 동의** — Claude 잡마다 사람이 동의한다(설계 자료 · 지식카드가 나간다).
- **판정 짐** — 3절 6의 거르기(중대 이상 · 기각 아님 · 인용 성함)로 줄인다. 판정자에게 조합 이름을 숨기면 치우침이 준다.
