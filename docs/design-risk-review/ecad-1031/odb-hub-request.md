# ODB 허브에 보내는 요청 — 리스크 심사 ECAD 2단계(묶음 읽기, 2026-10-31)

받는 곳은 ODB 허브(게이트웨이 백엔드 `odb-hub`) 담당이다. 이 세션 · 사용자의 리포가 아니라 **사람이 보낸다.** 근거와 실측은 [`request.md`](request.md) 3절 · 부록 A · B 에 있다(cae00 10-31, 표본 보드 둘에 읽기 도구만 불렀다).

**사용자 결정(10-31, D-1 = 가)** — 계약 4도구를 새로 내지 않고 **지금 도구에 묶음 읽기를 더한다.** 200건에서 말없이 잘리는 일은 리스크 심사뿐 아니라 심의 좌석 · 챗도 같은 도구로 겪으므로, 지금 도구를 고치는 쪽이 모두에게 낫고 도구 수도 늘지 않는다.

| # | 등급 | 무엇이 | 할 일 |
|---|---|---|---|
| OH-01 | 높음 | `find_nets` 가 200건에서 말없이 자른다(`limit=20000` 도 `count=200`, total · offset · has_more 없음, 동점 묶음 가운데서 잘림). | offset · total · has_more 를 내고, 자를 때는 `truncated: true` 와 상한을 적는다. 넷마다 핀 수(`pin_count`)를 목록에 함께 싣는다. |
| OH-02 | 높음 | 부품을 한 번에 읽는 길이 없다(`list_parts` page_size 가 100 으로 줄고, 좌표 · 회전 · 넷이 없고, 분류 안 된 부품을 빼거나 그 범주로 거를 수 없다). | `list_parts` 에 분류 안 된 부품 포함 선택지 · x · y · rotation · mirror · 넷 이름(넷당 1개) 칸을 두고 page_size 를 2000 까지 받는다. |
| OH-03 | 중간 | 넷이 200개 넘는 부품은 넷을 다 얻지 못한다(`get_part_detail.nets` · `find_nets(refdes=…)` 둘 다 200, 정렬이 달라 합쳐도 빠진다). | 부품 하나의 넷 전체를 내거나 offset 을 받는다. |
| OH-04 | 중간 | 보드 외곽을 부품 좌표와 같은 기준으로 내지 않는다(폭 · 높이 · 면적뿐, 원점이 보드마다 다르다). | 외곽 bbox(min · max, 부품 좌표와 같은 기준)를 낸다. |
| OH-05 | 낮음 · 선택 | 넷 총수 · ODB++ 형식 판 · 넷 분류 · 동박층 plane 구분 · 원판 동박 무게 · 부품 높이 전체가 없다. | ODB 에 있는 것만이라도 낸다. 없으면 없다고 문서에 적는다. |

**다시 볼 시험** — `find_nets` 를 offset 으로 끝까지 읽었을 때 total 과 받은 수가 같고 잘렸으면 표지가 있다(OH-01). 분류 안 된 부품을 포함한 목록 수가 `get_volume_result` 의 배치 수와 같다(OH-02).

**우리 쪽** — 리스크 심사 앱은 1단계(지금 도구로 보드 · 적층 · 분류된 부품)를 먼저 하고, OH-01 · OH-02 가 들어오면 2단계(부품 좌표 · 넷 · 넷 노드 · 부품→넷 엣지)를 한다(ER-06).
