# 리스크 심사 ECAD 싣기(10-31) — 판단 기록

## E-1 누가 하나

- 사용자(10-31) — 「ODB 허브는 나한테 없는데 리스크 심사 앱은 내가 개발한 쪽에 있다 — 확인해 보고 해당하는 세션에서 수정을 진행하게 하라」.
- 리스크 앱(HWAXRisk)의 살아 있는 세션이 없다. 백엔드는 그동안 포털 세션이 맡아 왔으므로(설계 리스크 심사 · M1 ~ M3) 이 세션이 1단계를 짓는다. 화면은 종전처럼 리스크 앱 화면 세션 몫이라 요청서로 넘긴다.
- ODB 허브는 바깥 팀 몫이라 사람이 보낸다(`odb-hub-request.md`).

## E-2 두 단계 · D-1

- 사용자 결정 D-1 = (가) — ODB 허브가 지금 도구에 묶음 읽기(OH-01 ~ OH-04)를 더한다. 계약 4도구를 새로 내는 (나)는 고르지 않았다 — 200건 잘림은 심의 · 챗도 같은 도구로 겪는다.
- 그래서 리스크 앱 1단계는 지금 도구(게이트웨이 odb-hub 39개)로 보드 · 적층 · 분류된 부품만 싣고, 빠진 칸은 표지(ER-04)로 남긴다. 좌표 · 넷은 2단계(ER-06)다.
- dev 게이트웨이에는 odb-hub 가 없다. 그래서 시험은 요청서 부록 A(cae00 실측 꼴)로 지은 가짜로 하고, 실물 확인은 cae00 다시 볼 시험(요청서 6절)이다.
