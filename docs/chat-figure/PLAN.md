# 챗 그림 — 눌러서 크게 보기 + 보이는 품질

## 문제 (사용자 보고 2026-09-09)

"이미지를 html 로 그리는 경우 가로로 아주 길게 나오면 잘 안 읽힌다. 눌러서 확대해 볼 수
있어야 할 것 같다. 그리고 UX 퀄리티도 보강해야 한다 — 그림이 fancy 해 보여야 한다."

## 지금 어떻게 되어 있나

챗 본문에 그림이 나오는 표면이 **셋**인데, 셋 다 챗 칼럼 폭에 그냥 눌린다.

| 표면 | 지금 | 문제 |
|---|---|---|
| `.md-img` — 도구 산출 그래프(`/agent/artifacts/…`) | `max-width:100%` | 가로로 긴 차트가 축소돼 축 라벨을 못 읽는다. 확대 수단 없음 |
| `.md-mermaid` — 구조도 SVG | 컨테이너에 그대로 | 노드가 많으면 글자가 뭉갠다. 확대 수단 없음 |
| `.preview-frame` — html/svg 펜스 sandbox iframe | 고정 높이 | '새 탭' 은 있는데 챗 안에서는 못 키운다 |

셋 다 **클릭해도 아무 일이 없다.** 크게 보려면 이미지를 새 탭에 직접 여는 수밖에 없고,
mermaid 는 그것도 안 된다(SVG 가 DOM 안에만 있다).

## 만들 것

### ① 라이트박스 — 눌러서 크게

세 표면이 **하나의** 오버레이를 공유한다. 표면마다 따로 만들면 조작감이 갈린다.

- 클릭·Enter 로 열기(그림 자체가 버튼이다)
- 배경 클릭·`Esc` 로 닫기
- 휠·`+`/`-` 로 확대·축소, 끌어서 이동, `0` 으로 맞춤 복귀
- 열릴 때 기본은 **화면 맞춤**, 한 번 더 누르면 **원본 크기(100%)** — 가로로 긴 그림은
  이게 실제로 읽는 방법이다
- 원본 열기·다운로드는 이미지일 때만(아티팩트 URL 이 있을 때)

### ② 가로로 긴 그림을 챗 안에서도 덜 답답하게

라이트박스가 근본이지만, 챗 본문에서도 한 단계 낫게 만든다.

- 그림이 칼럼보다 훨씬 넓으면 **축소하지 말고 가로 스크롤**로 둔다(축 라벨이 살아난다)
- 그때 "가로로 깁니다 — 눌러서 크게 보기" 를 한 줄로 알린다

### ③ 보이는 품질

- `<figure>` 로 감싸고 alt 를 **캡션**으로 쓴다(도구가 준 제목이 버려지고 있었다)
- 은은한 그림자·라운드·경계, 호버 시 살짝 떠오르고 우상단에 확대 아이콘
- 로딩 중 스켈레톤(높이가 튀지 않게)
- 라이트/다크 양쪽에서 흰 배경 차트가 뜨지 않게 배경 톤 정리

## 원칙

- **격리를 낮추지 않는다.** html/svg 미리보기는 라이트박스에서도 `sandbox="allow-scripts"`
  그대로다. `allow-same-origin` 은 어디에도 넣지 않는다.
- 그림이 곧 버튼이므로 **키보드로도 열린다**(`tabindex`·`Enter`·`Space`).
- 확대 상태는 오버레이 안에서만 산다 — 챗 본문 레이아웃을 건드리지 않는다.
- 애니메이션은 `prefers-reduced-motion` 을 존중한다.
