## Q1. 카드 ↔ 허브 객체 연결 범위(O0a)

까닭 — 전문가 고르기와 앉은 전문가의 카드 조회를 온톨로지에 이으려면 카드가 정본 허브 객체(고장모드 · 시험 항목 · 재료 물성 · 과제 · 모델 …)에 정확히 이어져야
한다. 카드의 절반 넘게가 논문 · 특허라 얼마나 이어질지 모르고, 허브가 이 박스에만 있어 여기서만 잴 수 있다. 숫자가 낮으면 짓지 않는다(계획 3.1 관문 G-EO1).

탐침은 정본 허브 `objects_list` 로 타입마다 이름 · 식별자 · 별칭 사전을 짓고, AIDataHub 카드를 문서 종류로 층화해 300장 뽑아 제목 · 요약 · 절을 맞춘 뒤
`objects_resolve_many` 가 exact 인 것만 센다. 부르는 도구는 읽기 다섯(허브 `objects_list` · `objects_resolve_many`, AIDataHub `list_records` · `get_record` ·
`get_record_sections`)뿐이고 그 밖은 부르기 전에 거절한다. 카드 글 · 사람 이름은 내지 않는다. 호출은 1,500 ~ 3,000번이라 몇 분 걸린다(호출 사이 0.05초 쉼).

```bash
cd ~/Projects/HWAXPortal                                   # update-all 로 이 글이 든 판을 받은 뒤
export HWAX_GATEWAY_PAT='<포털 /auth/pat 로 발급한 PAT>'     # AIDataHub 와 정본 허브를 읽을 수 있는 사람의 PAT
../HWAXAgentServer/.venv/bin/python infra/scripts/card-entity-probe.py; echo "rc=$?"
```

- 끝에 찍히는 요약(`summary.txt` 와 같다) 줄을 그대로 답에 옮긴다 — 수뿐이다. 결과 폴더(`infra/.state/card-entity-probe/<시각>/`)는 지우지 않고 둔다.
- `rc=2` 면 찍힌 까닭을 옮긴다(PAT 가 비었다 · 게이트웨이에 허브 도구가 없다 · mcp 모듈이 없다). `rc=3` 이면 요약의 '문제' 줄을 함께 옮긴다.
- 표본을 바꾸지 않는다(씨앗 20261103 · 층 기본값) — 같은 표본으로 Q3 와 견준다.

## Q4. CAD 위치 가시화 · 분석 — 실제 데이터로 끝에서 끝까지

까닭 — 짝 단면 · 묶음 · 접힘 · 적층 그림 · 그림 보관 · 보고서 넣기는 dev 에서 걸음마다 확인했지만, 실제 리스크 항목 → 위치 → 그림 → 보고서를 한 번에 돈 적이
없다. ODB 허브 · Report Archive · 실제 개정 CAD 가 이 박스에만 있다. 점검은 `infra/scripts/cad-figure-check.py` 가 차례로 부른다 — 읽기가 기본이고, 보고서 · 문서에
넣는 쓰기는 그 대상을 줄 때만 한다.

준비 — update-all 과 0절의 Drive 받기를 먼저 한다(hwax-risk `dist-20261103-011742Z` · step_forge `dist-20261104-135504Z` — a79, a77 · a78 까지 앞 판들을 품고 덮는다).
PAT 은 그 리스크 과제의 구성원이고 StepForge · ODB 허브를 읽을 수 있는 사람의 것이다.

1. 고를 것 보기(읽기) — 이름이 화면에 나오니 답에 옮기지 않는다. 기구 CAD 가 붙은 리스크 과제 하나와 그 CAD 의 다른 개정(견줄 판) StepForge 과제 하나를 고른다.

```bash
cd ~/Projects/HWAXPortal
export HWAX_GATEWAY_PAT='<포털 /auth/pat 로 발급한 PAT>'
PY=../HWAXAgentServer/.venv/bin/python
$PY infra/scripts/cad-figure-check.py list
```

2. 항목 — MCAD 몸체가 주제인 리스크 항목이면 변환 없이 된다(`--finding <id>`). 보드 부품(`--refdes`) · 넷(`--net`) · 보드 좌표(`--x --y`)로 하려면 그 과제에 보드 ↔ CAD
   변환이 등록돼 있어야 한다. 없으면 점검이 `transform_missing` 과 고칠 곳을 찍고 멈춘다 — 그때는 개인 Claude 로 `risk_propose_board_transform`(읽기)의 제안을 보고,
   맞다고 판단하면 `risk_set_board_transform`(쓰기 — 사람이 정한다)으로 적은 뒤 다시 돌린다.

3. 점검(읽기)

```bash
$PY infra/scripts/cad-figure-check.py run --project <리스크 과제 id> --refdes <부품> --compare <견줄 판 과제 id>; echo "rc=$?"
# 폴더블이면 접힌 상태도 — 힌지 축의 한 점 · 방향 · 각도 · 움직이는 쪽 파트 글롭
$PY infra/scripts/cad-figure-check.py run --project <id> --refdes <부품> --compare <id> \
    --fold '{"axis_point":[x,y,z],"axis_dir":[0,1,0],"angle_deg":180,"moving":["*<움직이는 쪽>*"]}'
# 두 보드 적층 그림 — 쌓임 축을 준다(축을 모르면 잡을 넣지 않고 까닭을 준다 — a76). 큰 보드는 측정 잡이 저절로 걸리고 진행이 움직인다
$PY infra/scripts/cad-figure-check.py run ... --stackup-other <다른 보드 과제 id> --axis-a z --axis-b z
```

4. 그림을 사람이 본다 — 결과 폴더(`infra/.state/cad-figure-check/<시각>/figs/`)의 그림을 열어 본다.
   - 두 평면이 그 부품 자리를 지나는가 · 강조된 파트가 그 부품인가(두 판 모두)
   - 간극 치수(D1 …)가 그럴듯한가 — 손으로 아는 값이 있으면 견준다
   - 접힘이면 움직인 쪽이 닫힌 자리에 있는가(그림 제목 `CLOSED STATE`)

5. (고르면) 보고서까지 — 시험용 RA 보고서 · MX 백서 문서를 하나씩 만들어 두고 그 id 로 돌린다. **쓰기다 — 시험용에만.** RA 화면에서 그림 블록이 들어갔는지 본다.

```bash
$PY infra/scripts/cad-figure-check.py run ... --ra-report <시험 보고서 id> --mxwp-doc <시험 문서 slug> --mxwp-section <절 id>
```

- 돌려받을 것 — 요약(`summary.txt`) 줄 그대로(상태 · 수 · 초만) · 끝 코드 · 4 의 판정(맞음 / 아님 + 까닭 한 줄) · 5 를 했으면 RA · MX 백서 화면에서 보인 것.
  이름 · id 는 적지 않는다.
