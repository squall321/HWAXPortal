## Q1 — MaterialTwin 자연 키(HH-10)

- **까닭** — MaterialTwinWeb 세션이 HH-10 을 보려 했는데 그 id 들이 dev DB 에 없다. id 는 박스마다 따로 매긴다. 같은 행을 dev 에서 찾으려면 자연 키가 필요하다 —
  출처는 제목 · DOI · URL · 로컬 경로, 값은 재료 이름 · 물성 키 · 값 · 단위 · 조건.
- **명령(읽기 전용으로 연다)** —

  ```bash
  DB=~/Projects/HEAXHub/var/app_data/materialtwin_web/materialtwin.db    # 없으면 ls ~/Projects/HEAXHub/var/app_data/materialtwin_web/
  python3 - "$DB" <<'PY'
  import sqlite3, sys
  db = sqlite3.connect(f"file:{sys.argv[1]}?mode=ro", uri=True)
  q1 = "SELECT id, kind, title, doi, url, local_path FROM source WHERE id IN (1534, 3184) ORDER BY id"
  q2 = ("SELECT v.id, v.material_id, m.name, v.property_key, v.value_num, v.value_text, v.unit, v.conditions, v.source_id "
        "FROM property_value v JOIN material m ON m.id = v.material_id WHERE v.id BETWEEN 67907 AND 67910 ORDER BY v.id")
  for q in (q1, q2):
      rows = db.execute(q).fetchall()
      print(len(rows), "행")
      for r in rows:
          print(r)
  PY
  ```

- **기대** — 출처 2행 · 값 4행(모두 `material_id` 254). 행이 모자라면 그 id 가 이 박스에도 없다는 뜻이다 — '없음' 이라 적는다(파일을 못 열었으면 '못 봄').
- **돌려받을 것** — 두 결과 그대로. 사용자가 MaterialTwinWeb 세션에 옮긴다(로컬 경로가 들어 있으니 리포에는 적지 않는다).
