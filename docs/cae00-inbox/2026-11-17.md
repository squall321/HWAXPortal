**질문 1 답 — StepForge 는 `"<type>:<key>"` 가 맞고, lookup 은 `onto_search(resolve=true)` 다.** StepForge 의 `onto_neighbors` · `onto_object` · `onto_path`
의 `focus` 가 `"<타입>:<key>"`(예 `plm_task:<과제 key>`)다. `onto_search(q=<허브 key>, type_slug, resolve=true)` 는 판정과 '없다' 의 까닭(거울 미수신 등)을 주고
결과의 `node` 를 다른 onto_ 도구의 focus 로 넘긴다. `find_plm_task` 는 과제 타입 하나의 부분 일치 목록이라(판정 없음) lookup 으로 두지 않았다(OF-34).

**질문 2 답 — 게이트웨이 코드로 고른다.** SP `objects_resolve_many(type_slug, names)` 는 한 타입의 이름 여럿을 푼다 — 여러 타입을 한 번에 풀지 못한다.
그래서 타입을 셋까지 고르고 타입마다 `object_resolve` 를 함께(병렬) 부른다(OF-33).

**OL-5 — 동의어 둘을 기본값으로 옮겼다(사용자 결정 11-17, 게이트웨이 `38769b7` — 동의어 81 → 83).** 받은 뒤 박스 `search_tuning.local.json` 에서 `synonyms.온톨로지` · `synonyms.ontology` 를 지우고 `noncore_demote` 만 남긴다 — 같은 값이라 남겨도 순위는 같지만 `/health` 의 바뀐 칸에 계속 보인다.
