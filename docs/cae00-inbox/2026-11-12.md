## Q11. StepForge 단계가 든 사람 기록 절차

StepForge 가 193 도구 전부의 입력 스키마에서 pydantic `title` 을 빼고 92 도구의 설명을 줄였다. 그래서 사람이 기록한 절차 가운데 StepForge 단계에 지문이
박힌 것은 다음 실행에서 '스키마가 바뀌었다 — 자동 진행하지 않는다' 로 멈춘다. 그 단계를 다시 기록해 저장하면 된다. 씨앗에서 들인 절차는 지문이 없어
멈추지 않는다(dev 는 0).

읽기 명령(포털 리포의 `backend` 폴더에서) —

```bash
python3 - <<'PY'
import sqlite3, json
c = sqlite3.connect("file:data/procedures.sqlite?mode=ro", uri=True)
latest = {}
for pid, vno, spec in c.execute("select procedure_id, version_no, spec_json from procedure_versions"):
    if pid not in latest or vno > latest[pid][0]:
        latest[pid] = (vno, spec)
n = sum(1 for v, s in latest.values()
        if any(str(st.get("backend") or "").startswith("heax-step_forge") and st.get("schema_fp")
               for st in (json.loads(s).get("steps") or [])))
print("StepForge 단계에 지문이 박힌 절차(최신 판)", n, "/", len(latest))
PY
```

돌려받을 것 — 그 수. 파일을 못 열면 '못 봄' 과 까닭.

## Q14. MaterialTwinWeb 비공개 전환 준비 — 읽기 전용 토큰을 먼저

사용자 결정으로 MaterialTwinWeb 저장소가 비공개로 바뀐다. 전환 뒤에는 허브의 익명 받기가 막혀 새 커밋이 들어오지 않는다(앱은 받은 SIF 로 계속 뜨고
`source_unavailable` 경고만 난다). 그래서 **토큰을 전환 전에 심는다** — 받기가 끊기는 구간이 생기지 않는다.

- 순서 — ① 이 글의 update-all(Q1) ② 토큰(아래 0 ~ 2) ③ 사용자가 GitHub 에서 비공개로 돌린다 ④ 확인(아래 3 · 4 — 전환 뒤). 전환은 라운드 사이에 넣는다.
- 토큰은 사용자가 만들어 건넨다 — fine-grained personal access token · 이 저장소 하나만 · 권한 `Contents: Read-only` 하나 · 만료일. 값은 리포 · 글 · 채팅에
  적지 않는다. 주소에 토큰을 박지 않는다(로그 · 프로세스 목록에 찍힌다).
- 허브 백엔드(uvicorn · celery worker · beat)는 호스트에서 start.sh 를 돌린 계정으로 뜨고 git 을 그 계정의 환경 그대로 부른다. 그래서 그 계정의 git 자격
  도우미에 넣으면 코드 고침 없이 받는다(HEAXHub 세션 확인 — 기동 스캔 · 5분 스캔 · `redeploy-app.sh --rebuild` 셋이 같은 길이다. 셋째는 같은 계정으로 sudo 없이).
- 지금 판의 기준 — MaterialTwin main `4273720` · SIF 파일 sha256 `36668c27…`. 이 박스가 받은 판이 다르면 알려 달라.

백엔드를 돌리는 계정으로, sudo 없이 —

```bash
# 0) 백엔드 · 워커의 계정과 env — user 가 지금 로그인한 계정이고 HOME 이 그 홈이며, XDG_CONFIG_HOME · GIT_CONFIG_* · GIT_ASKPASS 줄이 없어야 한다
for pat in '\.venv/bin/uvicorn app\.main:app --host 0\.0\.0\.0 --port 4040' '\.venv/bin/celery -A app\.workers\.celery_app worker'; do
  pid=$(pgrep -nf "$pat"); echo "== pid=$pid user=$(ps -o user= -p "$pid")"
  tr '\0' '\n' < /proc/$pid/environ | grep -E '^(HOME|XDG_CONFIG_HOME|GIT_[A-Z_]+)='
done
cd <HEAXHub 리포 루트> && { grep -nE '^(export )?(HOME|XDG_CONFIG_HOME|GIT_[A-Z_]+)=' .env || echo ".env 덮어쓰기 없음"; }
git config --global --get-regexp '^credential' || echo "기존 credential 설정 없음"

# 1) 읽기 전용 토큰을 0600 파일에 심는다(입력은 화면에 안 보인다)
umask 077; mkdir -p ~/.config/git
read -rs -p 'MaterialTwinWeb read-only token: ' TOKEN; echo
printf 'https://squall321:%s@github.com\n' "$TOKEN" > ~/.config/git/github-ro.cred; unset TOKEN
chmod 600 ~/.config/git/github-ro.cred
git config --global credential.https://github.com.helper "store --file=$HOME/.config/git/github-ro.cred"

# 2) 도우미가 잡히는지 — 1 이 나와야 한다
printf 'protocol=https\nhost=github.com\n\n' | git credential fill | grep -c '^password='

# 3) 비공개 전환 뒤 — 프롬프트 없이 통과해야 한다
GIT_TERMINAL_PROMPT=0 git ls-remote https://github.com/squall321/MaterialTwinWeb.git HEAD
GIT_TERMINAL_PROMPT=0 git -C <HEAXHub 리포 루트>/var/integration_workspaces/materialtwin-web/upstream fetch --dry-run origin

# 4) 다음 스캔(5분 안) 뒤 — 새 실패 줄이 없어야 한다
grep -E 'integration_fetcher git failed for materialtwin-web|source unavailable for materialtwin' <HEAXHub 리포 루트>/var/logs/worker.log | tail -3
```

- 받기가 된 뒤 허브 `var/sifs/materialtwin-web.def` 의 `upstream commit` 이 저장소 main 과 같은지 본다.
- 곁들여 권한다 — 허브 `.env` 에 `GIT_TERMINAL_PROMPT=0` 을 둔다. 자격이 없거나 만료됐을 때 git 이 사용자 이름을 묻느라 최대 300초 매달리지 않고 곧바로
  실패해 사유가 로그에 남는다(MaterialTwin 세션 권고). 모르는 키라도 허브 기동은 깨지지 않는다. 다음 허브 재기동(update.sh · heal.sh)부터 먹고,
  start.sh 만 다시 돌리면 이미 도는 프로세스를 그대로 두어 먹지 않는다. `redeploy-app.sh` 는 매번 `.env` 를 읽어 바로 먹는다 — 터미널에서 돌려 묻는 창에서
  멈출 수 있는 것은 이 길뿐이고, 백그라운드 프로세스는 터미널이 없어 원래 곧바로 실패한다(HEAXHub 세션 확인).
- 이 걸음은 HEAXHub 리포를 건드리지 않는다. 공개 상태에서 먼저 해도 아무 일이 없다(토큰이 안 쓰일 뿐이다). 토큰이 만료되면 앱은 그대로 뜨고 경고만 난다.

돌려받을 것 — 0 의 결과(계정 · env 덮어쓰기 유무 — 값은 빼고), 2 의 수, 전환 뒤 3 · 4 의 결과.
