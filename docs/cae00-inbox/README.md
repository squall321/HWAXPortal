# cae00 받은 편지함 — 운영 쪽 답이 필요한 물음

dev 세션이 운영 박스(cae00)에서만 볼 수 있는 값이나 바깥 팀의 답이 필요한 물음을 여기에 날짜별 마크다운으로 싣는다.
사용자 지시(10-31)다 — 사람의 답이 필요한 것은 dev 세션에서 바로 묻고, 바깥 답이 필요한 것은 포털 리포에 실어 보내 cae00 에서 읽는다.
까닭과 경계는 [`../request-1030/context-notes.md`](../request-1030/context-notes.md) C-20 이다.

**이 리포는 공개(GitHub)다.** 그래서 물음에는 실제 이름 · 내부 주소 · 토큰 · 메일을 적지 않고, 답은 리포가 아니라 사용자를 거쳐 돌아온다.

## 언제 읽나

- update-all 이 git 받기 뒤 `→ cae00 받은 편지함 — 이번 판(… → …)에 새로 들었거나 바뀐 글 N개` 줄과 파일 이름을 찍는다. 끝 요약에서도 다시 낸다.
  그 글을 읽는다. 경고가 아니라 할 일이다.
- 줄이 없으면 이번 판에 새 글이 없다. `· cae00 받은 편지함 — 받기 전 판을 몰라 … 가리지 못했다` 면 이 폴더를 직접 본다(`ls -t docs/cae00-inbox/`).
- 이미 답한 글이 고쳐져 다시 찍히면, 바뀐 물음만 다시 본다 — 글마다 '고친 날' 줄이 있다.

## 어떻게 답하나

1. **이 박스에서 읽기만으로 볼 수 있는 것은 글에 적힌 명령으로 본다.** 쓰기 · 재기동 · 설정 바꾸기는 하지 않는다. 글이 '쓰기' 라 적은 걸음은 사람이 정한다.
2. **이 박스에서 볼 수 없는 것은 글이 적은 받는 곳(팀 · 담당 · 다른 세션)에 넘긴다.** 넘기는 길은 이 박스에서 쓰는 길(사람에게 전하기 등)이다.
   넘긴 날과 받는 곳의 역할을 답에 적는다.
3. **답은 리포 밖 파일에 적어 사용자에게 건넨다** — 예 `~/portal-inbox-answers/<글 날짜>.md`, 물음 번호(Q1 …)마다 한 절. 사용자가 dev 세션에 옮긴다.
   - 이 리포에 커밋 · push 하지 않는다. 공개 리포이고, update-all 이 작업 트리를 origin 으로 되돌리며 리포 안의 새 파일은 자동 stash 로 쓸려 간다.
   - '사용자에게만' 이라 적힌 답(실제 제품 · 과제 이름, 사람 이름이 든 것)은 사용자에게만 준다. 다른 채팅 · 문서에 옮기지 않는다.
   - 값을 볼 수 없었으면 '없음' 이 아니라 '못 봄' 과 까닭을 적는다(명령이 실패했는지, 결과가 정말 비었는지를 가른다).
4. 이미 답한 물음은 다시 하지 않는다 — 답 파일에 적은 번호는 건너뛴다.

## 쓰는 법(dev 세션)

- 파일 이름은 `YYYY-MM-DD.md`(KST)다. 맨 위에 물음 표(번호 · 받는 곳 · 무엇 · 돌려받을 것), 그 아래 물음마다 절 하나 — 까닭 · 읽기 명령 · 기대 꼴 · 돌려받을 것.
- 실제 이름 · 내부 주소 · 토큰 · 메일을 적지 않는다. 요청서에서 가린 이름(프로젝트 A · B)은 그대로 쓴다. 클러스터 이름은 규모로 가린다(ste 24대 · stcx 356대).
- 박스를 바꾸는 걸음(재기동 · 설정 · 데이터)은 이 폴더가 아니라 그 요청 폴더의 `server-setup.md` 에 둔다. 이 폴더는 묻는 곳이다.
- 받은 답은 그 요청 폴더(`outbound.md` · `server-setup.md` · `context-notes.md`)에 옮기고, 이 폴더의 글에는 그 물음 아래 '답 받음(날짜) — 옮긴 곳' 한 줄을 단다.
